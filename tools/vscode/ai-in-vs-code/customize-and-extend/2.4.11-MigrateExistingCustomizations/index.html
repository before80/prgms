2.4.11 迁移现有自定义项

　　将现有 Local 自定义项迁移到 Copilot 运行框架，同时保留依赖的工作流。使用迁移列表执行支持的文件移动和转换，然后用代表性任务验证结果，再停用原始设置。

　　从下面适合你的自定义项路径开始。不需要完成本文中的每个迁移。关于保留 Local、MCP 机密、自定义发现路径和智能体工具名称的答案，请参阅迁移常见问题。

　　更广泛的工作流过渡（包括会话连续性、组织推广和策略验证）请遵循从 Local 迁移到 Copilot 运行框架。

注意：本文介绍迁移到 Copilot 运行框架。Claude 或 Codex 运行框架请使用提供商文档中的位置和格式。

当 GitHub Copilot 企业托管设置生效时，Claude 和 Codex 运行框架会被禁用。请联系部署设置的 IT 团队讨论访问权限。

打开迁移列表

更改自定义项之前：

  • 提交或备份可能更改的工作区文件、脚本和用户设置。
  • 选择在原始自定义项下可工作的小任务。记录预期结果、所需工具和审批，以便迁移后比较。
  • 审查每个项的源和目标。原始副本和迁移副本不会同步。
  • 如果不维护仓库，请使用 使用智能体迁移 准备拉取请求，或请仓库维护者进行更改。

　　工作区需要自定义迁移时，聊天中会出现通知。选择 审查迁移 打开列表。要直接打开：

  1. 在聊天视图或智能体窗口中，选择 Copilot 作为 会话目标。
  2. 从命令面板（Ctrl + Shift + P，macOS：Cmd + Shift + P）运行 Chat: Open Customizations。
  3. 选择 迁移。

　　迁移树按工作区和用户作用域分组检测到的工作。

选择迁移处理方式：

  • 迁移：选择组中的项，可用时审查或更改目标，然后选择 迁移。VS Code 执行支持的文件移动或转换。
  • 使用智能体迁移：在聊天中为需要语义更改或仓库工作的自定义项启动引导式迁移。此操作使用 Copilot 点数。智能体创建恢复包，默认保留源文件，并在清理源之前单独询问。工作区迁移可以准备拉取请求。
  • 审查：打开 需要手动审查 下的项，了解无法自动迁移的原因并编辑其源配置。

　　不想现在处理某组时，使用迁移组操作中的 忽略。选择 显示已忽略的迁移 恢复已忽略组。

　　保留备份，直到验证迁移。自动 MCP 迁移会移除成功迁移的源条目，而 使用智能体迁移 默认保留源文件。原始文件仍存在时，仅在验证后停用，避免两个副本都处于活动状态。

为什么需要迁移

　　Copilot 运行框架从 Copilot 文件夹和可移植格式读取自定义项。将自定义智能体、指令和技能从编辑器特定存储和配置的自定义位置移到原生运行框架文件夹，以便跨 Copilot 客户端发现。VS Code 可以转发配置位置中的文件以兼容现有编辑器工作流，但其他客户端不会继承这些设置。

注意：对于 Local 运行框架会话：智能体读取 VS Code 配置文件自定义项以及通过这些设置配置的额外位置。为 Copilot 运行框架移动自定义项不会改变 Local 运行框架读取的源。

将自定义项移到这些位置有以下好处：

  • Copilot 运行框架可以直接加载它们，无需依赖编辑器提供。
  • 工作区自定义项保留在仓库中，可以通过源代码管理共享。
  • VS Code 和 Copilot CLI 读取相同的 Copilot 自定义文件。GitHub Copilot 应用也使用仓库和 Copilot CLI 技能及 MCP 服务器配置。
  • 可以移除旧位置设置，避免维护重复副本。

　　目标取决于迁移类型和作用域。用户数据迁移保留用户作用域。工作区迁移保留在工作区。迁移树显示每组选择的目标。

　　自定义类型和受支持位置的完整列表请参阅 Copilot 自定义速查表。这些自定义项在 GitHub Copilot 应用中的显示方式请参阅相关文档。

迁移 MCP 服务器

　　MCP 服务器迁移将兼容配置移到 Copilot 运行框架直接读取的文件：

现有配置目标
工作区 .vscode/mcp.json对应工作区根目录的 .mcp.json
VS Code 配置文件 mcp.json$COPILOT_HOME/mcp-config.json，未设置 COPILOT_HOME 时为 ~/.copilot/mcp-config.json

　　自动迁移将工作区服务器写入工作区根目录 .mcp.json。团队应共享配置时，请将文件提交到源代码管理。远程或 Dev Container 会话中，路径和用户配置属于智能体运行的机器或容器。

迁移 MCP 服务器：

  1. 展开工作区或配置文件的 MCP 服务器 组。
  2. 选择要迁移的服务器。
  3. 审查源、目标以及目标格式无法保留的属性。
  4. 为组选择 迁移。也可以打开单个服务器并从详情页选择 迁移。
  5. 打开目标文件，用 Copilot 运行框架测试服务器。

　　VS Code 在从源文件移除迁移条目之前，会写入并验证每个目标条目。未选择的服务器和无法迁移的服务器保留在当前文件中。

　　带更改的迁移可能移除 VS Code 特定元数据，包括注册表更新信息、版本元数据、开发模式行为或每服务器沙盒设置。迁移页面列出每个服务器的更改。

重要：禁用状态不存储在 .mcp.json 或 mcp-config.json 中。VS Code 尽可能在当前配置文件中保留工作区禁用状态，但用户级禁用状态可能丢失。其他 Copilot 客户端和其他机器可能将迁移服务器视为已启用。使用前请在每个客户端中审查服务器的启用状态。

　　无法自动迁移的服务器出现在 需要手动审查 下。选择 审查 打开服务器详情和源配置。解决配置错误、缺失值或重复服务器名称，然后重试。也可以使用 使用智能体迁移 获得引导帮助。MCP 格式和受支持位置请参阅 MCP 配置参考。

迁移前检查 MCP 值

使用下表判断服务器能否自动迁移以及需要审查什么。

源配置迁移结果操作
标准 command、args、env、url 和 headers 值自动迁移并添加 tools: ["*"]检查服务器工具。不希望所有服务器工具可用时，将 * 替换为 Copilot 应调用的特定工具。
${workspaceFolder}、${workspaceRoot}、${workspaceFolderBasename}、${workspaceRootFolderName}、${cwd} 或 ${pathSeparator}VS Code 解析变量并写入当前值后迁移共享目标文件或在其他机器使用前审查结果值。
gallery、version、dev 或 sandboxEnabled带更改迁移并移除这些属性审查迁移警告。决定迁移后如何处理更新、开发行为或沙盒。
同一源文件中声明的合格非密码 promptString 或 pickString 输入迁移为环境变量引用审查生成的变量名和默认值。Stdio 条目可以在 env 中包含默认或空值。HTTP 条目在 URL 或标头中使用引用。
密码输入、命令输入、${command:...} 或其他不支持变量不会自动迁移如果环境变量满足要求，将输入替换为环境变量引用。不要将已解析机密复制到 MCP 文件。
${config:...}合格设置引用根据有效设置值迁移为环境变量条目共享文件前审查生成值。与环境变量引用不同，此转换可能将设置值写入目标配置。
${env:NAME}合格引用自动迁移为 ${NAME}保留引用，不写入解析后的环境值。在运行或连接服务器的宿主环境中定义变量。
cwd不会自动迁移仅在服务器需要时手动添加 cwd，并在智能体运行的机器上验证路径。
envFile不会自动迁移在启动智能体的环境中导出所需变量，并从 env 引用。不要将机密值复制到 MCP 文件。
SSE 传输不会自动迁移仅在服务器不支持 Streamable HTTP 时使用 type: "sse"。SSE 已弃用。
VS Code oauth 对象不会自动迁移移除嵌套对象以使用 OAuth 发现，或将支持的客户端设置转换为扁平 Copilot OAuth 字段。Copilot 提示时进行身份验证。
值为 null 的环境变量不会自动迁移移除条目或提供支持的值。
额外 VS Code 特定属性不会自动迁移重试前移除或替换不支持的属性。
目标或另一工作区根目录中同名但不同的服务器迁移停止，不更改源重命名或移除冲突服务器，然后重试。

重要：VS Code 每服务器沙盒设置和顶级 sandbox 规则不会转移到 Copilot 运行框架配置。Copilot 运行框架使用会话级沙盒设置。仅当启用本地沙盒和 MCP 服务器沙盒时，本地 stdio MCP 服务器才会在 Copilot 运行框架沙盒中运行。远程 HTTP 和 SSE 服务器不会在本地沙盒中运行。启用迁移服务器前请审查这些设置。

服务器需要手动处理时：

  1. 保留原始配置，直到 Copilot 服务器启动并提供预期工具。

  4. 决定如何提供机密、身份验证或环境特定路径。不要将敏感值复制到已提交文件。

处理没有文档化等价项的字段

不要将这些假设带入迁移后的脚本：

  • 嵌套输出信封：接受 PascalCase 输入别名并不意味着支持每个 Local hookSpecificOutput 字段。请发出文档化的 Copilot 输出。
  • 记录和工具 ID：不要要求每个事件都有 transcript_path 或 tool_use_id。Copilot 为智能体工作流中的特定事件记录记录路径，而不是所有工具事件。记录文件名或子字符串不能证明智能体读取或遵循了指令。
  • 匹配器行为：Local 忽略匹配器值。Copilot 应用文档化匹配器规则，包括兼容 PreToolUse 名称的不同语义。重新检查每个筛选器，包括无效模式及其不应匹配的工具。
  • SDK 回调类型：程序化回调不是 JSON 文件命令钩子。SDK 源中的字段（例如仅回调的提示词覆盖）不能证明 shell 钩子可以使用它。
  • 强制执行：ask 依赖交互式审批流；不要假设它会暂停无人值守会话。GitHub 还记录失败开放超时，包括策略钩子。指令或迁移钩子本身都不能建立安全边界。

替换工具集

　　用户定义工具集已弃用，Copilot 运行框架不支持。工具集文件将现有工具分组到可复用名称下，不实现工具。请移动工具选择，而不是文件。

注意：工具集文件仍是 Local 运行框架兼容功能。Copilot 工具 选项卡显示的工具组和受支持内置工具别名与用户定义工具集文件不同。

根据使用工具集的原因选择替代方案：

以前用途替代
为重复角色选择相同能力在自定义智能体的 tools 属性中直接指定受支持工具。
控制编辑器提供的工具在智能体自定义编辑器的 工具 选项卡管理工具可用性。选择保存在配置文件中，不是每请求工具集别名。
将命名组附加到提示词，例如 #reader描述任务并选择相关自定义智能体。用户定义 #reader 别名没有直接替代。
共享工作流及其外部集成将工作流打包为技能，将工具打包为 智能体插件中的 MCP 服务器。插件打包能力，不重建工具集别名或强制工具允许列表。

替换现有工具集：

  1. 打开其 .toolsets.jsonc 文件并列出包含的工具。展开对其他工具集的引用。
  2. 在自定义智能体 tools 列表、提示词文件和提示词文本中查找该集合的使用。遵循提示词文件迁移将提示词文件转换为技能。
  3. 在 Copilot 运行框架会话中审查 工具 选项卡中的可用工具。将每个旧工具匹配到所需能力。不要假设 Local 工具 ID 有相同 Copilot 等价项。
  4. 用受支持工具名称配置替代自定义智能体。将工作流指令保留在智能体或技能中，不要将工具集 JSON 复制进去。
  5. 移除原始集合前测试工作流并检查实际使用的工具。

例如，reader 集合可能组合代码搜索、符号用法、诊断和源代码管理更改。创建一个具有相应可用工具的审查智能体，不要将 reader 复制到其 tools 列表。能力依赖扩展时，保持扩展安装且编辑器连接。没有等价工具时，请适配工作流以使用显式附加上下文、添加适当集成或记录缺失能力。

重要：技能指令不能替代工具允许列表。将提示词转换为技能不会保留其 tools 选择。工具可用性也独立于权限和审批。

常见问题

适配自定义项时可以继续使用 Local 运行框架吗？

　　可以，前提是组织控制允许。在编辑器聊天视图中启动新会话，选择 Local 作为 会话目标。Local 运行框架可用性和自动 Copilot 选择取决于设置和组织策略。请参阅迁移期间保持 Local 可用。

　　管理员可以使用从 1.142 版开始提供的临时 vscode.temporaryDefaultToLocalHarness 企业托管设置。它保持 Local 运行框架可用并抑制自动 Copilot 路由，但 Local 不执行 Copilot 运行时独有的沙盒和权限规则。它不会覆盖从 1.143 版开始提供的 vscode.temporaryAllowLocalHarness: false。请审查管理员指导和安全注意事项。

为什么带输入提示的 MCP 服务器缺失？

　　需要 ${input:...} 或 ${command:...} 变量的服务器不会从 .vscode/mcp.json 或配置文件 mcp.json 转发到 Copilot 运行框架。因此服务器工具在会话中不可用。先在 Local 会话解决提示没有帮助：Copilot 转发在解析值（包括缓存值）之前拒绝这些变量。

　　将相同配置移到 .mcp.json 不会添加输入提示支持。迁移会将合格非机密输入转换为环境变量。密码输入或其他手动更改请参阅将输入提示替换为环境变量。保留原始配置，直到有受支持身份验证方法并在 Copilot 会话中验证工具。请参阅 MCP 输入变量以及未解决报告 microsoft/vscode#334271 和 microsoft/vscode#337311。

Copilot 可以在没有环境变量或文件的情况下将提示式机密传递给 HTTP MCP 服务器吗？

　　没有内置 MCP 配置选项可以将 VS Code ${input:...} 值或现有 SecretStorage 值读入 Copilot 运行框架 HTTP 服务器的身份验证标头。在输入上设置 password: true 不会改变此限制。

　　服务器支持 OAuth 时，请使用其支持的授权流程，而不是配置静态 bearer token。OAuth 是单独身份验证机制，不是转发提示式 API 密钥的方式。身份验证 UI 差距记录在 microsoft/vscode#339960。

　　服务器需要固定 bearer token 且要求同时排除环境变量和文件凭据时，Copilot 运行框架没有等价的內置输入提示工作流。评估受支持身份验证选项期间，请继续对该集成使用 Local。不要在共享或个人 MCP 文件中用字面机密替换占位符：个人文件也可能被工具读取并包含在日志或其他工件中。请参阅身份验证和机密。

需要将每个自定义智能体移到仓库 agents 文件夹吗？

　　使用原生 Copilot 位置，但不一定是仓库文件夹。共享智能体放在 .github/agents，个人智能体放在 ~/.copilot/agents。这些是跨 Copilot 客户端使用智能体的推荐位置。

　　chat.agentFilesLocations 设置未弃用，编辑器会从其他配置位置向 Copilot 运行框架转发智能体。这是兼容性支持，不是推荐设置：Copilot CLI 和 GitHub Copilot 应用不读取此编辑器设置。请参阅配置位置迁移。

　　动态下载的智能体，请配置生成它们的工具使用原生工作区或用户智能体文件夹。验证生成文件是有效智能体文件，并在所选运行框架的 Chat: Open Customizations 中出现。如果仍然缺失，请在缺陷报告中包含产品版本、本地或远程环境、路径和最小智能体定义。从报告中移除机密。

为什么协调者的子智能体调用停止工作？

　　Local 使用 runSubagent 调用子智能体。Copilot 运行框架使用原生 task 工具。要求特定 Local 工具名称的指令不会自动切换到 Copilot 工具。

　　请审查协调者的 Markdown 指令和 tools 列表。工作流应跨运行框架工作时，优先使用“将此审查委派给 reviewer 智能体”等指令。如果工作流要求显式工具调用，请适配其名称和参数到所选运行框架，而不只是重命名工具。验证每个专业智能体被发现并可用于子智能体调用。请参阅按运行框架划分的子智能体。

为什么智能体因工具发现能力错误而失败？

　　找到智能体文件并不意味着其工具列表与所选运行框架兼容。agent/runSubagent 和用户定义工具集等 Local 委派引用不是可移植 Copilot 工具配置。限定客户端工具引用（包括 vscode/<tool>）在这些工具提供给 Copilot 会话时可以有效。

　　根据 Copilot 会话中的可用能力审查 tools 中的每个条目。在编辑智能体文件前选择 Copilot，并使用其补全保留规范工具引用。检查工具选项卡、自定义智能体工具参考和工具集迁移指导。保持所需能力显式配置。移除整个工具限制不是等价迁移。

　　不要假设移除前缀或替换工具名称能修复所有发现错误。这些编辑器提示不能证明运行时工具发现失败。

　　另一个报告 microsoft/vscode#342961 描述即使 MCP 工具可调用，工具搜索也返回空结果。兼容工具仍无法发现时，请报告确切错误、所选模型、智能体工具列表和环境，不要将所有发现失败视为身份验证问题。

如果维护参与者

　　本节面向替换参与者实现的扩展发布者。仅使用已安装参与者时，请遵循替换聊天参与者。

选择、诊断或其他编辑器状态让用户附加上下文，或通过扩展工具公开编辑器特定操作。MCP 服务器不会自动访问 VS Code API。扩展工具需要贡献扩展和连接的编辑器。
必须按固定顺序运行的过程将过程保留在脚本或工具实现中，并使用技能描述何时调用。模型指令不能替代确定性执行或验证。
自定义模型调用、对话历史或响应呈现将有界操作重构为工具，或在扩展命令和视图中保留定制体验。自定义智能体或技能不会接管运行框架对话循环。参与者历史、反馈事件、路由规则和任意响应部分没有自动映射。

　　MCP 应用需要支持其 UI 的客户端。为不支持客户端提供有用的文本或结构化工具结果。在每个目标客户端测试应用行为，不要假设每个 Copilot 界面都呈现相同控件。在 VS Code 中，请审查 MCP 应用行为和限制，包括应用如何添加消息和上下文。

示例：将代码导师迁移到插件

不要用一个大型自定义智能体提示词替换代码导师参与者，而是分离其能力：

  • 教学流程：teach-concept 技能询问学习者经验、解释概念并提出练习。
  • 练习操作：MCP 工具检索练习并检查答案。
  • 交互式练习：MCP 应用显示问题、接受答案并显示反馈。为不支持应用的客户端保留基于文本的练习路径。
  • 可选 Tutor 智能体：自定义智能体保存较长对话的教学风格。
  • 可选编辑器集成：工作流需要实时编辑器 API 时，扩展工具提供诊断或所选代码。否则请让学习者附加代码。
