# 6.2 调试配置

　　当应用程序需要的设置比运行活动文件更多时，请创建调试配置。配置可以指定应用程序入口点、参数、环境变量、启动任务或要附加到的进程。

## 启动配置 {#launch-configurations}

　　VS Code 将调试配置存储在 `launch.json` 文件中。对于项目专用配置，请将文件放在工作区根目录的 `.vscode` 文件夹中。也可以在 `launch` 用户设置或多根工作区的工作区文件夹设置中定义配置。

　　以下 `launch.json` 示例启动 Node.js 应用程序：

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "type": "node",
            "request": "launch",
            "name": "Launch Program",
            "skipFiles": [
                "<node_internals>/**"
            ],
            "program": "${workspaceFolder}/app.js"
        }
    ]
}
```

　　`configurations` 数组中的每个对象都会显示在 **运行和调试** 视图的配置下拉列表中。可以为不同入口点、环境或调试模式添加多个配置。

> **注意**：无需打开文件夹即可调试受支持的活动文件。但要创建和管理工作区 `launch.json` 文件，必须打开文件夹或工作区。

## 创建调试配置文件 {#create-a-debug-configuration-file}

1. 从活动栏打开 **运行和调试** 视图（`Ctrl + Shift + D`，macOS：`Cmd + Shift + D`）。
2. 选择 **创建 launch.json 文件**。
3. 选择适用于你的应用程序的调试器。VS Code 会根据所选调试器创建起始配置，并打开 `.vscode/launch.json`。
4. 根据应用程序更新生成的配置。

### 使用 AI 生成启动配置 {#generate-a-launch-configuration-with-ai}

　　Copilot 可以检查项目并建议启动配置：

1. 使用 `Ctrl + Alt + I`（macOS：`Ctrl + Cmd + I`） 打开聊天视图。
2. 描述应用程序以及通常的启动方式。例如：

    ```text
    为这个 Express 应用创建一个调试配置。使用 npm run dev 启动它。
    ```

    智能体会根据需要搜索工作区中的相关上下文。如果要明确要求对整个工作区进行语义搜索，请在提示词中添加 `#codebase`。

3. 审查建议的属性，将配置应用到 `launch.json`，然后开始调试。

> **重要**：运行配置之前，请验证生成的命令、参数和环境变量。

### 将配置添加到 launch.json {#add-a-configuration-to-launch-json}

* 在编辑器中选择 **添加配置**，然后选择调试器片段。
* 将光标放在 `configurations` 数组内，使用 IntelliSense（`Ctrl + Space`）。
* 选择 **运行** > **添加配置** 菜单项。

## 使用启动配置开始调试 {#start-a-debugging-session-with-a-launch-configuration}

1. 打开 **运行和调试** 视图。
2. 从配置下拉列表中选择一个配置。
3. 按 `F5` 开始调试，或选择 **开始调试**。也可以从命令面板运行 **Debug: Select and Start Debugging**，然后选择配置。

## 启动配置与附加配置 {#launch-versus-attach-configurations}

　　`request` 属性决定调试器如何连接到应用程序：

| 请求 | 行为 | 使用场景 |
|---------|----------|----------|
| `launch` | 启动应用程序并将调试器附加到新进程。 | 希望由 VS Code 管理应用程序启动。 |
| `attach` | 将调试器连接到已在调试模式下运行的应用程序或进程。 | 另一个工具启动应用程序，或需要连接长期运行/远程进程。 |

　　调试器扩展定义每种请求类型所需的属性。请在 `launch.json` 中使用 IntelliSense，或查阅调试器扩展文档。

## 自定义启动配置 {#customize-a-launch-configuration}

### launch.json 属性 {#launchjson-attributes}

　　每个启动配置都有以下属性：

* `type`：要使用的调试器。例如，内置 Node.js 调试器使用 `node`。
* `request`：连接模式，大多数调试器支持 `launch`、`attach` 或两者。
* `name`：配置下拉列表中显示的标签。

　　所有启动配置可用的属性：

* `presentation`：控制配置下拉列表和快速选择中的 `order`、`group` 和 `hidden` 状态。
* `preLaunchTask`：调试会话开始前运行的任务，可使用任务标签或 `${defaultBuildTask}`。
* `postDebugTask`：调试会话结束后运行的任务。
* `internalConsoleOptions`：控制调试控制台何时打开。
* `serverReadyAction`：应用程序报告服务器就绪时执行操作。

　　调试器专用属性通常包括：`program`（要运行的可执行文件或文件）、`args`（参数）、`env` 或 `envFile`（环境变量）、`cwd`（工作目录）、`port`（附加端口）、`stopOnEntry`（启动时暂停）和 `console`（`internalConsole`、`integratedTerminal` 或 `externalTerminal`）。

　　支持的属性和值因调试器而异。设置 `type` 后，使用 IntelliSense 查看该调试器的架构。将鼠标悬停在红色波浪线上可查看验证错误。

## 变量替换 {#variable-substitution}

　　在 `launch.json` 中使用变量可避免硬编码路径和值，例如 `${workspaceFolder}`（工作区文件夹路径）、`${file}`（活动编辑器中的文件）和 `${env:Name}`（环境变量 `Name` 的值）。

```json
{
    "type": "node",
    "request": "launch",
    "name": "Launch Program",
    "program": "${workspaceFolder}/app.js",
    "cwd": "${workspaceFolder}",
    "args": [
        "--input",
        "${workspaceFolder}/data folder/input.txt"
    ]
}
```

　　`args` 等数组中的每个元素在变量替换后仍是一个参数，即使解析后的值包含空格。不要仅为处理空格而在变量周围添加转义引号。完整变量列表请参阅[3.4.3 变量替换](../../editor/3.4-Reference/3.4.3-SubstitutionVariables/)。

## 平台特定属性 {#platform-specific-properties}

　　使用 `windows`、`linux` 或 `osx` 部分为特定操作系统覆盖属性：

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "type": "node",
            "request": "launch",
            "name": "Launch Program",
            "program": "${workspaceFolder}/app.js",
            "args": ["scripts/start.js"],
            "windows": {
                "args": ["scripts\\start.js"]
            }
        }
    ]
}
```

　　操作系统部分中的属性会覆盖配置级属性。`type` 属性不能按平台设置，因为它决定运行配置的调试器，包括在远程调试场景中。

## 全局启动配置 {#global-launch-configuration}

　　要在多个工作区中复用配置，请将其添加到 `launch` 用户设置：

```json
"launch": {
    "version": "0.2.0",
    "configurations": [
        {
            "type": "node",
            "request": "launch",
            "name": "Launch Active File",
            "program": "${file}"
        }
    ]
}
```

　　当配置依赖项目文件、任务或共享环境细节时，请使用工作区 `launch.json`。工作区配置可以与项目一起进行版本控制，并供其他贡献者使用。

## 高级调试场景 {#advanced-debugging-scenarios}

### 复合启动配置 {#compound-launch-configurations}

　　复合配置会一起启动两个或多个启动配置，适用于客户端和服务器等多进程应用程序。在 `launch.json` 中与 `configurations` 数组并列添加 `compounds` 数组：

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "type": "node",
            "request": "launch",
            "name": "Server",
            "program": "${workspaceFolder}/server.js"
        },
        {
            "type": "node",
            "request": "launch",
            "name": "Client",
            "program": "${workspaceFolder}/client.js"
        }
    ],
    "compounds": [
        {
            "name": "Server and Client",
            "configurations": ["Server", "Client"],
            "preLaunchTask": "${defaultBuildTask}",
            "stopAll": true
        }
    ]
}
```

　　复合配置会出现在配置下拉列表中。启动时，VS Code 会运行可选的 `preLaunchTask`，并并行启动列出的配置。如果 `stopAll` 为 `true`，手动停止一个会话会停止复合配置中的所有会话。

### 调试服务器程序时自动打开 URI {#automatically-open-a-uri-when-debugging-a-server-program}

　　使用 `serverReadyAction` 在服务器报告就绪后打开或调试 URI。该操作使用正则表达式匹配程序输出，并使用捕获组构造 URI：

```json
{
    "type": "node",
    "request": "launch",
    "name": "Launch Server",
    "program": "${workspaceFolder}/app.js",
    "serverReadyAction": {
        "pattern": "listening on port ([0-9]+)",
        "uriFormat": "http://localhost:%s",
        "action": "openExternally"
    }
}
```

　　`pattern` 匹配 `listening on port 3000` 等输出并捕获端口号；`uriFormat` 将第一个 `%s` 替换为捕获值；`action` 在系统默认应用程序中打开 URI。

#### 通过 Microsoft Edge 或 Chrome 触发调试 {#trigger-debugging-via-microsoft-edge-or-chrome}

　　将 `action` 设置为 `debugWithEdge` 或 `debugWithChrome` 可启动浏览器调试会话。还可以设置 `webRoot`，默认为 `${workspaceFolder}`。

#### 触发任意启动配置 {#triggering-an-arbitrary-launch-config}

　　将 `action` 设置为 `startDebugging`，在模式匹配后启动另一个启动配置。使用 `name` 引用同一文件或工作区文件夹中的配置。对于需要更多控制的配置，使用 `config` 属性内联定义配置。

### 重定向调试目标的输入/输出 {#redirect-inputoutput-tofrom-the-debug-target}

　　输入和输出行为取决于调试器和运行时，没有适用于所有配置的重定向语法。可以使用以下方法：

* 当应用程序需要交互式标准输入时，将调试器专用的 `console` 属性设置为 `integratedTerminal` 或 `externalTerminal`。
* 在终端中手动启动应用程序，使用所需的 shell 重定向和调试选项，然后运行 `attach` 配置将调试器连接到该进程。

　　在 `args` 中传递 `<` 或 `>` 等 shell 运算符通常会将它们作为字面应用参数。只有当调试器通过 shell 显式运行目标时，才会重定向输入或输出。

## 排查启动配置问题 {#troubleshoot-launch-configurations}

### 没有显示配置 {#no-configurations-appear}

　　检查是否打开了文件夹或工作区；`.vscode/launch.json` 是否包含有效的 `configurations` 数组；配置 `type` 对应的调试器扩展是否已安装并处于活动状态；配置是否将 `presentation.hidden` 设置为 `true`。

### 配置显示红色波浪线 {#a-configuration-has-red-squiggles}

　　将鼠标悬停在突出显示的属性上查看验证消息。确认该属性受所选 `type` 和 `request` 支持。一个调试器的属性不会自动适用于另一个调试器。

### 配置没有启动预期的应用程序 {#a-configuration-does-not-start-the-expected-application}

　　验证 `program`、`cwd`、`args`、环境变量和所有 `preLaunchTask`。对于附加配置，确认目标进程已在调试模式下运行，并且端口等连接详细信息匹配。
