# 8.10 Linux 前提条件

　　Linux 环境变化很大，服务器、容器和桌面发行版数量众多，很难确定哪些受支持。VS Code 远程开发对要连接的主机/容器/WSL 发行版有特定前提条件。

　　已知这些扩展可以连接到以下稳定/LTS 版本的近期版本：

* **Ubuntu 64 位 x86、ARMv8l（AArch64）**（20.04+）
* **Debian 64 位 x86、ARMv8l（AArch64）**（Buster/10+）
* **Raspberry Pi OS ARMv7l（AArch32）32 位**（Buster/10+）
* **CentOS / RHEL 64 位 x86**（8+）
* **Alpine Linux 64 位 x86 容器或 WSL 主机**（3.16+，用于开发容器、WSL）

　　还支持以下非 Linux SSH 主机：

* **Windows 10/11 / Server 2016/2019 SSH 主机**（1803+），使用[官方 OpenSSH Server](https://learn.microsoft.com/windows-server/administration/openssh/openssh_install_firstuse)。
* **macOS** 10.14+（Mojave）SSH 主机，并[启用远程登录](https://support.apple.com/guide/mac-help/allow-a-remote-computer-to-access-your-mac-mchlp1066/mac)。

　　如果使用非标准配置或 Linux 的下游发行版，可能会遇到问题。本文提供要求和提示，帮助你在仅受社区支持的配置上运行。

　　请注意，**其他扩展可能有额外依赖**。某些扩展包含编译的本机代码，**可能无法在 Alpine Linux、ARMv7（AArch32）或 ARMv8（AArch64）上工作**。因此这些平台被视为“预览”。如果问题仅在特定扩展中出现，请联系扩展作者了解其本机依赖。

## 本地 Linux 前提条件 {#local-linux-prerequisites}

　　如果在本地运行 Linux，[VS Code 前提条件](https://code.visualstudio.com/docs/supporting/requirements)决定大部分要求。此外，特定远程开发扩展还有进一步要求：

* **Remote - SSH**：`ssh` 必须在路径中。shell 二进制文件通常位于 `openssh-client` 包中。
* **Dev Containers**：Docker CE/EE 18.06+ 和 Docker Compose 1.21+。请按照发行版的 [Docker CE/EE 官方安装说明](https://docs.docker.com/install/#supported-platforms)操作。如果使用 Docker Compose，请同时按照 [Docker Compose 安装说明](https://docs.docker.com/compose/install/)操作。不支持 Ubuntu Snap 包，发行版中的包可能已过时。`docker` 和 `docker-compose` 也必须在路径中。不过，如果[使用远程主机](https://aka.ms/vscode-remote/containers/remote-host)，Docker 无需运行。

## 远程主机/容器/WSL 的 Linux 前提条件 {#remote-host-container-wsl-linux-prerequisites}

　　平台前提条件主要由远程终结点上自动安装的服务器组件所附带的 Node.js 运行时版本（以及 [V8 JavaScript 引擎](https://v8docs.nodesource.com)）决定。该服务器还需要为每个目标编译和测试一组相关的本机 Node 模块。基于 **64 位 x86 glibc** 的 Linux 发行版目前提供最佳支持。

　　在基于 **ARMv7l（AArch32）/ARMv8l（AArch64）glibc** 的主机、容器或 WSL 以及 **64 位 x86 musl 的 Alpine Linux** 上，可能遇到某些具有本机依赖项的扩展问题。对于 ARMv7l/ARMv8l，扩展可能只包含 x86_64 版本的本机模块或运行时。对于 Alpine Linux，包含的本机代码或运行时可能因 Alpine Linux（`musl`）和其他发行版（`glibc`）在 `libc` 实现上的[根本差异](https://wiki.musl-libc.org/functional-differences-from-glibc.html)而无法工作。这些情况下，扩展需要选择支持这些平台，编译/包含相应目标的二进制文件。

| 发行版 | 基本要求 | Remote - SSH 要求 | 说明 |
|--------------|-------------------|------------------|-------|
| 通用 | 内核 >= 4.18，glibc >= 2.28，libstdc++ >= 3.4.25，tar | OpenSSH 服务器、`bash` 以及 `curl` 或 `wget` | 运行 `ldd --version` 检查 glibc 版本。运行 `strings /usr/lib64/libstdc++.so.6 \| grep GLIBCXX` 检查 libstdc++ 3.4.25 是否可用。 |
| ARM32 通用 | `libatomic1` | 无额外要求。 | |
| Ubuntu 20.04+、Debian 10+、Raspberry Pi OS Buster/10+ 及下游发行版 | `libc6 libstdc++6 ca-certificates tar` | `openssh-server bash` 以及 `curl` 或 `wget` | 需要内核 >= 4.18、glibc >= 2.28、libstdc++ >= 3.4.25。 |
| RHEL / CentOS 8+ | `glibc libgcc libstdc++ ca-certificates tar` | `openssh-server bash` 以及 `curl` 或 `wget` | 需要内核 >= 4.18、glibc >= 2.28、libstdc++ >= 3.4.25。 |
| Alpine Linux 3.16+ | `musl libgcc libstdc++`。musl >= 1.2.3，不需要 glibc。 | 尚不支持。 | 在开发容器和 WSL 中支持。安装在容器中的扩展可能因扩展本机代码的 `glibc` 依赖而无法工作。 |
| openSUSE Leap / SUSE Linux Enterprise 15+ | `glibc libgcc_s1 libstdc++6 ca-certificates gzip tar` | `curl` 或 `wget` | 需要内核 >= 4.18、glibc、libstdc++6。 |

## 按 Linux 发行版划分的提示 {#tips-by-linux-distribution}

　　以下是可能缺少基本要求的发行版列表。不包含已停止支持的版本。

* ✅ = 可用
* ⚠️ = 可用，但有限制
* 🔬 = 实验性
* 🛑 = 不受支持，但有变通方法
* ❌ = 不受支持

| 服务器发行版 | Docker 映像 | 缺少的库 | 说明/其他步骤 |
|---------------------|--------------|-------------------|------------------|
| ⚠️ Alpine Linux 3.16（64 位） | `alpine:3.16` | `libgcc libstdc++` | 仅在开发容器和 WSL 中支持。某些扩展可能因 `glibc` 依赖而无法工作。 |
| ✅ CentOS 8 Server（64 位） | `centos:8` | 无 | 无 |
| ❌ CentOS 7 Server（64 位） | `centos:7` | `glibc` >= 2.28、`libstdc++` >= 3.4.25 | 无 |
| ✅ Debian 10 Server（64 位） | `debian:10` | 无 | 无 |
| ❌ Debian 9 Server（64 位） | `debian:9` | `glibc` >= 2.28、`libstdc++` >= 3.4.25 | 无 |
| ✅ openSUSE Leap Server 15（64 位） | `opensuse/leap:15` | Docker 映像缺少 `tar` 和 `gzip`。 | 无 |
| ✅ Oracle Linux 8（64 位） | `oraclelinux:8` | 无 | 无 |
| ❌ Oracle Linux 7（64 位） | `oraclelinux:7` | `glibc` >= 2.28、`libstdc++` >= 3.4.25。Docker 映像缺少 `tar`。 | 无 |
| ⚠️ Raspberry Pi OS Buster/10（ARMv7l 32 位） | 不适用 | 无 | 某些扩展可能因 x86 本机代码而无法工作。开发容器支持连接到 ARM 主机上的容器。 |
| ✅ RedHat Enterprise Linux 8（64 位） | 无 | 无 | 无 |
| ❌ RedHat Enterprise Linux 7（64 位） | 无 | `glibc` >= 2.28、`libstdc++` >= 3.4.25 | 无 |
| ✅ SUSE Linux Enterprise Server 15（64 位） | 无 | Docker 映像缺少 `tar` 和 `gzip`。 | 无 |
| ✅ Ubuntu Server 20.04（64 位） | `ubuntu:20.04` | 无 | 无 |
| ❌ Ubuntu Server 18.04（64 位） | `ubuntu:18.04` | `glibc` >= 2.28 | 无 |
