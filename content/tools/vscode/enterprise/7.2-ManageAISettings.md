# 7.2 管理企业 AI 设置

　　组织可以通过三种管理方案治理 VS Code 中的 AI 功能：GitHub Copilot 企业托管设置、VS Code 设备策略以及 GitHub 组织或企业设置。

　　这些方案控制 AI 体验的不同层。组织可能同时使用三种方案，但重叠控制应只在一个系统中配置。

　　现有 Local 部署请遵循[从 Local 迁移到 Copilot 运行框架](../../ai-in-vs-code/choose-models-and-agents/2.3.3-MoveFromLocalToCopilot/)，了解开发者步骤、兼容性清单以及管理员推广和验证流程。

> **注意**：如果你是开发者且智能体、模型或工具不可用，请先检查 [AI 故障排除指导](../../ai-in-vs-code/reference-and-help/troubleshooting/2.8.2.1-Troubleshooting/)。组织管理限制请询问管理员哪些能力已批准。

## 了解三种管理解决方案 {#understand-the-three-management-solutions}

选择方案前，请了解每种方案的配置位置和控制内容。

### GitHub Copilot 企业托管设置 {#copilot-enterprise-managed-settings}

　　企业托管设置用于应在受支持客户端（例如 VS Code 和 Copilot CLI）之间应用的 Copilot 防护措施。

　　管理员使用 GitHub 支持的服务器托管、MDM 托管或基于文件的交付方法定义这些设置。即使使用 MDM 解决方案，企业托管设置也使用 Copilot 配置格式和交付路径，而不是 VS Code 设备策略命名空间。

　　服务器托管部署中，管理员可以为特定企业团队覆盖受支持设置。GitHub 根据每个人的企业团队成员身份应用匹配值。请参阅[为企业团队覆盖企业托管设置](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/use-managed-settings/override-settings-for-teams)。

　　受支持键、客户端覆盖、配置 schema 和优先级请参阅[企业托管设置设置指南](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/use-managed-settings/get-started)和[设置参考](https://docs.github.com/en/copilot/reference/enterprise-administrators/enterprise-managed-settings)。

### VS Code 设备策略 {#vs-code-device-policies}

　　设备策略用于受管理 VS Code 安装上的编辑器特定控制。

　　管理员通过平台管理工具（例如组策略、Microsoft Intune 或 macOS 配置描述文件）部署这些策略。策略应用于受管理设备，并覆盖 VS Code 中相应的用户设置。

　　策略名称、接受值、支持平台和最低版本请参阅 [VS Code 企业策略参考](../7.1-Policies/)。

### GitHub 组织和企业设置 {#github-organization-and-enterprise-settings}

　　GitHub 组织和企业设置用于账户级和服务端控制，例如 Copilot 访问、模型可用性、内容排除和组织提供的自定义项。

　　管理员在 GitHub 上配置这些控制。它们遵循已登录 GitHub 账户及其组织或企业成员身份，而不是 VS Code 设备策略渠道。

　　配置和参考信息请参阅[为企业管理 Copilot](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise)。

## 选择管理解决方案 {#choose-a-management-solution}

　　这些方案并不互斥。请根据需要的作用域为每个控制选择方案。

| 需求 | 管理方案 | 配置位置 | 作用域 |
|-------------|---------------------|------------------------|-------|
| 在受支持客户端之间应用一致的 Copilot 防护措施。 | Copilot 企业托管设置 | GitHub 支持的服务器、MDM 或文件交付 | 受支持 Copilot 客户端和键 |
| 在受管理设备上控制 VS Code 特定编辑器功能。 | VS Code 设备策略 | 操作系统或设备管理 | 受管理 VS Code 安装 |
| 控制 Copilot 访问或 GitHub 托管的组织/企业行为。 | GitHub 组织或企业设置 | GitHub 组织或企业管理 | 已登录账户和 GitHub 托管服务 |

　　某些控制可以通过多个方案使用。组合前请审查[优先级顺序](#understand-precedence)。

　　广泛推广前，请使用代表性项目、设备和账户测试配置。确认开发者可以完成已批准任务，同时预期限制仍然生效。

## 了解优先级 {#understand-precedence}

### 跨托管设置交付方法 {#across-managed-settings-delivery-methods}

　　同一托管设置可从多个来源提供时，VS Code 按以下顺序应用：

1. MDM 托管设置。
2. 服务器托管设置。
3. 基于文件的设置。
4. 用户设置。

　　大多数键使用最高优先级来源的值。某些键（包括 `permissions.deny`、`permissions.ask` 和 `permissions.allow`）会按最严格方向合并多个来源的限制。完整当前规则请参阅[部署方法优先级](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/use-managed-settings/deploy-managed-settings#precedence-of-deployment-methods)。

### 与 VS Code 设备策略 {#with-vs-code-device-policies}

　　某些企业托管设置映射到 VS Code 设备策略。管理员同时配置两个系统时：

* 系统配置不同控制时，两个控制都应用。
* 两个系统配置同一控制时，企业托管设置优先，值不合并。
* 企业托管设置不提供该控制时，VS Code 设备策略继续生效。

　　尽可能通过一个管理方案配置重叠控制。运行 **Developer: Policy Diagnostics** 检查有效值及其来源。

## 使用 Copilot 企业托管设置 {#use-copilot-enterprise-managed-settings}

　　按照 GitHub 文档配置和管理企业托管设置：

* [企业托管设置入门](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/use-managed-settings/get-started)介绍交付、配置文件、团队覆盖、验证和故障排除。
* [企业托管设置参考](https://docs.github.com/en/copilot/reference/enterprise-administrators/enterprise-managed-settings)列出受支持键、值、组合行为和客户端覆盖。

　　并非每个企业托管设置都适用于每个客户端。为 VS Code 配置设置前，请检查[企业托管设置参考](https://docs.github.com/en/copilot/reference/enterprise-administrators/enterprise-managed-settings#supported-keys)中的 **支持的客户端** 列。

### 配置托管 MCP 服务器访问 {#configure-managed-mcp-server-access}

　　使用 Copilot 企业托管设置中的 `allowedMcpServers` 限制开发者可安装和运行的 [MCP 服务器](../../ai-in-vs-code/customize-and-extend/2.4.7-AddMCPServers/)。使用 `deniedMcpServers` 阻止即使匹配允许列表的服务器。请通过[受支持的托管设置交付方法](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/use-managed-settings/get-started)配置这些键，不要在开发者编辑器设置或 `mcp.json` 中配置。

例如，以下托管设置允许 `https://mcp.example.com/` 下的远程服务器，但阻止被阻止的终结点：

```json
{
    "allowedMcpServers": [
        {
            "serverUrl": "https://mcp.example.com/*"
        }
    ],
    "deniedMcpServers": [
        {
            "serverUrl": "https://mcp.example.com/blocked"
        }
    ]
}
```

每个规则使用一个匹配器：

* `serverUrl` 匹配远程服务器 URL，支持 `*` 通配符。
* `serverCommand` 按顺序匹配本地服务器的确切命令及参数。
* `serverName` 匹配配置的服务器名称。名称由配置作者提供，因此不能验证命令、终结点或发布者。

　　需要约束运行内容或连接位置时，请优先使用命令或 URL 规则。允许列表包含命令规则时，本地服务器必须匹配命令规则而不是名称规则；包含 URL 规则时，远程服务器必须匹配 URL 规则。

#### 托管允许列表和注册表优先级 {#managed-allowlists-and-registry-precedence}

　　MCP 注册表是发现和安装服务器的目录。托管允许列表决定组织允许哪些服务器。从 VS Code 1.145 开始，企业托管允许列表优先于编辑器管理 MCP 服务器的仅注册表访问：

| 服务器配置 | 结果 |
|----------------------|--------|
| 匹配托管允许列表但不在注册表中。 | 允许，除非拒绝规则或 MCP 禁用阻止。 |
| 出现在注册表中但不匹配托管允许列表。 | 阻止。注册表成员身份不授予例外。 |

　　注册表仍可用于发现。这些优先级规则适用于编辑器管理的服务器（包括 Local 运行框架会话），不适用于 [Agent Host](../../ai-in-vs-code/reference-and-help/reference/2.8.1.11-AgentHostArchitecture/) 拥有的服务器。

* 显式 `allowedMcpServers: []` 阻止所有服务器，不会回退到注册表批准。
* 移除 `allowedMcpServers` 恢复有效访问模式，包括仅注册表访问和任何拒绝规则。
* 拒绝规则和显式 MCP 禁用（例如 `chat.mcp.access` 设置为 `"none"`）仍优先于允许列表。

　　用户设置和工作区服务器定义不能扩大企业托管允许列表或移除拒绝规则。命令和 URL 在变量解析后会再次检查。即使服务器保留注册表名称，配置编辑仍必须匹配托管规则。

　　检查有效配置及其来源请参阅[验证已应用的托管设置](#verify-applied-managed-settings)。

### 设置托管模型默认值 {#set-managed-model-defaults}

　　为开发者提供一致的起始模型，同时不阻止他们为单个任务选择其他模型。将顶级 `model` 托管设置设为 `auto` 或可用模型 ID。

　　Copilot 运行框架会话使用 `fusionTier` 设置起始 Auto 或 Fusion 层级：

| 值 | 起始层级 |
|-------|---------------|
| `"standard"` | Fusion **Standard**，Fusion 不可用时 Auto **Balance**。 |
| `"high"` | 可用时 Fusion **High**，否则 Auto **Intelligence**。 |
| `"max"` | 可用时 Fusion **Max**；不可用时保持运行时默认值。 |
| `"unmanaged"` | 不选择托管层级，旧 `autoTier` 设置也被忽略。 |

例如，将以下值添加到企业托管设置：

```json
{
    "model": "auto",
    "fusionTier": "high"
}
```

　　此示例在账户可用 [Copilot Fusion](../../ai-in-vs-code/choose-models-and-agents/2.3.1-ChooseAndConfigureModels/) 时，新对话从 Fusion **High** 开始；否则使用 Auto **Intelligence**。托管 `model` 值 `"fusion"` 也接受为 `"auto"`，但不会启用 Fusion 或授予不可用层级访问权限。

　　`fusionTier` 优先于旧 `autoTier` 设置。它适用于 Copilot 运行框架，不适用于 Local 会话。

　　托管模型默认值优先于编辑器和智能体窗口中新对话的已保存个人偏好。开发者仍可在对话中更改模型或层级，现有对话保留其选择。移除托管默认值后，新对话重新使用已保存个人偏好。

　　要验证模型默认值，请检查模型选择器中的 **组织默认值** 以及设置中 `chat.defaultModel` 的公文包指示器。请参阅[组织管理的模型默认值](../../ai-in-vs-code/choose-models-and-agents/2.3.1-ChooseAndConfigureModels/)。

### Claude 和 Codex 可用性 {#claude-and-codex-availability}

　　GitHub Copilot 企业托管设置生效时，VS Code 中的 Claude 和 Codex 运行框架集成会被禁用。这包括通过服务器托管、MDM 托管或基于文件部署的设置。

　　Copilot 运行时强制执行这些设置，但 Claude 和 Codex 运行框架无法执行。VS Code 会禁用这些运行框架，使会话无法绕过组织控制。

　　此限制不会删除现有 Claude 或 Codex 会话。

　　限制取决于托管设置是否存在，而不仅是某个限制是否启用。例如：

* 托管权限设置（例如 `permissions.disableBypassPermissionsMode`、`permissions.allow`、`permissions.ask` 或 `permissions.deny`）会禁用这些运行框架。空规则列表也算托管设置。
* 托管 `sandbox.enabled` 即使值为 `false` 也会禁用运行框架。
* 其他企业托管控制（例如插件或遥测设置）也可能禁用运行框架。

　　将 `chat.agentHost.claudeAgent.enabled` 或 `chat.agentHost.codexAgent.enabled` 设置为 `true` 不能覆盖此限制。将 `Claude3PIntegration` 或 `Codex3PIntegration` 设备策略设置为 `true` 也不能覆盖。使用 Claude API 密钥或 ChatGPT 账户时限制同样适用。

　　此限制适用于运行框架可用性，不适用于 Copilot 运行框架会话中选择的 Claude 或 OpenAI 模型。模型可用性单独管理。

#### Claude 或 Codex 缺失时 {#if-claude-or-codex-is-missing}

如果需要访问这些运行框架：

1. 从命令面板运行 **Developer: Policy Diagnostics**，检查有效 `Claude3PIntegration` 和 `Codex3PIntegration` 策略及其来源。
2. 联系部署托管设置的 IT 团队，告知哪个运行框架不可用以及相关策略值和来源。
3. 不知道设置所有者时，请 IT 帮助台将请求转给负责 Copilot 企业托管设置或设备管理的管理员。

　　询问管理员哪些运行框架已批准用于工作，以及部署配置是否需要审查。你不能通过更改用户或工作区设置恢复访问。

### 运行时策略和运行框架选择 {#runtime-policies-and-harness-selection}

　　Claude 和 Codex 限制独立于自动路由到 Copilot 运行框架。从 VS Code 1.143 开始，以下托管设置要求 Copilot 运行框架，除非管理员启用[临时 Local 默认值](#keep-local-harness-as-default)：

* `sandbox.enabled` 设置为 `true`。
* 非空 `permissions.deny` 规则列表。

　　其他 `permissions.*` 设置和空拒绝列表不会触发该路由。

　　要禁止 Local、Claude 和 Codex，请在企业托管设置中将 `vscode.temporaryAllowLocalHarness` 设置为 `false`。此控制从 1.143 版可用，优先于 `vscode.temporaryDefaultToLocalHarness: true`。设置为 `true` 不会覆盖其他策略。

　　默认值不是运行框架要求。`ChatEditorPreferCopilotHarness` 设备策略在新编辑器聊天本应使用 Local 时优先 Copilot，但不禁止其他运行框架。

　　企业托管设置生效期间，临时 Local 默认值不会重新启用 Claude 或 Codex。要求 Copilot 时的对话和归档行为请参阅[继续现有 Local 对话](../../ai-in-vs-code/choose-models-and-agents/2.3.3-MoveFromLocalToCopilot/)。

### 保持 Local 运行框架为默认 {#keep-local-harness-as-default}

　　从 VS Code 1.142 开始，组织可以将 Local 运行框架保留为新智能体会话的默认值，并阻止自动选择 Copilot 运行框架。

在企业托管设置中将 `vscode.temporaryDefaultToLocalHarness` 设置为 `true`：

```json
{
    "vscode": {
        "temporaryDefaultToLocalHarness": true
    }
}
```

　　此控制抑制[自动路由到 Copilot 运行框架](#runtime-policies-and-harness-selection)，包括由托管沙盒要求或非空拒绝列表触发的路由。它不改变显式、记住的或当前运行框架选择，也不覆盖 `vscode.temporaryAllowLocalHarness: false`。将 `vscode.temporaryDefaultToLocalHarness` 设置为 `false` 或移除该键可恢复正常路由。

> **警告**：Local 不执行运行时独有的沙盒和权限规则。这些托管规则在 Copilot 运行框架会话中继续执行。使用此临时控制前请审查安全影响。

### 验证已应用的托管设置 {#verify-applied-managed-settings}

在 VS Code 中运行 **Developer: Policy Diagnostics** 检查有效策略值及其来源。详情请参阅[验证策略强制执行](../7.1-Policies/)。

　　诊断显示服务器托管来源值意外时，请检查 `copilot/managed-settings.json`、`copilot/team-mappings.json`、`copilot/teams/` 下映射文件以及用户企业团队成员身份。GitHub 在将服务器托管设置交付给 VS Code 前解析团队覆盖。

　　GitHub 侧验证错误或交付故障排除请遵循[验证服务器托管设置](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/use-managed-settings/get-started#validate-server-managed-settings)。

### 满足最低版本要求 {#meet-minimum-version-requirements}

　　托管设置服务可以要求最低 VS Code 版本后才能使用 AI 功能。安装版本不满足要求时：

* 聊天显示所需版本和已安装版本，并提供相应更新操作。
* 即使聊天关闭，编辑器窗口也显示横幅。其他编辑器功能仍可用。
* 智能体窗口显示阻止通知和 **打开编辑器窗口** 操作。

　　内置更新被策略禁用时，通知会引导开发者联系管理员。安装版本满足要求后 AI 功能可用。

### 在 VS Code 中应用托管遥测 {#apply-managed-telemetry-in-vs-code}

　　托管 OpenTelemetry 配置适用于 Copilot Chat 扩展和 [Agent Host](../../ai-in-vs-code/reference-and-help/reference/2.8.1.11-AgentHostArchitecture/)（运行智能体会话的进程）。扩展可能在配置更改后提供 **重新加载窗口**。VS Code 解析托管遥测更改后会自动重启本地 Agent Host。

　　从 VS Code 1.143 开始，使用 `telemetry.filePath` 将 Copilot Agent Host 遥测保存到 JSONL 文件，无需收集器或个人 OTel 选择加入。托管文件目标优先于收集器配置，除非托管 `telemetry.enabled` 为 `false` 关闭导出。配置、路径要求和移除行为请参阅[将托管遥测导出到文件](../../ai-in-vs-code/reference-and-help/reference/2.8.1.10-OpenTelemetryMonitoring/)。

　　从 VS Code 1.143 开始，使用 `telemetry.headersProvider` 为 Copilot Agent Host 会话的 OTLP 导出生成和刷新 HTTP 标头。标头可以提供收集器特定元数据、路由遥测或与收集器身份验证。托管导出不要求开发者通过个人 OTel 设置选择加入。配置示例和辅助程序要求请参阅[配置动态标头](../../ai-in-vs-code/reference-and-help/reference/2.8.1.10-OpenTelemetryMonitoring/)。

　　提供 `telemetry` 的[最高优先级交付来源](#across-managed-settings-delivery-methods)拥有整个块。该来源省略的字段不会从低优先级来源继承值。

　　身份捕获默认关闭，独立于内容捕获。部署前审查两个控制，并从受管理设备移除冲突的 OpenTelemetry 环境变量。配置 schema 和受支持客户端请参阅[企业托管设置参考中的 `telemetry`](https://docs.github.com/en/copilot/reference/enterprise-administrators/enterprise-managed-settings#telemetry)。
## 使用 VS Code 设备策略 {#use-vs-code-device-policies}

以下各节介绍 VS Code 设备策略。请按照[企业策略](../7.1-Policies/)部署，并使用[策略参考](../7.1-Policies/)了解接受值和最低版本。

> **重要**：Copilot 运行框架会话不会像 Local 运行框架会话那样执行每个设备策略。以下各节说明已知差异。依赖某个策略前，请在开发者使用的运行框架中测试。

### 控制访问和功能可用性 {#control-access-and-feature-availability}

#### 将 AI 功能限制为已批准的 GitHub 组织 {#restrict-ai-features-to-approved-github-organizations}

　　将 `ChatApprovedAccountOrganizations` 策略设置为要求开发者使用属于已批准组织的 GitHub 账户登录后才能激活 AI 功能。

提供 GitHub 组织登录名 JSON 数组，例如 `["contoso", "contoso-research"]`。使用 `["*"]` 允许任何已登录 GitHub 账户。

　　该策略是故障关闭的。账户策略数据解析完成且已登录账户属于已批准组织前，AI 功能保持禁用。运行 **Developer: Policy Diagnostics** 检查 **账户策略门** 状态。

#### 启用或禁用智能体 {#enable-or-disable-the-use-of-agents}

　　将 `ChatAgentMode` 策略设置为 `false` 禁用[智能体](../../ai-in-vs-code/concepts/2.7.1-Agents/)。此策略控制 `chat.agent.enabled`。

　　策略禁用时，智能体下拉列表中没有 **智能体** 选项，智能体窗口不可用。开发者仍可以使用[询问或编辑](../../ai-in-vs-code/work-with-ai/2.2.5-UseChat/)进行代码解释和文件编辑。

　　该策略不会从编辑器 [**会话目标** UI 控件](../../ai-in-vs-code/choose-models-and-agents/2.3.2-ChooseAnAgentHarness/)移除 **Copilot** 等 Agent Host 会话目标。开发者仍可以从这些目标启动智能体会话。

#### 启用或禁用扩展语言工具 {#enable-or-disable-extension-language-tools}

使用以下策略控制扩展、浏览器和插件工具：

* 将 `ChatAgentExtensionTools` 设置为 `false` 禁用扩展贡献的工具。
* 将 `BrowserChatTools` 设置为 `false` 禁用浏览器工具。
* 将 `ChatPluginsEnabled` 设置为 `false` 禁用智能体插件集成。

#### 配置 Copilot 代码审查 {#configure-copilot-code-review}

　　使用 `CopilotReviewSelection` 控制所选代码的代码审查。使用 `CopilotReviewAgent` 控制拉取请求和更改文件的代码审查智能体访问。

#### 配置下一次编辑建议 {#configure-next-edit-suggestions}

　　将 `CopilotNextEditSuggestions` 设置为 `false` 禁用下一次编辑建议。

#### 启用或禁用 Claude Agent {#enable-or-disable-claude-agent}

　　将 `Claude3PIntegration` 设置为 `false` 禁用 VS Code 中的 Claude Agent 会话。

　　将此策略设置为 `true` 不能覆盖[企业托管设置下的 Claude 和 Codex 限制](#claude-and-codex-availability)。

#### 启用或禁用 copilot 命令 {#enable-or-disable-the-copilot-command}

　　VS Code 包含运行 Copilot CLI 的 `copilot` 命令。未安装 Copilot CLI 时，该命令会提示从 GitHub 安装。Windows 上，设置还可以将命令添加到 `PATH` 并安装 Copilot CLI。

　　将 `CopilotCliCommand` 策略设置为 `false` 关闭该命令。此策略控制 `chat.copilotCliCommand.enabled`。策略禁用时：

* 新的集成终端不包含 `copilot` 命令。
* Windows 上，设置不显示 **Copilot CLI** 页面，也不安装 Copilot CLI。下次运行设置（例如更新时）会从 `PATH` 移除 `copilot` 命令。在此之前，该命令不会安装 Copilot CLI。

　　该策略不影响单独部署的 Copilot CLI 安装。要控制开发者使用的 Copilot CLI 版本及其来源，请禁用该策略并使用自己的软件分发工具部署 Copilot CLI。请参阅[安装 Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/install-copilot-cli)。

　　开发者是否可以使用 Copilot CLI 由 [GitHub 组织和企业设置](#use-github-organization-and-enterprise-settings)控制，Copilot CLI 在登录后应用这些设置。

### 配置模型和数据处理 {#configure-models-and-data-handling}

#### 设置默认聊天模型 {#set-a-default-chat-model}

　　将 `ChatDefaultModel` 策略设置为新对话选择默认模型。此策略控制 `chat.defaultModel`，接受 `auto`、模型系列名称或完整模型 ID。

　　开发者可以为单个对话选择其他模型。重新打开的对话保留已保存模型。

　　通过 Copilot 企业托管设置交付的默认值请参阅[设置托管模型默认值](#set-managed-model-defaults)。

#### 控制听写数据 {#control-dictation-data}

使用以下策略控制听写音频和转录是否离开开发者设备。

| 策略 | 设置 | 行为 |
|--------|---------|----------|
| `DictationEnabled` | `dictation.enabled` | 控制是否可用内置听写。 |
| `DictationModel` | `dictation.model` | 选择设备上模型或 `mai` 云转录服务。 |
| `DictationLLMCleanup` | `dictation.experimental.llmCleanup` | 控制最终转录是否发送给语言模型清理。 |

　　要将听写音频保留在设备上，请将 `DictationModel` 设置为 `nemotron-3.5-asr-streaming-0.6b`。在 Web 版 VS Code 中，设备上转录不受支持，此策略会使听写不可用。

　　要阻止转录文本发送给语言模型，请将 `DictationLLMCleanup` 设置为 `false`。更多信息请参阅[听写隐私](../../editor/3.3-ConfigureTheEditor/3.3.9-Accessibility/3.3.9.2-Voice/)。

### 治理智能体和工具 {#govern-agents-and-tools}

#### 启用或禁用钩子 {#enable-or-disable-hooks}

　　钩子控制取决于所选运行框架。对于 Copilot 运行框架会话，请使用[策略钩子](#verify-policy-hook-coverage)和下面的[托管钩子源控制](#restrict-hook-sources)。

> **注意**：**对于 Local 运行框架会话**：将 `ChatHooks` 策略设置为 `false` 禁用钩子。此策略控制 `chat.useHooks`，不适用于 Copilot 运行框架会话。

##### 验证策略钩子覆盖 {#verify-policy-hook-coverage}

　　Copilot 策略钩子适用于 Copilot 运行框架会话，使用 Copilot SDK 钩子实现。依赖这些钩子执行限制前，请确认开发者从[**会话目标** UI 控件](../../ai-in-vs-code/choose-models-and-agents/2.3.2-ChooseAnAgentHarness/)选择 **Copilot**。在将执行工作的会话中测试所需钩子行为。

　　Local 运行框架会话不加载 SDK 策略钩子。为一个运行框架配置钩子不会在另一个运行框架中执行。请参阅[钩子兼容性](../../ai-in-vs-code/customize-and-extend/2.4.9-Hooks/)。

　　迁移到 Copilot 时，请清点策略钩子、托管插件以及任何允许的用户或仓库钩子。转换并测试其脚本和配置。请参阅[迁移钩子](../../ai-in-vs-code/customize-and-extend/2.4.11-MigrateExistingCustomizations/)。

> **警告**：Copilot 策略钩子在宿主机上运行，位于会话沙盒之外。请将脚本保存在管理员控制的位置。不要将仓库钩子提升为策略钩子同时保留工作区控制的脚本路径，否则会在沙盒外运行可编辑的工作区代码。请参阅[策略钩子和沙盒会话](https://docs.github.com/en/copilot/reference/hooks-reference#sandboxed-sessions)。

　　请分别测试失败和超时。Copilot 命令钩子参考将超时记录为故障开放，即使策略钩子也是如此。因此，完整审计覆盖或故障关闭执行要求不能仅依赖钩子文件存在。

##### 限制钩子源 {#restrict-hook-sources}

　　将 `ChatAllowManagedHooksOnly` 设置为仅允许来自企业托管源和策略强制启用插件的钩子。还需要阻止独立的用户和工作区技能、智能体、指令和 MCP 服务器时，请设置 `ChatStrictPluginOnlyCustomization`。

　　插件分发是单独决定。要在受支持 Copilot 客户端强制启用插件或治理 Marketplace，请使用[企业托管设置参考](https://docs.github.com/en/copilot/reference/enterprise-administrators/enterprise-managed-settings#enabledplugins)中的插件控制。

#### 管理智能体插件和 Marketplace {#manage-agent-plugins-and-marketplaces}

使用以下策略治理[智能体插件](../../ai-in-vs-code/customize-and-extend/2.4.2-Plugins/)和 VS Code 中的自定义项发现：

* `ChatEnabledPlugins` 强制启用或强制禁用指定插件。
* `ChatExtraMarketplaces` 添加插件 Marketplace。
* `ChatStrictMarketplaces` 将插件安装限制为已批准的 Marketplace 源。空列表阻止从所有 Marketplace 安装。
* `ChatCustomizationMarketplace` 控制统一的 **浏览** 发现界面。禁用后，Marketplace 发现仍在现有自定义管理页面中可用。
* `ChatCopilotConnectors` 控制连接器发现以及已连接连接器 MCP 服务器是否可用于 Copilot 会话。

　　策略阻止的插件仍然可见，但显示为禁用。在 **自定义** > **插件** 中，策略管理的插件标识为由策略管理，其开关锁定。策略管理的 Marketplace 在 Marketplace 选择器中标识。

　　需要跨客户端插件治理而不是仅 VS Code 策略时，请遵循[管理插件 Marketplace 和插件](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/use-managed-settings/manage-plugin-marketplaces-and-plugins)配置 Copilot 企业托管设置。

　　企业托管插件设置只要求或阻止插件，不设置可选默认值。

　　可选项目特定插件请使用[仓库默认值](../../ai-in-vs-code/customize-and-extend/2.4.2-Plugins/)。成员可以关闭这些默认值，除非托管策略要求该插件。

　　企业托管 `strictKnownMarketplaces` 设置也会禁用内置 Marketplace。请显式配置允许的源。

#### 配置智能体工具审批 {#configure-agent-tool-approvals}

　　使用 Copilot 企业托管设置控制会话权限级别。使用 VS Code 设备策略控制其他审批行为。

##### 管理权限级别 {#manage-permission-levels}

　　对于 Copilot 运行框架会话，使用企业托管设置控制开发者可选择的权限级别以及新会话的初始级别。

| 托管设置 | 在 VS Code 中的效果 |
|-----------------|------------------------------------------------------------------|
| `permissions.disableBypassPermissionsMode` | 设置为 `"disable"` 禁用权限选择器中的 **全部允许**。 |
| `permissions.disableAssistedPermissionsMode` | 设置为 `true` 禁用权限选择器中的 **辅助权限**。 |
| `permissions.defaultMode` | 设置初始权限级别。支持值：`"manual"`、`"assisted"` 和 `"allow-all"`。 |

例如，可用时以 **辅助权限** 启动会话，同时阻止 **全部允许**：

```json
{
    "permissions": {
        "disableBypassPermissionsMode": "disable",
        "disableAssistedPermissionsMode": false,
        "defaultMode": "assisted"
    }
}
```

　　配置的默认值不可用时，新会话使用 **手动权限**。设置默认值不会阻止开发者切换到组织允许的其他权限级别。

　　编辑器和智能体窗口中，受策略限制的受支持权限级别仍然可见但禁用。选择器显示带公文包图标的 **已被策略禁用** 及说明。不支持的权限级别不显示。

　　这些托管设置控制[会话权限级别](../../ai-in-vs-code/work-with-ai/permissions-and-security/2.2.12.1-ApprovalsAndPermissions/)。`ChatToolsAutoApprove` 设备策略单独控制全局自动批准。配置和部署详情请参阅[企业托管设置参考](https://docs.github.com/en/copilot/reference/enterprise-administrators/enterprise-managed-settings)。

##### 禁用全局自动批准 {#disable-global-auto-approval}

　　将 `ChatToolsAutoApprove` 设置为 `false` 阻止开发者启用全局自动批准。策略设置期间，工具确认只提供一次性批准，之前保存的工具批准不会应用。

> **警告**：全局自动批准绕过工具调用的安全提示。除非威胁模型明确支持此行为，否则请禁用。

##### 要求特定工具手动批准 {#require-manual-approval-for-specific-tools}

　　使用 `ChatToolsEligibleForAutoApproval` 要求特定工具手动批准。

　　对于 Copilot 运行框架会话，标记为 `false` 的工具会从整个会话的权限选择器中移除 **全部允许**。它不要求每次调用该工具都确认，因此 **辅助权限** 和已保存会话批准仍可批准它。

##### 配置终端自动批准 {#configure-terminal-auto-approval}

　　将 `ChatToolsTerminalEnableAutoApprove` 设置为 `false` 关闭基于规则的终端自动批准。对于 Local 运行框架会话，此策略不阻止沙盒命令的自动批准或通过会话级权限批准。

　　对于 Copilot 运行框架会话，此策略要求通过内置 shell 工具运行的命令获得批准。将这些会话保留在该工具上，请将 `ChatAgentHostCustomTerminalTool` 设置为 `false`。

　　详细了解[工具审批](../../ai-in-vs-code/work-with-ai/permissions-and-security/2.2.12.1-ApprovalsAndPermissions/)。

#### 控制 GitHub Environments（预览） {#control-github-environments-preview}

　　[GitHub Environments](../../ai-in-vs-code/work-across-apps-and-machines/2.5.2-RemoteAgentSessions/)通过注册现有开发机器进行远程访问，在受支持 Copilot 客户端之间提供连续性。管理员可以控制此注册和连接路径，以满足远程访问和数据处理要求，同时允许已批准的跨设备工作。

　　将 `ChatAgentHostGitHubEnvironments` 设备策略设置为 `false`，阻止将机器共享为 GitHub Environment，并阻止通过此功能发现或连接其他已注册机器。该策略控制 `chat.agentHost.githubEnvironments.enabled`，要求 VS Code 1.144 或更高版本。通过组织策略关闭 Copilot 预览功能也会强制关闭此设置。

　　此控制不治理所有远程连接。它不是对 SSH 或开发隧道的全面限制，也不配置其他客户端策略。将其视为组织范围远程访问边界前，请单独审查这些访问路径。

### 配置安全和可观测性 {#configure-security-and-observability}

#### 配置智能体沙盒 {#configure-agent-sandboxing}

　　对于 Copilot 运行框架会话，请使用[会话沙盒控制](../../ai-in-vs-code/work-with-ai/permissions-and-security/2.2.12.2-AgentSandboxing/)并在运行命令的机器上验证[有效沙盒策略](../../ai-in-vs-code/work-with-ai/permissions-and-security/2.2.12.2-AgentSandboxing/)。

　　使用企业托管设置中的共享 `sandbox` 键强制执行支持的沙盒最低限制。请遵循[沙盒 schema 和最低客户端版本](https://docs.github.com/en/copilot/reference/enterprise-administrators/enterprise-managed-settings#sandbox)。在智能体运行位置（包括远程主机和容器）验证策略交付和[有效沙盒策略](../../ai-in-vs-code/work-with-ai/permissions-and-security/2.2.12.2-AgentSandboxing/)。Local 运行框架会话无法执行这些运行时独有控制。

**Local 运行框架会话的沙盒设备策略**

以下 VS Code 设备策略已弃用，适用于 Local 运行框架会话。它们不为 Copilot 运行框架会话执行沙盒。

| 策略 | Local 会话行为 |
|--------|------------------------|
| `ChatAgentSandboxEnabled` | 要求或禁用受支持终端命令的沙盒。 |
| `ChatAgentSandboxAllowNetwork` | 控制沙盒终端命令的出站网络访问。 |
| `ChatAgentSandboxAllowUnsandboxedCommands` | 控制用户确认后命令是否可在沙盒外运行。 |

　　Local 运行框架会话自动批准沙盒终端命令。[终端自动批准策略](#configure-terminal-auto-approval)控制基于规则的批准，而不是沙盒自动批准。

#### 配置智能体网络筛选 {#configure-agent-network-filtering}

　　将 `ChatAgentNetworkFilter` 设置为 `true`，根据允许和拒绝域策略限制网络访问。

　　使用 `ChatAgentAllowedNetworkDomains` 设置允许的域模式，使用 `ChatAgentDeniedNetworkDomains` 设置阻止的模式。拒绝域优先。

　　Local 运行框架会话中，网络筛选适用于 fetch 工具和集成浏览器。Copilot 运行框架会话中，这些策略也适用于集成浏览器。

　　`ChatAgentNetworkFilter` 策略为 `true` 且 `ChatAgentAllowedNetworkDomains` 包含允许域时，Copilot 运行框架会话会阻止运行时 Web fetch 工具访问列表外的域，即使选择了 **全部允许**。此限制不需要沙盒。

　　终端覆盖取决于所选运行框架、平台和沙盒配置。请参阅[配置沙盒网络访问](../../ai-in-vs-code/work-with-ai/permissions-and-security/2.2.12.2-AgentSandboxing/)。

　　更改网络筛选设置后请重启 VS Code，使新的集成浏览器会话使用更新策略。

#### 使用 OpenTelemetry 配置遥测导出 {#configure-telemetry-export-with-opentelemetry}

　　使用 `CopilotOtel*` 策略控制 VS Code 中 Copilot 的 [OpenTelemetry](https://opentelemetry.io/) 导出。这些策略涵盖导出启用、收集器终结点和协议、内容和身份捕获、服务名称、资源属性以及导出器标头。

　　策略完整列表及其控制的设置请参阅[企业策略参考](../7.1-Policies/)。

## 使用 GitHub 组织和企业设置 {#use-github-organization-and-enterprise-settings}

　　GitHub 托管控制通过已登录账户和 GitHub 服务应用，不是 VS Code 设备策略。

　　使用 GitHub 组织和企业设置管理 Copilot 访问、可用模型和功能、内容排除以及其他服务端策略。请参阅[为企业管理 Copilot](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise)。

　　要限制统一 Marketplace 和 Copilot 连接器，请关闭 **编辑器预览功能**。这会强制关闭 `chat.customizations.marketplace.enabled` 和 `chat.customizations.copilotConnectors.enabled`，即使两者默认 `true`。开发者不能在设置中覆盖此限制。允许预览功能时，其他资格要求和托管限制仍然适用。

### 了解 MCP 注册表策略刷新失败 {#understand-mcp-registry-policy-refresh-failures}

　　GitHub 组织和企业策略可以将 MCP 访问限制为配置注册表中的服务器。从 VS Code 1.145 开始，刷新该策略时临时网络或服务故障不会移除之前收到的限制。VS Code 保留最后已知注册表 URL 和访问限制。

　　确认没有适用注册表的响应会移除缓存的注册表限制。退出登录或切换账户也会清除它。

> **重要**：保留缓存策略不是启动强制执行保证。没有缓存注册表策略且首次获取失败时，仅注册表策略不会限制 MCP 访问。必须独立于成功 GitHub 策略获取而应用的限制，请配置 `ChatMCP` [设备策略](../7.1-Policies/)。

　　此刷新行为适用于编辑器管理的 MCP 服务器。它独立于[托管允许列表优先级](#managed-allowlists-and-registry-precedence)，也不描述 Agent Host 拥有服务器的执行。

### 配置组织级自定义指令 {#configure-organization-level-custom-instructions}

　　组织管理员在 GitHub 上创建自定义指令。`github.copilot.chat.organizationInstructions.enabled` 为 `true` 时，VS Code 中受支持 Copilot 会话包含已登录账户可访问的组织指令。

　　详细了解[为组织添加自定义指令](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/add-custom-instructions/add-organization-instructions)。

### 配置组织级自定义智能体 {#configure-organization-level-custom-agents}

　　组织管理员在 GitHub 上创建自定义智能体。`github.copilot.chat.organizationCustomAgents.enabled` 为 `true` 时，已登录账户可访问的组织和企业智能体会出现在智能体下拉列表中。

　　详细了解[为组织创建自定义智能体](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/create-custom-agents)。

　　Copilot 安全、隐私、合规和透明度信息请参阅 [Copilot 信任中心常见问题](https://copilot.github.trust.page/faq)。
