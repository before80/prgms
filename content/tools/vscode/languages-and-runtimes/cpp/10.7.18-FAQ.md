# 10.7.18 C++ 常见问题

## 如何让 IntelliSense 正常工作？ {#how-do-i-get-intellisense-to-work-correctly}

　　未配置时，扩展会搜索工作区文件夹并模拟计算机上找到的编译器（Windows 上 `cl.exe`/MinGW，macOS/Linux 上 gcc/clang）。自动配置不足时，可以运行 **C/C++: Edit Configurations (UI)** 修改默认值，包括模拟的编译器、包含路径和预处理器定义。

安装与扩展接口的构建系统扩展时，也可以让该扩展提供配置。例如 CMake Tools 可以为 CMake 项目配置。使用 **C/C++: Change Configuration Provider...** 启用。

第三种选择是使用 `compile_commands.json`。在配置 UI 的 **Advanced** 部分提供路径，扩展会使用其中的编译信息配置 IntelliSense。

**注意**：扩展无法解析源代码中的任何 `#include` 时，不会显示源文件主体的 Lint 信息。**问题** 窗口会提供无法定位的文件信息。需要显示 Lint 信息时，可以修改 `C_Cpp.errorSquiggles`。

## includePath 和 browse.path 有什么区别？ {#what-is-the-difference-between-includepath-and-browsepath}

### includePath {#includepath}

　　字符串路径数组，供“Default”IntelliSense 引擎使用，提供语义感知功能。这些路径等同于编译器 `-I` 开关。解析源文件时，IntelliSense 会将这些路径添加到 `#include` 指定的文件前。除非以 `/**` 结尾，否则 **不递归** 搜索。

### browse.path {#browsepath}

　　字符串路径数组，供“Tag Parser”（浏览引擎）使用，填充全局符号数据库。该引擎会 **递归** 枚举路径下所有文件，并在 Tag Parse 项目时跟踪潜在包含。要禁用某路径的递归枚举，请在路径后添加 `/*`。

首次打开工作区时，扩展将 `${workspaceFolder}/**` 添加到 `includePath`，`browse.path` 未定义（默认使用 `includePath`）。不需要时可以修改 `c_cpp_properties.json`。

## 为什么标准库类型下有红色波浪线？ {#why-do-i-see-red-squiggles-under-standard-library-types}

　　最常见原因是缺少包含路径和定义。最简单的修复是在 `c_cpp_properties.json` 中将 `compilerPath` 设置为编译器路径。

## 为什么格式化后文件损坏？ {#why-are-my-files-corrupted-on-format}

　　通过包含符号链接的路径打开工作区文件夹时，文件可能损坏或其他功能失败（[vscode-cpptools#5061](https://github.com/microsoft/vscode-cpptools/issues/5061)）。解决方法是使用解析了符号链接的目标路径打开工作区。

从命令面板运行 **C/C++: Reset IntelliSense Database** 命令。

## ipch 文件夹是什么？ {#what-is-the-ipch-folder}

　　语言服务器缓存包含头文件信息以提高 IntelliSense 性能。编辑 C/C++ 文件时，缓存文件存放在 `ipch` 文件夹。默认位于用户目录：

* Windows：`%LocalAppData%/Microsoft/vscode-cpptools`
* Linux：`$XDG_CACHE_HOME/vscode-cpptools/`（未定义时为 `$HOME/.cache/vscode-cpptools/`）
* macOS：`$HOME/Library/Caches/vscode-cpptools/`

默认每个用户一个缓存位置，缓存大小限制作用于该位置，限制磁盘占用。

### `"C_Cpp.intelliSenseCachePath": <string>` {#c_cppintellisensecachepath-string}

设置工作区或全局缓存路径。例如希望所有工作区共享一个缓存位置时，在用户设置中配置 **IntelliSense Cache Path**。

### `"C_Cpp.intelliSenseCacheSize": <number>` {#c_cppintellisensecachesize-number}

设置缓存大小限制。扩展会尽力接近该限制。跨工作区共享缓存时，也应在用户设置中调整 **IntelliSense Cache Size**。

## 如何禁用 IntelliSense 缓存（ipch）？ {#how-do-i-disable-the-intellisense-cache-ipch}

将 **IntelliSense Cache Size** 设置为 0（JSON 中 `"C_Cpp.intelliSenseCacheSize": 0`）。出现过多磁盘写入（尤其编辑头文件时）时，禁用缓存可能有帮助。

## 如何设置调试？ {#how-do-i-set-up-debugging}

调试器需要知道使用哪个可执行文件和调试器：

从主菜单选择 **运行 > 添加配置...**，打开 `launch.json` 编辑。默认设置通常可用，但需要指定 `program`。详情请参阅[配置 C/C++ 调试](10.7.13-LaunchJsonReference/)。

## 如何启用调试符号？ {#how-do-i-enable-debug-symbols}

取决于编译器。常见选项：

### Clang（C++） {#clang-c}

* 手动调用时添加 `--debug`。
* 使用脚本时设置 `CXXFLAGS`，例如 `export CXXFLAGS="${CXXFLAGS} --debug"`。
* 使用 CMake 时设置 `CMAKE_CXX_FLAGS`，例如 `export CMAKE_CXX_FLAGS=${CXXFLAGS}`。

### Clang（C） {#clang-c-1}

同 Clang C++，但使用 `CFLAGS` 而不是 `CXXFLAGS`。

### gcc 或 g++ {#gcc-or-g}

手动调用时添加 `-g`。

### cl.exe {#clexe}

符号位于 `*.pdb` 文件。

## 为什么调试不工作？ {#why-is-debugging-not-working}

### 断点未命中 {#my-breakpoints-arent-being-hit}

断点未绑定（实心红圈）或未命中时，可能需要在编译时启用[调试符号](#how-do-i-enable-debug-symbols)。

### 调试启动但堆栈跟踪所有行都是灰色 {#debugging-starts-but-all-the-lines-in-my-stack-trace-are-grey}

调试器显示灰色堆栈、断点不停或调用堆栈符号为灰色时，可执行文件编译时未包含[调试符号](#how-do-i-enable-debug-symbols)。

## 怀疑 C/C++ 扩展问题时怎么办？ {#what-do-i-do-if-i-suspect-a-cc-extension-problem}

请在 [GitHub discussions](https://github.com/microsoft/vscode-cpptools/discussions)提问，或向 [GitHub issues](https://github.com/microsoft/vscode-cpptools/issues)提交缺陷。

如果问题无法根据报告信息诊断，可能需要启用调试日志并提供日志。详情请参阅 [C/C++ 扩展日志](https://code.visualstudio.com/docs/cpp/enable-logging-cpp)。
