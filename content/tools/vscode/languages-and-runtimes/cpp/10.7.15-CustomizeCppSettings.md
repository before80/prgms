# 10.7.15 C++ 设置参考

　　本文介绍 `c_cpp_properties.json` 的架构。通用设置请参阅[配置设置](../../../editor/3.3-ConfigureTheEditor/3.3.4-Settings/)、[变量参考](../../../editor/3.4-Reference/3.4.3-SubstitutionVariables/)和默认设置。

C++ 项目配置入门请参阅[配置 IntelliSense](10.7.16-ConfigureIntelliSense/)。

## 变量示例 {#example-of-variables}

```json
{
    "env": {
        "myIncludePath": [
            "${workspaceFolder}/include",
            "${workspaceFolder}/src"
        ],
        "myDefines": [
            "DEBUG",
            "MY_FEATURE=1"
        ]
    },
    "configurations": [
        {
            "name": "Mac",
            "compilerPath": "/usr/bin/clang++",
            "intelliSenseMode": "macos-clang-x64",
            "includePath": [
                "${myIncludePath}",
                "${workspaceFolder}/**"
            ],
            "defines": [
                "${myDefines}"
            ],
            "cStandard": "c17",
            "cppStandard": "c++20",
            "macFrameworkPath": [
                "/System/Library/Frameworks",
                "/Library/Frameworks"
            ],
            "browse": {
                "path": [
                    "${myIncludePath}",
                    "${workspaceFolder}"
                ]
            }
        }
    ],
    "version": 4,
    "enableConfigurationSquiggles": true
}
```

只需包含相关变量，缺少字段由扩展填充默认值。

## 顶级属性 {#top-level-properties}

* `env`：用户定义变量数组，可在配置中通过 `${<var>}` 或 `${env:<var>}` 替换。接受字符串或字符串数组。
* `configurations`：配置对象数组，向 IntelliSense 引擎提供项目和偏好信息。默认根据操作系统创建一个配置，可以添加更多。
* `version`：建议不要编辑，跟踪 `c_cpp_properties.json` 版本。
* `enableConfigurationSquiggles`：设为 `true` 时报告 `c_cpp_properties.json` 中的错误。

## 配置属性 {#configuration-properties}

* `name`：配置名称。`Linux`、`Mac`、`Win32` 是平台自动选择的特殊标识。状态栏显示活动配置，可以单击切换。
* `compilerPath`：编译器完整路径（例如 `/usr/bin/gcc`），用于查询系统包含路径和默认定义。设为 `""` 跳过查询；省略不会跳过。
* `compilerArgs`：修改包含路径或定义的编译器参数（例如 `-nostdinc++`、`-m32`）。带参数的选项应拆分为数组元素。
* `intelliSenseMode`：IntelliSense 模式，映射到 MSVC、gcc 或 Clang 的架构变体。未设置或 `${default}` 时使用平台默认：
  * Windows：`windows-msvc-x64`
  * Linux：`linux-gcc-x64`
  * macOS：`macos-clang-x64`
  仅指定 `<compiler>-<architecture>` 的旧模式会自动转换。
* `includePath`：头文件包含路径列表。搜索不递归，末尾 `/**` 表示递归。Windows 安装 Visual Studio 或指定 `compilerPath` 时不应列出系统包含路径。
* `defines`：预处理器定义列表，可使用 `=` 赋值，例如 `VERSION=1`。
* `cStandard`：C 语言标准，例如 `c17`、`gnu23`、`${default}`。
* `cppStandard`：C++ 语言标准，例如 `c++20`、`gnu++23`、`${default}`。
* `configurationProvider`：提供 IntelliSense 配置的扩展 ID，例如 `ms-vscode.cmake-tools`。提供程序的配置优先于其他设置。
* `mergeConfigurations`：设为 `true` 时合并配置提供程序的包含路径、定义和强制包含。
* `windowsSdkVersion`：Windows SDK 包含路径版本，例如 `10.0.17134.0`。
* `macFrameworkPath`：Mac 框架头文件搜索路径。
* `forcedInclude`：在处理源文件前包含的文件列表，按顺序包含。
* `compileCommands`：`compile_commands.json` 文件路径数组。匹配打开文件时使用其中的命令行配置 IntelliSense。
* `dotConfig`：Kconfig 生成的 `.config` 文件路径。
* `customConfigurationVariables`：可通过 `${cpptools:activeConfigCustomVariable}` 查询的自定义变量，用于 `launch.json` 或 `tasks.json`。
* `browse`：与 IntelliSense 配合识别代码库所有符号的属性，用于转到定义/声明、全局符号搜索等。
* `recursiveIncludes`：配置递归 `includePath` 处理方式。

### Browse 属性 {#browse-properties}

* `path`：全局符号搜索解析的源文件路径列表。省略时使用 `includePath`。默认递归，`*` 表示非递归。
* `limitSymbolsToIncludedHeaders`：`true` 时 Tag Parser 只解析被 `${workspaceFolder}` 中源文件直接或间接包含的头文件；`false` 时解析 `browse.path` 中所有代码文件。
* `databaseFilename`：生成的符号数据库路径。相对路径相对于工作区默认存储位置。

### 递归包含属性 {#recursive-includes-properties}

* `reduce`：默认 `always` 时先 Tag Parse 源文件，确定所需包含路径，减少 IntelliSense 路径数量；`never` 时提供完整递归展开，启动更快但后续可能变慢。
* `priority`：`beforeSystemIncludes` 在系统包含路径前搜索递归路径；`afterSystemIncludes` 在之后搜索。
* `order`：子目录搜索顺序，`breadthFirst` 或 `depthFirst`。

## 支持的变量 {#supported-variables}

可以在 `tasks.json` 或 `launch.json` 中使用 `${command:cpptools.activeConfigName}` 查询 `c_cpp_properties.json` 的活动配置名称。

### 默认 VS Code 设置 {#default-vs-code-settings}

`C_Cpp.default.includePath` 等所有默认 VS Code 设置都在 `c_cpp_properties.json` 中支持，例外是：

```json
C_Cpp.default.systemIncludePath : string[]
```

此设置允许单独指定系统包含路径。扩展从编译器收到的系统包含路径不会传给 IntelliSense，仅在编译器不受支持等少数场景使用。大多数情况下建议使用 `compilerArgs` 的 `-isystem` 标志指定系统头文件。
