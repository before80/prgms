# 10.7.13 launch.json 参考

　　本文介绍 C/C++ 扩展 `launch.json` 的调试配置属性。基础配置请参阅[调试 C++](10.7.12-CppDebug/)和[调试配置](../../../debugging-and-testing/6.2-DebuggingConfiguration/)。

## 配置 VS Code 调试行为 {#configure-vs-codes-debugging-behavior}

### `program`（必需） {#program-required}

要调试的程序的完整路径。例如：

```json
"program": "${workspaceFolder}/a.out"
```

### `symbolSearchPath` {#symbolsearchpath}

调试器查找符号文件（PDB）的路径，多个路径用分号分隔。例如：

```json
"symbolSearchPath": "C:\\symbols;\\\\server\\symbols"
```

### `requireExactSource` {#requireexactsource}

默认 `true`，要求源文件与调试信息完全匹配。设为 `false` 可以使用不完全匹配的源文件。

### `additionalSOLibSearchPath` {#additionalsolibsearchpath}

GDB/LLDB 查找共享库的额外路径，多个路径用分号分隔。

### `externalConsole` {#externalconsole}

Windows 上设为 `true` 使用外部控制台窗口。Linux/macOS 上此属性被忽略。

### `avoidWindowsConsoleRedirection` {#avoidwindowsconsoleredirection}

设为 `true` 避免 Windows 控制台重定向，可能改善某些程序的输出行为。

### `logging` {#logging}

调试器日志：

```json
"logging": {
    "engineLogging": true,
    "trace": true,
    "traceResponse": true,
    "programOutput": true
}
```

* `engineLogging`：记录调试器引擎通信。
* `trace`：记录调试适配器与调试器之间的通信。
* `traceResponse`：记录调试器响应。
* `programOutput`：记录程序输出。

### `visualizerFile` {#visualizerfile}

Natvis 可视化文件路径，用于自定义类型显示：

```json
"visualizerFile": "${workspaceFolder}/my.natvis"
```

### `showDisplayString` {#showdisplaystring}

设为 `true` 时在 **变量** 视图中显示 Natvis `DisplayString`。

## 配置目标应用程序 {#configure-the-target-application}

### `args` {#args}

传给程序的命令行参数数组：

```json
"args": ["--port", "8080", "input.txt"]
```

### `cwd` {#cwd}

程序工作目录，默认 `${workspaceFolder}`。

### `environment` {#environment}

环境变量数组：

```json
"environment": [
    { "name": "DEBUG", "value": "1" },
    { "name": "PATH", "value": "${env:PATH};C:\\tools" }
]
```

## 自定义 GDB 或 LLDB {#customizing-gdb-or-lldb}

### `MIMode` {#mimode}

调试器类型：`gdb`、`lldb` 或 `vsdbg`（Windows MSVC 使用 `cppvsdbg` 类型时不需要）。

### `miDebuggerPath` {#midebuggerpath}

调试器可执行文件完整路径：

```json
"miDebuggerPath": "/usr/bin/gdb"
```

### `miDebuggerArgs` {#midebuggerargs}

传给调试器的额外参数。

### `stopAtEntry` {#stopatentry}

设为 `true` 时在程序入口（`main`）暂停。默认 `false`。

### `stopAtConnect` {#stopatconnect}

附加时是否在连接后暂停。

### `setupCommands` {#setupcommands}

调试器启动后执行的命令数组：

```json
"setupCommands": [
    {
        "description": "Enable pretty-printing for gdb",
        "text": "-enable-pretty-printing",
        "ignoreFailures": true
    }
]
```

### `customLaunchSetupCommands` {#customlaunchsetuPcommands}

替换默认启动命令的数组。设置为 `[]` 可以完全自定义启动。

### `launchCompleteCommand` {#launchcompletecommand}

调试器启动完成命令，默认 `exec-run`。可以设为 `exec-continue` 或 `None`。

### `symbolLoadInfo` {#symbolloadinfo}

控制符号加载：

```json
"symbolLoadInfo": {
    "loadAll": true,
    "exceptionList": ["module1.dll", "module2.dll"]
}
```

或：

```json
"symbolLoadInfo": {
    "loadAll": false,
    "includeList": ["module3.dll"]
}
```

## 调试转储文件 {#debugging-dump-files}

### `dumpPath` {#dumppath}

Windows 内存转储文件路径：

```json
"dumpPath": "C:\\dumps\\app.dmp"
```

### `coreDumpPath` {#coredumppath}

Linux core dump 文件路径：

```json
"coreDumpPath": "/tmp/core.app.1234"
```

## 远程调试或本地调试服务器 {#remote-debugging-or-debugging-with-a-local-debugger-server}

### `miDebuggerServerAddress` {#midebuggerserveraddress}

GDB/LLDB 服务器地址，例如 `localhost:1234`。

### `debugServerPath` {#debugserverpath}

要启动的调试服务器可执行文件路径。

### `debugServerArgs` {#debugserverargs}

调试服务器参数。

### `serverStarted` {#serverstarted}

调试服务器输出中表示启动完成的字符串。

### `filterStdout` {#filterstdout}

是否过滤调试服务器 stdout。

### `filterStderr` {#filterstderr}

是否过滤调试服务器 stderr。

### `serverLaunchTimeout` {#serverlaunchtimeout}

等待调试服务器启动的超时毫秒数。

### `pipeTransport` {#pipetransport}

通过管道连接远程调试器：

```json
"pipeTransport": {
    "pipeProgram": "ssh",
    "pipeArgs": ["user@remote"],
    "debuggerPath": "/usr/bin/gdb"
}
```

### `hardwareBreakpoints` {#hardwarebreakpoints}

硬件断点配置：

```json
"hardwareBreakpoints": {
    "require": true,
    "limit": 4
}
```

### `debuginfod` {#debuginfod}

启用 [debuginfod](https://sourceware.org/elfutils/Debuginfod.html) 下载调试信息：

```json
"debuginfod": {
    "enabled": true,
    "urls": ["https://debuginfod.elfutils.org/"]
}
```

## 其他属性 {#additional-properties}

### `processId` {#processid}

附加到指定进程 ID，可以使用 `${command:pickProcess}` 选择。

### `request` {#request}

`launch` 或 `attach`。

### `targetArchitecture` {#targetarchitecture}

目标架构，例如 `x64`、`x86`、`arm64`。通常自动检测。

### `type` {#type}

调试器类型：`cppdbg`（GDB/LLDB）或 `cppvsdbg`（Windows MSVC）。

### `sourceFileMap` {#sourcefilemap}

源文件路径映射：

```json
"sourceFileMap": {
    "/build/path": "C:\\source\\path"
}
```

## 环境变量定义文件 {#environment-variable-definitions-file}

可以使用 `envFile` 从文件加载环境变量：

```json
"envFile": "${workspaceFolder}/.env"
```

`.env` 格式：

```text
DEBUG=1
PATH=C:\tools;%PATH%
```

## 符号选项 {#symbol-options}

`symbolLoadInfo` 支持两种模式：

### `loadAllButExcluded` 模式属性 {#properties-for-loadallbutexcluded-mode}

* `loadAll`：是否加载所有符号。
* `exceptionList`：不加载符号的模块列表。

### `loadOnlyIncluded` 模式属性 {#properties-for-loadonlyincluded-mode}

* `loadAll`：设为 `false`。
* `includeList`：只加载这些模块的符号。

更多调试配置请参阅[调试配置](../../../debugging-and-testing/6.2-DebuggingConfiguration/)。
