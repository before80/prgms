# 10.2.4 Emmet

　　VS Code 内置对 [Emmet](https://emmet.io/) 代码片段和展开的支持，**无需安装扩展**。[Emmet 2.0](https://code.visualstudio.com/blogs/2017/08/07/emmet) 支持大多数 [Emmet 操作](https://docs.emmet.io/actions/)，包括展开 [Emmet 缩写和代码片段](https://docs.emmet.io/cheat-sheet/)。

## 如何展开 Emmet 缩写和代码片段 {#how-to-expand-emmet-abbreviations-and-snippets}

　　Emmet 缩写和代码片段展开默认在 `html`、`haml`、`pug`、`slim`、`jsx`、`xml`、`xsl`、`css`、`scss`、`sass`、`less` 和 `stylus` 文件中启用，也适用于继承上述语言的任何语言，例如 `handlebars` 和 `php`。

<video src="https://code.visualstudio.com/assets/docs/languages/emmet/emmet.mp4" title="建议/自动补全列表中的 Emmet。" autoplay loop controls muted></video>

　　开始输入 Emmet 缩写时，缩写会显示在建议列表中。如果建议文档浮出控件已打开，输入时会看到展开预览。在样式表文件中，展开的缩写会按其他 CSS 建议排序显示在建议列表中。

### 使用 Tab 展开 Emmet {#using-tab-for-emmet-expansions}

如果希望使用 `Tab` 键展开 Emmet 缩写，请添加以下设置：

```json
"emmet.triggerExpansionOnTab": true
```

　　此设置允许在文本不是 Emmet 缩写时使用 `Tab` 键缩进。

### 禁用 quickSuggestions 时的 Emmet {#emmet-when-quicksuggestions-are-disabled}

　　如果禁用了 `editor.quickSuggestions` [设置](../../../editor/3.3-ConfigureTheEditor/3.3.4-Settings/)，输入时不会看到建议。仍可以按 `Ctrl + Space` 手动触发建议并查看预览。

### 在建议中禁用 Emmet {#disable-emmet-in-suggestions}

如果完全不想在建议中看到 Emmet 缩写，请使用：

```json
"emmet.showExpandedAbbreviation": "never"
```

　　仍可以使用 **Emmet: Expand Abbreviation** 命令展开缩写，也可以为命令 ID `editor.emmet.action.expandAbbreviation` 绑定任意快捷键。

### Emmet 建议排序 {#emmet-suggestion-ordering}

要确保 Emmet 建议始终位于建议列表顶部，请添加：

```json
"emmet.showSuggestionsAsSnippets": true,
"editor.snippetSuggestions": "top"
```

## 其他文件类型中的 Emmet 缩写 {#emmet-abbreviations-in-other-file-types}

　　要在默认不支持的文件类型中启用 Emmet 缩写展开，请使用 `emmet.includeLanguages` 设置。确保映射两侧都使用[语言标识符](../../10.1-Overview/#language-identifier)，右侧为 Emmet 支持语言的语言标识符（见上方列表）。

例如：

```json
"emmet.includeLanguages": {
  "javascript": "javascriptreact",
  "razor": "html",
  "plaintext": "pug"
}
```

　　Emmet 不了解这些新语言，因此非 HTML/CSS 上下文中也可能出现 Emmet 建议。要避免这种情况，请使用：

```json
"emmet.showExpandedAbbreviation": "inMarkupAndStylesheetFilesOnly"
```

> **注意**：以前使用 `emmet.syntaxProfiles` 映射新文件类型时，从 VS Code 1.15 起应改用 `emmet.includeLanguages`。`emmet.syntaxProfiles` 仅用于[自定义最终输出](https://docs.emmet.io/customization/syntax-profiles)。

## 使用筛选器 {#using-filters}

　　筛选器是特殊后处理器，在展开缩写输出到编辑器之前修改结果。有两种使用方式：通过 `emmet.syntaxProfiles` 设置全局使用，或直接在当前缩写中使用。

以下是第一种方式的示例，使用 `emmet.syntaxProfiles` 为 HTML 文件中的所有缩写应用 `bem` 筛选器：

```json
"emmet.syntaxProfiles": {
  "html": {
    "filters": "bem"
  }
}

```

　　只为当前缩写提供筛选器时，请将筛选器追加到缩写。例如 `div#page|c` 会对 `div#page` 缩写应用 `comment` 筛选器。

### BEM 筛选器（bem） {#bem-filter-bem}

　　使用 [Block Element Modifier](http://getbem.com/)（BEM）方式编写 HTML 时，`bem` 筛选器非常方便。用法详情请参阅 [Emmet 中的 BEM 筛选器](https://docs.emmet.io/filters/bem/)。

　　可以按照 [Emmet 偏好设置](https://docs.emmet.io/customization/preferences/)使用 `bem.elementSeparator` 和 `bem.modifierSeparator` 自定义此筛选器。

### 注释筛选器（c） {#comment-filter-c}

　　此筛选器在重要标签周围添加注释。默认“重要标签”是带 id 和/或 class 属性的标签。

例如 `div>div#page>p.title+p|c` 会展开为：

```xml
<div>
    <div id="page">
        <p class="title"></p>
        <!-- /.title -->
        <p></p>
    </div>
    <!-- /#page -->
</div>
```

　　可以按照 [Emmet 偏好设置](https://docs.emmet.io/customization/preferences/)使用 `filter.commentTrigger`、`filter.commentAfter` 和 `filter.commentBefore` 自定义。

　　`filter.commentAfter` 偏好的格式在 VS Code Emmet 2.0 中不同。

例如，不再使用：

```json
"emmet.preferences": {
  "filter.commentAfter": "\n<!-- /<%= attr('id', '#') %><%= attr('class', '.') %> -->"
}
```

在 VS Code 中应使用更简单的：

```json
"emmet.preferences": {
  "filter.commentAfter": "\n<!-- /[#ID][.CLASS] -->"
}
```

### 修剪筛选器（t） {#trim-filter-t}

　　此筛选器仅适用于为 **Emmet: Wrap with Abbreviation** 命令提供缩写时。它会从被包裹行中[移除行标记](https://docs.emmet.io/actions/wrap-with-abbreviation/#removing-list-markers)。

## 使用自定义 Emmet 代码片段 {#using-custom-emmet-snippets}

　　自定义 Emmet 代码片段需要定义在名为 `snippets.json` 的 JSON 文件中。`emmet.extensionsPath` 设置应指向包含此文件的目录。

以下是 `snippets.json` 文件内容示例：

```json
{
    "html": {
        "snippets": {
            "ull": "ul>li[id=${1} class=${2}]*2{ Will work with html, pug, haml and slim }",
            "oll": "<ol><li id=${1} class=${2}> Will only work in html </ol>",
            "ran": "{ Wrap plain text in curly braces }"
        }
    },
    "css": {
        "snippets": {
            "cb": "color: black",
            "bsd": "border: 1px solid ${1:red}",
            "ls": "list-style: ${1}"
        }
    }
}
```

　　Emmet 2.0 通过 `snippets.json` 编写自定义代码片段与旧方式有几处不同：

| 主题 | 旧 Emmet | Emmet 2.0 |
|------|----------|-----------|
| 代码片段与缩写 | 在 `snippets` 和 `abbreviations` 两个属性中分别支持 | 合并为单个 `snippets` 属性。请参阅默认 [HTML 代码片段](https://github.com/emmetio/emmet/blob/master/src/snippets/html.json)和 [CSS 代码片段](https://github.com/emmetio/emmet/blob/master/src/snippets/css.json) |
| CSS 代码片段名称 | 可以包含 `:` | 定义名称时不要使用 `:`。Emmet 模糊匹配缩写时用它分隔属性名和值 |
| CSS 代码片段值 | 可以以 `;` 结尾 | 不要在值末尾添加 `;`。Emmet 会根据文件类型（css/less/scss 与 sass/stylus）或 `css.propertyEnd`、`sass.propertyEnd`、`stylus.propertyEnd` 偏好添加 |
| 光标位置 | 可以使用 `${cursor}` 或 `\|` | 只使用 `${1}` 等 TextMate 语法表示制表位和光标位置 |

### HTML Emmet 代码片段 {#html-emmet-snippets}

　　HTML 自定义代码片段适用于所有其他标记语言，例如 `haml` 或 `pug`。代码片段值是缩写而不是实际 HTML 时，可以根据语言类型应用适当转换得到正确输出。

例如，对于带列表项的无序列表，如果代码片段值是 `ul>li`，可以在 `html`、`haml`、`pug` 或 `slim` 中使用同一片段；但如果值是 `<ul><li></li></ul>`，则只能在 `html` 文件中使用。

　　需要纯文本代码片段时，请用 `{}` 包围文本。

### CSS Emmet 代码片段 {#css-emmet-snippets}

　　CSS Emmet 代码片段值应是完整的属性名和值对。

　　CSS 自定义代码片段适用于所有其他样式表语言，例如 `scss`、`less` 或 `sass`。因此不要在值末尾添加 `;`，Emmet 会根据语言是否需要自动添加。

　　不要在代码片段名称中使用 `:`。Emmet 模糊匹配缩写时用 `:` 分隔属性名和值。

### 自定义代码片段中的制表位和光标 {#tab-stops-and-cursors-in-custom-snippets}

　　自定义 Emmet 代码片段中的制表位语法遵循 [TextMate 代码片段语法](https://manual.macromates.com/en/snippets)。

* 使用 `${1}`、`${2}` 表示制表位，使用 `${1:placeholder}` 表示带占位符的制表位。
* 以前使用 `|` 或 `${cursor}` 表示光标位置，现已不支持，请改用 `${1}`。

## Emmet 配置 {#emmet-configuration}

以下 Emmet [设置](../../../editor/3.3-ConfigureTheEditor/3.3.4-Settings/)可用于自定义 VS Code 中的 Emmet 体验。

* `emmet.includeLanguages`

  在所选语言与 Emmet 支持语言之间添加映射，使前者使用后者的语法启用 Emmet。映射两侧都应使用语言 ID。

  例如：

  ```json
  "emmet.includeLanguages": {
    "javascript": "javascriptreact",
    "plaintext": "pug"
  }
  ```

* `emmet.excludeLanguages`

  不希望看到 Emmet 展开的语言，请添加到此设置。该设置接受语言 ID 字符串数组。

* `emmet.syntaxProfiles`

  了解如何自定义 HTML 缩写输出，请参阅 [Emmet 输出配置文件自定义](https://docs.emmet.io/customization/syntax-profiles/#create-your-own-profile)。

  例如：

  ```json
  "emmet.syntaxProfiles": {
    "html": {
      "attr_quotes": "single"
    },
    "jsx": {
      "self_closing_tag": true
    }
  }
  ```

* `emmet.variables`

  自定义 Emmet 代码片段使用的变量。

  例如：

  ```json
  "emmet.variables": {
    "lang": "de",
    "charset": "UTF-16"
  }
  ```

* `emmet.showExpandedAbbreviation`

  控制建议/补全列表中显示的 Emmet 建议。

  | 设置值 | 说明 |
  |--------|------|
  | `never` | 任何语言的建议列表中都不显示 Emmet 缩写。 |
  | `inMarkupAndStylesheetFilesOnly` | 仅对纯标记和样式表语言（`html`、`pug`、`slim`、`haml`、`xml`、`xsl`、`css`、`scss`、`sass`、`less`、`stylus`）显示 Emmet 建议。 |
  | `always` | 在所有 Emmet 支持模式以及 `emmet.includeLanguages` 中映射的语言中显示 Emmet 建议。 |

  **注意**：`always` 模式下新 Emmet 实现不具备上下文感知。例如编辑 JavaScript React 文件时，不仅在编写标记时会出现 Emmet 建议，编写 JavaScript 时也会出现。

* `emmet.showAbbreviationSuggestions`

  将可能的 Emmet 缩写显示为建议，默认 `true`。

  例如输入 `li` 时，会看到所有以 `li` 开头的 Emmet 代码片段建议，例如 `link`、`link:css`、`link:favicon` 等。这有助于学习不熟悉的 Emmet 代码片段。

  不适用于样式表，也不适用于 `emmet.showExpandedAbbreviation` 为 `never` 时。

* `emmet.extensionsPath`

  提供包含 `snippets.json` 文件的目录位置，该文件包含自定义代码片段。

* `emmet.triggerExpansionOnTab`

  设置为 true 以使用 `Tab` 键展开 Emmet 缩写。没有缩写可展开时，此设置会提供适当的缩进回退。

* `emmet.showSuggestionsAsSnippets`

  设置为 `true` 时，Emmet 建议会与其他代码片段分组，可以按 `editor.snippetSuggestions` 设置排序。将其设置为 `true` 并将 `editor.snippetSuggestions` 设置为 `top`，可确保 Emmet 建议始终位于其他建议顶部。

* `emmet.preferences`

  可以使用此设置按照 [Emmet 偏好设置](https://docs.emmet.io/customization/preferences/)自定义 Emmet。目前支持：

  * `css.propertyEnd`
  * `css.valueSeparator`
  * `sass.propertyEnd`
  * `sass.valueSeparator`
  * `stylus.propertyEnd`
  * `stylus.valueSeparator`
  * `css.unitAliases`
  * `css.intUnit`
  * `css.floatUnit`
  * `bem.elementSeparator`
  * `bem.modifierSeparator`
  * `filter.commentBefore`
  * `filter.commentTrigger`
  * `filter.commentAfter`
  * `format.noIndentTags`
  * `format.forceIndentationForTags`
  * `profile.allowCompactBoolean`
  * `css.fuzzySearchMinScore`

  `filter.commentAfter` 偏好的格式在 Emmet 2.0 中更简单。

  例如，不再使用旧格式：

  ```json
  "emmet.preferences": {
    "filter.commentAfter": "\n<!-- /<%= attr('id', '#') %><%= attr('class', '.') %> -->"
  }
  ```

  而使用：

  ```json
  "emmet.preferences": {
    "filter.commentAfter": "\n<!-- /[#ID][.CLASS] -->"
  }
  ```

  需要支持 [Emmet 偏好设置](https://docs.emmet.io/customization/preferences/)中记录的其他偏好时，请提交[功能请求](https://github.com/microsoft/vscode/issues/new)。

## 故障排除 {#troubleshooting}

### 自定义标签不会在建议列表中展开 {#custom-tags-do-not-get-expanded-in-the-suggestion-list}

　　自定义标签用于 `MyTag>YourTag` 或 `MyTag.someclass` 等表达式时会显示在建议列表中；但单独使用 `MyTag` 时不会出现。这是为了避免建议列表噪音，因为每个单词都可能是自定义标签。

添加以下设置，使用 Tab 展开 Emmet 缩写，使自定义标签在所有情况下都能展开：

```json
"emmet.triggerExpansionOnTab": true
```

### 以 `+` 结尾的 HTML 代码片段不工作 {#my-html-snippets-ending-with--do-not-work}

　　[Emmet 速查表](https://docs.emmet.io/cheat-sheet/)中以 `+` 结尾的 HTML 代码片段（例如 `select+` 和 `ul+`）不受支持。这是 Emmet 2.0 的已知问题（[emmetio/html-matcher#1](https://github.com/emmetio/html-matcher/issues/1)）。变通方法是为这些场景创建自己的[自定义 Emmet 代码片段](#using-custom-emmet-snippets)。

### 缩写无法展开 {#abbreviations-are-failing-to-expand}

　　首先检查是否使用了自定义代码片段（`emmet.extensionsPath` 设置是否选中了 `snippets.json` 文件）。自定义代码片段格式在 VS Code 1.53 中发生变化。不要用 `|` 表示光标位置，请使用 `${1}`、`${2}` 等标记。[默认 CSS 代码片段文件](https://github.com/emmetio/emmet/blob/master/src/snippets/css.json)展示了新的光标位置格式。

如果缩写仍然无法展开：

* 检查[内置扩展](../../../editor/3.3-ConfigureTheEditor/3.3.6-Extensions/3.3.6.2-ExtensionMarketplace/)，确认 Emmet 是否被禁用。
* 尝试在[命令面板](../../../editor/3.1-GettingStarted/3.1.2-UserInterface/)运行 **Developer: Restart Extension Host**（`workbench.action.restartExtensionHost`）重启扩展宿主。

### 在哪里设置 Emmet 偏好设置？ {#where-can-i-set-all-the-preferences-as-documented-in-emmet-preferences}

　　可以使用 `emmet.preferences` 设置。只有 [Emmet 偏好设置](https://docs.emmet.io/customization/preferences/)中记录的子集可以自定义。请阅读 [Emmet 配置](#emmet-configuration)中的偏好设置部分。

### 有什么提示和技巧吗？ {#any-tips-and-tricks}

当然有！

* CSS 缩写中使用 `:` 时，左侧用于模糊匹配 CSS 属性名，右侧用于匹配属性值。可以利用这一点使用 `pos:f`、`trf:rx`、`fw:b` 等缩写。
* 探索 [Emmet 操作](https://docs.emmet.io/actions/)中记录的所有其他 Emmet 功能。
* 不要犹豫，创建自己的[自定义 Emmet 代码片段](#using-custom-emmet-snippets)。
