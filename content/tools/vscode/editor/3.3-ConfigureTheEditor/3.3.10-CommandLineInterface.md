# 3.3.10 命令行界面

　　VS Code 内置强大的命令行界面，可以控制编辑器启动方式。可以通过命令行选项（开关）打开文件、安装扩展、更改显示语言和输出诊断信息。

![命令行示例](../images/command-line/hero.png)

　　如果想知道如何在 VS Code 内运行命令行工具，请参阅[集成终端](../../../terminal/5.2-TerminalBasics/)。

## 命令行帮助 {#command-line-help}

　　要查看 VS Code 命令行界面概览，请打开终端或命令提示符并输入 `code --help`。会看到版本、用法示例和命令行选项列表。

![命令行帮助](../images/command-line/command-line-help.png)

## 从命令行启动 {#launching-from-command-line}

　　可以从命令行启动 VS Code 快速打开文件、文件夹或项目。通常会在文件夹上下文中打开 VS Code。为此，请在打开的终端或命令提示符中导航到项目文件夹并输入 `code .`：

![启动 VS Code](../images/command-line/launch-vscode.png)

> **注意**：macOS 上请先运行 **Shell Command: Install 'code' and optionally 'copilot' commands in PATH**，将 VS Code 可执行文件添加到 `PATH` 环境变量。安装 Copilot CLI 是可选的。请参阅 [macOS 命令行设置说明](../../../advanced-setup/9.3-macOS/)。

　　Windows 和 Linux 安装应将 VS Code 二进制文件位置添加到系统路径。如果没有，可以手动将位置添加到 `Path` 环境变量（Linux 上为 `$PATH`）。例如，Windows 上默认 VS Code 二进制文件位置为 `AppData\Local\Programs\Microsoft VS Code\bin`。平台特定设置说明请参阅[安装](../../../get-started/)。

> **注意**：使用 VS Code [Insiders](https://code.visualstudio.com/insiders) 预览版时，请使用 `code-insiders` 启动。

## 核心 CLI 选项 {#core-cli-options}

通过 `code` 在命令行启动 VS Code 时可以使用以下可选参数：

| 参数 | 说明 |
|------------------|-----------|
| `-h` 或 `--help` | 打印用法 |
| `-v` 或 `--version` | 打印 VS Code 版本（例如 1.22.2）、GitHub 提交 ID 和架构（例如 x64）。 |
| `-n` 或 `--new-window` | 打开新的 VS Code 会话，而不是恢复上一个会话（默认）。 |
| `-r` 或 `--reuse-window` | 强制在最后活动窗口中打开文件或文件夹。 |
| `-` | 从 stdin 读取并在 VS Code 中打开（例如 `echo Hello World | code.exe -`） |
| `-g` 或 `--goto` | 与 *file:line{:character}* 一起使用时，在指定行和可选字符位置打开文件。某些操作系统允许文件名包含 `:`，因此提供此参数。 |
| `-d` 或 `--diff <file1> <file2>` | 打开文件差异编辑器。需要两个文件路径参数。 |
| `-m` 或 `--merge <path1> <path2> <base> <result>` | 执行三方合并，提供文件两个修改版本的路径、共同原始版本和保存合并结果的输出文件。 |
| `-w` 或 `--wait` | 等待文件关闭后返回。 |
| `--locale <locale>` | 设置 VS Code 会话的[显示语言](https://code.visualstudio.com/docs/configure/locales)（区域设置），例如 `en-US` 或 `zh-TW`。 |

![使用区域设置启动](../images/command-line/launch-locale.png)

## 打开文件和文件夹 {#opening-files-and-folders}

　　有时需要打开或创建文件。指定文件不存在时，VS Code 会创建文件及任何新的中间文件夹：

```bash
code index.html style.css documentation\readme.md
```

　　文件和文件夹都可以使用绝对或相对路径。相对路径相对于运行 `code` 的命令提示符当前目录。

　　命令行指定多个文件时，VS Code 只打开单个实例。

　　命令行指定多个文件夹时，VS Code 会创建包含每个文件夹的[多根工作区](../../3.2-WriteCode/3.2.8-Workspaces/3.2.8.2-MultiRootWorkspaces/)。

| 参数 | 说明 |
|------------------|-----------|
| `file` | 要打开的文件名。文件不存在时会创建并标记为已编辑。可以用空格分隔多个文件名。 |
| `file:line[:character]` | 与 `-g` 参数一起使用。在指定行和可选字符位置打开文件名。 |
| `folder` | 要打开的文件夹名。可以指定多个文件夹，会创建新的[多根工作区](../../3.2-WriteCode/3.2.8-Workspaces/3.2.8.2-MultiRootWorkspaces/)。 |
| `--skip-add-to-recently-opened` | 阻止打开的文件和文件夹添加到最近打开列表。 |

![转到行和列](../images/command-line/goto-line-column.png)

## 选择配置文件 {#select-a-profile}

　　可以通过 `--profile` 命令行选项使用特定[配置文件](../3.3.8-Profiles/)启动 VS Code。在 `--profile` 参数后传递配置文件名称，并使用该配置文件打开文件夹或工作区。以下命令使用“Web Development”配置文件打开 `web-sample` 文件夹：

`code ~/projects/web-sample --profile "Web Development"`

　　指定配置文件不存在时，会创建具有该名称的新空配置文件。

## 使用扩展 {#working-with-extensions}

可以从命令行安装和管理 VS Code [扩展](../3.3.6-Extensions/3.3.6.2-ExtensionMarketplace/)。

| 参数 | 说明 |
|------------------|-----------|
| `--install-extension <extension-id> \| <extension-vsix-path>` | 安装或更新扩展。提供完整扩展名 `publisher.extension` 或 VSIX 文件路径。要安装特定版本，请附加 `@{version}`，例如 `vscode.csharp@1.2.3`。使用 `--force` 避免提示。使用 `--profile` 为特定配置文件安装。 |
| `--uninstall-extension <extension-id>` | 卸载扩展。提供完整扩展名 `publisher.extension`。使用 `--profile` 为特定配置文件卸载。 |
| `--disable-extensions` | 禁用所有已安装扩展。扩展仍显示在扩展视图 **已禁用** 部分，但从不激活。 |
| `--list-extensions` | 列出已安装扩展。可以使用 `--profile` 列出特定配置文件。 |
| `--show-versions` | 与 `--list-extensions` 一起显示已安装扩展版本。 |
| `--enable-proposed-api <ext>` | 为扩展启用提议 API 功能。提供完整扩展名 `publisher.extension`。 |
| `--update-extensions` | 更新已安装扩展并退出。 |

![安装扩展](../images/command-line/install-extension.png)

## 从命令行启动聊天 {#start-chat-from-the-command-line}

　　可以使用 VS Code CLI 中的 `chat` 子命令直接从命令行启动聊天会话。这会在当前工作目录中打开聊天会话，并使用提供的提示词。

例如，以下命令为当前目录打开聊天并询问“Find and fix all untyped variables”：

```bash
code chat Find and fix all untyped variables
```

`chat` 子命令有以下命令行选项：

* `-m`、`--mode <mode>`：聊天会话使用的自定义智能体。可用选项：`ask`、`edit`、`agent` 或自定义智能体标识符。默认 `agent`。
* `-a`、`--add-file <path>`：将文件作为上下文添加到聊天会话。
* `--maximize`：最大化聊天会话视图。
* `-r`、`--reuse-window`：使用最后活动窗口进行聊天会话。
* `-n`、`--new-window`：为聊天会话打开空窗口。

`chat` 子命令还支持在命令末尾传递 `-` 从 `stdin` 管道输入。例如：

```bash
python app.py | code chat why does it fail -
```

## 高级 CLI 选项 {#advanced-cli-options}

以下 CLI 选项有助于复现错误和高级设置。

| 参数 | 说明 |
|------------------|-----------|
| `--extensions-dir <dir>` | 设置扩展根路径。在[便携模式](../../../advanced-setup/9.7-PortableMode/)中被 `data` 文件夹覆盖。 |
| `--user-data-dir <dir>` | 指定用户数据目录。可用于运行具有独立环境、设置和扩展的多个隔离 VS Code 实例，也适合以 root 运行。在[便携模式](../../../advanced-setup/9.7-PortableMode/)中被 `data` 文件夹覆盖。 |
| `-s`、`--status` | 打印进程使用和诊断信息。 |
| `-p`、`--performance` | 启动时启用 **Developer: Startup Performance** 命令。 |
| `--disable-gpu` | 禁用 GPU 硬件加速。 |
| `--verbose` | 打印详细输出（隐含 `--wait`）。 |
| `--prof-startup` | 启动期间运行 CPU 分析器。 |
| `--upload-logs` | 将当前会话日志上传到安全终结点。 |
| `--remote <authority>` | 连接远程开发环境。authority 指定 [WSL](../../../remote/8.6-WSL/)（`wsl+<distro name> <path in WSL>`）或 [SSH](../../../remote/8.2-SSH/)（`ssh-remote+<remote_server> <path on remote>`）的远程连接。 |
| `--add <dir>` | 将文件夹添加到多根工作区的最后活动窗口。 |
| `--remove <dir>` | 从多根工作区的最后活动窗口移除文件夹。 |

## 隔离 VS Code 实例 {#isolating-vs-code-instances}

　　默认情况下，VS Code 实例按以下方式共享环境变量：

* 如果是第一个 VS Code 实例，环境变量从父进程继承。
* 如果不是第一个实例，环境变量从已运行的 VS Code 实例继承。

　　不同项目或构建配置需要不同环境变量时，这可能导致问题。例如处理需要不同 Node.js 版本或不同 `PATH` 设置的两个项目。

　　要运行具有独立环境变量的 VS Code 实例，请使用 `--user-data-dir` 为每个实例指定唯一用户数据目录：

```bash
# 具有自己环境的第一个实例
code ~/project1 --user-data-dir ~/vscode-data-project1

# 具有不同环境的第二个实例
code ~/project2 --user-data-dir ~/vscode-data-project2
```

每个使用不同 `--user-data-dir` 的实例维护自己的：

* 环境变量
* 设置和偏好
* 已安装扩展
* UI 状态和布局

> **注意**：使用 `--user-data-dir` 时，需要为每个用户数据目录重新安装扩展，因为扩展单独存储。

## 创建远程隧道 {#create-remote-tunnel}

　　VS Code 与其他[远程环境](../../../remote/8.1-VSCodeForTheWeb/)集成，变得更强大灵活。目标是通过统一 CLI 管理本地和远程机器。

　　[Remote - Tunnels](https://marketplace.visualstudio.com/items?itemName=ms-vscode.remote-server) 扩展可以通过安全隧道连接桌面 PC 或 VM 等远程机器。隧道安全地从一个网络传输数据到另一个网络，然后可以从任何位置安全连接该机器，无需 SSH。

　　`code` CLI 内置在远程机器上启动隧道的功能。可以运行：

```bash
code tunnel
```

在远程机器上创建隧道。可以通过 Web 或桌面 VS Code 客户端连接该机器。

运行 `code tunnel -help` 查看其他隧道命令：

![隧道帮助 CLI 命令输出](../images/command-line/tunnel-help.png)

　　远程机器可能无法安装 VS Code Desktop，因此 CLI 也可以在 [VS Code 下载页](https://code.visualstudio.com/insiders/)独立安装。

更多信息请参阅[远程隧道](../../../remote/8.4-Tunnels/)。

## 使用 URL 打开 VS Code {#opening-vs-code-with-urls}

　　也可以使用平台 URL 处理机制打开项目和文件。使用以下 URL 格式：

打开项目：

```bash
vscode://file/{full path to project}/

vscode://file/c:/myProject/
```

打开文件：

```bash
vscode://file/{full path to file}

vscode://file/c:/myProject/package.json
```

打开文件到行和列：

```bash
vscode://file/{full path to file}:line:column

vscode://file/c:/myProject/package.json:5:10
```

打开设置编辑器：

```bash
vscode://settings/{setting-id}

vscode://settings/editor.wordWrap
```

克隆 Git 仓库：

```bash
vscode://vscode.git/clone?url={url-encoded repository URL}

vscode://vscode.git/clone?url=https%3A%2F%2Fgithub.com%2Fmicrosoft%2Fvscode.git
```

在扩展视图中打开扩展：

```bash
vscode:extension/{publisher}.{extensionName}

vscode:extension/ms-python.python
```

向扩展发送请求（URI 处理程序）：

　　扩展可以使用 `vscode.window.registerUriHandler` API 注册自定义 URI 处理程序，处理来自外部网站或工具的深层链接，例如 OAuth 身份验证回调。URL authority 匹配扩展 ID（`{publisher}.{extensionName}`）：

```bash
vscode://{publisher}.{extensionName}/{path}?{query}

vscode://vscode-samples.uri-handler-sample/hello?name=world
```

　　详细了解[扩展 API 文档](https://code.visualstudio.com/api/advanced-topics/remote-extensions#callbacks-and-uri-handlers)中的 URI 处理程序注册。

打开远程资源：

```bash
vscode://vscode-remote/{remoteName}+{authority}/{path}
```

例如在远程工作区中打开远程 SSH 主机或容器路径。

### 准备新的智能体会话草稿 {#prepare-a-new-agent-session-draft}

　　使用 `agents/new` URL 打开智能体窗口，提示词和工作区已准备好审查：

```text
vscode://agents/new?prompt=<url-encoded-prompt>&workspace=<url-encoded-folder-uri>
```

两个查询参数都是可选的：

* `prompt` 将解码文本添加到 **新会话** 编辑器。
* `workspace` 选择会话文件夹 URI。省略时草稿使用 **无工作区**。

　　对每个查询参数值进行 URL 编码。例如，以下 URL 准备无工作区草稿聊天：

```text
vscode://agents/new?prompt=Explain%20how%20this%20project%20runs%20its%20tests.%20Do%20not%20run%20anything%20yet.
```

　　打开 URL 不会提交提示词。请审查或编辑草稿，准备好后发送。新会话编辑器已有草稿时，VS Code 会保留它，而不是用 URL 内容替换。

　　可以在浏览器或文件资源管理器等能解析和重定向 URL 的应用中使用 URL。例如，Windows 上可以将 `vscode://` URL 直接传递给 Windows 资源管理器，或在命令行使用 `start vscode://{full path to file}`。

![Windows 资源管理器中的 vscode URL](../images/command-line/vscode-url.png)

> **注意**：使用 VS Code [Insiders](https://code.visualstudio.com/insiders) 版本时，URL 前缀为 `vscode-insiders://`（例如 `vscode-insiders://file/{full path to file}`）。要通过 HTTPS 链接启动桌面应用，请使用 `https://vscode.dev/redirect?url=<url-encoded-vscode-URL>`。

## 常见问题 {#common-questions}

### “code”不是内部或外部命令 {#code-is-not-recognized-as-an-internal-or-external-command}

　　操作系统在路径中找不到 VS Code 二进制文件 `code`。Windows 和 Linux 安装应将 VS Code 添加到路径。请尝试卸载并重新安装 VS Code。如果仍找不到 `code`，请查阅 [Windows](../../../advanced-setup/9.4-Windows/)和 [Linux](../../../advanced-setup/9.2-Linux/)平台特定设置主题。

　　macOS 上需要手动运行 **Shell Command: Install 'code' command in PATH** 命令（通过 **命令面板** `Ctrl + Shift + P`（macOS：`Cmd + Shift + P`） 可用）。详情请参阅 [macOS](../../../advanced-setup/9.3-macOS/)特定设置主题。

### 如何在 VS Code 内访问命令行（终端）？ {#how-do-i-get-access-to-a-command-line-terminal-from-within-vs-code}

　　VS Code 有[集成终端](../../../terminal/5.2-TerminalBasics/)，可以在 VS Code 内运行命令行工具。

### 可以指定 VS Code 设置位置以使用便携版本吗？ {#can-i-specify-the-settings-location-for-vs-code-in-order-to-have-a-portable-version}

　　不能直接通过命令行指定，但 VS Code 有[便携模式](../../../advanced-setup/9.7-PortableMode/)，可以将设置和数据保存在安装位置（例如 USB 驱动器）中。

### 如何检测 shell 是否由 VS Code 启动？ {#how-do-i-detect-when-a-shell-was-launched-by-vs-code}

　　VS Code 启动时可能启动 shell 以加载“shell 环境”，帮助设置工具。这会启动**交互式登录** shell 并获取其环境。根据 shell 设置，这可能导致问题。例如，shell 以交互会话启动可能出乎意料，但 VS Code 需要它来尝试将 `$PATH` 与用户创建的终端中的确切值对齐。

　　VS Code 启动此初始 shell 时，会将变量 `VSCODE_RESOLVING_ENVIRONMENT` 设置为 `1`。如果 shell 或用户脚本需要知道自己是否在此 shell 上下文中运行，可以检查 `VSCODE_RESOLVING_ENVIRONMENT` 值。
