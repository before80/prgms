# 2.8.2.1 故障排除

　　当聊天、智能体或内联建议未按预期工作时，请从观察到的症状开始。本文帮助你选择正确的诊断工具、解释结果，并在需要报告问题时收集有用证据。

## 选择故障排除路径 {#choose-a-troubleshooting-path}

| 症状 | 从这里开始 | 下一步 |
|---------|------------|-----------|
| 聊天或智能体不可用 | 检查[聊天和智能体要求](../2.8.2.4-FAQ/#chat-features-arent-working-for-me)。 | 确认账户、套餐、设置和组织策略。 |
| 内联建议不出现 | 检查[内联建议要求](../2.8.2.4-FAQ/#inline-suggestions-are-not-working-in-the-editor)。 | 满足要求后检查 Copilot 日志。 |
| Copilot 无法连接或登录 | [收集网络诊断](#collect-network-diagnostics)。 | 检查防火墙、代理或 VPN 配置。 |
| GitHub Environment 或其会话缺失、离线或断开 | [排查 GitHub Environments](../../../work-across-apps-and-machines/2.5.2-RemoteAgentSessions/#troubleshoot-github-environments)。 | 检查功能可用性、账户、主机共享、连接状态和会话筛选器。 |
| 云会话无法启动或现有云会话只读 | [排查云会话](../../../work-across-apps-and-machines/2.5.3-CloudSessions/#troubleshoot-cloud-sessions)。 | 检查功能设置、服务和仓库访问以及环境连接状态。 |
| 云自动化不可用、无法运行或在隐藏控件后继续运行 | [排查云自动化](../../../work-with-ai/plan-and-run-tasks/2.2.10.5-Automations/#troubleshoot-cloud-automations)。 | 检查账户和仓库资格、触发器类型、启用状态以及 GitHub 上的自动化配置。 |
| 指令被忽略 | [检查自定义诊断](#check-customization-diagnostics)。 | 检查会话，确认哪些指令到达模型。 |
| 响应中缺少文件、工具或预期步骤 | [检查聊天交互](#inspect-chat-interactions)。 | 将会话事件与发送给模型的请求比较。 |
| 响应缓慢或使用比预期更多的令牌 | 打开智能体调试日志摘要视图。 | 仅在会话报告缓存复用率低时使用缓存浏览器。 |
| MCP 服务器或工具不可用 | [排查 MCP 服务器](#troubleshoot-mcp-servers)。 | 检查服务器输出和请求可用工具。 |
| 沙盒报告缺少依赖项，或沙盒工具因证书错误失败 | [排查智能体沙盒](../../../work-with-ai/permissions-and-security/2.2.12.2-AgentSandboxing/)。 | 检查智能体主机上的依赖项、代理访问和证书信任。 |

## 从基本检查开始 {#start-with-basic-checks}

收集详细日志之前：

1. 从命令面板运行 **Code: Check for Updates** 更新 VS Code。
2. 确认访问方式。使用具有 Copilot 套餐的 GitHub 账户登录，或为受支持聊天功能选择配置的 BYOK 模型。某些功能需要 GitHub Copilot 服务。详情请参阅 [GitHub Copilot 订阅问题](../2.8.2.4-FAQ/)。
3. 在状态栏打开 Copilot 状态仪表板，检查是否达到额度。临时速率限制与每月额度不同。
4. 检查工作区设置或组织策略是否关闭了受影响功能。智能体可用性请参阅[智能体在聊天中不可用](../2.8.2.4-FAQ/#agents-are-not-available-in-chat)。
5. 在新聊天会话中复现问题。比较两次运行时，保持提示词、模型和可用工具一致。

## 检查自定义诊断 {#check-customization-diagnostics}

调查模型是否遵循指令之前，先检查发现：

1. 选择受影响会话使用的运行框架和仓库。
2. 从命令面板（`Ctrl + Shift + P`，macOS：`Cmd + Shift + P`）运行 **Chat: Open Customizations**，选择 **指令**。
3. 找到指令文件，检查其来源、位置和任何报告的错误。

根据结果选择下一步：

* **文件缺失**：验证运行框架、文件名和受支持位置。确认会话使用包含更改的文件夹，尤其是在创建新工作树后。
* **文件有错误**：修复报告的 frontmatter 或内容错误，然后再次检查发现。
* **文件被发现但未包含**：检查激活规则。对于基于模式的指令，测试匹配 `applyTo` 或 Claude `paths` 的文件。对于 Local 基于任务的发现，检查 `description`。也可以手动附加指令。检查 **引用**（如果可用），或在调试日志中检查请求。
* **文件已包含但未遵循**：解决矛盾指导或澄清模糊规则。在新聊天中重复代表性任务，并审查更改和工具活动。仅包含不能证明遵守。
* **请求中缺少提示词文件**：提示词文件仅在 Local 运行框架会话中支持。请在聊天中手动调用，因为提示词文件不使用 `applyTo`。对于兼容技能的智能体的可复用工作流，请创建[智能体技能](../../../customize-and-extend/2.4.3-AgentSkills/)。

　　文件位置、激活规则和设置请参阅[自定义指令参考](../reference/2.8.1.6-CustomInstructionsReference/)。完整测试过程请参阅[验证指令](../../../customize-and-extend/2.4.4-Instructions/#verify-your-instructions)。要检查请求内容和加载活动，请[准备日志](#inspect-chat-interactions)并复现问题。

## 检查聊天交互 {#inspect-chat-interactions}

基本检查通过但智能体行为异常时，使用以下工具：

| 工具 | 用途 |
|------|-----------|
| `/troubleshoot` | 要求 AI 分析捕获的会话事件并回答特定问题。 |
| **智能体调试日志** 面板（预览） | 跟踪模型请求、工具调用、自定义项发现、错误和智能体活动的顺序。 |
| **Chat Debug 视图** | 检查请求的精确系统提示词、用户提示词、上下文、工具定义和工具负载。 |
| **缓存浏览器** | 会话指标显示缓存复用率低时，比较连续模型请求。 |

在复现问题前准备会话：

* 在要检查的活动之前启用实验性 `chat.agentHost.agentDebugLog.enabled` 设置。它会捕获 [Agent Host](../../../concepts/)管理会话的事件，无论使用聊天视图还是智能体窗口。捕获不是追溯性的。
* 复现问题，然后在打开日志或使用 `/troubleshoot` 时选择该会话。

> **注意**：**对于 Local 运行框架会话：** 改为启用实验性 `github.copilot.chat.agentDebugLog.fileLogging.enabled` 设置。使用 `/troubleshoot` 前重新加载编辑器窗口。

使用聊天分析会话：

1. 打开智能体窗口。
2. 在聊天输入框中输入 `/troubleshoot #session`。
3. 选择包含问题的会话。
4. 添加聚焦问题，例如 `which tool failed and what error did it return?`，然后发送请求。

　　详细过程和基于场景的指导请参阅[调试聊天交互](../2.8.2.2-DebugChatInteractions/)。

## 查看 GitHub Copilot 日志 {#view-logs-for-github-copilot}

　　GitHub Copilot 输出通道记录连接失败、扩展错误和其他运行时信息。仅在复现问题时提高日志级别，因为跟踪日志会产生详细输出。

1. 打开命令面板（`Ctrl + Shift + P`，macOS：`Cmd + Shift + P`）。
2. 运行 **Developer: Set Log Level**，将 GitHub Copilot 和 Copilot Chat 扩展设置为 **Trace**。
3. 复现问题。
4. 运行 **Output: Show Output Channels**，选择 **GitHub Copilot** 或 **Copilot Chat**。
5. 审查失败操作前后的错误和警告。
6. 再次运行 **Developer: Set Log Level**，恢复之前的日志级别。

　　要切换输出通道，请使用输出面板右侧的下拉列表。

## 收集网络诊断 {#collect-network-diagnostics}

　　如果 Copilot 无法连接，请收集诊断以确定失败的连接检查及相关代理或网络配置。

1. 打开命令面板（`Ctrl + Shift + P`，macOS：`Cmd + Shift + P`）。
2. 运行 **GitHub Copilot: Chat Diagnostics**。
3. 审查在编辑器中打开的诊断报告。

　　如果检查失败，请将结果与防火墙、代理和 VPN 配置比较。没有失败检查的报告只排除了报告覆盖的连接，因此如果问题仍然存在，请继续检查 Copilot 输出通道。

　　所需域和网络特定指导请参阅[Copilot 的网络和防火墙配置](../2.8.2.4-FAQ/)。

## 排查 MCP 服务器 {#troubleshoot-mcp-servers}

如果 MCP 服务器或其某个工具不可用：

1. 打开命令面板，运行 **MCP: List Servers**。
2. 选择服务器并审查状态。
3. 选择 **显示输出**，检查失败请求的错误。
4. 修正报告的配置或连接问题。
5. 选择 **重启服务器**，然后重试请求。

　　如果服务器运行但模型不调用其工具，请遵循[未调用 MCP 工具](../2.8.2.2-DebugChatInteractions/#an-mcp-tool-is-not-being-invoked)。

　　服务器特定检查请参阅[管理和排查 MCP 服务器](../../../customize-and-extend/2.4.8-ManageMCPServers/#troubleshoot-mcp-servers)。

## 报告未解决的问题 {#report-an-unresolved-issue}

如果问题仍然存在，请提供足够证据以复现和诊断：

> **警告**：智能体调试日志导出、Chat Debug 输出和 Copilot 日志可能包含提示词、源代码、文件路径、工具输入输出和其他敏感数据。共享报告前请审查并移除敏感内容。绝不要包含凭据或机密。

* **幽灵文本建议**：将鼠标悬停在建议上，选择 **发送 Copilot 完成反馈**。
* **下一次编辑建议**：在编辑器边距的下一次编辑建议菜单中选择 **反馈**。
* **聊天和智能体问题**：打开 **帮助** > **报告问题**，选择 **VS Code 扩展**，然后选择 **GitHub Copilot Chat**。

　　包含 VS Code 版本、清晰的复现步骤、预期和实际结果以及相关诊断输出。
