# 2.8.1.6 自定义指令参考

　　使用本参考查找智能体运行框架的指令文件格式、位置、激活规则和设置。首次设置、示例和验证步骤请参阅[使用自定义指令](../../../customize-and-extend/2.4.4-Instructions/)。

## 支持的格式和位置 {#supported-formats-and-locations}

　　所选[智能体运行框架](../../../choose-models-and-agents/2.3.2-ChooseAnAgentHarness/)而非语言模型决定指令支持。下表列出常见项目格式。除非另有说明，路径相对于仓库根目录。

| 运行框架 | 项目指令 | 有针对性的指令 |
|---------|----------------------|-----------------------|
| Copilot | `.github/copilot-instructions.md` 或 `AGENTS.md` | `.github/instructions/**/*.instructions.md` 或嵌套 `AGENTS.md` 文件 |
| Anthropic Claude | `CLAUDE.md` 或 `.claude/CLAUDE.md` | `.claude/rules` 中的 Markdown 文件 |
| OpenAI Codex | `AGENTS.md` | 会话工作目录路径上的 `AGENTS.md` 文件 |
| Local | `.github/copilot-instructions.md`、`AGENTS.md` 或 `CLAUDE.md` | `.github/instructions/**/*.instructions.md` 或 `.claude/rules` 中的 Markdown 文件 |

　　`AGENTS.md` 是跨智能体指令格式。它不是自定义智能体定义，且发现规则因运行框架而异。如果团队使用多个运行框架，请尽可能选择共享支持格式，并保持任何单独副本一致。

　　某些运行框架支持额外原生格式。运行时特定规则请参阅 [Copilot 指令位置](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-custom-instructions)、[Claude 指令位置](https://code.claude.com/docs/en/memory)和 [Codex 指令发现](https://developers.openai.com/codex/guides/agents-md)。

### 用户指令 {#user-instructions}

　　用户指令包含跨项目的个人指导。`~` 指智能体运行机器上的用户主目录。

| 运行框架 | 个人项目无关指导 |
|---------|---------------------------------------|
| Copilot | `~/.copilot/copilot-instructions.md` 用于一般指导；`~/.copilot/instructions/**/*.instructions.md` 用于模块化指令 |
| Anthropic Claude | `~/.claude/CLAUDE.md` 用于一般指导；`~/.claude/rules` 用于模块化规则 |
| OpenAI Codex | Codex 主目录中的 `AGENTS.md`，默认为 `~/.codex` |
| Local | VS Code 用户配置文件中的指令，通过智能体自定义编辑器创建 |

　　运行框架用户文件夹独立于 VS Code 配置文件存储，不通过设置同步漫游。迁移现有配置文件指令请参阅[用户自定义迁移](../../../customize-and-extend/2.4.11-MigrateExistingCustomizations/)。

　　要跨设备同步 Local 配置文件指令，请开启[设置同步](../../../../editor/3.3-ConfigureTheEditor/3.3.5-SettingsSync/)，从命令面板（`Ctrl + Shift + P`，macOS：`Cmd + Shift + P`）运行 **Settings Sync: Configure**，选择 **提示词和指令**。

### 额外搜索位置 {#additional-search-locations}

　　编辑器递归搜索指令目录，因此 `.github/instructions` 可以包含语言、团队或模块子文件夹。

　　`chat.instructionsFilesLocations` 设置添加搜索位置。它仍受支持，编辑器会将其他配置位置的指令转发到 Agent Host 运行框架。为了可移植性，请优先使用原生运行框架文件夹：Copilot CLI 和 GitHub Copilot 应用不会继承编辑器设置。请参阅[迁移配置位置](../../../customize-and-extend/2.4.11-MigrateExistingCustomizations/)。

　　对于打开仓库子文件夹的 Local 会话，`chat.useCustomizationsInParentRepositories` 启用从父仓库发现。此设置不控制其他运行框架。请参阅[monorepo 发现](../../../customize-and-extend/2.4.1-Overview/)。

## 文件语法 {#file-syntax}

　　项目文件（例如 `.github/copilot-instructions.md`、`AGENTS.md` 和 `CLAUDE.md`）包含 Markdown 指令，不需要 YAML frontmatter。

### 指令文件字段 {#instructions-file-fields}

　　`*.instructions.md` 文件包含 `---` 分隔符之间的可选 YAML 头，后跟 Markdown 指令：

```markdown
---
name: 'Python tests'
description: 'Use when creating or updating Python tests.'
applyTo: 'tests/**/*.py'
---
Reuse fixtures from `tests/conftest.py`.
Run `python -m pytest <test-file>` after changing a test.
```

这些字段描述编辑器识别的指令格式。激活取决于[运行框架](#discovery-and-activation)。

| 字段 | 类型 | 必需 | 含义 |
|-------|------|----------|---------|
| `name` | String | 否 | UI 中的显示名称。默认为文件名。 |
| `description` | String | 否 | 描述相关任务。Local 会话中，智能体可以用它决定是否按需加载文件。 |
| `applyTo` | String | 否 | 一个或多个逗号分隔的 glob 模式，用于匹配文件。`**` 表示所有文件。没有默认模式。 |

　　对于 Local 会话，同时省略 `description` 和 `applyTo` 会使文件可用于手动附加，而不是自动激活。描述不是 `applyTo` 生效前必须匹配的额外条件。

　　与其他 Copilot 功能共享的文件还可以使用 `excludeAgent` 等功能特定字段。请检查 [GitHub 指令支持参考](https://docs.github.com/en/copilot/reference/custom-instructions-support)和[仓库指令配置](https://docs.github.com/en/copilot/how-tos/copilot-in-your-ide/customize-copilot/configure-custom-instructions/add-repository-instructions-in-your-ide)，不要假设这些字段会切换 VS Code 运行框架。

### Claude 规则字段 {#claude-rules-fields}

　　`.claude/rules` 中的 Markdown 规则使用 `paths` 而不是 `applyTo`：

```markdown
---
paths:
  - 'tests/**/*.py'
---
Reuse fixtures from `tests/conftest.py`.
```

　　`paths` 是 glob 模式数组。省略它会使规则普遍适用，而不是限制到特定路径。Local 也读取此格式。原生运行框架行为请参阅 [Claude 规则](https://code.claude.com/docs/en/memory)。

## 发现和激活 {#discovery-and-activation}

　　发现意味着运行框架或编辑器找到指令文件。包含意味着其内容成为请求的一部分。两者都不能保证模型遵循每条规则。

### 文件模式 {#file-patterns}

　　对于仓库指令文件，模式相对于工作区或项目根目录，而不是包含指令文件的目录。跨操作系统使用 `/` 路径分隔符。

| 模式 | 匹配 | 不匹配 |
|---------|---------|----------------|
| `*.py` | 根目录的 `app.py` | `src/app.py` |
| `src/*.py` | `src/app.py` | `src/api/routes.py` |
| `src/**/*.py` | `src/app.py`、`src/api/routes.py` | `tests/test_app.py` |
| `tests/**/*.py` | `tests/test_app.py`、`tests/unit/test_app.py` | `src/app.py` |
| `**/*.ts, **/*.tsx` | 任意深度的 TypeScript 和 TSX 文件 | JavaScript 文件 |
| `**` | 所有文件 | 模式未排除任何文件 |

　　在 Copilot 会话中，`applyTo` 目标为智能体处理的文件。Local 中，`chat.includeApplyingInstructions` 开启时，匹配文件上下文可以自动附加指令。Local 还可以根据描述提供按需加载指令。需要文件作用域指导时，不要用描述替代模式。

### 嵌套项目指令 {#nested-project-instructions}

| 运行框架 | 嵌套文件行为 |
|---------|----------------------|
| Copilot | 发现仓库根目录、工作目录、中间目录以及处理的文件路径上的 `AGENTS.md`。适用指令会合并。 |
| OpenAI Codex | 从项目根目录到会话工作目录构建指令链。要使用子文件夹中的指令，请以该子文件夹作为会话工作目录启动会话。 |
| Local | `chat.useAgentsMdFile` 开启时包含工作区根 `AGENTS.md`。嵌套文件需要该设置和 `chat.useNestedAgentsMdFiles`。 |

　　Local 嵌套文件发现是实验性的，默认关闭。启用后，它列出嵌套文件及其文件夹位置，以便智能体按需加载相关指令。这些 Local 设置不会改变 Copilot 或 Codex 发现。

　　Claude 基于目录的加载请参阅 [Claude 指令发现](https://code.claude.com/docs/en/memory#how-claude-md-files-load)。

### 引用其他文件 {#reference-other-files}

　　Markdown 链接让指令指向支持文件和 URL。相对文件链接从指令文件解析。链接到文档并不保证其内容包含在每个请求中。

　　Local 中，`chat.includeReferencedInstructions` 控制自动包含引用指令，默认关闭。其他运行框架使用原生包含机制。请参阅 [Copilot 文件引用](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-custom-instructions#referencing-other-files)和 [Claude 指令](https://code.claude.com/docs/en/memory)。

　　将重要规则保留在指令本身。任务依赖支持文档时，请附加该文档或明确要求智能体读取，并验证结果请求或工具活动。

### 手动附加 {#manual-attachment}

　　支持指令附件的会话在聊天输入框中提供 **添加上下文** > **指令**。如果该选项不可用，请将 Markdown 文件作为普通文件上下文附加，并要求智能体在当前任务中遵循。请参阅[将指令附加到单个请求](../../../customize-and-extend/2.4.4-Instructions/)。

## 组合指令来源 {#combine-instruction-sources}

　　没有适用于所有运行框架的优先级规则。

* Copilot 组合适用的用户和仓库指令，没有指令文件之间的一般优先级顺序。
* Local 可以包含多个适用指令文件。请避免矛盾规则，而不要依赖其顺序。
* Codex 从根目录向工作目录组合项目指令，链中后面的指导更具体。其原生配置还支持覆盖文件。
* Claude 对用户、项目和目录指导使用自己的加载规则。

　　详细信息请使用[支持格式](#supported-formats-and-locations)中链接的原生文档。解决冲突规则时，请更改其来源并[重复代表性任务](../../../customize-and-extend/2.4.4-Instructions/)。

## 组织指令 {#organization-instructions}

　　组织指令在 GitHub 上管理，而不是在仓库文件中。其可用性取决于客户端和功能，不要假设登录后每个运行框架都能使用。

　　Local 有由 `github.copilot.chat.organizationInstructions.enabled` 控制的组织指令提供程序，默认开启。请在智能体自定义编辑器中验证账户和会话的发现。

　　组织配置和受支持 GitHub 体验请参阅[组织自定义指令](https://docs.github.com/en/copilot/concepts/prompting-and-context/custom-instructions#about-organization-custom-instructions)。请保持适用的组织和项目指导一致。

## 设置 {#settings}

### Local 运行框架设置 {#local-harness-settings}

这些设置控制 Local 发现和激活，不控制其他运行框架的原生发现规则：

| 目的 | 设置 |
|---------|---------|
| 包含 `.github/copilot-instructions.md` | `github.copilot.chat.codeGeneration.useInstructionFiles` |
| 包含匹配的 `.instructions.md` 文件 | `chat.includeApplyingInstructions` |
| 包含链接指令 | `chat.includeReferencedInstructions` |
| 包含工作区根 `AGENTS.md` | `chat.useAgentsMdFile` |
| 发现嵌套 `AGENTS.md` | `chat.useNestedAgentsMdFiles` |
| 包含 Claude 指令文件 | `chat.useClaudeMdFile` |
| 发现父仓库自定义项 | `chat.useCustomizationsInParentRepositories` |

　　对于 Claude 指令文件，Local 检查工作区根 `CLAUDE.md`、`.claude/CLAUDE.md`、`~/.claude/CLAUDE.md` 和 `CLAUDE.local.md`。如果个人项目文件（例如 `CLAUDE.local.md`）不应共享，请将其添加到 `.gitignore`。

　　默认值和额外配置请参阅[自定义指令设置](../2.8.1.3-SettingsReference/)。额外位置设置单独在[搜索位置](#additional-search-locations)中描述。

### 生成内容设置 {#generated-content-settings}

　　代码审查、提交消息生成和拉取请求描述生成有单独设置。每个接受对象数组，对象包含内联规则的 `text` 属性或 Markdown 文件路径的 `file` 属性。

| 场景 | 设置 |
|----------|---------|
| 审查所选代码 | `github.copilot.chat.reviewSelection.instructions` |
| 生成提交消息（实验性） | `github.copilot.chat.commitMessageGeneration.instructions` |
| 生成拉取请求描述（实验性） | `github.copilot.chat.pullRequestDescriptionGeneration.instructions` |

　　基于设置的代码生成和测试生成指令已弃用。这些场景请改用指令文件。
