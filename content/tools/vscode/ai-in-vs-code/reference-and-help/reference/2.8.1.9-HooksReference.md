# 2.8.1.9 钩子参考

　　使用本参考解释现有 **Local** 钩子，以便[迁移到 Copilot 运行框架](../../../customize-and-extend/2.4.11-MigrateExistingCustomizations/#migrate-hooks)。对于新钩子，请从[配置智能体钩子](../../../customize-and-extend/2.4.9-Hooks/)开始，它使用共享 Copilot 运行时。Local 运行框架在扩展宿主中运行，即使接受兼容配置格式，也会发送此处记录的负载。

　　对于由提供商运行框架执行的钩子，请使用相应提供商文档：

* **Copilot** 会话请使用 [GitHub Copilot 钩子参考](https://docs.github.com/en/copilot/reference/hooks-reference)。
* **Claude** 会话请使用 [Claude 钩子参考](https://code.claude.com/docs/en/hooks)。
* **Codex** 会话请使用 [Codex 钩子文档](https://developers.openai.com/codex/hooks/)。

> **注意**：当 [GitHub Copilot 企业托管设置生效](../../../../enterprise/7.2-ManageAISettings/#claude-and-codex-availability)时，Claude 和 Codex 运行框架会被禁用。请联系部署设置的 IT 团队讨论访问权限。

　　如果从 **会话目标** UI 控件选择 **Local**，即使钩子文件使用 Copilot 或 Claude 兼容格式，也请使用本参考。Local 运行框架会映射配置，然后发送此处记录的负载。

　　选择运行框架、创建钩子或迁移现有钩子的帮助，请参阅[配置智能体钩子](../../../customize-and-extend/2.4.9-Hooks/)。

## 配置格式 {#configuration-format}

　　钩子文件包含 `hooks` 对象。每个属性是受支持事件名，值是一组命令条目数组：

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "type": "command",
        "command": "./scripts/validate-tool.sh",
        "windows": "powershell -File scripts\\validate-tool.ps1",
        "timeout": 15
      }
    ]
  }
}
```

### 命令属性 {#command-properties}

　　使用显式 `type: "command"` 和此格式中至少一个命令属性。Local 解析器也接受没有 `type` 的条目作为命令钩子：

| 属性 | 类型 | 说明 |
|----------|------|-------------|
| `type` | string | 必须为 `"command"`。 |
| `command` | string | 默认跨平台命令。 |
| `windows` | string | Windows 特定命令覆盖。 |
| `linux` | string | Linux 特定命令覆盖。 |
| `osx` | string | macOS 特定命令覆盖。 |
| `cwd` | string | 工作目录，相对于工作区根目录或绝对路径。Local 将 `~` 展开为用户主目录。 |
| `env` | object | 额外环境变量。 |
| `timeout` | number | 超时秒数。默认 30 秒。 |

　　运行框架从扩展宿主平台选择操作系统覆盖。该平台未定义覆盖时使用 `command`。Local 接受 `bash` 作为 `linux` 和 `osx` 的后备，接受 `powershell` 作为 `windows` 的后备。`timeout` 缺失时接受 `timeoutSec`。迁移时不要同时指定两个超时别名；Copilot 运行时给它们相反的优先级。

　　Local 在钩子文件中接受 PascalCase 和 Copilot 事件别名；数字 `version` 不会选择不同的 Local 负载 schema。它也接受嵌套 Claude 命令组，但忽略匹配器值。复用文件前请参阅[迁移兼容性矩阵](../../../customize-and-extend/2.4.11-MigrateExistingCustomizations/)。

## 通用输入 {#common-input}

　　每个钩子通过标准输入（stdin）接收 JSON 对象。除事件字段外，对象包含以下通用字段：

| 字段 | 类型 | 说明 |
|-------|------|-------------|
| `timestamp` | string | 钩子触发的 ISO 8601 时间戳。 |
| `cwd` | string | 可选的智能体执行工作目录。 |
| `session_id` | string | 可选的当前智能体会话标识符。 |
| `hook_event_name` | string | 钩子事件名，例如 `PreToolUse`。 |
| `transcript_path` | string | 可选，包含对话记录的文件绝对路径。 |

> **注意**：记录文件格式不是稳定的钩子 API，可能在 VS Code 版本之间变化。请尽可能使用文档化事件字段，例如 `tool_name`、`tool_input` 或 `prompt`。

## 通用输出 {#common-output}

　　钩子可以将 JSON 对象写入标准输出（stdout）。所有事件支持以下顶级字段：

```json
{
  "continue": false,
  "stopReason": "Security policy violation",
  "systemMessage": "Review the hook result."
}
```

| 字段 | 类型 | 说明 |
|-------|------|-------------|
| `continue` | boolean | 是否继续处理。默认 `true`。设置为 `false` 停止智能体执行。 |
| `stopReason` | string | `continue` 为 `false` 时向用户显示的原因。 |
| `systemMessage` | string | 向用户显示的警告消息。 |

　　事件还可以支持 `decision` 或 `hookSpecificOutput` 等字段，事件部分会说明。

### 退出代码 {#exit-codes}

　　钩子命令的退出代码控制运行框架如何处理结果：

| 退出代码 | 行为 |
|-----------|----------|
| `0` | 将命令视为成功并处理 stdout。 |
| `2` | 将 stderr 视为阻塞错误并提供给模型。 |
| 其他任何值 | 向用户显示非阻塞警告并继续处理。 |

### 选择控制机制 {#choose-a-control-mechanism}

使用满足要求且干扰最小的输出：

* 使用退出代码 `2` 阻止当前操作并向模型提供 stderr。
* 使用 `continue: false` 和 `stopReason` 停止整个智能体执行。
* 使用 `hookSpecificOutput` 进行事件特定控制，例如拒绝一个工具调用或添加上下文。
* 使用 `systemMessage` 显示警告而不更改事件决定。

　　输出冲突时，最严格结果优先。例如，即使 `PreToolUse` 输出允许工具调用，`continue: false` 仍会停止智能体执行。

## `PreToolUse` {#pretooluse}

　　`PreToolUse` 钩子在智能体调用工具前触发。

### 输入 {#input}

除[通用输入](#common-input)外，钩子接收：

```json
{
  "tool_name": "<local-tool-name>",
  "tool_input": {},
  "tool_use_id": "tool-123"
}
```

| 字段 | 类型 | 说明 |
|-------|------|-------------|
| `tool_name` | string | 工具名称。 |
| `tool_input` | object | 工具调用参数。 |
| `tool_use_id` | string | 工具调用标识符。 |

　　不同运行框架的工具名称和输入 schema 不同。过滤或修改工具调用前，请打开[智能体调试日志](../../troubleshooting/2.8.2.2-DebugChatInteractions/)检查 Local 运行框架会话的工具 schema。

### 输出 {#output}

使用 `hookSpecificOutput` 控制工具调用：

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "Destructive command blocked by policy.",
    "additionalContext": "Production files are read-only."
  }
}
```

| 字段 | 值或类型 | 说明 |
|-------|----------------|-------------|
| `hookEventName` | `"PreToolUse"` | 标识事件特定输出。 |
| `permissionDecision` | `"allow"`、`"deny"` 或 `"ask"` | 允许、拒绝或要求用户确认工具调用。 |
| `permissionDecisionReason` | string | 向用户显示的原因。 |
| `updatedInput` | object | 可选的替换工具输入。值必须匹配 Local 运行框架会话的工具 schema。 |
| `additionalContext` | string | 模型的额外上下文。 |

　　多个钩子对同一工具调用返回权限决定时，最严格决定优先：

1. `deny` 阻止工具调用。
1. `ask` 要求用户确认。
1. `allow` 批准工具调用。

　　如果 `updatedInput` 不匹配 Local 运行框架会话的工具 schema，运行框架会忽略它。

## `PostToolUse` {#posttooluse}

　　`PostToolUse` 钩子在工具成功完成后触发。

### 输入 {#input-1}

除[通用输入](#common-input)外，钩子接收：

```json
{
  "tool_name": "<local-tool-name>",
  "tool_input": {},
  "tool_use_id": "tool-123",
  "tool_response": "<tool-result>"
}
```

| 字段 | 类型 | 说明 |
|-------|------|-------------|
| `tool_name` | string | Local 工具名称。 |
| `tool_input` | object | 工具调用参数。 |
| `tool_use_id` | string | 工具调用标识符。 |
| `tool_response` | string 或 object | 工具返回结果。 |

### 输出 {#output-1}

钩子可以添加上下文或阻止进一步处理：

```json
{
  "decision": "block",
  "reason": "Post-processing validation failed.",
  "hookSpecificOutput": {
    "hookEventName": "PostToolUse",
    "additionalContext": "The edited file has lint errors."
  }
}
```

| 字段 | 值或类型 | 说明 |
|-------|----------------|-------------|
| `decision` | `"block"` | 阻止进一步处理的可选决定。 |
| `reason` | string | 阻止处理时提供给模型的原因。 |
| `hookSpecificOutput.hookEventName` | `"PostToolUse"` | 标识事件特定输出。 |
| `hookSpecificOutput.additionalContext` | string | 模型的额外上下文。 |

## `SessionStart` {#sessionstart}

　　`SessionStart` 钩子在第一条提示词启动会话时触发。

### 输入 {#input-3}

除[通用输入](#common-input)外，钩子接收：

```json
{
  "source": "new"
}
```

| 字段 | 类型 | 说明 |
|-------|------|-------------|
| `source` | string | 会话如何启动。目前始终为 `"new"`。 |

### 输出 {#output-2}

钩子可以向对话添加上下文：

```json
{
  "hookSpecificOutput": {

  }
}
```

| 字段 | 值或类型 | 说明 |
|-------|----------------|-------------|
| `hookEventName` | `"SessionStart"` | 标识事件特定输出。 |
| `additionalContext` | string | 添加到对话的上下文。 |

## `Stop` {#stop}

　　`Stop` 钩子在当前智能体执行即将停止时触发。该事件不表示会话已结束或变为非活动。

　　自定义智能体作为子智能体运行时，其 `Stop` 钩子会被视为 `SubagentStop`。

### 输入 {#input-4}

除[通用输入](#common-input)外，钩子接收：

```json
{
  "stop_hook_active": false
}
```

| 字段 | 类型 | 说明 |
|-------|------|-------------|
| `stop_hook_active` | boolean | 智能体因先前 `Stop` 钩子阻止而继续时为 `true`。 |

### 输出 {#output-3}

钩子可以要求智能体继续：

```json
{
  "hookSpecificOutput": {
    "hookEventName": "Stop",
    "decision": "block",
    "reason": "Run the test suite before finishing."
  }
}
```

| 字段 | 值或类型 | 说明 |
|-------|----------------|-------------|
| `hookEventName` | `"Stop"` | 标识事件特定输出。 |
| `decision` | `"block"` | 阻止智能体执行停止。 |
| `reason` | string | `decision` 为 `"block"` 时必需。解释智能体应继续的原因。 |

> **重要**：`Stop` 钩子阻止智能体时，额外轮次会消耗 [AI 点数](https://docs.github.com/en/copilot/concepts/billing/usage-based-billing-for-individuals)。请检查 `stop_hook_active`，防止智能体无限继续。

## `SubagentStart` {#subagentstart}

　　`SubagentStart` 钩子在智能体启动子智能体时触发。

### 输入 {#input-5}

除[通用输入](#common-input)外，钩子接收：

```json
{
  "agent_id": "subagent-456",
  "agent_type": "Plan"
}
```

| 字段 | 类型 | 说明 |
|-------|------|-------------|
| `agent_id` | string | 子智能体标识符。 |
| `agent_type` | string | 智能体名称，例如 `"Plan"` 或自定义智能体名称。 |

### 输出 {#output-4}

钩子可以向子智能体添加上下文：

```json
{
  "hookSpecificOutput": {
    "hookEventName": "SubagentStart",
    "additionalContext": "Follow the project coding guidelines."
  }
}
```

| 字段 | 值或类型 | 说明 |
|-------|----------------|-------------|
| `hookEventName` | `"SubagentStart"` | 标识事件特定输出。 |
| `additionalContext` | string | 添加到子智能体对话的上下文。 |

## `SubagentStop` {#subagentstop}

　　`SubagentStop` 钩子在子智能体即将停止时触发。

### 输入 {#input-6}

除[通用输入](#common-input)外，钩子接收：

```json
{
  "agent_id": "subagent-456",
  "agent_type": "Plan",
  "stop_hook_active": false
}
```

| 字段 | 类型 | 说明 |
|-------|------|-------------|
| `agent_id` | string | 子智能体标识符。 |
| `agent_type` | string | 智能体名称，例如 `"Plan"` 或自定义智能体名称。 |
| `stop_hook_active` | boolean | 子智能体因先前 `SubagentStop` 钩子阻止而继续时为 `true`。 |

### 输出 {#output-5}

钩子可以要求子智能体继续：

```json
{
  "decision": "block",
  "reason": "Verify the results before completing."
}
```

| 字段 | 值或类型 | 说明 |
|-------|----------------|-------------|
| `decision` | `"block"` | 阻止子智能体停止。 |
| `reason` | string | `decision` 为 `"block"` 时必需。解释子智能体应继续的原因。 |

### 输入 {#input-7}

```json
}
```

| 字段 | 类型 | 说明 |
|-------|------|-------------|
