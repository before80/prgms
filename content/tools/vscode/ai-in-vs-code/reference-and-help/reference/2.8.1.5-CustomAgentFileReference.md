# 2.8.1.5 自定义智能体文件参考

　　本文介绍 VS Code 中自定义智能体文件位置、语法、frontmatter 字段和运行框架特定配置。分步创建和验证工作流请参阅[创建和使用自定义智能体](../../../customize-and-extend/2.4.5-CustomAgents/)。

## 文件结构 {#file-structure}

　　自定义智能体文件包含由 `---` 分隔符包围的可选 YAML 头，后跟带智能体指令的 Markdown 正文：

```markdown
---
name: Reviewer
description: Review changes without editing files
tools: ['read', 'search']
---
Review the supplied changes for correctness and missing tests.
Report actionable findings with file references. Do not edit files.
```

　　以下字段描述 VS Code 格式。`.claude/agents` 中的文件使用 [Claude 智能体格式](#claude-agent-format)。

## 自定义智能体文件位置 {#custom-agent-file-locations}

　　可以为特定工作区或用户级别定义自定义智能体，用户级别可在所有工作区使用。创建智能体前选择目标运行框架，以便智能体自定义编辑器将其存储在受支持位置。

| 作用域 | 默认文件位置 | 文件格式 |
|-------|-----------------------|-------------|
| 工作区 | `.github/agents` 文件夹 | `.agent.md` 或 `.md` 文件 |
| 工作区（Claude 格式） | `.claude/agents` 文件夹 | [Claude 智能体格式](#claude-agent-format)的 `.md` 文件 |
| 用户（Copilot） | `~/.copilot/agents` 文件夹 | `.agent.md` 或 `.md` 文件 |
| 用户（Anthropic Claude） | `~/.claude/agents` 文件夹 | [Claude 智能体格式](#claude-agent-format)的 `.md` 文件 |

　　要创建用户级自定义智能体，请使用智能体自定义编辑器或 **Chat: New Custom Agent** 命令。将文件存储在所选运行框架运行机器上的受支持文件夹。

　　monorepo 中启用 `chat.useCustomizationsInParentRepositories`，从父仓库根目录发现自定义智能体。详细了解[父仓库发现](../../../customize-and-extend/2.4.1-Overview/)。

### Local 运行框架位置和迁移 {#local-harness-locations-and-migration}

　　**Local** 运行框架将用户级自定义智能体存储在 VS Code 配置文件存储中，独立于 `~/.copilot/agents` 和 `~/.claude/agents` 等运行框架用户文件夹。要在其他运行框架中复用基于配置文件的智能体，请[将它们移到该运行框架的用户文件夹](../../../customize-and-extend/2.4.11-MigrateExistingCustomizations/)。

　　优先使用原生运行框架文件夹（例如 `.github/agents` 和 `~/.copilot/agents`），而不是自定义搜索位置。`chat.agentFilesLocations` 设置仍受支持且未弃用。编辑器会将其他配置位置的智能体转发到 Agent Host 运行框架（包括 Copilot），以兼容现有编辑器工作流。旧的 `chat.modeFilesLocations` 设置已弃用。

　　不建议在 Copilot 工作流中使用自定义位置，因为 Copilot CLI 和 GitHub Copilot 应用不会继承编辑器位置设置。要在 Copilot 客户端之间使用智能体，请[将它们移到原生运行框架位置](../../../customize-and-extend/2.4.11-MigrateExistingCustomizations/)。

　　自定义智能体以前称为自定义聊天模式。如果有 `.chatmode.md` 文件，请将其重命名为 `.agent.md` 并放到受支持的自定义智能体位置。

　　如果智能体 frontmatter 包含 `hooks`，请审查[智能体作用域钩子契约](../../../customize-and-extend/2.4.9-Hooks/)。VS Code 在为 Copilot 转换智能体（包括插件提供的智能体）时会保留这些钩子。请将智能体特定自动化限定到该智能体，并在完成迁移前验证其钩子运行。

### 组织级智能体 {#organization-level-agents}

　　要在组织内跨多个工作区共享自定义智能体，可以在 GitHub 组织级别定义它们。

　　VS Code 会自动检测账户有权访问的组织级自定义智能体。这些智能体与内置、个人和工作区智能体一起出现在智能体下拉列表中。

　　组织级自定义智能体发现默认启用。要停止在聊天中显示，请将 `github.copilot.chat.organizationCustomAgents.enabled` 设置为 `false`。

　　请在 GitHub 文档中了解如何[为组织创建自定义智能体](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/coding-agent/create-custom-agents)。

## 运行框架兼容性 {#harness-compatibility}

　　所选[智能体运行框架](../../../choose-models-and-agents/2.3.2-ChooseAnAgentHarness/)决定哪些字段和工具名称生效。共享文件位置不意味着不同运行框架行为相同。

* **Local** 支持下面描述的 VS Code 工具名称、子智能体配置、交接和智能体作用域钩子。
* **Copilot** 通过其运行时支持自定义智能体配置。请使用下面的字段特定指导以及 [Copilot 自定义智能体文档](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/about-custom-agents)。Local 交接不适用。编辑器识别但智能体转换时不转发的字段请参阅 [Copilot 特定配置](#copilot-specific-configuration)。
* **Claude** 使用自己的[智能体格式](#claude-agent-format)和运行时行为。
* **Copilot 云智能体**有单独的[配置参考](https://docs.github.com/en/copilot/reference/custom-agents-configuration)。

　　默认情况下，所选运行框架决定编辑器的补全、悬停和验证。设置 `target: github-copilot` 使用 Copilot schema 解释文件，或 `target: vscode` 使用 Local schema。`target` 字段覆盖文件解释，不覆盖运行会话的运行框架。

　　编辑器会标识有效目标不支持的属性。例如，Local 不接受 `skills` 或 `mcp-servers`，Copilot 不接受 `handoffs`、`agents`、`argument-hint` 或 `advancedOptions`。

### 编辑自定义智能体文件 {#edit-a-custom-agent-file}

　　在 `.agent.md` 文件中使用补全和悬停详情为目标运行框架选择值。显式 `target` 覆盖编辑器解释文件的方式，但不会切换会话运行框架。

　　对于 Copilot 辅助编辑，需要目标特定指导时请显式设置 `target`。没有显式目标时，提供给 Copilot 的文件上下文只描述共享属性，不会建议目标特定模型或工具值。这不同于遵循所选运行框架的常规编辑器补全。

　　将鼠标悬停在值上检查详情或可用性。运行框架清单变化时编辑器会刷新验证。未知值提示依赖发现完成，因此发现待处理时没有提示并不确认值可用。

　　编辑前选择目标运行框架，然后在该运行框架中尝试智能体以验证行为。编辑器反馈不能替代检查运行智能体可使用哪些工具和技能。请参阅[验证自定义智能体](../../../customize-and-extend/2.4.5-CustomAgents/)。

## 头部字段 {#header-fields}

　　除非注明，字段都是可选的。适用处列出默认值和运行框架特定行为。

| 字段 | 类型 | 说明 |
|-------|------|-------------|
| `name` | String | UI 中的智能体名称。默认为文件名。 |
| `description` | String | 智能体做什么以及何时使用。Copilot schema 必需。 |
| `argument-hint` | String | 描述智能体预期输入的提示文本。显示在 Local 聊天输入框中。 |
| `advancedOptions` | Object | Local 专用的高级智能体选项映射。Copilot schema 不支持。 |
| `tools` | String 或字符串数组 | 智能体可用工具。工具名称和支持的别名取决于运行框架。用户定义工具集已弃用，Copilot 运行框架不支持。请参阅[工具](#tools)。 |
| `agents` | 字符串数组 | 可作为子智能体使用的自定义智能体。Local 中使用 `['*']` 或省略字段允许所有可用智能体，使用 `[]` 阻止子智能体。请在 `tools` 中包含 `agent` 工具集。请参阅[子智能体配置](#subagent-configuration)。 |
| `model` | String 或字符串数组 | Copilot 运行框架使用的模型。数组按优先级指定模型，使用第一个可用模型。省略时使用当前选择模型。Local 子智能体也将其作为[模型选择顺序](../../../work-with-ai/plan-and-run-tasks/2.2.10.4-Subagents/)的一部分。 |
| `model-policy` | String | Copilot 编辑器 schema 识别，值为 `preferred` 和 `required`。转换插件提供的智能体时不转发。请参阅[模型偏好](#model-preferences)。 |
| `reasoning-effort` | String | Copilot 运行框架中智能体的推理强度。支持值取决于模型。可用时补全使用配置模型公布的能力。请参阅[思考强度](../../../choose-models-and-agents/2.3.1-ChooseAndConfigureModels/)。 |
| `skills` | 字符串数组 | 在 Copilot 中加载到智能体上下文的技能名称。补全和悬停使用匹配运行框架的技能清单。请参阅[技能](#skills)。 |
| `deferred-tool-loading` | Boolean | Copilot schema 字段，用于按需加载工具。依赖前请参阅[转换限制](#copilot-specific-configuration)。 |
| `strict-tools-list` | Boolean | Copilot schema 字段，用于省略未显式列出的标准必需工具。依赖前请参阅[转换限制](#copilot-specific-configuration)。 |
| `include-custom-instructions` | Boolean | Copilot schema 字段，用于在智能体上下文中包含仓库自定义指令。依赖前请参阅[转换限制](#copilot-specific-configuration)。 |
| `github` | Object | Copilot schema 识别的 GitHub MCP 配置，包含 `toolsets` 和 `permissions` 属性。请参阅 [Copilot 特定配置](#copilot-specific-configuration)。 |
| `user-invocable` | Boolean | 智能体是否出现在 Local 和 Copilot 智能体下拉列表中。默认 `true`。设置为 `false` 可从选择器隐藏仅子智能体使用的助手。 |
| `disable-model-invocation` | Boolean | 是否阻止其他智能体将其作为子智能体调用。默认 `false`。Local 显式列表例外请参阅[子智能体配置](#subagent-configuration)。 |
| `infer` | Boolean | **已弃用。** 使用 `user-invocable` 和 `disable-model-invocation` 分别控制选择器可见性和子智能体调用。 |
| `target` | String | 覆盖编辑器解释文件所用的运行框架：`vscode` 表示 Local，`github-copilot` 表示 Copilot。省略则遵循所选运行框架。不会切换会话运行框架。 |
| `mcp-servers` | Object 或 null | Copilot 文件编辑识别的智能体作用域 MCP 服务器定义。schema 支持和转换限制请参阅 [Copilot 特定配置](#copilot-specific-configuration)。 |
| `handoffs` | 对象数组 | Local 中响应后建议的智能体过渡。请参阅[交接字段](#handoff-fields)。 |
| `hooks` | Object | 作用于此智能体的钩子事件映射。Local 和 Copilot 支持，包括插件提供的智能体。请参阅[智能体作用域钩子](../../../customize-and-extend/2.4.9-Hooks/)。Local 执行需要 `chat.useHooks` 和受信任工作区。 |

### 工具 {#tools}

　　Copilot 中，`tools` 支持内置别名 `execute`、`read`、`edit`、`search`、`agent`、`web` 和 `todo`。使用 `*` 选择所有工具。

　　使用补全选择可用客户端工具及其规范限定引用，例如 `browser/<tool>`、`notebook/<tool>` 和 `vscode/<tool>`。扩展工具保留 `<extensionId>/<tool>` 引用。不要去掉这些前缀或替换为内部运行时注册名称。

　　要包含已配置 MCP 服务器发布的所有工具，请使用 `<server name>/*`。命名空间可用性取决于会话 MCP 清单。在其他运行框架中复用工具列表前，请审查[工具可用性](../../../work-with-ai/plan-and-run-tasks/2.2.10.2-UseTools/)。

　　Local 中，`tools` 可以包含内置工具、MCP 工具和扩展提供的工具。现有用户定义工具集引用已弃用，Copilot 不支持。请参阅[替换工具集](../../../customize-and-extend/2.4.11-MigrateExistingCustomizations/)。`read` 和 `search` 等内置别名与用户定义工具集文件不同。

例如，Local 智能体可以组合内置工具和 MCP 服务器命名空间：

```yaml
tools: ['read', 'search', '<server name>/*']
```

　　将 `<server name>` 替换为已配置 MCP 服务器名称。Local 中省略 `tools` 时，工具选择器中启用的工具可用。不可用工具会被忽略。

　　Local 的 `agent/runSubagent` 引用不是可移植委派工具名称。Copilot 使用原生 `task` 工具委派。`vscode/toolSearch` 等限定客户端工具引用仅在该工具提供给 Copilot 会话时有效；仅前缀不会使其成为 Local 专用。请审查工具列表和需要特定工具的指令。兼容性检查和已知编辑限制请参阅[工具发现迁移常见问题](../../../customize-and-extend/2.4.11-MigrateExistingCustomizations/)。

### 模型偏好 {#model-preferences}

　　使用目标运行框架补全插入的模型标识符。Copilot 补全插入运行时模型 ID，包括 BYOK 模型的精确提供商限定 ID。这些不同于 Local 的限定模型显示名称。

要为 Copilot 指定优先级列表，请将占位符替换为可用模型 ID，并按偏好顺序保留数组：

```yaml
model: ['<preferred model ID>', '<fallback model ID>']
```

　　Copilot 编辑器 schema 还识别 `model-policy: preferred` 和 `model-policy: required`。转换插件提供的智能体时会从编写列表选择模型，但不转发 `model-policy`。不要依赖 `required` 为这些转换智能体强制模型策略。

### 技能 {#skills}

　　Copilot 中，使用 `skills` 指定加载到自定义智能体上下文的技能：

```yaml
skills: ['<skill name>']
```

　　将 `<skill name>` 替换为目标 Copilot 运行框架可用的已启用技能。补全和悬停显示描述、来源和可用性详情。已禁用或暂时不可用的技能也可能出现，因此选择前请审查状态。

　　此清单验证特定于 Copilot 文件。设置 `target: vscode` 会改用 Local 解释。技能创建和受支持位置请参阅[智能体技能](../../../customize-and-extend/2.4.3-AgentSkills/)。

### Copilot 特定配置 {#copilot-specific-configuration}

　　编辑器为以下 Copilot 字段提供嵌套补全、悬停和结构验证：

* `github`：`toolsets` 数组和 `permissions` 映射。GitHub MCP 工具集不是 Local 用户定义工具集文件。
* `mcp-servers`：服务器定义映射，包含本地基于命令或远程基于 URL 的配置。编辑器检查属性类型、工具数组、URL 和正超时。
* `hooks`：带操作数组的事件映射。验证检查事件特定操作组合、匹配器模式、URL 和正超时。运行时要求请使用[智能体作用域钩子参考](../../../customize-and-extend/2.4.9-Hooks/)。

　　结构验证不会启动或验证 MCP 服务器，也不能证明钩子执行。

> **重要**：编辑器 schema 支持不保证运行时支持。将智能体文件转换为 SDK 自定义智能体配置（包括插件提供的智能体）时，VS Code 不转发 `model-policy`、`mcp-servers`、`github`、`deferred-tool-loading`、`strict-tools-list` 或 `include-custom-instructions`。不要依赖这些字段配置转换后智能体的运行时行为。要使 MCP 工具对会话可用，请使用[受支持的 MCP 服务器配置](../../../customize-and-extend/2.4.7-AddMCPServers/)。

### 子智能体配置 {#subagent-configuration}

　　Local 中，通过组合 `agents` 和 `agent` 工具集将协调者限制到命名工作智能体：

```yaml
tools: ['agent']
agents: ['Researcher', 'Implementer']
```

　　智能体名称区分大小写。在 `agents` 中显式列出智能体会允许调用，即使该工作智能体设置了 `disable-model-invocation: true`。要允许子智能体进一步委派，请启用 `chat.subagents.allowInvocationsFromSubagents`。这也适用于列出自己的智能体。请参阅[嵌套子智能体](../../../work-with-ai/plan-and-run-tasks/2.2.10.4-Subagents/)。

　　完整协调者和工作智能体文件请参阅[将实现委派给工作智能体](../../../work-with-ai/plan-and-run-tasks/2.2.10.4-Subagents/)。

### 可见性和调用 {#visibility-and-invocation}

要从选择器隐藏智能体但保留其可用于委派：

```yaml
user-invocable: false
disable-model-invocation: false
```

　　这些字段更改共享智能体定义，不是个人可见性偏好。请参阅[自定义智能体下拉列表](../../../customize-and-extend/2.4.5-CustomAgents/)。

### 交接字段 {#handoff-fields}

　　`handoffs` 数组中的每个对象定义 Local 运行框架中的过渡：

| 字段 | 类型 | 说明 |
|-------|------|-------------|
| `label` | String，必需 | 交接按钮上的文本。 |
| `agent` | String，必需 | 目标智能体标识符。 |
| `prompt` | String，必需 | 用户选择交接时预填的提示词。 |
| `send` | Boolean | 是否自动提交提示词。默认 `false`。 |
| `model` | String | 交接时选择的模型。使用 `<model name> (<vendor>)` 格式的限定名称，例如 `<model name> (copilot)`。 |

```yaml
handoffs:
  - label: Implement Plan
    agent: agent
    prompt: Implement the plan outlined above.
    send: false
    model: <model name> (copilot)
```

　　将模型占位符替换为可用模型，或省略 `model`。规划到实现演练请参阅[交接](../../../customize-and-extend/2.4.5-CustomAgents/)。

## 正文 {#body}

　　Markdown 正文包含智能体遵循的指令，例如任务、指南和预期输出。

　　在聊天视图中选择自定义智能体时，其正文指令会添加在自定义指令之后，冲突时优先。

### Local 文件和工具引用 {#local-file-and-tool-references}

　　Local 中，使用 Markdown 链接或 `#file:` 语法引用文件。相对路径从自定义智能体文件解析。使用 `~` 或 `~/` 引用用户主文件夹，使用 Unix 风格 `/` 分隔符以保持路径跨操作系统可移植。

```markdown
Follow the [review checklist](./review-checklist.md).
Use #file:~/copilot/security-guidelines.md for security reviews.
```

　　Local 中，使用 `#tool:<tool-name>` 引用工具，例如 `#tool:web/fetch`。

### Copilot 正文占位符 {#copilot-body-placeholders}

　　Copilot 文件编辑识别以下区分大小写的占位符：

| 占位符 | 含义 |
|-------------|---------|
| `{{cwd}}` | 当前工作目录。 |
| `{{homedir}}` | 用户主目录。 |
| `{{configDir}}` | Copilot 配置目录。 |
| `{{grepToolName}}` | 有效文件内容搜索工具名称。 |
| `{{globToolName}}` | 有效文件 glob 工具名称。 |
| `{{shellToolName}}` | 有效 shell 工具名称。 |
| `{{shellCommandExamples}}` | shell 适用命令示例。 |

　　编辑器为识别的占位符提供补全、悬停和高亮，并标识未知的类似占位符值。Local `#file:` 和 `#tool:` 引用被标识为 Copilot 不支持。请使用普通 Markdown 链接引用文件，并使用 `tools` frontmatter 字段配置工具。

## 工具列表优先级 {#tool-list-priority}

　　Local 中，提示词文件的 `tools` 列表优先于自定义智能体的 `tools` 列表。其他运行框架不加载提示词文件。完整顺序请参阅[工具列表优先级](../../../customize-and-extend/2.4.10-PromptFiles/)。

## Claude 智能体格式 {#claude-agent-format}

　　`.claude/agents` 中的智能体文件使用普通 `.md` 文件和 [Claude 子智能体格式](https://code.claude.com/docs/en/sub-agents)。

| 字段 | 说明 |
|-------|-------------|
| `name` | 必需的唯一智能体标识符，使用小写字母和连字符。 |
| `description` | 必需的描述，说明何时委派给该智能体。 |
| `tools` | 逗号分隔的允许工具名称，例如 `"Read, Grep, Glob, Bash"`。省略时智能体继承所有工具。 |
| `disallowedTools` | 逗号分隔的要阻止工具名称。 |
| `model` | `sonnet`、`opus`、`haiku` 或 `inherit`（默认）。 |
| `permissionMode` | `default`、`acceptEdits`、`dontAsk`、`bypassPermissions` 或 `plan`。 |
| `skills` | 启动时加载到智能体上下文的技能。 |
| `mcpServers` | 智能体可用的 MCP 服务器。 |
| `hooks` | 在此智能体工作流配置点运行的钩子。 |
| `memory` | 持久记忆作用域：`user`、`project` 或 `local`。 |

　　Claude 运行框架根据其提供商文档实现这些字段。Local 加载 Claude 格式智能体时，会将支持的 Claude 工具和模型名称映射到 VS Code 对应项。此兼容性不会使所有 Claude 运行时功能在 Local 中可用。
