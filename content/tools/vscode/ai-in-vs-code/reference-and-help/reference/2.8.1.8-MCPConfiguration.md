# 2.8.1.8 MCP 配置

　　本文提供 VS Code 中的 MCP 配置格式、支持字段、命令和设置。首次连接服务器请参阅[添加 MCP 服务器](../../../customize-and-extend/2.4.7-AddMCPServers/)。操作任务请参阅[管理和排查 MCP 服务器](../../../customize-and-extend/2.4.8-ManageMCPServers/)。

## 配置文件 {#configuration-file}

　　MCP 服务器配置使用以下文件格式之一：

* **VS Code 格式**存储在工作区或[用户配置文件](../../../../editor/3.3-ConfigureTheEditor/3.3.8-Profiles/)中的 `.vscode/mcp.json`。它在顶级 `servers` 对象中定义服务器。VS Code 为此格式提供 IntelliSense。
* **可移植 Copilot 格式**存储在工作区根目录 `.mcp.json` 中，或用户级 `$COPILOT_HOME/mcp-config.json` 中，后备位置为 `~/.copilot/mcp-config.json`。它在顶级 `mcpServers` 对象中定义服务器。

　　Copilot 运行框架会话直接读取可移植格式。VS Code 将 VS Code 格式中符合条件的服务器转发到会话，但需要交互输入的服务器除外，例如 `${input:...}` 变量。智能体不会直接读取 `.vscode/mcp.json`。设置步骤请参阅[选择配置目标](../../../customize-and-extend/2.4.7-AddMCPServers/)。

　　其他提供商请使用其 MCP 配置文档。其配置位置和 schema 可能与这里描述的两种格式不同。

两种格式和位置支持的能力不同：

| 能力 | 工作区或配置文件 `mcp.json` | 工作区根 `.mcp.json` | Copilot 用户 `mcp-config.json` |
|------------|---------------------------------|----------------------------|--------------------------------|
| 顶级服务器对象 | `servers` | `mcpServers` | `mcpServers` |
| 智能体自定义编辑器 | 只读 JSON | 配置表单 | 配置表单 |
| 服务器传输 | stdio、HTTP 和 SSE | stdio 和 HTTP | stdio、HTTP 和 SSE |
| 环境变量引用 | `${env:NAME}` | `${NAME}` 或 `${NAME:-default}` | `${NAME}` 或 `${NAME:-default}` |
| 工作目录 | 是 | 否 | 是 |
| 环境文件 | 是 | 否 | 否 |
| VS Code 输入变量 | 是 | 否 | 否 |
| 开发模式和每服务器沙盒 | 是 | 否 | 否 |

　　配置表单会保留未显示的属性。选择表单中的 **其他属性** 可在 JSON 中打开完整服务器条目。

### 可移植配置 {#portable-configuration}

在工作区根 `.mcp.json` 或 Copilot 用户 `mcp-config.json` 中使用顶级 `mcpServers` 对象。此示例配置一个本地 Playwright 服务器：

```json
{
    "mcpServers": {
        "playwright": {
            "command": "npx",
            "args": ["-y", "@playwright/mcp@latest"]
        }
    }
}
```

　　启动服务器前安装发布者运行时前提条件。[Playwright 设置要求](https://github.com/microsoft/playwright-mcp#requirements)包括 Node.js 18 或更高版本。

　　对于 HTTP 服务器，将服务器条目替换为发布者终结点：

```json
{
    "mcpServers": {
        "context7": {
            "type": "http",
            "url": "https://mcp.context7.com/mcp"
        }
    }
}
```

　　身份验证和服务限制请遵循 [Context7 设置说明](https://context7.com/docs/resources/all-clients)。仅终结点不会授予服务访问权限。

　　下面的属性表描述 VS Code 格式，不是所有 MCP 客户端的共享 schema。将属性复制到可移植文件前，请检查[能力比较](#configuration-file)。

### 环境变量引用 {#environment-variable-references}

　　可移植配置独立于 VS Code 输入提示支持环境变量。使用 `${NAME}` 引用值，或使用 `${NAME:-default}` 表示非机密默认值。Stdio 服务器可以在 `command`、`args` 和 `env` 值中使用引用。HTTP 服务器可以在标头值中使用。

　　在运行或连接服务器的宿主环境中提供变量。对于远程会话，即远程主机或容器。使用带花括号的 `${NAME}` 形式，以兼容 Copilot 运行时和 VS Code MCP 客户端；它们将裸 `$NAME` 视为字面文本。

　　可以在 [MCP 配置表单](../../../customize-and-extend/2.4.8-ManageMCPServers/)中编辑环境变量和 HTTP 标头。表单将配置值写入文件。请输入引用而不是字面凭据。

　　环境变量支持不包括 `envFile`、输入提示或到 VS Code `SecretStorage` 的桥接。完整示例请参阅[用环境变量替换输入提示](../../../customize-and-extend/2.4.11-MigrateExistingCustomizations/)。

### 配置结构 {#configuration-structure}

以下结构适用于 VS Code 格式。可移植 Copilot 格式使用单独的 schema，带顶级 `mcpServers` 对象。

配置文件有三个主要部分：

* **`"servers": {}`**：将服务器名称映射到配置的对象。每个键是服务器名，值是服务器配置对象。根据服务器类型，需要不同字段。
* **`"inputs": []`**：可选的输入变量定义数组，用于 API 密钥等敏感信息。
* **`"sandbox": {}`**：可选对象，为沙盒服务器定义文件系统和网络访问规则。请参阅[沙盒配置](#sandbox-configuration)。仅适用于 macOS 和 Linux。

　　可以在服务器配置中使用[预定义变量](https://code.visualstudio.com/docs/reference/variables-reference)，例如引用工作区文件夹（`${workspaceFolder}`）。

### 标准 I/O（stdio）服务器 {#standard-io-stdio-servers}

　　用于通过标准输入和输出流通信的服务器。这是本地运行 MCP 服务器最常见的类型。

| 字段 | 必需 | 说明 | 示例 |
|-------|----------|-------------|----------|
| `type` | 是 | 服务器连接类型 | `"stdio"` |
| `command` | 是 | 启动服务器可执行文件的命令。必须在系统路径中可用或包含完整路径。 | `"npx"`、`"node"`、`"python"`、`"docker"` |
| `args` | 否 | 传递给命令的参数数组 | `["server.py", "--port", "3000"]` |
| `cwd` | 否 | 服务器命令工作目录。在工作区中运行时默认为工作区文件夹。 | `"${workspaceFolder}"` |
| `env` | 否 | 服务器环境变量。值可以是字符串、数字或 null。 | `{"API_KEY": "${input:api-key}"}` |
| `envFile` | 否 | 加载更多变量的环境文件路径 | `"${workspaceFolder}/.env"` |
| `dev` | 否 | 开发模式设置，用于监视文件更改和调试服务器。请参阅[开发模式](#development-mode)。 | `{"watch": "src/**/*.ts"}` |
| `sandboxEnabled` | 否 | 在沙盒环境中运行服务器。仅 macOS 和 Linux 支持。 | `true` |
| `sandbox` | 否 | 此服务器的文件系统和网络权限。根级沙盒拒绝规则也适用。 | `{"filesystem": {"allowWrite": ["${workspaceFolder}"]}}` |

> **注意**：使用 Docker 和 stdio 服务器时，不要使用分离选项（`-d`）。服务器必须在前台运行才能与 VS Code 通信。

**示例本地服务器配置**

此示例以 VS Code 格式配置相同的 Playwright 服务器：

```json
{
    "servers": {
        "playwright": {
            "type": "stdio",
            "command": "npx",
            "args": ["-y", "@playwright/mcp@latest"]
        }
    }
}
```

### 沙盒配置 {#sandbox-configuration}

　　可以为本地运行的 stdio MCP 服务器启用沙盒，限制其对文件系统和网络的访问。沙盒规则可以拒绝文件访问、授予写访问权限并授予特定网络域访问权限。沙盒仅在 macOS 和 Linux 上可用。

要启用服务器沙盒，请在其配置中设置 `"sandboxEnabled": true`。添加 `sandbox` 对象定义其文件系统和网络权限。还可以添加与 `servers` 和 `inputs` 同级的顶级 `sandbox` 对象，定义适用于文件中所有沙盒服务器的拒绝规则。

　　允许规则仅在服务器的 `sandbox` 对象中支持。顶级 `allowWrite` 和 `allowedDomains` 规则会被忽略。

> **注意**：启用沙盒时，工具确认会自动批准，因为服务器在受控环境中运行。

服务器级和顶级 `sandbox` 对象支持：

| 属性 | 类型 | 支持范围 | 说明 |
|----------|------|-----------------|-------------|
| `filesystem.allowWrite` | string[] | 仅服务器 | 允许服务器写入的文件路径。 |
| `filesystem.denyRead` | string[] | 服务器和顶级 | 不允许服务器读取的文件路径。 |
| `filesystem.denyWrite` | string[] | 服务器和顶级 | 不允许服务器写入的文件路径。 |
| `network.allowedDomains` | string[] | 仅服务器 | 允许服务器访问的域。支持通配符，例如 `*.example.com`。 |
| `network.deniedDomains` | string[] | 服务器和顶级 | 不允许服务器访问的域。 |

　　可以在文件系统路径值中使用[预定义变量](https://code.visualstudio.com/docs/reference/variables-reference)，例如 `${workspaceFolder}`。

**示例沙盒配置**

此示例授予一个服务器工作区写访问权限和特定域网络访问权限。顶级规则拒绝文件中所有沙盒服务器访问 `.ssh` 目录：

```json
{
    "servers": {
        "myServer": {
            "type": "stdio",
            "command": "npx",
            "args": ["-y", "@example/mcp-server"],
            "sandboxEnabled": true,
            "sandbox": {
                "filesystem": {
                    "allowWrite": ["${workspaceFolder}"]
                },
                "network": {
                    "allowedDomains": ["api.example.com", "*.cdn.example.com"]
                }
            }
        }
    },
    "sandbox": {
        "filesystem": {
            "denyRead": ["${userHome}/.ssh"]
        }
    }
}
```

### HTTP 和 Server-Sent Events（SSE）服务器 {#http-and-server-sent-events-sse-servers}

　　用于通过 HTTP 通信的服务器。VS Code 首先尝试 HTTP Stream 传输，HTTP 不支持时回退到 SSE。

| 字段 | 必需 | 说明 | 示例 |
|-------|----------|-------------|----------|
| `type` | 是 | 服务器连接类型 | `"http"`、`"sse"` |
| `url` | 是 | 服务器 URL | `"http://localhost:3000"`、`"https://api.example.com/mcp"` |
| `headers` | 否 | 用于身份验证或配置的 HTTP 标头 | `{"Authorization": "Bearer ${input:api-token}"}` |
| `oauth` | 否 | 与服务器身份验证的 OAuth 配置 | `{"clientId": "example-client-id"}` |

　　除了网络可用的服务器，VS Code 还可以连接监听 Unix 套接字或 Windows 命名管道的 MCP 服务器，在 `unix:///path/to/server.sock` 或 Windows 上 `pipe:///pipe/named-pipe` 中指定套接字或管道路径。可以使用 URL 片段指定子路径，例如 `unix:///tmp/server.sock#/mcp/subpath`。

`oauth` 对象支持：

| 属性 | 类型 | 必需 | 说明 |
|----------|------|----------|-------------|
| `clientId` | string | 是 | 与服务器身份验证时使用的 OAuth 客户端 ID。 |

> **注意**：配置 `oauth` 后，VS Code 自动处理 OAuth 流程。首次连接服务器时会打开浏览器窗口进行授权。

> **注意**：客户端密钥不属于 `mcp.json`。如果服务器 OAuth 客户端是机密客户端，请选择 `mcp.json` 中 `oauth.clientId` 上方出现的 **设置客户端密钥** CodeLens。VS Code 将密钥保存在机密存储中。以后要更改，请选择 **替换客户端密钥**。

**示例远程服务器配置**

此示例指定远程 MCP 终结点。使用前请遵循发布者身份验证说明：

```json
{
    "servers": {
        "context7": {
            "type": "http",
            "url": "https://mcp.context7.com/mcp"
        }
    }
}
```

**使用 OAuth 的 HTTP 服务器示例**

此示例展示使用 OAuth 身份验证的 MCP 服务器配置。首次使用时 VS Code 会打开浏览器窗口完成 OAuth 流程。

```json
{
    "servers": {
        "slack": {
            "type": "http",
            "url": "https://mcp.slack.com/mcp",
            "oauth": {
                "clientId": "example-client-id"
            }
        }
    }
}
```

### 身份验证和机密 {#authentication-and-secrets}

　　身份验证授予外部服务访问权限。它独立于信任服务器启动和批准单个工具调用。

选择服务器和配置都支持的身份验证方法：

| 服务器要求 | 指导 |
|--------------------|----------|
| 浏览器登录或 OAuth | 遵循发布者连接说明并审查请求的权限。出现提示时完成授权流程。上述 `oauth` 字段适用于 VS Code 格式。 |
| 环境变量 | 可移植配置支持 stdio 服务器配置和 HTTP 标头中的[环境变量引用](#environment-variable-references)。在运行或连接服务器的宿主环境中提供凭据，而不仅是在无关终端中，或对于远程会话仅在本地机器上提供。 |
| VS Code 输入提示 | 使用 VS Code 格式支持的[输入变量](#input-variables-for-sensitive-data)。需要这些交互输入的服务器不会转发到 Copilot 运行框架会话。 |
| 环境文件 | `envFile` 在 VS Code 格式中支持，在可移植 `.mcp.json` 或 Copilot 用户 `mcp-config.json` 中不支持。请将包含凭据的文件排除在源代码管理之外。 |

　　不要提交令牌、密码或填充的身份验证标头。个人配置文件不是机密存储。对于需要固定令牌的服务器，请遵循发布者针对客户端和运行框架的安全配置指导，而不是将凭据复制到共享示例中。

　　Copilot 运行框架没有内置 MCP 配置选项，可将 `${input:...}` 机密转发或将现有 VS Code `SecretStorage` 值读入 HTTP 身份验证标头。服务器支持时 OAuth 可以作为替代方案，但不能替代提示式 API 密钥。如果集成需要静态 bearer token 且不能使用环境变量或文件凭据，请参阅[迁移常见问题](../../../customize-and-extend/2.4.11-MigrateExistingCustomizations/)。

### 敏感数据的输入变量 {#input-variables-for-sensitive-data}

　　VS Code 格式中的输入变量可以为 API 密钥或密码等值定义占位符。可移植配置文件不支持它们，需要它们的服务器不会转发到 Copilot 运行框架会话。

　　转发会在解析前拒绝输入和命令变量。先在 Local 会话中输入或缓存机密不会使服务器对 Copilot 可用。请保留原始配置，直到目标运行框架支持的身份验证方法可用。

使用 `${input:variable-id}` 引用输入变量时，VS Code 会在服务器首次启动时提示输入值。值随后被安全存储以供后续使用。详细了解 VS Code 中的[输入变量](https://code.visualstudio.com/docs/reference/variables-reference#_input-variables)。

　　每个输入变量有 `type`，决定 VS Code 如何提示。支持以下输入类型：

* `promptString`：打开输入框要求用户输入自由文本值。
* `pickString`：显示选项列表供用户选择。
* `command`：运行命令并使用其结果作为输入值。

**通用属性：**

| 字段 | 必需 | 说明 | 示例 |
|-------|----------|-------------|---------|
| `type` | 是 | 输入提示类型：`promptString`、`pickString` 或 `command` | `"promptString"` |
| `id` | 是 | 在服务器配置中引用的唯一标识符 | `"api-key"`、`"database-url"` |

**`promptString` 属性：**

| 字段 | 必需 | 说明 | 示例 |
|-------|----------|-------------|---------|
| `description` | 是 | 用户友好的提示文本 | `"GitHub Personal Access Token"` |
| `default` | 否 | 输入默认值 | `"https://localhost"` |
| `password` | 否 | 隐藏输入（默认 false） | API 密钥和密码使用 `true` |

**`pickString` 属性：**

| 字段 | 必需 | 说明 | 示例 |
|-------|----------|-------------|---------|
| `description` | 是 | 用户友好的提示文本 | `"Select an environment"` |
| `options` | 是 | 可选选项数组。每个选项是字符串，或包含 `label` 和 `value` 属性的对象。 | `["dev", "prod"]` |
| `default` | 否 | 输入默认值 | `"dev"` |

**`command` 属性：**

| 字段 | 必需 | 说明 | 示例 |
|-------|----------|-------------|---------|
| `command` | 是 | 为获取输入值而运行的命令 ID | `"myExtension.getApiKey"` |
| `args` | 否 | 传递给命令的参数。可以是字符串、数组或对象。 | `{ "scope": "global" }` |

**带输入变量的服务器配置示例**

此示例配置需要 API 密钥的本地服务器：

```json
{
    "inputs": [
        {
            "type": "promptString",
            "id": "perplexity-key",
            "description": "Perplexity API Key",
            "password": true
        }
    ],
    "servers": {
        "perplexity": {
            "type": "stdio",
            "command": "npx",
            "args": [
                "-y",
                "server-perplexity-ask"
            ],
            "env": {
                "PERPLEXITY_API_KEY": "${input:perplexity-key}"
            }
        }
    }
}
```

### 开发模式 {#development-mode}

　　可以向服务器配置添加 `dev` 键启用 MCP 服务器*开发模式*。该对象有两个属性：

* `watch`：用于监视文件更改并重启 MCP 服务器的 glob 模式或模式数组。适用于所有服务器类型。
* `debug`：允许为 MCP 服务器设置调试器。目前 VS Code 支持调试 Node.js 和 Python MCP 服务器。仅适用于 stdio 服务器。

　　详细了解 MCP 开发指南中的 [MCP 开发模式](https://code.visualstudio.com/api/extension-guides/ai/mcp#mcp-development-mode-in-vs-code)。

### 服务器命名约定 {#server-naming-conventions}

定义 MCP 服务器时，服务器名称请遵循：

* 使用 camelCase，例如“uiTesting”或“githubIntegration”。
* 避免空白或特殊字符。
* 为每个服务器使用唯一名称以避免冲突。
* 使用反映服务器功能或品牌描述性名称，例如“github”或“database”。

## 自动发现 MCP 服务器 {#automatic-mcp-server-discovery}

　　VS Code 可以自动检测并复用受支持应用程序中的 MCP 服务器配置。使用 `chat.mcp.discovery.enabled` 选择发现来源。

| 来源 | 设置属性 | 配置位置 |
|--------|------------------|------------------------|
| Claude Desktop | `claude-desktop` | Windows：`%APPDATA%\Claude\claude_desktop_config.json`<br/>macOS：`~/Library/Application Support/Claude/claude_desktop_config.json`<br/>Linux：`$XDG_CONFIG_HOME/Claude/claude_desktop_config.json`，未设置 XDG_CONFIG_HOME 时为 `~/.config/Claude/claude_desktop_config.json` |
| Copilot CLI | `copilot` | `<COPILOT_HOME>/mcp-config.json`，未设置 COPILOT_HOME 时为 `~/.copilot/mcp-config.json` |
| Cursor（全局） | `cursor-global` | `~/.cursor/mcp.json` |
| Cursor（工作区） | `cursor-workspace` | `<workspace>/.cursor/mcp.json` |
| Windsurf | `windsurf` | `~/.codeium/windsurf/mcp_config.json` |

　　Copilot CLI 发现默认开启，其他发现来源默认关闭。远程窗口中，VS Code 在远程环境中解析配置位置和环境变量。

　　对于 Copilot CLI，设置 `COPILOT_HOME` 会替换默认 `~/.copilot` 位置。VS Code 不会同时检查两个位置。

> **注意**：Copilot 运行框架会话独立读取 Copilot CLI MCP 配置，无论使用聊天视图还是智能体窗口。发现设置不会改变这些会话接收 MCP 服务器的方式。请参阅[配置格式和转发](#configuration-file)。

## 命令 {#commands}

命令面板（`Ctrl + Shift + P`，macOS：`Cmd + Shift + P`）中可用的 MCP 命令：

| 命令 | 说明 |
|---------|-------------|
| **MCP: Add Server** | 将新 MCP 服务器添加到工作区或用户配置文件。 |
| **MCP: Browse MCP Servers** | 在扩展视图中打开 [MCP 发现](../../../customize-and-extend/2.4.7-AddMCPServers/)。启用 Marketplace 发现时，选择 **浏览 MCP 服务器** 在智能体自定义编辑器中继续。 |

### 命令行安装 {#command-line-installation}

　　使用 `code --add-mcp` 和包含唯一 `name` 及服务器配置的 JSON 对象。命令将服务器添加到 VS Code 用户配置文件配置。

例如，在 Bash shell 中：

```bash
code --add-mcp '{"name":"playwright","type":"stdio","command":"npx","args":["-y","@playwright/mcp@latest"]}'
```

　　这使用 VS Code 格式，不是可移植 Copilot 用户文件。要选择可移植目标，请使用[引导连接流程](../../../customize-and-extend/2.4.7-AddMCPServers/)。安装后请[验证工具调用](../../../customize-and-extend/2.4.7-AddMCPServers/)。

## 设置 {#settings}

　　完整 VS Code AI 设置列表请参阅 [AI 设置参考](../2.8.1.3-SettingsReference/)。以下设置特定于 MCP 服务器。

| 设置 | 说明 |
|---------|-------------|
| `chat.mcp.access` | 管理 VS Code 中可使用哪些 MCP 服务器。 |
| `chat.mcp.discovery.enabled` | 配置从其他应用程序自动发现 MCP 服务器配置。 |
| `chat.mcp.workspaceRootConfig.enabled` | （实验性）控制 **MCP: Add Server** 是否提供工作区根 `.mcp.json` 目标。关闭时现有 `.mcp.json` 文件仍可用。 |
| `chat.mcp.autostart` | 控制提交聊天消息时 VS Code 自动启动哪些 MCP 服务器。此设置不会阻止 Copilot 运行框架会话启动其独立管理的服务器。请参阅 [MCP 自动启动行为](../../../customize-and-extend/2.4.8-ManageMCPServers/)。 |
| `chat.mcp.serverSampling` | 配置向 MCP 服务器公开哪些模型用于采样（后台发起请求）。 |
| `chat.mcp.apps.enabled` | 启用或禁用 MCP 应用，即 MCP 服务器提供的丰富用户界面。 |
| `accessibility.verbosity.mcpServerConfiguration` | 控制 MCP 服务器配置表单是否播报打开辅助功能帮助的信息。 |
