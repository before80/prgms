# 2.8.1.7 智能体插件编写参考

　　将相关自定义项打包为插件，让开发者一起安装。本参考涵盖清单、目录布局、组件和 Marketplace 配置、管理命令以及跨插件格式和智能体运行框架的兼容性。

　　创建插件或检查其组件配置时使用本参考。查找、安装、更新或移除现有插件请参阅[使用智能体插件](../../../customize-and-extend/2.4.2-Plugins/)。

## 包结构 {#package-structure}

　　Agent Plugins 1.0 将技能和 MCP 服务器定义为可移植组件类型。其他能力是客户端特定的，使用标准的反向域[客户端扩展命名空间](https://agent-plugins.org/plugin-authors/client-extensions)。VS Code 从 `com.github.copilot` 命名空间读取 Copilot 特定组件，并忽略其他客户端拥有的命名空间。

| 能力 | 说明 | 客户端特定 | 标准 |
|------------|-------------|:--------------:|:--------:|
| [MCP 服务器](../../../customize-and-extend/2.4.7-AddMCPServers/) | 外部工具集成 | | ✓ |
| [技能](../../../customize-and-extend/2.4.3-AgentSkills/) | 按需加载的指令、脚本和资源 | | ✓ |
| [智能体](../../../customize-and-extend/2.4.5-CustomAgents/) | 专门角色和工具配置 | ✓ | |
| [钩子](../../../customize-and-extend/2.4.9-Hooks/) | 在智能体工作流特定点运行的 shell 命令 | ✓ | |
| [自动化模板](#automations-in-plugins) | 可复用的智能体任务提示词和计划 | ✓ | |
| 斜杠命令 | 在聊天中使用 `/` 调用的命令 | ✓ | |

例如，测试插件可以包含带脚本的 `test-runner` 技能、带只读工具的 `test-reviewer` 智能体以及用于测试报告仪表板的 MCP 服务器。Agent Plugins 格式中的目录结构如下：

```text
my-testing-plugin/
  plugin.json              # Plugin metadata and configuration
  skills/
    test-runner/
      SKILL.md             # Testing skill instructions
      run-tests.sh         # Supporting script
  mcp.json                 # MCP server definitions
  automations/
    review.automation.md   # Automation template
  scripts/
    validate-tests.sh      # Hook script
  com.github.copilot/
    agents/
      test-reviewer.agent.md  # Code review agent
    hooks/
      hooks.json           # Hook configuration
```

　　Copilot 和 Claude 格式的插件从不同位置提供相同能力。请参阅[插件格式](#plugin-formats)。

## 插件清单（plugin.json） {#plugin-manifest-pluginjson}

　　Agent Plugins 1.0 包根目录有 `plugin.json` 文件，声明标准 schema：

```json
{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json",
  "name": "my-dev-tools",
  "description": "React development utilities",
  "version": "1.2.0"
}
```

| 字段 | 类型 | 必需 | 说明 |
|-------|------|:--------:|-------------|
| `$schema` | string | 是 | 规范 Agent Plugins schema 标识符。 |
| `name` | string | 是 | 插件名称和包标识符。 |
| `version` | string | 否 | 插件版本。建议语义化版本。 |
| `description` | string | 否 | 插件简短说明。 |
| `author` | object | 否 | 作者信息，可选 `name`、`email` 和 `url` 字段。 |
| `homepage` | string | 否 | 文档或主页。 |
| `repository` | string | 否 | 源仓库。 |
| `license` | string | 否 | 许可证标识符。建议 SPDX 标识符。 |
| `keywords` | string[] | 否 | 搜索和发现关键词。 |
| `extensions` | object | 否 | 按反向域命名空间键控的客户端特定数据。 |

　　技能从 `skills/` 文件夹发现，MCP 服务器配置从 `mcp.json` 文件发现。无需在清单中列出这些组件路径。自定义智能体、钩子、命令和 MCP 服务器定义不是可移植的顶级清单字段。

　　Copilot 特定组件位于插件根目录的 `com.github.copilot` 目录，Copilot 特定清单数据位于 `extensions` 下匹配键中：

```text
my-plugin/
  plugin.json              # $schema declares Agent Plugins 1.0
  skills/                  # Portable: agent skills
  mcp.json                 # Portable: MCP server configuration
  com.github.copilot/      # Copilot-specific components
    agents/
    commands/
    rules/
    hooks/
      hooks.json
```

　　其他客户端忽略 `com.github.copilot` 命名空间，因此包保持可移植，同时保留 Copilot 能力。

　　完整字段约束和验证规则请参阅 [Agent Plugins 清单文档](https://agent-plugins.org/plugin-authors/manifest)。

> **注意**：不声明 Agent Plugins schema 的现有 Copilot 格式插件仍受支持。其清单字段请参阅 [Copilot CLI 插件参考](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference#pluginjson)。

## 插件格式 {#plugin-formats}

　　VS Code 通过检查根清单和格式特定清单路径自动检测插件格式。声明规范 Agent Plugins `$schema` 的根 `plugin.json` 使用 Agent Plugins 语义。未找到其他格式标记时，Copilot 格式用作默认值。

| 插件格式 | 插件清单 |
|---------------|-----------------|
| Agent Plugins 1.0 | `plugin.json`，`$schema` 设置为 `https://agent-plugins.org/schemas/1.0.0/plugin.schema.json` |
| Copilot | `plugin.json` |
| Claude | `.claude-plugin/plugin.json` |
| 旧版 OpenPlugin | `.plugin/plugin.json` |

### 插件环境变量 {#plugin-environment-variables}

　　某些插件格式提供根令牌，可在钩子命令和 MCP 服务器配置中引用插件目录内文件。VS Code 在运行时展开令牌，并将其设置为钩子或服务器进程中的环境变量。

| 插件格式 | 插件根 |
|---------------|------------------|
| Agent Plugins 1.0 | `${PLUGIN_ROOT}` |
| Claude | `${CLAUDE_PLUGIN_ROOT}` |
| Copilot | `${PLUGIN_ROOT}` 或 `${CLAUDE_PLUGIN_ROOT}` |
| 旧版 OpenPlugin | `${PLUGIN_ROOT}` |

　　Agent Plugins 1.0 还为打包文件定义 `${PLUGIN_ROOT}`，为跨插件更新持久化的可写状态定义 `${PLUGIN_DATA}`。VS Code 保留这些占位符供插件运行时展开。支持位置详情请参阅 [Agent Plugins 规范](https://github.com/agentplugins/agent-plugins-spec/blob/main/spec/1.0.0.md#9-environment-variables-and-placeholder-expansion)。

## 插件中的自动化 {#automations-in-plugins}

　　Agent Plugins 可以提供自动化模板，显示在智能体窗口的 **来自插件的模板** 下。模板提供可复用名称、提示词和计划。安装插件时不会创建或启用自动化。

> **注意**：自动化模板是 VS Code 特定插件能力，不是可移植 Agent Plugins 1.0 组件类型。

### 自动化模板位置 {#automation-template-location}

　　将自动化模板存储在 Agent Plugins 包根目录的 `automations/` 文件夹。每个文件必须使用 `.automation.md` 后缀：

```text
my-plugin/
  plugin.json
  automations/
    daily-review.automation.md
    weekly-review.automation.md
```

　　要从其他文件夹添加模板，请在 `plugin.json` 中配置 `extensions.com.github.copilot.automations.paths`。这些路径相对于 `com.github.copilot/` 文件夹，并补充默认 `automations/` 文件夹：

```json
{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json",
  "name": "my-dev-tools",
  "version": "1.2.0",
  "extensions": {
    "com.github.copilot": {
      "automations": {
        "paths": [
          "./team-automations/"
        ]
      }
    }
  }
}
```

　　在 `paths` 旁将 `exclusive` 设置为 `true`，只从配置文件夹加载模板并跳过默认 `automations/` 文件夹。

### 自动化模板格式 {#automation-template-format}

　　自动化模板是带 YAML frontmatter 的 Markdown 文件。Markdown 正文是提示词：

```markdown
---
version: 1
id: weekly-review
name: Weekly review
description: Review the workspace for regressions.
schedule:
  kind: cron
  expression: "30 10 * * 5"
  timeZone: local
---
Review the workspace changes from the past week.
Identify regressions and suggest follow-up actions.
```

frontmatter 支持：

| 字段 | 必需 | 说明 |
|-------|:--------:|-------------|
| `version` | 是 | 文件格式版本。使用 `1`。 |
| `id` | 是 | 插件内唯一标识符。使用小写字母、数字、句点或连字符，最多 64 个字符。 |
| `name` | 是 | 模板显示名称。 |
| `description` | 否 | 自动化用途简短说明。 |
| `schedule` | 是 | 手动、每小时或五字段 cron 计划。 |

使用以下计划格式之一：

| 计划 | YAML |
|----------|------|
| 手动 | `kind: manual` |
| 每小时 | `kind: hourly` |
| 每天 | `kind: cron`、五字段表达式（例如 `"0 9 * * *"`）以及 `timeZone: local` |
| 每周 | `kind: cron`、五字段表达式（例如 `"30 10 * * 5"`）以及 `timeZone: local` |
| Cron | `kind: cron`、受支持的五字段表达式（例如 `"0 9,17 * * MON-FRI"`）以及 `timeZone: local` |

　　Cron 计划支持[五字段表达式语法](../../../work-with-ai/plan-and-run-tasks/2.2.10.5-Automations/)，包括列表、范围和步长。Cron 模板需要 `timeZone: local`。模板文件不支持命名时区。VS Code 会忽略无效模板，而不是更改其计划。

　　插件模板不能指定工作区、提供商、模型、权限、启用状态或运行历史。选择模板时会打开 **新建自动化** 对话框，供用户审查提示词并选择执行配置。**启用** 复选框默认清除。

　　禁用插件会从自动化视图移除其模板。之前从这些模板创建的自动化及其运行历史仍可用。

## 插件中的 MCP 服务器 {#mcp-servers-in-plugins}

　　插件可以捆绑 [MCP 服务器](../../../customize-and-extend/2.4.7-AddMCPServers/)，为智能体提供额外工具和数据源。插件启用时其 MCP 服务器自动启动，禁用时停止。

### MCP 配置文件 {#mcp-configuration-file}

**Agent Plugins 1.0**

　　将 MCP 服务器定义放在插件根目录 `mcp.json` 文件，并遵循[可移植 MCP 配置格式](https://agent-plugins.org/plugin-authors/mcp-servers)。

```text
my-plugin/
  plugin.json             # Plugin metadata and configuration
  skills/
  mcp.json              # MCP server definitions
  servers/
    db-server             # Server executable
  config.json             # Server configuration
```

**Copilot 和 Claude**

　　将 MCP 服务器定义放在插件根目录 `.mcp.json` 文件。VS Code 加载插件时自动发现。

```text
my-plugin/
  plugin.json             # Plugin metadata and configuration
  skills/
  .mcp.json              # MCP server definitions
  servers/
    db-server             # Server executable
  config.json             # Server configuration
```

　　在 `.mcp.json` 中，MCP 服务器在顶级 `mcpServers` 对象中定义。每个服务器条目指定命令、参数和可选环境变量：

```json
{
  "mcpServers": {
    "plugin-database": {
      "command": "${CLAUDE_PLUGIN_ROOT}/servers/db-server",
      "args": ["--config", "${CLAUDE_PLUGIN_ROOT}/config.json"],
      "env": {
        "DB_PATH": "${CLAUDE_PLUGIN_ROOT}/data"
      }
    },
    "plugin-api": {
      "command": "npx",
      "args": ["@company/mcp-server", "--plugin-mode"],
      "cwd": "${CLAUDE_PLUGIN_ROOT}"
    }
  }
}
```

### 在服务器配置中引用插件路径 {#reference-plugin-paths-in-server-configuration}

　　对于 Claude 格式插件，请在 MCP 服务器字段中使用 `${CLAUDE_PLUGIN_ROOT}` 令牌引用插件目录内的可执行文件和文件。VS Code 会在以下字段中展开：

* `command`：可执行文件路径
* `args`：命令行参数
* `cwd`：工作目录
* `env`：环境变量值
* `envFile`：环境文件路径
* `url`：HTTP MCP 服务器 URL
* `headers`：HTTP 标头值

　　VS Code 还会向服务器进程注入 `CLAUDE_PLUGIN_ROOT` 环境变量，使服务器代码可以在运行时访问插件路径。

### 插件 MCP 服务器如何与其他服务器交互 {#how-plugin-mcp-servers-interact-with-other-servers}

　　插件 MCP 服务器与工作区和用户级 MCP 服务器一起出现。可以通过相同工具管理：

* 在聊天视图中选择 **配置工具** 查看所有 MCP 服务器的工具，包括插件服务器。
* 从命令面板运行 **MCP: List Servers** 查看插件服务器和其他服务器。

　　安装插件时插件 MCP 服务器被隐式信任。与工作区 MCP 服务器不同，启动时不显示单独信任提示。

　　禁用插件会停止其 MCP 服务器。停止服务器提供的工具不再在聊天中可用。

## 插件中的钩子 {#hooks-in-plugins}

　　插件可以包含在智能体工作流特定点运行 shell 命令的[钩子](../../../customize-and-extend/2.4.9-Hooks/)。插件级钩子与工作区和用户级钩子一起工作。插件启用时，这些钩子会与同一事件的其他已配置钩子一起触发。

> **注意**：钩子是客户端特定的，不是可移植 Agent Plugins 1.0 组件类型。Agent Plugins 包中它们来自 `com.github.copilot` 命名空间。

　　组织可以通过插件分发已批准钩子。托管设置指定 `allowManagedHooksOnly: true` 时，插件钩子仅在通过托管 `enabledPlugins["plugin@marketplace"]: true` 强制启用插件时运行。仅用户启用不够，`allowManagedHooksOnly` 本身也不会启用插件。请参阅[通过托管插件部署钩子](../../../../enterprise/7.2-ManageAISettings/)。

　　对于 Copilot 会话，请使用 [Copilot 钩子参考](https://docs.github.com/en/copilot/reference/hooks-reference)了解配置、事件负载和输出决定。插件打包钩子，但不会将 Local 脚本转换为共享运行框架契约。

　　采用或更新插件时，请遵循[迁移钩子](../../../customize-and-extend/2.4.11-MigrateExistingCustomizations/)。更新源包，而不是其安装缓存。检查捆绑脚本、路径引用、智能体作用域钩子以及用户设置或仓库钩子文件中的重复命令。

### 钩子文件位置 {#hook-file-location}

钩子文件位置取决于插件格式：

| 插件格式 | 钩子文件路径 |
|---------------|----------------|
| Agent Plugins 1.0 | `com.github.copilot/hooks/hooks.json` |
| Claude | `hooks/hooks.json` |
| Copilot | `hooks.json`（插件根目录） |

　　VS Code 自动检测插件格式并发现钩子文件。

```text
my-plugin/
  plugin.json
  com.github.copilot/
    hooks/
      hooks.json         # Hook configuration (Agent Plugins format)
  scripts/
    review-tool-copilot.cjs
```

### 钩子配置格式 {#hook-configuration-format}

　　使用插件目标运行时支持的钩子 schema。Copilot 请审查[命令钩子格式](https://docs.github.com/en/copilot/reference/hooks-reference#command-hooks)和[匹配器语义](https://docs.github.com/en/copilot/reference/hooks-reference#matcher-filtering)。事件别名会影响负载和工具名称，因此请一起测试脚本和匹配器。

### 在钩子命令中引用插件路径 {#reference-plugin-paths-in-hook-commands}

　　使用插件根引用，而不是硬编码安装目录。这些引用标识包根，不是当前仓库或包含钩子配置的文件夹：

| 插件格式 | 令牌 | 环境变量 |
|---------------|-------|----------------------|
| Agent Plugins 1.0 | `${PLUGIN_ROOT}` | `PLUGIN_ROOT` |
| Copilot | `${PLUGIN_ROOT}` | `PLUGIN_ROOT` |
| Claude | `${CLAUDE_PLUGIN_ROOT}` | `CLAUDE_PLUGIN_ROOT` |
| 旧版 OpenPlugin | `${PLUGIN_ROOT}` | `PLUGIN_ROOT` |

例如，将[转换后的审查脚本](../../../customize-and-extend/2.4.11-MigrateExistingCustomizations/)作为 `scripts/review-tool-copilot.cjs` 包含在上面的包结构中。Agent Plugins 1.0 包将此配置放在 `com.github.copilot/hooks/hooks.json`：

```json
{
  "version": 1,
  "hooks": {
    "preToolUse": [
      {
        "type": "command",
        "command": "node \"${PLUGIN_ROOT}/scripts/review-tool-copilot.cjs\"",
        "env": { "REVIEW_TOOL_NAME": "<copilot-tool-name>" },
        "timeoutSec": 10
      }
    ]
  }
}
```

　　将 `<copilot-tool-name>` 替换为要审查的工具。带引号的脚本路径使包含空格的安装目录保持为一个命令参数。此示例要求执行主机安装 Node.js，且不写入已安装包。

　　[插件解析器](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/platform/agentPlugins/common/pluginParsers.ts)定义格式特定钩子根引用及其命令路径展开。请使用包格式对应的令牌和钩子文件位置，不要复制已安装缓存路径。在一次性 Copilot 会话中测试包之前，请停用同一钩子的任何独立副本。

### 支持的钩子事件 {#supported-hook-events}

　　插件级钩子请使用共享运行框架的[事件参考](https://docs.github.com/en/copilot/reference/hooks-reference#hook-event-input-payloads)。

　　插件提供的自定义智能体 frontmatter 中的钩子[作用域为该智能体](../../../customize-and-extend/2.4.9-Hooks/)。VS Code 在将智能体传递给 Copilot 时转发这些钩子。智能体出现在选择器中不能证明其钩子运行，请在受信任会话中验证预期事件和决定。请将智能体特定钩子保留在智能体 frontmatter 中，不要扩大到插件级执行。

### 插件钩子如何与其他钩子交互 {#how-plugin-hooks-interact-with-other-hooks}

　　插件级钩子与其他适用钩子来源一起运行。对于 Copilot `preToolUse`，拒绝会阻止工具调用。钩子应保持正常权限流程不变时，请返回无决定。依赖钩子验证前，请审查运行时超时和失败规则。

　　禁用插件也会禁用其钩子。除非企业策略控制插件启用，否则可以在智能体自定义编辑器中为当前配置文件或特定工作区[启用或禁用插件](../../../customize-and-extend/2.4.2-Plugins/)。

## 跨工具兼容性 {#cross-tool-compatibility}

　　Agent Plugins 1.0 是为跨工具兼容性设计的开放标准。符合规范的插件使用根 `plugin.json`，将技能放在 `skills/`，将 MCP 服务器配置放在 `mcp.json`。兼容客户端可以从同一包发现其支持的便携组件类型。

　　Agent Plugins 还可以在稳定的反向域命名空间下包含客户端特定清单数据和文件。客户端忽略未实现的命名空间，因此客户端特定能力不会阻止其他客户端加载便携组件。VS Code 从 `com.github.copilot` 命名空间读取自定义智能体、斜杠命令、规则、钩子和自动化路径配置。其他客户端仅使用该命名空间中它们支持的能力。

例如：

```text
my-plugin/
  plugin.json
  skills/
  mcp.json
  com.github.copilot/      # Read by VS Code and other Copilot clients
  com.example.client/      # Ignored by VS Code
```

　　VS Code 继续支持现有 Copilot、Claude 和旧版 OpenPlugin 格式。未声明 Agent Plugins schema 的插件继续使用其现有格式特定发现规则。

　　可移植格式详情请参阅 [Agent Plugins 规范](https://github.com/agentplugins/agent-plugins-spec/blob/main/spec/1.0.0.md)。其他格式请参阅 [Copilot CLI 插件参考](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference)和 [Claude Code 插件 Marketplace 文档](https://code.claude.com/docs/en/plugin-marketplaces)。

## Marketplace 来源格式 {#marketplace-source-formats}

　　使用 `chat.plugins.marketplaces`（实验性）在设置中配置其他 Marketplace 仓库。支持来源格式包括：

* **简写**：公共 GitHub 仓库的 `owner/repo`，例如 `anthropics/claude-code`。附加 `#<ref>` 选择 branch、tag 或完整 40 字符提交 SHA。
* **HTTPS git remote**：以 `.git` 结尾的完整 URL，例如 `https://github.com/anthropics/claude-code.git`。
* **SCP 风格 git remote**：SSH 风格引用，例如 `git@github.com:anthropics/claude-code.git`。
* **文件 URI**：磁盘上已克隆 Marketplace 仓库的 `file:///` 路径。

例如，将此属性添加到 `settings.json`，保留其他设置：

```json
{
    "chat.plugins.marketplaces": [
        "anthropics/claude-code"
    ]
}
```

　　要获得可重现安装，请使用完整 40 字符提交 SHA，例如 `owner/repo#<commit-sha>`。VS Code 从该确切修订安装插件。Branch 和 tag 引用使用获取 Marketplace 时解析的修订。

　　私有仓库也受支持。登录 GitHub 并确保有权读取 Marketplace 仓库。仅组织成员身份不会授予仓库访问权限。公共查找失败时，VS Code 会回退到直接克隆仓库。

　　Marketplace 索引声明插件位于相对路径时，VS Code 在安装前验证仓库、解析修订和路径。缺少修订、无效路径或路径匹配不明确时，来源会被拒绝。

　　Marketplace 插件还可以引用 npm 或 PyPI 包等外部包来源。完整 Marketplace 插件 schema 请参阅 [Claude Code 插件 Marketplace 文档](https://code.claude.com/docs/en/plugin-marketplaces)。企业管理员可以[管理插件和 Marketplace 可用性](../../../../enterprise/7.2-ManageAISettings/)。

## 本地插件注册 {#local-plugin-registration}

　　要注册现有开发目录而不安装，请使用 `chat.pluginLocations`（实验性）。此设置将插件目录路径映射到启用或禁用状态。值设置为 `true` 启用插件，设置为 `false` 保持注册但禁用。

例如，将此属性合并到 `settings.json`，将路径替换为机器上的目录：

```json
{
    "chat.pluginLocations": {
        "/path/to/my-plugin": true,
        "/path/to/another-plugin": false
    }
}
```

　　要从本地文件夹安装插件，请遵循[从源安装插件](../../../customize-and-extend/2.4.2-Plugins/)。

　　对于远程工作区，请在 **远程** 设置中添加此设置，并使用远程机器或容器内路径。请参阅[在远程窗口中使用插件](../../../customize-and-extend/2.4.2-Plugins/)。

## 工作区插件设置 {#workspace-plugin-settings}

　　项目可以在 `.claude/settings.json` 中配置插件推荐，或在 `.github/copilot/settings.json` 中配置仓库默认值：

* **`extraKnownMarketplaces`**：为项目注册额外 Marketplace。这些 Marketplace 出现在智能体自定义编辑器的可用来源中。
* **`enabledPlugins`**：列出默认应启用的插件。

例如：

```json
{
    "extraKnownMarketplaces": {
        "company-tools": {
            "source": {
                "source": "github",
                "repo": "your-org/plugin-marketplace"
            }
        }
    },
    "enabledPlugins": {
        "code-formatter@company-tools": true
    }
}
```

　　Marketplace 键（示例中 `company-tools`）必须匹配 Marketplace `marketplace.json` 中的 `name`。插件标识符使用 `<plugin>@<marketplace>`，不是 Marketplace 仓库名称。请保持 Marketplace 名称稳定，以便共享设置继续引用相同插件。

　　Local 推荐、Copilot 仓库默认值和企业策略的差异请参阅[工作区插件推荐](../../../customize-and-extend/2.4.2-Plugins/)。

## 插件管理命令 {#plugin-management-commands}

　　在 Copilot 运行框架会话中输入 `/plugin ` 查看插件和 Marketplace 操作补全。

> **注意**：`/plugin` 命令和智能体自定义编辑器当前使用单独插件清单。请在安装插件的界面管理它。

| 命令 | 用途 |
|---------|---------|
| `/plugin list` | 列出已安装插件及其状态。 |
| `/plugin install <source>` | 从 Marketplace 或 Git 仓库安装插件。 |
| `/plugin update <plugin>` | 更新已安装插件。 |
| `/plugin enable <plugin>` | 启用已安装 Marketplace 插件。 |
| `/plugin disable <plugin>` | 禁用已安装 Marketplace 插件。 |
| `/plugin uninstall <plugin>` | 移除已安装插件。 |
| `/plugin marketplace list` | 列出内置和已注册 Marketplace。 |
| `/plugin marketplace browse <name>` | 浏览 Marketplace 中的插件。 |
| `/plugin marketplace add <source>` | 从 Git 仓库添加 Marketplace。 |
| `/plugin marketplace update [name]` | 更新一个或所有已注册 Marketplace。 |
| `/plugin marketplace remove <name> [--force]` | 移除已注册 Marketplace。安装了来自该 Marketplace 的插件时使用 `--force`。 |

　　Marketplace 插件使用限定身份 `<plugin>@<marketplace>`。多个 Marketplace 中插件同名时使用此身份。命令补全会为每个操作建议有效 Marketplace 和插件身份。

　　直接从 Git 仓库安装的插件可以更新或卸载，但不能通过这些命令启用或禁用。要停止使用直接安装的插件，请卸载。内置和集中管理的 Marketplace 不能移除。

## 测试和分发插件 {#test-and-distribute-a-plugin}

　　分发插件前，请为计划支持的每个运行框架和客户端验证行为：

1. 将开发副本注册为[本地插件](#local-plugin-registration)。此配置是实验性的。
2. 检查支持的组件出现，然后运行代表性任务验证插件提供的技能、智能体、钩子和工具。测试前审查钩子或 MCP 服务器运行的代码。
3. 如果插件包含自动化模板，确认它们出现在 **来自插件的模板** 中，并在创建自动化前审查其配置。
4. 发布更新前，提升 `plugin.json` 和适用时 `marketplace.json` 插件条目中的 `version` 字段。遵循插件格式对应的 Marketplace schema。
5. 测试开发者将使用的[安装](../../../customize-and-extend/2.4.2-Plugins/)和[更新](../../../customize-and-extend/2.4.2-Plugins/)路径。

　　Marketplace schema 和分发详情请参阅 [Agent Plugins 规范](https://github.com/agentplugins/agent-plugins-spec/blob/main/spec/1.0.0.md)、[Copilot CLI 插件参考](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference)和 [Claude Code Marketplace 文档](https://code.claude.com/docs/en/plugin-marketplaces)。
