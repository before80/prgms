# 2.2.10.1 规划工作

　　规划帮助你在智能体更改代码前明确需求、比较方法并识别风险。当方法不确定或更改跨越项目多个部分时，请使用单独规划步骤。对于小型、定义明确的编辑，可以直接要求智能体实现。

　　可以在聊天视图或智能体窗口中创建和审查计划。对于专门规划工作流，请使用 **Plan** 智能体（`/plan`）。智能体研究会项目、提出澄清问题并创建计划供你在实现前审查。

　　本文介绍如何使用 Copilot 创建计划、审查和完善计划，以及选择实现还是保存。还介绍 [Local 运行框架会话中的规划](#plan-in-a-local-harness-session)控件。

　　端到端示例请遵循[向现有项目添加功能](../../../tutorials-and-guides/2.6.3-AddAFeature/)指南，从定义需求到审查测试后的更改。

## 如何规划任务 {#how-to-plan-a-task}

　　开始前[设置 GitHub Copilot](../../../getting-started/2.1.2-SetUpCopilot/)。可以从聊天视图或智能体窗口规划。

以下步骤使用 Copilot 运行框架。详细了解[选择智能体运行框架](../../../choose-models-and-agents/2.3.2-ChooseAnAgentHarness/)。

1. 为项目启动会话。
2. 打开 **会话目标** 控件，选择 **Copilot**。
3. 输入 `/plan`，后跟想要的结果、约束以及如何验证成功。例如：

    ```text
    /plan Add pagination to this project's product-list API.
    Follow the existing API conventions and preserve the behavior of requests
    that don't specify pagination. Include tests for invalid parameters,
    empty results, and compatibility with existing clients.
    Identify decisions I need to make before implementation.
    ```

4. 智能体研究项目时回答其澄清问题。例如，在最终确定计划前就分页方法和默认值达成一致。如果不确定，请要求它推荐方法并解释权衡。

　　智能体呈现包含实现步骤、相关文件和验证步骤的计划。分页任务的示例大纲：

* 使用 API 现有验证模式添加可选分页参数。
* 请求时应用分页，保留现有客户端的响应格式和行为。
* 为有效和无效参数、空结果以及不带分页的请求添加测试。
* 运行 API 测试套件，验证现有客户端仍收到预期结果。

　　实际计划应标识项目中的文件和代码模式，而不仅是列出通用任务。

### 要求当前智能体规划 {#ask-the-current-agent-to-plan}

　　对于方法讨论，可以要求当前智能体提供计划，而无需显式选择 Plan 模式：

```text
研究如何为此项目的产品列表 API 添加分页。提出实现计划并识别兼容性风险。
不要更改项目文件。实现前等待我的批准。
```

　　此请求引导智能体行为，但不更改会话权限。当希望显式启动专门工作流时，请选择 Plan 模式或使用 `/plan`。

### 规划前研究（预览） {#research-before-planning-preview}

　　当需要在选择方法前获得带引用的详细 Markdown 报告时，请在 [Copilot 运行框架会话](../../../choose-models-and-agents/2.3.2-ChooseAnAgentHarness/#copilot)中使用内置研究智能体。在 VS Code Insiders 中，输入 `/research <topic>` 从代码库、相关 GitHub 仓库和 Web 收集发现。

　　要直接用于实现计划的研究，请使用 [Plan 智能体](#how-to-plan-a-task)。要返回当前对话的聚焦研究，请使用[子智能体](../2.2.10.4-Subagents/)。

## 审查和完善计划 {#review-and-refine-the-plan}

　　当 Copilot 显示 **审查计划** 卡片时，启动实现前阅读完整计划：

1. 选择 **打开完整计划** 在 Markdown 编辑器中打开计划文件。
2. 审查方法、受影响代码和验证步骤。可以编辑计划或添加内联评论。
3. 要请求修订，请在卡片反馈区添加总体评论并选择 **提交反馈**。这会将总体和内联评论发送给智能体，但不批准实现。

　　会话提供计划文件时，卡片提供 **打开完整计划**。其他会话可能显示 **计划摘要** 或 **打开计划** 标签。

对照预期结果检查计划：

* **范围**：解决请求的问题并排除无关更改。
* **项目契合**：标识受影响文件并复用现有模式。
* **决策**：假设、依赖项和未解决选择明确。
* **验证**：提议的测试和手动检查证明更改有效且不破坏现有行为。

例如，提交以下反馈：

```text
保持当前响应格式不变，排除 UI 更改。将实现拆分为可独立测试的步骤。
为省略分页参数的请求添加兼容性检查。
```

　　审查更新后的计划并在选择实现操作前解决未决问题。待处理反馈会禁用批准，直到提交或清除。审查控件会在提交批准或反馈前保存计划文件编辑。

## 实现或保存计划 {#implement-or-save-the-plan}

审查计划后，从计划审查卡片选择操作。可用操作取决于会话：

| 操作 | 作用 |
|--------|--------------|
| **实现计划** | 批准计划并在当前会话开始实现。 |
| **仅批准计划** | 批准计划而不执行。 |
| **使用 Autopilot 实现** | 使用 Copilot 会话中选定的审批级别自主继续。 |
| **拒绝** | 拒绝计划而不开始实现。 |

　　要共享计划或与项目一起保留，请打开完整计划并另存副本。要在另一会话中实现，请使用目标智能体启动会话并附加保存的计划。这会共享计划，而不是转移整个对话。

> **注意**：批准计划和批准工具操作是分开的决定。开始实现前审查会话[权限](../../permissions-and-security/2.2.12.1-ApprovalsAndPermissions/#permission-levels)。在 Copilot 会话中，Autopilot 控制智能体如何继续工作，所选审批级别控制哪些操作需要确认。

## 自定义规划 {#customize-planning}

　　复杂规划使用能力较强的推理模型，然后选择能可靠实现已审查、范围明确计划的低成本模型。这可以减少 AI 点数使用量，但请比较总成本和质量的权衡，因为重试和返工可能超过便宜模型的节省。

　　在 Copilot 会话中，使用[语言模型选择器](../../../choose-models-and-agents/2.3.1-ChooseAndConfigureModels/#change-the-model-for-chat)选择规划模型。要为单独实现请求使用不同模型：

1. 在提供时选择 **仅批准计划**，等待规划请求完成。
2. 选择实现模型，并在智能体模式选择器中从 **Plan** 切换到 **交互**。
3. 要求智能体在同一对话中实现已批准计划。

　　模型选择指导请参阅[优化 AI 点数使用量](../../../tutorials-and-guides/2.6.14-ReduceCreditUsage/)。

　　对于可重复规划工作流，请定义带架构指南或必需规划交付物等指令的[自定义智能体](../../../customize-and-extend/2.4.5-CustomAgents/)。

## 在 Local 运行框架会话中规划 {#plan-in-a-local-harness-session}

　　Local 运行框架提供内置 Plan 智能体，其控件与 Copilot Plan 模式不同。从 **会话目标** UI 控件选择 **Local**，然后从智能体下拉列表选择 **Plan**，或输入 `/plan` 后跟任务。

　　默认情况下，此智能体研究项目而不编辑项目文件。创建计划后，使用以下操作：

| 目标 | 操作 |
|------|--------|
| 阅读完整计划 | 从命令面板（`Ctrl + Shift + P`，macOS：`Cmd + Shift + P`）运行 **Chat: Show Memory Files**，选择会话的 `plan.md`。计划存储在[会话记忆](../../sessions/2.2.11.2-Memory/)的 `/memories/session/plan.md`，不是项目文件。 |
| 在当前对话中实现 | 选择 **开始实现**。这会切换到 Agent 并立即提交实现请求。 |
| 交接给另一个目标 | 打开 **开始实现** 旁的下拉列表，选择可用的 **继续于** 目标。仅当有受支持目标时显示下拉列表。详细了解[使用不同运行框架继续](../../../choose-models-and-agents/2.3.2-ChooseAnAgentHarness/#continue-with-a-different-harness)。 |
| 保存可编辑副本 | 选择 **在编辑器中打开**。这会切换到 Agent 并要求它创建计划的无标题副本，可以保存到项目。与 **打开完整计划** 不同，它创建副本而不是打开现有计划文件。 |

> **警告**：在 Local 运行框架会话中，**使用 Autopilot 开始**（预览）以自动工具批准启动实现并自主继续。这包括文件编辑、终端命令和外部工具调用的批准。组织可以限制此选项。

### Local 规划设置 {#local-planning-settings}

这些选项适用于 Local 运行框架会话中的内置 Plan 智能体，不适用于 Copilot Plan 模式：

* **选择默认模型**：使用 `chat.planAgent.defaultModel` 进行规划。实验性 `github.copilot.chat.implementAgent.model` 设置选择 **开始实现** 在当前对话中使用的模型。
* **添加工具（实验性）**：使用 `github.copilot.chat.planAgent.additionalTools` 添加研究工具。额外工具可以扩展智能体超出默认只读项目访问的能力。
* **允许 Agent 切换到 Plan（实验性）**：启用 `github.copilot.chat.switchAgent.enabled` 后，Agent 可以选择切换到 Plan 进行研究或复杂任务。模型决定何时切换。希望显式启动专门工作流时，请使用 `/plan`。
