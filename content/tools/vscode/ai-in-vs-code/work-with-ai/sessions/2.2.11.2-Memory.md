# 2.2.11.2 记忆

　　记忆帮助智能体复用编码偏好和仓库知识，而无需在每个对话中重复。记忆系统取决于[智能体运行框架](../../../choose-models-and-agents/2.3.2-ChooseAnAgentHarness/)：

* **Copilot 运行框架**：使用 Copilot 记忆将仓库事实和用户偏好存储在云中。实验性本地存储选项则将仓库事实存储在工作树中。
* **Local 运行框架**：使用记忆文件保存持久笔记和临时会话上下文。

　　关于记忆如何融入智能体架构的背景知识，请参阅[智能体概念](../../../concepts/2.7.1-Agents/#memory)。

　　本文介绍如何设置云支持记忆、选择仓库本地存储、审查或删除存储信息以及管理 Local 运行框架记忆文件。

## Copilot 记忆 {#copilot-memory}

　　本地使用 Copilot 运行框架的会话可以使用 Copilot 记忆，它与 GitHub Copilot CLI、Copilot 云智能体和代码审查使用相同的云记忆服务。一个受支持功能捕获的记忆可以为另一个功能提供信息，但支持范围不同。例如，代码审查使用仓库事实，不使用用户偏好。

### 设置云支持记忆 {#set-up-cloud-backed-memory}

　　Copilot 记忆在 VS Code 中默认开启。使用步骤：

1. 使用 GitHub 账户[登录 GitHub Copilot](../../../getting-started/2.1.2-SetUpCopilot/)。
2. 在 [GitHub 上的个人 Copilot 设置](https://github.com/settings/copilot/features)中，检查 **Copilot 记忆** 是否为 **已启用**。如果套餐由组织或企业管理，其策略必须允许记忆。
3. 检查 VS Code 设置中的 `chat.copilot.memory.enabled` 是否开启。如果之前关闭，它会保持关闭直到你开启。
4. 在聊天视图或智能体窗口中创建或恢复本地 Copilot 会话。设置在更改后创建或恢复的会话中生效。

　　VS Code 编辑器预览功能策略不控制云记忆。

　　仓库记忆需要 GitHub 托管的仓库。用户偏好与登录的 GitHub 账户绑定，可以跨仓库应用。

　　如果设置开启但记忆不可用，请检查 GitHub 账户设置和组织策略。必需功能不可用或被锁定时，请联系管理员。关于账户资格和多个许可证时的默认计费实体要求，请参阅[管理个人账户的 Copilot 记忆](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/copilot-memory/manage-for-yourself)。

### 选择要记住的内容 {#choose-what-to-remember}

云支持记忆有两个作用域：

| 作用域 | 存储内容 | 适用范围 |
|---|---|---|
| **仓库** | 持久代码库事实和约定，由代码引用支持。 | 与有权访问仓库和 Copilot 记忆的人共享。仅用于该仓库。 |
| **用户** | 跨仓库适用的编码和工作流偏好。 | 用于你自己的受支持 Copilot 交互，不用于其他贡献者的交互。 |

　　存储仓库事实需要仓库写入权限，并为账户启用记忆。在组织或企业管理套餐中，管理员还可以审查和删除用户偏好。请参阅[管理组织或企业的 Copilot 记忆](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/copilot-memory/manage-as-administrator)。

> **警告**：不要在记忆中存储凭据、机密或敏感个人信息。仓库事实是共享的，不是私人笔记。将已审查的团队要求放在源代码管理项目文档或[自定义指令](../../../customize-and-extend/2.4.4-Instructions/)中。

### 存储、回忆和更正记忆 {#store-recall-and-correct-memories}

　　要求智能体记住持久约定或偏好。重要时请说明作用域：

```text
查找此仓库如何验证更改，并记住此仓库的命令。
```

```text
在我所有仓库中，记住我偏好简洁的提交消息主题。
```

　　会话开始时，智能体会回忆相关仓库事实和用户偏好。它使用 **存储记忆** 保存新信息。验证现有记忆时，它可以点赞而不是存储重复项。它可以点踩过时记忆并存储更正后的替代项。

　　如果记住的约定错误，请向智能体指出当前代码并要求更正记忆。持久记忆用于持久信息，不用于临时任务状态。

### 审查和删除云记忆 {#review-and-delete-cloud-memories}

在 GitHub 上审查存储信息：

* **用户偏好**：打开[个人记忆设置](https://github.com/settings/copilot/memory)查看和删除偏好。
* **仓库事实**：拥有仓库管理访问权限时，打开仓库 **Settings** > **Copilot** > **Memory**。删除仓库事实会对该仓库所有使用记忆的人移除它。

　　要求智能体忘记云记忆会点踩它，而不是永久删除。要永久删除，请使用上面的 GitHub 设置。下面的本地记忆文件命令不会删除云记忆。

　　未使用的事实和偏好会在 28 天后自动删除。成功验证和使用可以重置计时器。详细了解[记忆保留和验证](https://docs.github.com/en/copilot/concepts/prompting-and-context/copilot-memory#retention-and-validation)。

　　要在新创建或恢复的 VS Code 会话中停止使用云记忆，请关闭 `chat.copilot.memory.enabled`。GitHub 上的个人记忆设置控制其在受支持 Copilot 功能中的使用。要移除存储信息，请在 GitHub 上删除。

### 在仓库中存储 Copilot 记忆（实验性） {#store-copilot-memory-in-the-repository-experimental}

　　对于在计算机上运行的 Copilot 运行框架会话，可以将仓库记忆存储在 `.github/copilot-memories.jsonl` 中，而不是云记忆服务。此选项需要 GitHub 托管仓库，不支持用户作用域记忆。

1. 开启 `chat.copilot.memory.enabled`。
2. 开启 `chat.copilot.memory.local.enabled`。它默认关闭。更改它会在活动轮次结束后重启 Copilot 运行时。
3. 在仓库中创建或恢复 Copilot 运行框架会话。

　　此存储不同于 [Local 运行框架记忆文件](#local-memory-files)，不会复用这些文件。请直接管理仓库本地文件，而不是通过 GitHub 上的云记忆设置。

> **警告**：GitHub 上的云记忆设置和组织策略不适用于仓库本地存储。文件是工作树的一部分，可能包含在提交中，包括智能体或智能体窗口所做的提交。提交或共享前审查内容。不要存储凭据、机密或敏感个人信息。

## Local 记忆文件 {#local-memory-files}

　　Local 运行框架有单独基于文件的记忆工具，在智能体工作时保存和回忆笔记。也可以显式要求智能体记住某些内容。默认情况下，用户、仓库和会话记忆存储在本地计算机上。

　　以下部分描述本地记忆文件。如果仓库记忆由 GitHub 支持，请在 GitHub 上管理这些仓库事实，而不是使用本地文件管理命令。

### 记忆作用域 {#memory-scopes}

每个作用域用途不同，取决于信息应持续多久以及适用范围。

| 作用域 | 路径 | 跨会话持久 | 跨工作区持久 | 用途 |
|---|---|---|---|---|
| **用户** | `/memories/` | 是 | 是 | 偏好、模式、常用命令 |
| **仓库** | `/memories/repo/` | 是 | 否（工作区作用域） | 代码库约定、项目结构、构建命令 |
| **会话** | `/memories/session/` | 否（仅当前对话） | 否 | 任务特定上下文、进行中的计划 |

#### 记忆还是共享项目指导 {#memory-or-shared-project-guidance}

　　本节记忆文件存储在本地。用于个人偏好、临时任务上下文或团队尚未审查的新兴项目知识。仓库记忆文件与当前工作区关联，但不是共享项目文件。

　　将贡献者依赖的已审查架构决策、命令、约定和工作流放在源代码管理项目文档或[自定义指令](../../../customize-and-extend/2.4.4-Instructions/)中。这让指导可用于团队正常审查和维护流程。

当仓库记忆变得稳定且对团队有用时：

1. 对照仓库代码和配置验证信息。
2. 将其移到适当项目文档或指令文件。
3. 通过仓库正常流程审查更改。
4. 更新或删除本地记忆，避免过时或冲突副本。

　　创建、验证和共享项目指令的工作流请参阅[为代码库配置 AI](../../../tutorials-and-guides/2.6.10-AdaptAgentsToYourProject/)。

#### 用户记忆 {#user-memory}

　　本地用户记忆跨所有工作区和对话持久。每个会话开始时，前 200 行会自动加载到智能体上下文。用户记忆用于适用于任何项目的一般偏好和见解。

例如，要求智能体记住编码偏好：

```text
记住我偏好先给出简短摘要，再给出详细代码示例
```

　　在之后的对话中，即使在不同工作区，智能体也会回忆此偏好并应用到响应。

#### 仓库记忆 {#repository-memory}

　　仓库记忆作用于当前工作区，并在该工作区对话之间持久。用于特定代码库事实，例如架构决策、命名约定或构建命令。

例如：

```text
记住此工作区中的旧版 API 路由使用仓库模式进行数据访问
```

　　仓库记忆文件存储在本地计算机上。

#### 会话记忆 {#session-memory}

　　会话记忆仅在当前对话可用。用于临时工作笔记或智能体处理多步骤任务时跟踪的任务特定上下文。

　　Plan 智能体使用会话记忆将实现计划持久化到 `plan.md` 文件。计划在当前对话可用，可以使用 **Chat: Show Memory Files** 命令查看。详细了解[使用智能体规划](../../plan-and-run-tasks/2.2.10.1-PlanWork/)。

### 存储和检索记忆 {#store-and-retrieve-memories}

　　要存储记忆，请用自然语言要求智能体记住某些内容。智能体确定适当作用域并创建或更新相应记忆文件。

```text
记住我偏好简洁的提交消息主题
```

　　要检索记忆，请在新对话中询问。智能体会检查记忆文件并回忆相关信息。

```text
我们的提交消息约定是什么？
```

　　智能体聊天响应中的记忆文件引用可单击，因此可以直接查看记忆文件内容。

### 管理记忆文件 {#manage-memory-files}

　　VS Code 提供命令在 Local 运行框架会话中查看和管理本地记忆文件：

* **Chat: Show Memory Files**：打开所有作用域的记忆文件列表。选择文件查看内容。
* **Chat: Clear All Memory Files**：移除所有作用域的所有记忆文件。

> **注意**：要更新或删除单个记忆文件，请要求智能体。使用 **Chat: Clear All Memory Files** 移除所有记忆文件。
