# 2.6.9 让智能体回到正轨

　　AI 智能体可能误解目标、重复不成功的操作、更改超出预期的文件或忘记先前决策。一旦发现不匹配就立即干预。早期纠正可以保留有用工作，并减少需要审查或撤销的更改。

　　本指南帮助你选择干扰最小的恢复操作。你将学习如何重定向正在运行的请求、纠正已完成工作、恢复不需要的更改、重置对话上下文并诊断重复失败。

## 选择恢复操作 {#choose-a-recovery-action}

从观察到的症状开始：

| 症状 | 恢复操作 |
|---|---|
| 智能体似乎空闲或受阻 | [检查当前状态](#assess-the-current-state)，查看待回答问题、审批请求或正在运行的终端命令。 |
| 智能体仍在运行，当前方法安全但不正确 | 使用有针对性的更正[引导请求](#redirect-a-running-request)。 |
| 智能体即将执行不安全、破坏性或无关操作 | 立即[停止请求](#redirect-a-running-request)并说明不得做什么。 |
| 响应完成，大部分工作有用 | [发送聚焦的后续消息](#correct-a-completed-response)，指出具体不匹配。 |
| 含糊的早期提示词导致错误方法 | [编辑早期请求](#correct-a-completed-response)并重新发送。 |
| 只有特定待处理文件编辑不需要 | [撤销这些编辑](#recover-unwanted-changes)，不回退对话。 |
| 已知点之后的文件更改不需要 | [恢复检查点](#recover-unwanted-changes)。 |
| 希望比较另一种方法而不丢失当前对话 | [分叉对话](#reset-conversation-context)。 |
| 对话包含过多无关或冲突上下文 | [压缩上下文或开始新聊天](#reset-conversation-context)。 |
| 智能体遵循指令但反复遇到同一错误 | 在重试前[诊断失败](#diagnose-repeated-failures)。 |

> **警告**：如果智能体即将运行破坏性命令、部署更改、暴露敏感信息或修改外部服务，请先停止请求再调查。

## 评估当前状态 {#assess-the-current-state}

要求智能体继续之前，确定发生了什么以及要保留什么：

1. 检查智能体是否在等待回答或批准，或正在跟踪仍在运行的终端命令。
2. 找到智能体工作偏离意图的最早点。
3. 审查已更改文件、最近的工具调用、终端输出和错误消息。
4. 将正确工作与需要修订或移除的更改分开。
5. 检查已完成操作是仅影响工作区文件，还是也影响终端、网络、部署或外部服务。
6. 写下智能体遗漏的预期结果、约束和验证。

　　在更正中使用这些事实。避免“再试一次”或“修好它”等提示词，它们没有告诉智能体需要更改什么。

## 重定向正在运行的请求 {#redirect-a-running-request}

请求运行期间，在聊天输入框中输入更正。输入消息后 **发送** 按钮菜单可用。打开菜单，选择新消息应如何影响当前请求：

* 当当前操作安全但智能体需要不同方法时，选择 **通过消息引导**。智能体会完成当前工具调用、停止当前响应并处理更正。
* 当智能体不应继续当前请求时，选择 **停止并发送**。VS Code 取消请求并立即发送新消息。

例如，在智能体进行更多编辑前引导它：

```text
不要更改数据库架构或添加依赖。当前工具调用后停止编辑。
解释现有 API 测试失败的原因，然后提出仅限 src/api 的修复。更改文件前等待我的批准。
```

　　如果操作存在直接风险，请停止并让智能体报告当前状态：

```text
停止。不要运行部署命令或修改外部服务。总结已经完成的命令和工具调用，
列出其影响，并等待进一步指示。
```

　　引导或停止请求不会撤销已完成操作。审查当前更改，如果需要回退工作区文件，请[恢复检查点](#recover-unwanted-changes)。

　　详细了解[在请求运行期间发送消息](../../work-with-ai/2.2.5-UseChat/#send-messages-while-a-request-is-running)。

## 纠正已完成的响应 {#correct-a-completed-response}

响应完成后，选择保留多少对话和工作。

### 发送聚焦的后续消息 {#send-a-focused-follow-up}

　　整体方法正确时保留当前工作。描述观察到的不匹配、预期结果、更正边界以及如何验证：

```text
新测试通过，但现有分页测试现在失败，因为响应结构改变了。
保持公共 API 不变。只更新分页计算，运行完整 API 测试套件，并报告测试结果。
```

　　如果智能体重复同一不成功操作，请在下一次尝试前要求分析：

```text
不要重新运行未更改的命令。总结第一个错误，确定该错误否定了哪个假设，
并提出两个不同的恢复选项。在我选择之前不要编辑文件或运行命令。
```

### 编辑早期请求 {#edit-an-earlier-request}

　　如果早期请求的措辞引入了错误需求或遗漏重要约束，请编辑该请求。编辑并重新发送请求时，VS Code 会还原该请求及所有后续请求的工作区文件更改，然后处理修订后的提示词。

　　编辑请求之前，审查受影响更改，了解将移除哪些工作。在对话中选择提示词，修改文本并重新发送。详细了解[编辑之前的聊天请求](../../work-with-ai/2.2.8-ReviewAndRevertChanges/#edit-a-previous-chat-request)。

## 恢复不需要的更改 {#recover-unwanted-changes}

要还原特定待处理编辑而不更改对话，请使用编辑器审查控件或工作集中的 **撤销**。Copilot 运行框架会话在编辑器窗口中支持此工作流，即使没有 Git。工作集只包含通过受跟踪编辑工具所做的编辑，不包括终端命令。如果可用，请使用源代码管理，或自行编辑文件以还原工作集之外的更改。Local 运行框架会话也支持撤销待处理编辑。请参阅[按运行框架和界面划分的审查控件](../../work-with-ai/2.2.8-ReviewAndRevertChanges/#choose-your-review-approach)。

　　当能确定智能体工作区更改出错前的最后一个请求时，请使用检查点。恢复检查点会将受影响工作区文件和聊天历史返回到该点。

　　在受支持聊天会话中，检查点默认启用，并在处理每个请求前自动创建。在智能体进行更改前发送请求即可建立检查点，无需手动创建。

恢复之前：

1. 审查计划移除的请求对应的已更改文件。
2. 检查工作区之外已完成的动作。
3. 记录修订请求所需的错误输出或决策。

　　恢复后，用遗漏的约束和预期验证重新陈述任务。

> **重要**：检查点不会撤销终端命令、网络请求、部署或对外部服务的更改。请使用 Git 或外部系统的恢复控制来撤销这些影响。检查点是临时的，不能替代 Git 版本控制。

　　完整过程和范围请参阅[恢复检查点](../../work-with-ai/2.2.8-ReviewAndRevertChanges/#restore-a-checkpoint)。

## 重置对话上下文 {#reset-conversation-context}

　　恢复有时需要更改对话而不是代码。选择与仍需保留的上下文量匹配的选项。

### 压缩当前对话 {#compact-the-current-conversation}

　　当想继续同一任务，但对话包含旧探索、重复输出或不再重要的细节时，使用 `/compact`。告诉智能体要保留哪些事实：

```text
/compact 保留已批准的 API 契约、分页失败的根本原因、目前已更改的文件以及所需测试命令。
丢弃已被取代的方法和重复命令输出。
```

　　压缩会总结早期历史，不会更改工作区文件。详细了解[压缩对话上下文](../../work-with-ai/sessions/2.2.11.1-ManageSessions/#compact-conversation-context)。

### 分叉对话 {#fork-the-conversation}

　　当希望探索不同方法并保留原始对话时，从检查点分叉。可以比较结果，如果替代方案没有用，可以返回原始会话。

　　分叉会创建单独对话历史，但并不总是提供单独文件。根据会话类型，分叉可能共享同一文件夹或 Git 工作树。当两种方法必须独立修改文件时，请使用单独的工作树隔离会话。详细了解[分叉聊天会话](../../work-with-ai/sessions/2.2.11.1-ManageSessions/#fork-a-chat-session)。

### 在会话中开始新聊天 {#start-a-new-chat-in-the-session}

　　如果工作仍属于同一工作区，但对话包含冲突指令或反复更正，请在支持时[在会话中开始另一个聊天](../../work-with-ai/sessions/2.2.11.1-ManageSessions/#run-multiple-chats-in-a-session)。新聊天不会继承其他聊天的历史。保持会话文件夹或工作树选中，以继续使用相同文件和代码更改。

　　在新提示词中提供已接受决策、当前状态和验证标准。开始聊天不会移除已保存文件、适用的自定义指令或持久记忆。如果运行框架不支持会话中的多个聊天，请开始新会话。

### 开始新会话 {#start-a-new-session}

在以下情况开始新会话：

* 目标已变为不同任务。
* 工作属于另一个项目。
* 需要单独文件夹或工作树来保持代码更改独立。

　　开始新会话不会撤销文件更改。请先审查或恢复工作区，然后提供简洁提示词，包含当前状态、已接受决策、约束和验证标准。

## 诊断重复失败 {#diagnose-repeated-failures}

　　如果智能体理解任务但无法取得进展，请停止自动重试并调查底层失败。

1. 要求智能体报告失败的确切命令或工具、第一个错误以及用于诊断错误的证据。
2. 验证工作目录、已安装依赖项、所需服务、身份验证和权限等前提条件。
3. 要求不重复失败操作的恢复选项。
4. 如果会话启用了调试日志，在需要理解被忽略指令、意外工具行为或慢响应时，使用 `/troubleshoot` 分析捕获的日志。
5. 要更深入检查，请使用智能体调试日志面板（预览）审查模型请求、工具调用、提示词文件发现和错误。

　　对于连接、扩展、自定义和 MCP 服务器问题，请遵循 [AI 故障排除过程](../../reference-and-help/troubleshooting/2.8.2.1-Troubleshooting/)。要检查智能体交互，请参阅[调试聊天交互](../../reference-and-help/troubleshooting/2.8.2.2-DebugChatInteractions/)。

## 防止智能体偏离 {#prevent-the-agent-from-drifting}

通过让预期结果可观察，减少恢复需求：

* 定义任务边界、约束以及不得更改的文件或系统。
* 包含验收标准、预期输出或测试命令。
* 任务跨越多个组件或风险较高时，在实现前要求计划。
* 大型更改前，用 Git 提交已知良好起点。
* 对于不熟悉的仓库、工具和工作流，保持 **手动审批** 选中。
* 审查第一个有意义的结果，而不是等到整个任务完成。
* 切换到无关任务时开始新会话。
