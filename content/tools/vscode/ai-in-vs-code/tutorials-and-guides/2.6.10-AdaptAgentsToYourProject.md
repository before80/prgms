# 2.6.10 为项目适配智能体

　　当 AI 智能体理解代码库结构、应运行哪些命令以及遵循哪些约定时，可以产生更好的结果。请将这些信息一次性配置为仓库自定义项，而不是在每个提示词中重复。

　　本指南帮助你在 VS Code 中配置 Copilot、Anthropic Claude 或 OpenAI Codex 运行框架。从一个观察到的项目问题和代表性任务开始。进行最小的有用自定义，确认其生效，重复任务并在共享配置前比较结果。工作流共用，并按运行框架提供特定格式和行为。

　　要了解自定义类型如何区分和协同工作，请参阅[智能体自定义](../../concepts/2.7.7-AgentCustomization/)。

　　对于现成工作流和集成，在自行编写之前请[浏览自定义 Marketplace](../../customize-and-extend/2.4.1-Overview/#discover-and-install-existing-customizations-preview)。可以复用现有技能或插件，同时仍按照本指南添加仓库特定指令。

## 前提条件 {#prerequisites}

> **注意**：当 [GitHub Copilot 企业托管设置生效](../../../enterprise/7.2-ManageAISettings/#claude-and-codex-availability)时，Claude 和 Codex 运行框架会被禁用。请联系部署设置的 IT 团队讨论访问权限。

* [下载并安装 VS Code](https://code.visualstudio.com/download)。
* 完成[运行框架的设置和身份验证](../../choose-models-and-agents/2.3.2-ChooseAnAgentHarness/#requirements-and-setup)。
* 打开要配置的仓库根目录。
* [启动会话](../../choose-models-and-agents/2.3.2-ChooseAnAgentHarness/#select-a-harness)，从 **会话目标** 控件选择 **Copilot**、**Claude** 或 **Codex**。创建和测试自定义项时使用同一运行框架。

　　本演练在当前文件夹中工作。如果使用智能体窗口，请不要选择 **新工作树**，以便新会话可以访问未提交的自定义文件。

　　选择**运行框架**对应的部分，而不是语言模型。例如，Copilot 会话中的 Claude 模型仍使用 Copilot 运行框架。

> **注意**：**Local** 运行框架也支持本指南中的 Copilot 文件布局，但工具名称和某些激活行为不同。Local 运行框架特定配置请参阅[自定义指令](../../customize-and-extend/2.4.4-Instructions/)、[智能体技能](../../customize-and-extend/2.4.3-AgentSkills/)和[自定义智能体](../../customize-and-extend/2.4.5-CustomAgents/)。

## 建立基线 {#establish-a-baseline}

　　选择一个反复出现的项目特定问题，例如使用错误测试命令、将文件放在错误目录或选择项目未使用的库。一次性需求应放在当前请求中，而不是共享项目配置。

　　定义一个具有明确成功标准的小型代表性任务。记录当前结果或使用最近任务的证据：

* 智能体创建或更改哪些文件。
* 它遵循哪些项目模式和库。
* 它运行哪些命令和测试，包括失败或跳过检查。
* 你必须提供哪些更正。

　　如果结果已满足成功标准，请停止。该行为不需要自定义项。对于编码任务，请参阅[添加功能指南](../2.6.3-AddAFeature/)了解建立基线测试和验证结果的指导。

## 第 1 步：创建项目指令 {#step-1-create-project-instructions}

　　从适用于整个代码库的项目指令文件开始。将初始更改聚焦于观察到的问题以及智能体无法从仓库可靠推断的决策。每个运行框架有自己的发现规则，因此请使用其预期文件名和位置。

在下面提示词中，将 `<observed problem>` 替换为要改善的行为。例如，描述智能体将 HTTP 处理程序放在 `src/api/routes` 之外，或使用仓库中无效的测试命令。

1. 为所选运行框架打开[智能体自定义编辑器](../../customize-and-extend/2.4.1-Overview/#agent-customizations-editor)。在聊天视图中从命令面板（`Ctrl + Shift + P`）运行 **Chat: Open Customizations**。
2. 在 **概述** 部分输入对应运行框架的提示词，按 `Enter` 提交。
3. 在打开的聊天中继续。确认它使用目标运行框架和仓库，并回答澄清问题。
4. 审查更改，并将指令保存在预期位置。如果文件已存在，请审查更新，而不是未经检查就替换现有指导。

**Copilot**

　　仓库根目录使用 `.github/copilot-instructions.md` 作为项目范围指令。

```text
Create or update .github/copilot-instructions.md to address this repeated problem: <observed problem>. Inspect relevant code and commands, then add only the project-specific guidance needed to avoid the problem. Preserve useful existing guidance, avoid duplication, and ask about anything you cannot verify. Do not change application code.
```

**Claude**

　　仓库根目录使用 `CLAUDE.md` 作为项目范围指令。

```text
Create or update CLAUDE.md at the repository root to address this repeated problem: <observed problem>. Inspect relevant code and commands, then add only the project-specific guidance needed to avoid the problem. Preserve useful existing guidance, avoid duplication, and ask about anything you cannot verify. Do not change application code.
```

**Codex**

　　仓库根目录使用 `AGENTS.md` 作为项目范围指令。

```text
Create or update AGENTS.md at the repository root to address this repeated problem: <observed problem>. Inspect relevant code and commands, then add only the project-specific guidance needed to avoid the problem. Preserve useful existing guidance, avoid duplication, and ask about anything you cannot verify. Do not change application code.
```

> **提示**：项目指令在记录智能体无法仅从代码可靠推断的决策时最有用。避免适用于任何项目的通用建议。

## 第 2 步：审查生成的指令 {#step-2-review-the-generated-instructions}

　　将生成的指令视为起点。检查与观察到问题相关的类别，而不是把每个类别都加入文件：

* **观察到的问题**：只包含改善基线行为所需的指导。
* **架构**：描述重要目录、组件边界以及在哪里添加不同类型代码。
* **命令**：包含正确的构建、测试、lint 和格式化命令。
* **技术选择**：确定首选框架、库和模式。
* **约定**：记录命名、错误处理、测试、安全和文档要求。
* **完成定义**：说明智能体完成任务前应运行哪些验证。

　　删除通用、过时或重复的信息。解决冲突指令并保持每条规则简洁。

例如，项目特定指令可以包含：

```markdown
## Project structure

* Add API routes under `src/api/routes`.
* Put shared validation schemas in `src/schemas`.
* Keep database access in the repository layer.

## Validation

* Run the unit tests for the changed package.
* Run the linter before completing a code change.
* Add or update tests for every behavior change.
```

　　详细了解如何编写有效的[自定义指令](../../customize-and-extend/2.4.4-Instructions/)。

## 第 3 步：验证改进 {#step-3-verify-the-improvement}

　　确认指令已应用，然后重复基线中的代表性任务。尽量保持运行框架、模型、工具、任务和相关上下文不变，使自定义项成为主要变化。

1. 在智能体自定义编辑器中为运行框架选择 **指令**，确认项目指令文件已列出。这检查发现，而不是智能体是否遵循每条指令。
2. 使用相同运行框架和仓库启动新聊天，使比较不依赖创建对话中的指导。
3. 使用相同成功标准重复代表性任务，不要重复提示词中已保存的指令。
4. 检查响应中的 **引用**（如果可用）是否包含预期指令。如果包含不明确，请[检查请求或指令加载活动](../../reference-and-help/troubleshooting/2.8.2.2-DebugChatInteractions/#instructions-or-a-prompt-file-are-not-applied)。
5. 将结果与基线比较。审查文件位置、项目模式、库、工具活动、命令、测试和错误，而不是依赖智能体总结。

对于 API 任务，记录以下标准的结果：

| 标准 | 基线观察 | 添加指令后的成功结果 |
|-----------|----------------------|---------------------------------------------|
| 处理程序位置 | 智能体创建新的顶级路由目录。 | 处理程序使用现有 `src/api/routes` 目录。 |
| 数据访问 | 处理程序包含数据库查询。 | 处理程序使用现有仓库层。 |
| 验证 | 智能体跳过测试或运行错误命令。 | 工具活动显示相关测试及其结果。 |

　　这些是示例标准，不是保证的模型输出。请使用相同模型和可用工具，比较相同起始代码的等价任务。

　　如果文件缺失、无效或已包含但未遵循，请使用[智能体自定义故障排除指南](../../reference-and-help/troubleshooting/2.8.2.1-Troubleshooting/)在添加更多指令前确定失败。

　　如果指令已包含但结果仍未达到成功标准，请澄清一条相关规则，并在另一个新聊天中重复任务。任务达到标准后停止。更多指令会消耗上下文，并可能引入冲突而不改善结果。

　　对于包含质量、可靠性、点数、令牌、时长和工具调用的更广泛受控比较，请使用[使用优化循环](../2.6.14-ReduceCreditUsage/#inspect-token-usage-and-caching)。

## 第 4 步：共享配置 {#step-4-share-the-configuration}

　　提交项目指令文件，并通过仓库正常拉取请求或审查流程共享。获得更新文件并使用兼容运行框架的贡献者可以复用指导，无需重新创建。

　　像其他开发配置一样审查指令。使用现有所有权和审查流程明确文件责任。当架构、命令、依赖项或团队实践变化时更新它，并删除过时或重复规则。

　　如果团队使用多个运行框架，请保持共享指导一致，避免矛盾副本。一个运行框架支持的文件不会自动被所有其他运行框架支持。

　　如果代表性任务现在满足成功标准，请停止。仓库已有有用的基线自定义项。其余步骤是可选的。当代码库不同部分需要不同指导，或团队反复执行相同工作流时，再添加它们。

## 第 5 步：添加有针对性的指令（可选） {#step-5-add-targeted-instructions-optional}

　　当代码库不同部分需要不同指导时，添加针对性指令。例如，前端代码和基础设施代码可能遵循不同约定。将项目范围标准保留在第 1 步的指令文件中。

在智能体自定义编辑器的 **概述** 部分，提交为运行框架创建文件的请求。描述应覆盖的约定，并使用仓库中现有文件类型或目录。

**Copilot**

　　创建 `.github/instructions/frontend.instructions.md`。对于 TypeScript React 文件，在 Markdown 指令前包含以下 YAML frontmatter：

```yaml
---
applyTo: "**/*.tsx"
---
```

　　该模式匹配仓库中的所有 `.tsx` 文件。审查模式，并要求智能体对特定匹配文件做小更改以测试指令。详细了解[有针对性的指令](../../customize-and-extend/2.4.4-Instructions/#apply-instructions-to-specific-files-or-tasks)和[模式语法](../../reference-and-help/reference/2.8.1.6-CustomInstructionsReference/#file-patterns)。

**Claude**

　　创建 `.claude/rules/frontend.md`。Claude 使用 `paths` 而不是 `applyTo` 定义路径范围规则：

```yaml
---
paths:
  - "**/*.tsx"
---
```

　　审查模式，并要求智能体对特定匹配文件做小更改以测试规则。没有 `paths` 时，规则文件普遍适用，而不是只适用于匹配文件。详细了解 [Claude 路径特定规则](https://code.claude.com/docs/en/memory#path-specific-rules)。

**Codex**

　　在需要自己指导的目录中使用 `AGENTS.md`，例如 `packages/frontend/AGENTS.md`。Codex 从仓库根目录向下发现到会话工作目录的指令。这是基于目录的指导，不是 `applyTo` 或 `paths` glob。

　　要测试嵌套指令，请以该子目录作为工作文件夹启动新的 Codex 运行框架会话。在编辑器中打开文件不会更改会话工作目录。详细了解 [Codex 指令发现](https://developers.openai.com/codex/guides/agents-md)。

　　审查并保存生成的文件，然后在相同运行框架的新聊天中测试。确认结果遵循针对性约定。如果没有，请在修订指令前检查发现和作用域。

　　如果为测试嵌套指令更改了会话工作文件夹，请在继续前返回仓库根目录。

## 第 6 步：打包重复工作流（可选） {#step-6-package-a-recurring-workflow-optional}

　　当团队反复解释同一多步骤过程时，创建智能体技能。技能可以包含指令、脚本、模板、示例和其他资源，智能体在相关时加载。

例如，创建 `validate-change` 技能，为代码更改选择并运行相关检查，然后报告通过、失败或未运行的内容。在智能体自定义编辑器的 **概述** 部分提交对应运行框架的提示词。

**Copilot**

```text
Create a workspace skill named validate-change at .github/skills/validate-change/SKILL.md. It should inspect a code change, choose and run the relevant tests and lint checks using this repository's commands, and report what passed, failed, or was not run. Describe when to use it in its frontmatter.
```

**Claude**

```text
Create a workspace skill named validate-change at .claude/skills/validate-change/SKILL.md. It should inspect a code change, choose and run the relevant tests and lint checks using this repository's commands, and report what passed, failed, or was not run. Describe when to use it in its frontmatter.
```

**Codex**

```text
Create a workspace skill named validate-change at .agents/skills/validate-change/SKILL.md. It should inspect a code change, choose and run the relevant tests and lint checks using this repository's commands, and report what passed, failed, or was not run. Describe when to use it in its frontmatter.
```

生成技能后：

1. 审查 `SKILL.md`。检查其 `name` 与目录名一致，`description` 说明作用和适用时机。
2. 审查技能目录中的脚本、模板或其他资源，并保存更改。
3. 使用相同运行框架和仓库启动新聊天。在聊天输入框中输入 `/`，选择 **validate-change** 显式调用技能。指定要验证的代码更改。
4. 审查工具活动和结果。确认智能体加载技能、选择适当检查，并准确报告失败或跳过检查。

　　也可以在单独聊天中通过要求智能体验证更改而不命名技能来测试自动选择。如果未选择，请审查描述和调用设置。显式调用和模型选择是分开的检查。

　　详细了解[智能体技能](../../customize-and-extend/2.4.3-AgentSkills/)。

## 第 7 步：添加专用智能体（可选） {#step-7-add-a-specialized-agent-optional}

　　当角色需要聚焦指令时，创建自定义智能体。例如，代码库研究员可以调查实现细节，并在你决定更改前报告发现。工具限制取决于运行框架，因此不要假设仅角色描述就能阻止编辑。

在智能体自定义编辑器的 **概述** 部分提交对应运行框架的提示词。

**Copilot**

```text
Create a workspace custom agent named researcher at .github/agents/researcher.agent.md. It should trace how features work and report findings with file locations, without changing the repository. Configure its tools to use only the Copilot harness's file-reading and code-search tools. Exclude tools that can edit files, run shell commands, or delegate to other agents.
```

　　审查生成文件中的 `tools` 允许列表。确认它只包含预期的读取和搜索工具，而不是不受限制的工具访问。

**Claude**

```text
Create a workspace custom agent named researcher at .claude/agents/researcher.md. It should trace how features work and report findings with file locations, without changing the repository. Restrict its tools to Read, Grep, and Glob.
```

　　审查生成智能体的 `tools` frontmatter，确认它只允许读取和搜索工具。详细了解 [Claude 自定义智能体和工具访问](https://code.claude.com/docs/en/sub-agents#available-tools)。

**Codex**

```text
Create a workspace custom agent named researcher at .github/agents/researcher.agent.md for Codex in Visual Studio Code. It should trace how features work and report findings with file locations. Instruct it not to edit files or run commands that change the repository.
```

　　VS Code 中的 Codex 集成会从该文件加载角色指令，但不会将 `tools` frontmatter 用作工具允许列表。将“不编辑”指令视为指导而非强制执行。使用智能体前请审查 [Codex 权限](../../choose-models-and-agents/2.3.2-ChooseAnAgentHarness/#codex)。

生成智能体后：

1. 审查并保存文件。检查指令定义清晰角色，并且不与项目指导冲突。
2. 使用相同运行框架和仓库启动新聊天，从智能体下拉列表选择 **researcher**。
3. 要求它研究功能工作方式。检查它识别相关文件、用证据支持发现并遵循配置角色。
4. 审查任何更改和工具活动，不要假设智能体名称或指令使其只读。

　　完整测试过程和角色完善指导请参阅[验证自定义智能体](../../customize-and-extend/2.4.5-CustomAgents/#verify-your-custom-agent)。

## 你配置了什么 {#what-you-configured}

　　如果完成可选步骤，仓库可以包含所选运行框架的以下文件。前端目录是示例，请使用仓库结构。

**Copilot**

```text
your-project/
  .github/
    copilot-instructions.md
    instructions/
      frontend.instructions.md
    skills/
      validate-change/
        SKILL.md
    agents/
      researcher.agent.md
```

**Claude**

```text
your-project/
  CLAUDE.md
  .claude/
    rules/
      frontend.md
    skills/
      validate-change/
        SKILL.md
    agents/
      researcher.md
```

**Codex**

```text
your-project/
  AGENTS.md
  packages/
    frontend/
      AGENTS.md
  .agents/
    skills/
      validate-change/
        SKILL.md
  .github/
    agents/
      researcher.agent.md
```

　　项目指令提供基线。有针对性的指令将指导聚焦到代码库的一部分。技能打包重复工作流，自定义智能体定义具有运行框架特定能力的专门角色。随着仓库需求增长，可以独立采用每一层。

　　通过与项目指令相同的流程审查和共享任何可选自定义文件。包含技能的支持资源，以便其他贡献者使用。
