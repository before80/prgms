# 2.6.1 查找指南

　　选择一个教程，通过示例项目学习；或者按照指南，将智能体工作流应用到自己的代码库。

　　仍在选择如何使用 AI？请先[比较内联建议、代码旁协作和智能体编排](../../#choose-how-you-work)，再选择指南。使用 AI 并不一定需要委派任务。

## 选择起点 {#choose-where-to-start}

　　如果你同时不熟悉 VS Code 和 AI，请先[安装编辑器并打开工作区](../../../get-started/)。否则，选择一个示例项目学习，或将智能体工作流应用到自己的仓库：

* [**完成第一个智能体任务**](../../getting-started/2.1.3-AgentsQuickstart/)：推荐起点。构建并验证一个小型 Web 应用，然后审查更改。示例项目，不需要运行时或构建工具。

* [**从智能体窗口开始，在编辑器中继续**](../../getting-started/2.1.4-AgentsTutorial/)：构建作品集页面，然后在代码旁继续同一会话，以完善、测试和审查。示例项目，需要 Git。

* [**在自己的仓库中工作**](#experienced-agent-fast-track)：已经使用智能体？按照快速路径探索代码库或添加功能。使用自己的仓库，并检查所选指南的要求。

　　要在开发计算机之外工作，可以[在云会话中启动任务，然后使用 Copilot CLI 从终端继续](../../getting-started/2.1.5-CloudContinuityTutorial/)。无需克隆仓库或安装项目依赖项，但需要云会话访问权限和 Copilot CLI。

或者直接跳到某个任务：

* [处理项目](#work-on-a-project)。
* [测试和验证](#test-and-validate)。
* [自定义和协调智能体](#customize-and-coordinate-agents)。
* [改善结果和恢复](#improve-results-and-recover)。

## 有经验的智能体用户快速路径 {#experienced-agent-fast-track}

　　使用自己的仓库，并遵循所选指南指定的运行框架、界面和前提条件。第一个任务请保留其推荐的会话设置。指南中的工具名称或自定义文件在其他运行框架中使用前可能需要更改。

　　如果要使用现有设置，请比较[智能体运行框架和支持的账户](../../choose-models-and-agents/2.3.2-ChooseAnAgentHarness/#requirements-and-setup)，或[使用自己的 API 密钥连接模型](../../choose-models-and-agents/2.3.1-ChooseAndConfigureModels/#bring-your-own-language-model-key)。使用所选指南的要求检查兼容性。

1. [将仓库作为工作区打开](../../../get-started/#open-your-code)，使文件、源代码管理、终端、测试和智能体共享同一项目上下文。

2. 将现有工作流映射到 [VS Code 会话](../../concepts/2.7.5-SessionsAndChats/)。检查账户和环境是否满足所选指南的[运行框架设置要求](../../choose-models-and-agents/2.3.2-ChooseAnAgentHarness/#requirements-and-setup)。

3. 在自己仓库中从一个有界任务开始：在不做更改的情况下[探索代码库](../2.6.2-ExploreACodebase/)，或者使用现有开发环境和测试[添加功能](../2.6.3-AddAFeature/)。

4. 整合之前[审查和验证代码编辑](../../work-with-ai/2.2.8-ReviewAndRevertChanges/)。

　　完成一个真实项目任务后，请[调整智能体以适应项目](../2.6.10-AdaptAgentsToYourProject/)，并[比较质量、可靠性和 AI 点数使用情况](../2.6.14-ReduceCreditUsage/)。如果会在受支持的应用程序之间切换，请了解如何[查看其他应用程序的会话](../../work-with-ai/sessions/2.2.11.1-ManageSessions/#view-sessions-from-other-applications)。

　　在受管理的设备上，组织可能控制可用的智能体和提供商。开发者可以查看[智能体可用性故障排除步骤](../../reference-and-help/troubleshooting/2.8.2.4-FAQ/#agents-are-not-available-in-chat)，管理员可以[管理 AI 设置](../../../enterprise/7.2-ManageAISettings/)。对于键盘、屏幕阅读器和低视力工作流，请使用[可访问视图和其他辅助功能](../../../editor/3.3-ConfigureTheEditor/3.3.9-Accessibility/3.3.9.1-Accessibility/#accessible-view)。

## 按设置匹配指南 {#match-a-guide-to-your-setup}

开始指南之前，请检查：

* **项目**：它创建示例项目，还是要求你自己的仓库具有可用的构建和测试命令？

* **运行框架**：它是否使用你所选运行框架的工具和自定义格式？选择相同的语言模型并不意味着这些格式可以互换。

* **界面**：哪些步骤使用聊天视图或智能体窗口？

　　两种界面都可以运行智能体。聊天视图强调在当前工作区中围绕代码协作；智能体窗口强调多项目编排和更高层级的任务分配。请按照指南为演练选择的界面操作。要比较不同方式，请参阅[选择你的工作方式](../../#choose-how-you-work)。

## 处理项目 {#work-on-a-project}

* [探索代码库](../2.6.2-ExploreACodebase/)：在不编辑文件的情况下跟踪一个行为，并对照源引用验证解释。**使用自己的仓库，在聊天视图中使用 GitHub Copilot。**

* [添加功能](../2.6.3-AddAFeature/)：研究、规划、实现并验证一个有界更改。**使用自己的仓库和可用的开发环境与测试，在聊天视图中使用 GitHub Copilot。**

* [修复 API 错误](../2.6.4-FixABug/)：重现分页错误、添加回归测试并审查修复。**示例项目，需要 Node.js 22 或更高版本以及 Git。**

* [安全重构](../2.6.5-RefactorSafely/)：以可审查的步骤更改代码结构，同时保留行为并检查现有调用方。**使用自己的仓库，在聊天视图中使用 GitHub Copilot。**

* [使用 Jupyter 笔记本](../2.6.13-JupyterNotebooks/)：创建或编辑笔记本、运行单元格并审查分析结果。**使用自己的数据，需要 Jupyter 扩展和笔记本内核。**

## 测试和验证 {#test-and-validate}

* [为现有代码添加测试](../2.6.6-AddTests/)：为函数或模块生成测试、运行并审查断言、失败和覆盖率。**使用自己的项目，在聊天视图中使用 GitHub Copilot。**

* [使用浏览器工具验证 Web 应用](../2.6.7-TestWebApps/)：构建计算器应用，并按照可观察的验收标准检查。**示例 Web 应用。**

* [设置测试驱动开发](../2.6.12-TestDrivenDevelopment/)：为可重复的测试优先工作流创建自定义智能体和指令。**使用自己的仓库和可用的测试，并在聊天视图中使用 Local 运行框架。**

## 自定义和协调智能体 {#customize-and-coordinate-agents}

* [调整智能体以适应项目](../2.6.10-AdaptAgentsToYourProject/)：与团队共享项目指令，然后按需添加技能或专用智能体。**使用自己的仓库。**

* [设置上下文工程工作流](../2.6.11-ContextEngineering/)：通过指令、自定义智能体和提示词文件整理项目上下文，并将规划与实现连接起来。**使用自己的仓库，并在聊天视图中使用 Local 运行框架。**

* [并行运行独立任务](../2.6.8-RunParallelTasks/)：在单独的 Git 工作树中工作，分别审查每个结果，然后整合并重新测试。**使用自己的 Git 仓库，在完成单个智能体任务后，在智能体窗口中使用 GitHub Copilot。**

## 改善结果和恢复 {#improve-results-and-recover}

* [让智能体回到正轨](../2.6.9-GetBackOnTrack/)：选择引导请求、恢复意外更改或重置对话上下文。

* [减少 AI 点数使用量](../2.6.14-ReduceCreditUsage/)：比较模型成本和结果、聚焦上下文并限定工具范围，以减少不必要的使用。

* [查找提示词示例](../2.6.15-PromptExamples/)：调整用于探索代码、构建功能、调试和测试的提示词。
