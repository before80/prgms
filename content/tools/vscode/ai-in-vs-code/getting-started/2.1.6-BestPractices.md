# 2.1.6 最佳实践

　　本文介绍在 Visual Studio Code 中使用 AI 的良好实践。从一个限定任务开始，提供相关上下文并验证结果。等出现重复需求时，再配置自定义指令、智能体或工具。

## 为任务选择正确的工具 {#pick-the-right-tool-for-the-task}

　　VS Code 中的 AI 提供多种交互模式。为当前任务选择合适的模式可以节省时间并产生更好的结果。

| 工具 | 最适合 | 示例 |
|------|----------|---------|
| [内联建议](../../../editor/3.2-WriteCode/3.2.3-InlineSuggestions/) | 在编写代码时保持心流 | 内联建议、变量名、样板代码 |
| [内联聊天](../../work-with-ai/2.2.4-InlineChatAndQuickChat/) | 不切换上下文的情况下进行有针对性的就地编辑 | 重构函数、添加错误处理 |
| [智能体](../) | 需要自主规划和工具使用的多文件更改 | 端到端实现一个功能 |
| [计划](../../work-with-ai/plan-and-run-tasks/2.2.10.1-PlanWork/) | 实现前的结构化规划 | 设计架构或迁移策略 |
| [智能操作](../../../editor/3.2-WriteCode/3.2.4-SmartActions/) | 内置的专门一步任务 | 生成提交消息、修复错误、重命名符号 |

## 将工作流应用到项目 {#apply-the-workflow-to-your-project}

　　准备在自己的项目中使用智能体时，请从你熟悉的项目中的一个有界任务开始：

1. 打开受信任的项目。提交或储藏无关工作，以便区分智能体的编辑和你自己的更改。

2. 选择一个较小的任务，并定义可观察的结果。如果实现方式不明确，请在聊天中提问，或在实现前使用[计划角色](../../work-with-ai/plan-and-run-tasks/2.2.10.1-PlanWork/)。

3. 提供相关文件、错误、约束和现有测试命令。例如：

    ```text
    为结果视图添加空状态文本。将更改限制在现有视图及其测试中。
    遵循当前组件模式，运行此区域的现有测试，并总结你验证的行为。
    ```

4. 在[聊天视图](../../work-with-ai/2.2.2-ChatView/)中，从 **会话目标** 中选择 **Copilot**，选择 **智能体** 角色，并在交互式首个任务中保持 **手动审批**。

    第一个任务请保留其他会话默认值。需要不同设置时，一次只更改一个选项，以便识别其影响。

5. 审查每个审批请求。智能体完成后，检查每个已更改文件，并亲自运行相关测试。

6. 只提交预期更改。如果结果错误，请[选择恢复操作](../../tutorials-and-guides/2.6.9-GetBackOnTrack/#choose-a-recovery-action)，例如提供有针对性的反馈或恢复检查点。

　　停止请求不会撤销已完成的操作。检查点会恢复受影响的工作区文件和聊天历史，但不会撤销已完成的终端命令、部署或对外部服务所做的更改。对于这些影响，请使用 Git 和外部服务的恢复控制。

　　现有项目中的分步指南：[探索代码库](../../tutorials-and-guides/2.6.2-ExploreACodebase/)、[添加功能](../../tutorials-and-guides/2.6.3-AddAFeature/)或[在不改变行为的情况下重构](../../tutorials-and-guides/2.6.5-RefactorSafely/)。

## 编写有效的提示词 {#write-effective-prompts}

　　AI 响应的质量取决于提示词的清晰度和具体程度。用明确目标、约束和相关上下编写请求通常称为*提示词工程*。以下技巧有助于获得更好的结果。

* **对输入、输出和约束保持具体。** 说明要使用的编程语言、框架和库。描述预期行为，或提供示例输入和输出。

    ```text
    编写一个验证电子邮件地址的 TypeScript 函数。
    有效地址返回 true，否则返回 false。不要使用正则表达式。
    示例：validateEmail("user@example.com") 返回 true
    示例：validateEmail("invalid") 返回 false
    ```

* **分解复杂任务。** 不要一次要求整个功能，而是将其拆分为更小、范围明确的步骤。这样可以产生更可靠的结果，并更容易尽早发现问题。

* **包含用于验证的预期输出。** 提供测试用例、预期结果或验收标准，让 AI 可以验证自己的工作。这是最高杠杆的做法之一。

    ```text
    使用令牌桶算法实现一个速率限制器。
    编写单元测试验证：每秒允许 10 个请求，第 11 个请求被拒绝，
    1 秒后令牌桶重新填充。实现后运行测试。
    ```

* **避免模糊提示词。** 类似“把它改得更好”的提示词没有给 AI 方向。请说明“更好”指什么：“降低时间复杂度”或“添加对 null 值的输入验证”。

* **通过后续提示词迭代。** 通过后续消息添加约束或更正，而不是重写整个提示词。

* **尽早纠正方向。** 如果 AI 方向错误，请通过后续消息[引导它](../../work-with-ai/2.2.5-UseChat/#send-messages-while-a-request-is-running)，重定向当前请求、排队后续请求，或停止并发送新提示词。有关选择引导、恢复更改或重新开始的帮助，请参阅[让智能体回到正轨](../../tutorials-and-guides/2.6.9-GetBackOnTrack/)。

* **让 AI 提出澄清问题。** 如果任务含糊，请让 AI 在继续之前向你提问。这比猜测需求更准确。

* **并行任务。** 如果有多项独立任务，可以让 AI 并行运行以节省时间。例如：“并行研究 X 和 Y，并总结发现。”

　　根据需要调整[提示词示例](../../tutorials-and-guides/2.6.15-PromptExamples/)，包括用于优化结果的多轮示例。视频介绍请观看 [Copilot 提示词工程核心原则](https://www.youtube.com/watch?v=hh1nOX14TyY)。

## 提供正确的上下文 {#provide-the-right-context}

　　AI 拥有相关上下文时响应更准确。使用以下技巧让 AI 获得正确信息：

* AI 会自动执行代码搜索来收集相关上下文。当提示词含糊时，可以使用 `#<file>`、`#<folder>` 或 `#<symbol>` 引用特定文件、文件夹或符号来引导 AI。

* 要获取网页或 GitHub 仓库中的信息，请使用 `#fetch` 为 AI 提供代码库之外的最新信息，或使用 GitHub MCP 等 MCP 服务器提供的工具。

* 引用 VS Code 环境上下文，例如源代码管理更改、终端输出或测试失败，帮助 AI 理解项目当前状态并给出更相关的响应。

* 添加图像或截图，让 AI 分析视觉内容。

* 使用[集成浏览器](../../../debugging-and-testing/6.5-IntegratedBrowser/)预览应用，并手动添加页面元素、截图或控制台日志作为上下文。

* 为智能体提供[浏览器工具](../../work-with-ai/plan-and-run-tasks/2.2.10.3-BrowserTools/)，让它执行用户流程、检查结果、修复问题并自主验证更改。

　　更多信息请参阅[向聊天提示词添加上下文](../../work-with-ai/2.2.7-AddPromptContext/)和[配置工具](../../work-with-ai/plan-and-run-tasks/2.2.10.2-UseTools/)。

## 选择合适的模型 {#choose-the-right-model}

　　每个 AI 模型各有所长。有些更擅长推理，另一些擅长代码生成或更快响应。为任务选择合适的模型可以改善结果。

* **让模型匹配任务复杂度。** 简单补全和样板代码使用快速模型。规划、调试或架构决策时切换到针对推理优化的模型。

* **使用最新模型。** 新模型通常能力更强。VS Code 会持续添加对新模型和模型版本的支持。查看[可用模型](../../choose-models-and-agents/2.3.1-ChooseAndConfigureModels/)并使用最新模型。

* **在提示词文件和智能体中固定模型。** 在提示词文件或自定义智能体定义中指定首选模型，确保特定任务始终使用正确模型。

* **试验并比较。** 如果对响应不满意，可以尝试其他模型。相同提示词下，不同模型可能产生显著不同的结果。

* **为推理模型调整思考强度。** 使用模型选择器中的[思考强度控件](../../choose-models-and-agents/2.3.1-ChooseAndConfigureModels/#configure-thinking-effort-and-context-size)，为复杂任务提高强度，为简单任务降低强度。

* **使用 BYOK 获得更多控制。** 自带 API 密钥可以获得更多模型选择和托管选项。

* **考虑点数消耗。** 能力更强的模型每个令牌消耗更多 [AI 点数](../../concepts/2.7.2-HowModelsWork/#ai-credits-and-model-costs)。自动模型选择会自动平衡质量和成本。更多提示请参阅[优化 AI 点数使用量](../../tutorials-and-guides/2.6.14-ReduceCreditUsage/)。

　　更多信息请参阅[选择 AI 模型](../../choose-models-and-agents/2.3.1-ChooseAndConfigureModels/)和 [Copilot Chat 可用模型](https://docs.github.com/en/copilot/using-github-copilot/ai-models/changing-the-ai-model-for-copilot-chat)。

## 先计划，再实现 {#plan-first-then-implement}

　　对于跨多个文件的复杂更改，请将规划与实现分开。这样可以防止 AI 解决错误的问题，并避免把 [AI 点数](../../concepts/2.7.2-HowModelsWork/#ai-credits-and-model-costs)花在需要丢弃的代码上。

1. **探索。** 在聊天中提问，或使用子智能体阅读相关代码，理解其工作方式后再更改。

2. **计划。** 使用[计划智能体](../../work-with-ai/plan-and-run-tasks/2.2.10.1-PlanWork/)创建结构化实现计划。执行前审查并完善计划。

3. **实现。** 切换到智能体模式，按照计划实现。包含测试或预期输出，让智能体可以验证自己的工作。使用 Copilot、Claude 或 Codex 运行框架并行运行独立会话。对于受管理的云执行，请[启动云会话](../../work-across-apps-and-machines/2.5.3-CloudSessions/)并带上任务及其上下文。

4. **审查。** 使用[检查点](../../work-with-ai/2.2.8-ReviewAndRevertChanges/#restore-a-checkpoint)审查进度，在智能体偏离时回退，或对生成的拉取请求[请求 Copilot 代码审查](https://docs.github.com/en/copilot/concepts/agents/code-review)。

　　更多信息请参阅[上下文工程工作流](../../tutorials-and-guides/2.6.11-ContextEngineering/)。

## 审查并验证 AI 输出 {#review-and-verify-ai-output}

　　AI 生成的代码可能包含错误、安全问题或细微逻辑错误。始终将 AI 输出视为需要审查的起点。

* **整合前审查。** 提交或合并更改之前，通读生成的代码。注意边界情况、错误处理以及 AI 可能做出的假设。

* **AI 更改后运行测试。** 在提示词中包含测试用例，让 AI 可以验证自己的工作。如果 AI 没有自动运行测试，请亲自运行后再继续。

* **使用检查点回退文件编辑和聊天。** 如果智能体偏离方向，请使用[检查点](../../work-with-ai/2.2.8-ReviewAndRevertChanges/#restore-a-checkpoint)恢复受影响的工作区文件和聊天历史。检查点不会撤销已完成的命令或对外部服务的更改。

* **检查安全问题。** 审查 AI 生成的代码是否存在常见漏洞，例如注入缺陷、硬编码机密或缺少输入验证。避免将凭据或敏感数据粘贴到提示词中。

　　更多信息请参阅 [GitHub Copilot 安全](../../work-with-ai/permissions-and-security/2.2.12.3-AISecurity/)和 [GitHub Copilot 信任中心](https://copilot.github.trust.page/faq)。

## 选择合适的智能体运行框架 {#choose-the-right-agent-harness}

　　使用智能体时，选择与任务和工作流匹配的运行框架。每个运行框架提供不同的提供商能力、工具和执行环境。

> **注意**：当 [GitHub Copilot 企业托管设置生效](../../../enterprise/7.2-ManageAISettings/#claude-and-codex-availability)时，Claude 和 Codex 运行框架会被禁用。请联系部署这些设置的 IT 团队。

* **日常编码使用 Copilot 运行框架。** 它在本机运行工具，并可访问工作区和运行时上下文。对大多数编码任务是良好的默认选择。工具执行位置与所选语言模型的运行位置相互独立。

* **需要提供商特定能力时使用 Claude 或 Codex。** 它们也在这台计算机上运行工具，并通过相同的 VS Code 会话体验提供各自的 SDK 能力。

* **受管理的执行使用云会话。** 对受管理计算资源上的交互式工作使用[云会话](../../work-across-apps-and-machines/2.5.3-CloudSessions/)，之后可以重新连接，而无需保持自己的主机在线。

* **独立任务使用并行会话。** 使用 Copilot、Claude 或 Codex 运行框架启动多个会话，或使用云会话，同时处理无关任务。在[会话列表](../../work-with-ai/sessions/2.2.11.1-ManageSessions/)中监控它们。

　　更多信息请参阅[选择智能体运行框架](../../choose-models-and-agents/2.3.2-ChooseAnAgentHarness/)和[智能体编码教程](../2.1.4-AgentsTutorial/)。

## 为 AI 优化项目 {#optimize-your-project-for-ai}

　　项目自定义是可选的。当你有 AI 无法可靠从代码推断的约定、项目上下文或工作流时再添加。简洁的自定义还可以通过减少重复的上下文收集、更正和重试，帮助[优化 AI 点数使用量](../../tutorials-and-guides/2.6.14-ReduceCreditUsage/)。

　　VS Code 支持多种机制来配置项目的 AI 行为。在聊天中输入 `/init` 可生成起始配置。

| 机制 | 最适合 | 开始使用 |
|-----------|----------|----------|
| [自定义指令](../../customize-and-extend/2.4.4-Instructions/) | 项目范围的编码标准和架构上下文 | 输入 `/init` 生成项目的常驻指令 |
| [自定义智能体](../../customize-and-extend/2.4.5-CustomAgents/) | 专用工作流或角色（TDD、安全审计） | 输入 `/create-agent <description>` 生成自定义智能体 |
| [技能](../../customize-and-extend/2.4.3-AgentSkills/) | 领域特定能力（测试、部署） | 输入 `/create-skill <description>` 生成技能 |
| [工具和 MCP 服务器](../../work-with-ai/plan-and-run-tasks/2.2.10.2-UseTools/) | 连接外部系统（数据库、API、CLI） | 在 `mcp.json` 中配置 |

有效项目配置的提示：

* **保持指令文件简洁。** 它们会在每次聊天交互时加载。重点放入 AI 无法从代码推断的信息，例如非默认约定、架构决策或环境设置。

* **使用 `applyTo` 模式限定指令范围。** 输入 `/instructions` 创建语言特定或文件夹特定的指令文件，而不是把所有内容放在一个文件中。

* **限制启用的工具。** 活动工具越少，响应越快、越相关。只在任务需要时启用工具。

* **从搜索中排除生成和嘈杂文件。** 配置 `search.exclude` 和 `files.exclude`，让智能体文本搜索和 grep 专注于源代码。请参阅[使用排除设置改善智能体搜索](../../reference-and-help/reference/2.8.1.11-AgentHostArchitecture/)。

　　完整设置详情请参阅[自定义智能体行为](../../customize-and-extend/2.4.1-Overview/)。

## 管理上下文和会话 {#manage-context-and-sessions}

　　当对话充满无关上下文时，AI 响应可能变差。请主动管理会话。

* **为无关任务启动新会话。** 不要把所有无关问题堆在一个对话中。上下文污染会降低响应质量，并把令牌浪费在无关历史上。

* **为相关工作启动新聊天。** 当任务仍属于同一工作区，但不需要当前对话历史时，请在支持的情况下[在会话中启动另一个聊天](../../work-with-ai/sessions/2.2.11.1-ManageSessions/#run-multiple-chats-in-a-session)。它共享会话的文件和代码更改，但不继承其他聊天的历史。

* **压缩上下文。** 使用 [`/compact`](../../work-with-ai/sessions/2.2.11.1-ManageSessions/#compact-conversation-context)并提供说明，选择性地压缩上下文，只保留最相关信息。压缩会减少后续每次请求发送的令牌，有助于[管理 AI 点数使用量](../../tutorials-and-guides/2.6.14-ReduceCreditUsage/)。

* **验证缓存性能。** 保持提示词的早期部分在多轮之间稳定，以复用提示词缓存并降低成本和延迟。使用[缓存浏览器](../../reference-and-help/troubleshooting/2.8.2.3-DiagnosePromptCaching/)检查缓存命中率并找出缓存中断的位置。

* **使用子智能体进行调查。** 提示 AI 使用[子智能体](../../work-with-ai/plan-and-run-tasks/2.2.10.4-Subagents/)在隔离环境中研究和探索，以免发现污染主上下文。

* **选择正确的运行框架和执行环境。** 日常在本地文件夹或隔离工作树中工作时，从 [Copilot 运行框架](../../choose-models-and-agents/2.3.2-ChooseAnAgentHarness/#copilot)开始；在受管理计算资源上进行交互式工作时，使用[云会话](../../work-across-apps-and-machines/2.5.3-CloudSessions/)。

* **通过并行会话扩展。** 在单独的文件夹或工作树中运行多个会话，以节省时间并保持上下文分离。可以在 VS Code 的[会话列表](../../work-with-ai/sessions/2.2.11.1-ManageSessions/)中，在本机、连接的主机、开发容器或提供商管理的云基础设施上的会话之间切换。

* **分叉而不是重新提示。** 使用 [`/fork`](../../work-with-ai/sessions/2.2.11.1-ManageSessions/#fork-a-chat-session)探索替代方案而不丢失上下文，而不是重新开始并从头重建上下文。

　　更多信息请参阅[会话管理](../../work-with-ai/sessions/2.2.11.1-ManageSessions/)、[工作区索引](../../reference-and-help/reference/2.8.1.11-AgentHostArchitecture/)和[优化 AI 点数使用量](../../tutorials-and-guides/2.6.14-ReduceCreditUsage/)。

## 优化 AI 点数使用量 {#optimize-ai-credit-usage}

　　本文中的许多实践也有助于控制成本。能力更强的模型、较大的上下文和无效工作都会消耗 [AI 点数](../../concepts/2.7.2-HowModelsWork/#ai-credits-and-model-costs)。以下几个杠杆影响最大：

* **让模型匹配任务。** 简单工作使用更快、更便宜的模型，把高级模型留给规划、调试和架构决策。自动模型选择会为你平衡质量和成本。

* **保持上下文精简。** 只发送相关上下文，[压缩](../../work-with-ai/sessions/2.2.11.1-ManageSessions/#compact-conversation-context)长对话，并为无关任务启动新会话，避免每次请求都为无关历史付费。

* **先计划再实现。** 将规划与实现分开，可以避免把点数花在会丢弃的代码上。

　　完整技巧请参阅[优化 AI 点数使用量](../../tutorials-and-guides/2.6.14-ReduceCreditUsage/)。

## 处理大型代码库 {#work-with-large-codebases}

　　Copilot 设计用于有效处理大型、复杂和多根工作区。使用以下实践在大规模场景中获得最佳结果。

* **使用工作区索引。** VS Code 会自动使用语义搜索、语言智能和 GitHub 代码搜索为项目建立索引，以进行深度跨文件推理。这适用于小型项目和大型企业代码库。对于大型仓库，请使用[远程索引](../../reference-and-help/reference/2.8.1.11-AgentHostArchitecture/)，在仓库及 GitHub 上的相关仓库中获得快速、全面的结果。

* **使用多根工作区限定范围。** 对于 monorepo 或多个服务的项目，请使用[多根工作区](../../../editor/3.2-WriteCode/3.2.8-Workspaces/3.2.8.2-MultiRootWorkspaces/)，为 AI 提供清晰边界和聚焦上下文。

* **提供项目级指令。** 使用[自定义指令](../../customize-and-extend/2.4.4-Instructions/)描述项目的架构、模块边界和 AI 无法仅从代码推断的约定。这为 AI 提供进行架构级更改所需的上下文。

* **为独立更改运行并行会话。** 将大型任务拆分为独立子任务，并在[并行会话](../../work-with-ai/sessions/2.2.11.1-ManageSessions/)中运行，每个会话专注于代码库的不同区域。

* **跨领域更改使用计划智能体。** 对于跨多个文件或模块的更改，请先从[计划智能体](../../work-with-ai/plan-and-run-tasks/2.2.10.1-PlanWork/)创建结构化实现计划，再执行。

　　更多信息请参阅[工作区上下文](../../reference-and-help/reference/2.8.1.11-AgentHostArchitecture/)和[智能体](../)。
