# 2.3.3 从 Local 迁移到 Copilot

　　Copilot 运行框架将 Copilot CLI 和 GitHub Copilot 应用背后的共享编码智能体运行时引入 VS Code。编辑器工作流可以受益于这些产品在模型集成、上下文效率和工具使用方面的持续改进。可以在编辑器中与代码一起工作，也可以使用智能体窗口监督跨项目任务。

　　对于组织，共享运行时为跨受支持客户端和开发环境治理智能体提供统一方法。管理员可以管理旧版 Local 运行框架无法强制的权限和沙盒限制，开发者则可以在工作流中使用已批准的工具和服务。

　　如果已经通过 Local 运行框架使用智能体，本指南帮助完成过渡：审查工作依赖的自定义项和集成，在需要时继续现有对话，并验证组织控制。目标是让日常工作可用，而不仅是切换会话目标。

## 为什么要迁移到 Copilot 运行框架 {#why-move-to-the-copilot-harness}

　　智能体完成任务的能力不仅取决于所选模型。运行框架准备模型收到的上下文，协调工具调用和审批，并在工作推进时维护对话。即使使用相同模型，更改运行框架也可能改变智能体执行请求的方式。

使用 Copilot 运行框架可以：

* 在通过[本地沙盒](../../work-with-ai/permissions-and-security/2.2.12.2-AgentSandboxing/)配置的文件系统和网络边界内运行构建、测试及其他智能体命令。
* 让 [Copilot Fusion](../2.3.1-ChooseAndConfigureModels/)选择模型并协调任务起草和审查。
* 在[智能体窗口](../../work-with-ai/2.2.3-AgentsWindow/)中跨项目委派任务，然后在需要编辑、调试或测试时在编辑器中继续同一会话。两个界面保持同步。
* 通过[辅助权限](../../work-with-ai/permissions-and-security/2.2.12.1-ApprovalsAndPermissions/)减少批准常规工具调用的时间。风险评估未批准的操作仍会请求确认。
* 将工作委派给[云沙盒](../../work-across-apps-and-machines/2.5.3-CloudSessions/)，然后关闭笔记本电脑，稍后重新连接查看进度并继续任务。
* 通过 [Copilot 连接器](../../customize-and-extend/2.4.6-CopilotConnectors/)将团队服务中的上下文带入智能体任务，无需自行配置 MCP 服务器。
* 通过[画布](../../work-with-ai/2.2.6-Canvases/)在任务板规划工作，或与智能体探索交互式图表。

　　对于组织，Copilot 运行框架增加了 Local 无法强制执行的治理。管理员可以：

* 通过[托管沙盒策略](../../../enterprise/7.2-ManageAISettings/)强制执行文件系统和网络限制。
* 阻止组织不允许的操作，并控制开发者可使用的[审批级别](../../../enterprise/7.2-ManageAISettings/)。运行时强制执行这些限制，而不是依赖模型遵循指令。
* 为团队提供一致的[起始模型和推理强度](../../../enterprise/7.2-ManageAISettings/)，同时允许开发者为特定任务选择其他可用选项。

　　管理员还可以通过[必需插件和受控 Marketplace](../../../enterprise/7.2-ManageAISettings/)在受支持客户端之间分发已批准的技能、工具和钩子，无需单独设置。

　　要实践这些能力和控制，请遵循[在组织中推广 Copilot 运行框架](#roll-out-the-copilot-harness-in-your-organization)。

## 了解变化 {#understand-what-changes}

　　**Local** 和 **Copilot** 是 **会话目标** 选择器中的运行框架选项。Local 运行框架是旧版、编辑器特定的实现。Copilot 运行框架使用 Copilot SDK，即跨 GitHub Copilot 产品的共享运行时。两者切换改变的是协调智能体工作的软件，而不是是否使用 Copilot。

　　运行框架也独立于模型和代码运行位置。选择 Claude 模型不会切换到 Claude 运行框架；选择 Copilot 运行框架不会将文件移到云端。[Agent Host](../../reference-and-help/reference/2.8.1.11-AgentHostArchitecture/)是运行 Copilot 会话的进程。编辑器的聊天视图和智能体窗口是使用这些会话的界面。

　　新工作流请使用 Copilot 运行框架，但在替换现有 Local 设置前审查兼容性。工具和自定义支持可能不同，个人设置不会自动跨客户端同步。如果某个集成仍需要 Local 运行框架，请与管理员一起审查[临时回退指导](#use-the-local-harness-temporarily-for-a-blocker)。这些区别的背景请参阅[智能体运行框架概念](../../concepts/2.7.6-AgentHarnesses/)。

## 开始之前 {#before-you-start}

* 更新到组织当前批准的 VS Code 版本。检查功能特定前提条件和任何[托管最低版本要求](../../../enterprise/7.2-ManageAISettings/)。
* 使用具有已批准 Copilot 访问权限的 GitHub 账户登录。请遵循 [Copilot 设置](../../getting-started/2.1.2-SetUpCopilot/)或适用的 [GHE.com 账户指导](../2.3.2-ChooseAnAgentHarness/)。
* 选择一个已在 Local 运行框架中正常工作的小任务。记录预期结果、所需工具、自定义项和审批，以便切换后比较工作流。
* 更改前备份自定义文件和设置。

## 设置工作流 {#set-up-your-workflow}

### 启动 Copilot 会话 {#start-a-copilot-session}

1. 在编辑器中打开[聊天视图](../../work-with-ai/2.2.2-ChatView/)，或打开[智能体窗口](../../work-with-ai/2.2.3-AgentsWindow/)。
2. 在聊天视图中选择 **新建聊天**（`+`），或在智能体窗口中选择 **新建**。提示时选择项目。
3. 打开 **会话目标** 并选择 **Copilot**。
4. 为任务选择可用模型和智能体。

要使用辅助权限，请打开聊天输入中的权限选择器并选择 **辅助权限**。可用选项请参阅[权限级别](../../work-with-ai/permissions-and-security/2.2.12.1-ApprovalsAndPermissions/)。

要检查现有会话，请[识别其当前运行框架](../2.3.2-ChooseAnAgentHarness/)。选择不同模型或在另一界面打开会话不会改变其运行框架。

### 审查自定义项和集成 {#review-customizations-and-integrations}

　　选择 **Copilot** 不会转换所有自定义项。打开 **Chat: Open Customizations**，选择 **迁移**，查看检测到的项目。文件位置、支持的转换和手动步骤请遵循[将自定义项迁移到 Copilot 运行框架](../../customize-and-extend/2.4.11-MigrateExistingCustomizations/)。

使用以下兼容性清单检查工作流：

| 检查项 | 验证内容 |
|-------|----------------|
| 提示词文件 | 将重复提示词转换为技能。重新检查转换未保留的智能体、模型和工具选择。 |
| 个人智能体、指令和技能 | 审查配置文件存储和配置的搜索位置。必须在没有编辑器时工作的工作流请使用 Copilot 运行框架的原生位置。 |
| 钩子 | 审查支持的事件、脚本输入输出和失败行为。钩子没有自动转换。 |
| MCP 服务器和身份验证 | 验证服务器配置、授权、工具和沙盒行为。输入提示和存储的编辑器机密不会自动转移。 |
| 内置和扩展工具 | 检查 Copilot 会话中可用的工具。扩展工具需要运行该扩展的编辑器窗口。 |
| 终端环境 | 验证智能体 shell 可以运行工作流所需命令。请参阅[shell 初始化](../../work-with-ai/plan-and-run-tasks/2.2.10.2-UseTools/)配置支持的环境设置。 |
| 工具集和聊天参与者 | 用受支持工具、智能体、技能或发布者集成替换 Local 特定别名和参与者工作流。 |

使用 `${input:...}` 或 `${command:...}` 的 MCP 服务器，请先审查[身份验证和机密限制](../../customize-and-extend/2.4.11-MigrateExistingCustomizations/)。不要在共享或个人配置文件中用字面凭据替换机密占位符。

　　原始文件和迁移文件不会同步。验证结果前保留备份，避免留下重复的活动副本。**迁移** 执行支持的文件移动和转换。**使用智能体迁移** 启动智能体主导的对话来适配工作流，并使用 Copilot 点数。

### 继续现有 Local 对话 {#continue-an-existing-local-conversation}

　　如果需要现有对话的上下文，请在编辑器中打开 Local 会话。在聊天输入中打开 **会话目标** 并选择 **Copilot**。交接会将对话历史和上下文带到目标会话。继续前审查可用模型、工具和权限，因为不同运行框架可能不同。这不是双向运行框架切换。请参阅[从 Local 交接](../2.3.2-ChooseAnAgentHarness/)。

　　组织策略要求 Copilot 运行框架时，打开未归档的 Local 对话可能自动移动。结果取决于宿主是否支持对话导入：

* 支持导入时，移动保留历史和未发送草稿。原 Local 对话归档为只读。
* 不支持导入时，**在 Copilot 中继续** 会启动新对话，将记录作为上下文附加，并保留未发送草稿。原对话仍可用。

　　两种方式都不会自动提交提示词。

　　如果早期工作没有出现，请检查原始工作区、执行宿主以及 **已归档** 或 **已完成** 筛选器，再判断是否丢失。Local 会话仅限编辑器。请遵循[查找缺失会话](../../work-with-ai/sessions/2.2.11.1-ManageSessions/)，如果历史或草稿不可用，请报告阻塞问题。

### 在界面之间继续 {#continue-between-interfaces}

可以在任一界面继续 Copilot 会话：

* 在编辑器中选择 **在智能体中打开**，然后选择现有会话。
* 在智能体窗口中选择 **在编辑器中打开**。

会话保留其运行框架、工作区和工作树。请参阅[在界面之间继续](../../work-with-ai/sessions/2.2.11.1-ManageSessions/)。

　　会话的 Agent Host 必须保持运行。对于你机器上的会话，不要退出 VS Code 或关闭机器。[编辑器提供的工具](../../reference-and-help/reference/2.8.1.11-AgentHostArchitecture/)仍需要连接的编辑器窗口。

## 在组织中推广 Copilot 运行框架 {#roll-out-the-copilot-harness-in-your-organization}

　　统一使用 Copilot 运行框架，让开发者使用其智能体能力，管理员执行权限和沙盒控制。先进行试点，覆盖开发者使用的项目、集成和执行环境，包括适用的 Remote SSH、WSL 和 Dev Containers。工作流验证后，为推广组要求该运行框架并部署组织需要的控制。

　　为试点参与者提供支持联系人和[报告过渡阻塞的步骤](#troubleshoot-a-transition-blocker)。扩展推广前解决阻塞工作流。

### 要求使用 Copilot 运行框架 {#require-the-copilot-harness}

　　要为推广组要求 Copilot 运行框架，请在 VS Code 1.143 或更高版本部署以下企业托管设置：

```json
{
    "vscode": {
        "temporaryAllowLocalHarness": false,
        "temporaryDefaultToLocalHarness": false
    }
}
```

　　将这些键添加到企业托管设置，而不是编辑器的用户或工作区设置。`temporaryAllowLocalHarness: false` 禁止 Local、Claude 和 Codex 运行框架，优先于临时 Local 默认值。将 `temporaryDefaultToLocalHarness` 设置为 `false` 也会清除该推广退出选项。

　　如果只想鼓励采用而不强制要求，可以将 `ChatEditorPreferCopilotHarness` 设备策略设置为 `true`。它会在新编辑器聊天本应使用 Local 运行框架时选择 Copilot，但不禁止其他运行框架。

　　运行框架要求与团队模型和权限默认值分开配置。例如，要让 Copilot Fusion 成为起始模型，请将 `model` 设置为 `"auto"`，并选择 `"standard"`、`"high"` 或 `"max"` 的 `fusionTier`。请参阅[托管模型默认值](../../../enterprise/7.2-ManageAISettings/)和[权限级别默认值](../../../enterprise/7.2-ManageAISettings/)。默认值设置新对话的起始选择，不限制后续选择。

　　要求运行框架不会开启沙盒或添加权限规则，请单独部署这些控制。从 VS Code 1.143 开始，托管非空 `permissions.deny` 规则或 `sandbox.enabled: true` 也会要求 Copilot 运行框架，除非适用临时 Local 默认值。其他 `permissions.*` 设置和空拒绝列表不会触发该路由。

　　单独的 [Claude 和 Codex 可用性规则](../../../enterprise/7.2-ManageAISettings/)取决于企业托管设置是否存在，而不仅是拒绝列表和沙盒路由触发器。将 `temporaryAllowLocalHarness` 设置为 `true` 不会覆盖其他限制。

　　部署后，启动新的编辑器聊天和新的智能体窗口会话。确认它们使用 Copilot 运行框架，被禁止的运行框架不可用，并且预期的模型默认值出现。如果结果不同，请检查 **Developer: Policy Diagnostics**，并在更改配置前检查有效的临时 Local 控制。请参阅[运行时策略和运行框架选择](../../../enterprise/7.2-ManageAISettings/)。

### 部署组织控制 {#deploy-your-organization-controls}

　　保留组织仍需的现有控制。切换运行框架不会替代编辑器特定的设备策略。

* 使用 [Copilot 企业托管设置](../../../enterprise/7.2-ManageAISettings/)为受支持客户端提供运行时控制。请遵循 GitHub 的[设置指南](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/use-managed-settings/get-started)和[设置参考](https://docs.github.com/en/copilot/reference/enterprise-administrators/enterprise-managed-settings)，了解 schema、交付方式、受支持客户端和最低版本。
* 编辑器特定控制请使用[设备策略](../../../enterprise/7.1-Policies/)。
* 账户访问、已批准模型和功能可用性请使用 GitHub 组织和企业设置。试点连接器或其他需要预览的功能前，请检查 **编辑器预览功能**。

　　控制重叠时请审查[优先级](../../../enterprise/7.2-ManageAISettings/)。同一控制中企业托管设置优先于设备策略。尽可能在一个系统中配置重叠控制，并验证有效值，不要假设现有策略未变。

### 验证每个执行环境 {#validate-each-execution-environment}

　　在每个已批准客户端和执行宿主上检查策略交付、支持的客户端版本和执行情况。共享配置不能保证编辑器、智能体窗口、CLI 或其他客户端具有相同覆盖。

　　对于远程和容器会话，请检查运行命令的机器或容器，而不仅是连接设备。在那里确认沙盒前提条件和有效路径。请参阅[沙盒前提条件](../../work-with-ai/permissions-and-security/2.2.12.2-AgentSandboxing/)和[Dev Containers 中的沙盒](../../work-with-ai/permissions-and-security/2.2.12.2-AgentSandboxing/)。

　　不要将 Local 运行框架的沙盒设备策略视为 Copilot 运行时控制。请审查[沙盒管理](../../../enterprise/7.2-ManageAISettings/)和[设备策略覆盖差异](../../../enterprise/7.2-ManageAISettings/)。

## 验证工作流和控制 {#verify-the-workflow-and-controls}

在依赖 Copilot 运行框架中的工作流之前：

1. 在目标环境启动 Copilot 会话并运行代表性任务。检查实际编辑、命令结果和测试，而不仅是智能体总结。
2. 确认预期自定义项加载，所需工具可用。执行工作流依赖的已迁移技能、钩子或 MCP 集成。
3. 从命令面板（`Ctrl + Shift + P`）运行 **Developer: Policy Diagnostics**。与管理员一起检查有效策略值及其来源。
4. 在 Copilot 会话中运行 `/sandbox policy`。检查执行宿主、沙盒状态、文件系统访问和网络限制。沙盒关闭时也会提供此报告。
5. 与管理员一起测试一个已批准操作和一个策略应阻止的无害操作。使用一次性测试路径或管理员选择的测试目标。确认限制生效，而不仅是出现审批提示。
6. 在已批准远程主机和容器上重复检查。如果还使用其他 Copilot 客户端，请单独验证其支持的控制。

　　使用[有效沙盒策略报告](../../work-with-ai/permissions-and-security/2.2.12.2-AgentSandboxing/)和[策略诊断](../../../enterprise/7.1-Policies/)调查意外结果。

## 遇到阻塞时临时使用 Local 运行框架 {#use-the-local-harness-temporarily-for-a-blocker}

　　如果某个集成在 Copilot 运行框架中尚无受支持替代方案，仅在组织控制允许时使用 Local 运行框架。在编辑器中启动新会话，在 **会话目标** 下选择 **Local**。Local 运行框架在智能体窗口中不可用。

　　如果 Local 运行框架不可用，请管理员审查有效限制。

　　管理员可以临时将 `vscode.temporaryDefaultToLocalHarness` 设置为 `true`。这会保持 Local 运行框架可用，并停止自动路由到 Copilot，即使托管拒绝规则或沙盒设置通常会要求它。显式和记住的运行框架选择会保留。

　　临时默认值不会覆盖 `vscode.temporaryAllowLocalHarness: false`，也不会在企业托管设置禁用 Claude 和 Codex 时恢复它们。

> **警告**：Local 运行框架无法执行 Copilot 运行时独有的权限和沙盒控制。回退到 Local 时保持相同托管配置不会保留这些保护。管理员必须审查并接受此差距后才能允许回退。

　　这些是临时过渡控制，不是长期兼容性保证。请跟踪集成阻塞、测试受支持替代方案，并在验证后移除临时例外。请参阅 [Local 运行框架可用性设置](../2.3.2-ChooseAnAgentHarness/)和[管理员回退指导](../../../enterprise/7.2-ManageAISettings/)。

## 常见问题 {#frequently-asked-questions}

### 如何试用 Copilot 运行框架功能？ {#how-do-i-try-the-copilot-harness-features}

先启动 Copilot 运行框架会话，再使用以下起始步骤。链接指南涵盖平台要求、账户访问和组织控制。

| 功能 | 开始使用 |
|---------|-------------|
| [本地沙盒](../../work-with-ai/permissions-and-security/2.2.12.2-AgentSandboxing/) | 在执行宿主上将 `chat.agent.sandbox.enabled` 设置为 `on`。启动新会话并运行 `/sandbox policy` 检查限制。 |
| [Copilot Fusion](../2.3.1-ChooseAndConfigureModels/) | 在模型选择器中选择 **Copilot Fusion**，然后选择可用推理强度。 |
| [辅助权限](../../work-with-ai/permissions-and-security/2.2.12.1-ApprovalsAndPermissions/) | 打开聊天输入中的权限选择器，选择 **辅助权限**。 |
| [Copilot 连接器](../../customize-and-extend/2.4.6-CopilotConnectors/) | 运行 **Chat: Open Customizations**，选择 **浏览**，选择 **Copilot Connectors**。选择服务并选择 **连接**，然后审查并授权访问。 |
| [画布](../../work-with-ai/2.2.6-Canvases/) | 开启 `chat.canvases.enabled`，启动新会话并发送消息。从 **浏览** > **画布** 安装提供画布的插件，然后要求智能体打开其画布。 |

### 还可以审查和撤销智能体的编辑吗？ {#can-i-still-review-and-undo-the-agents-edits}

　　可以。编辑器中的 Copilot 运行框架会话通过[工作集](../../work-with-ai/2.2.8-ReviewAndRevertChanges/)支持 **保留** 和 **撤销**，该功能默认开启。从更改文件列表打开文件，使用内联控件保留或撤销单个更改。智能体窗口中使用[更改视图](../../work-with-ai/2.2.8-ReviewAndRevertChanges/)。

　　待处理编辑已保存到磁盘。**保留** 清除其待审查状态，不会暂存或提交。工作集跟踪受支持的智能体编辑工具，不跟踪终端命令或脚本所做的更改。请另外审查这些更改，例如在源代码管理中。

### 在哪里选择智能体可用的工具？ {#where-do-i-choose-which-tools-the-agent-can-use}

　　选择 Copilot 运行框架后，运行 **Chat: Open Customizations** 并选择 **工具**。展开工具组以选择或清除单个工具。客户端工具选择保存在活动用户配置文件中，而不是像 Local 运行框架选择器那样仅应用于一个请求。

　　**Copilot** 组列出运行时的内置工具，无法在该列表中单独配置。客户端提供的工具需要贡献它的客户端保持连接。启用工具不会自动批准其使用。请参阅[管理可用工具](../../work-with-ai/plan-and-run-tasks/2.2.10.2-UseTools/)。

### 现有记忆会怎样？ {#what-happens-to-my-existing-memory}

　　Local 运行框架的记忆文件和 Copilot Memory 是独立系统。切换运行框架不会转换现有文件。默认情况下，Copilot 运行框架会话使用[云端 Copilot Memory](../../work-with-ai/sessions/2.2.11.2-Memory/)，受账户设置和组织策略约束。

　　[实验性仓库本地存储选项](../../work-with-ai/sessions/2.2.11.2-Memory/)也可用于本机 Copilot 运行框架会话。它使用与 Local 记忆不同的文件，不支持用户作用域记忆。GitHub 的云记忆设置和策略不适用于该本地存储，启用前请审查数据处理影响。

　　将必要的团队指导放在已审查的[指令](../../customize-and-extend/2.4.4-Instructions/)或[技能](../../customize-and-extend/2.4.3-AgentSkills/)中，不要仅依赖学习到的记忆。

### 为什么同一模型切换运行框架后表现不同？ {#why-can-the-same-model-behave-differently-after-switching-harnesses}

　　模型只是智能体的一部分。运行框架决定它收到的上下文和指令、可使用的工具，以及工具结果和审批如何反馈到对话。因此相同提示词和模型在 Local 与 Copilot 会话中可能产生不同结果。

　　请在你熟悉的任务上比较结果，包括编辑、测试结果和完成任务所需的干预。不要假设切换运行框架会保留每个工具或自定义项。请参阅[运行框架选择改变了什么](../../concepts/2.7.6-AgentHarnesses/)。

### 需要安装 Copilot CLI 或 SDK 吗？ {#do-i-need-to-install-copilot-cli-or-the-sdk}

　　不需要。VS Code 包含 Copilot 运行框架会话所需的运行时。与 Copilot CLI 和 Copilot SDK 共享该运行时不需要单独安装任一产品。请遵循运行框架的[账户和设置要求](../2.3.2-ChooseAnAgentHarness/)。

### 需要重建所有自定义项吗？ {#do-i-need-to-rebuild-all-my-customizations}

　　不需要。审查依赖 Local 特定位置、格式或工具的自定义项。例如，提示词文件需要转换为技能，编辑器配置文件存储中的个人智能体和指令需要移动，钩子需要手动审查。其他自定义项可能已使用受支持位置和格式。

　　从[迁移列表](../../customize-and-extend/2.4.11-MigrateExistingCustomizations/)开始，不要重写所有内容。插件和 Marketplace 单独管理，但其工具和钩子仍需兼容性检查。受支持格式有助于跨客户端复用自定义项，但不保证工具相同或自动同步个人文件。

### 审批、本地沙盒和云沙盒有什么区别？ {#how-do-approvals-local-sandboxing-and-cloud-sandboxes-differ}

这些控制解决不同问题：

| 控制 | 作用 |
|---------|--------------|
| [审批](../../work-with-ai/permissions-and-security/2.2.12.1-ApprovalsAndPermissions/) | 确定操作是自动运行还是需要确认。批准命令不会隔离它。 |
| [本地沙盒](../../work-with-ai/permissions-and-security/2.2.12.2-AgentSandboxing/) | 限制执行宿主上受支持进程的文件系统和网络访问。不会将任务移到另一台机器。 |
| [云沙盒](../../work-across-apps-and-machines/2.5.3-CloudSessions/) | 在受管理云环境中运行智能体、代码和工具，而不是在开发机器上。智能体仍可能影响该工作区及其有权访问的服务。 |

　　使用适合任务的保护。审批和单独执行环境都不能消除审查智能体更改和访问的需要。

　　使用 **手动权限** 时，选择 **仅允许一次** 仅批准当前操作。需要更广泛访问时，请审查[确认中显示的范围](../../work-with-ai/permissions-and-security/2.2.12.1-ApprovalsAndPermissions/)。

### 现有 OpenTelemetry 监控仍然有效吗？ {#will-our-existing-opentelemetry-monitoring-still-work}

　　OpenTelemetry 可用于 Local 和 Copilot 运行框架会话，包括受支持的托管导出配置。不需要留在 Local 运行框架才能将智能体活动导出到 OTel 收集器。

　　切换后请验证导出目标、捕获设置和仪表板依赖的属性。配置和覆盖详情请参阅[监控智能体使用情况](../../reference-and-help/reference/2.8.1.10-OpenTelemetryMonitoring/)。

## 排查过渡阻塞 {#troubleshoot-a-transition-blocker}

* 如果 Copilot 运行框架或模型不可用，请检查账户访问、已安装版本和组织限制，参见 [AI 故障排除](../../reference-and-help/troubleshooting/2.8.2.1-Troubleshooting/)。
* 如果自定义项或 MCP 工具缺失，请使用[自定义迁移常见问题](../../customize-and-extend/2.4.11-MigrateExistingCustomizations/)。
* 如果命令被阻止或沙盒工具无法启动，请检查 `/sandbox policy` 并遵循[沙盒故障排除](../../work-with-ai/permissions-and-security/2.2.12.2-AgentSandboxing/)。不要将关闭强制执行作为第一个排查步骤。

如果工作流仍然失败，请使用适当的报告或支持渠道：

* **组织策略或推广帮助**：联系组织的 AI 启用或 IT 支持团队。他们可以审查已部署配置和任何临时例外。
* **产品缺陷或兼容性差距**：通过 VS Code 问题报告器[报告未解决的问题](../../reference-and-help/troubleshooting/2.8.2.1-Troubleshooting/)。报告指南说明如何安全包含诊断证据。
* **GitHub 支持协助**：Copilot Business 和 Copilot Enterprise 客户可以[提交支持工单](https://docs.github.com/en/support/contacting-github-support/creating-a-support-ticket)。请使用该渠道，不要在公开议题中发布私有组织详情。

　　请包含产品版本、源和目标运行框架、操作系统、执行环境和最小复现。描述缺失能力和预期结果。共享日志或配置前移除凭据、私有代码和敏感策略详情。
