# 2.7.9 信任和安全

　　AI 生成的输出需要审查。VS Code 包含多种机制，让你控制进入代码库的更改。本文解释这些控制机制、AI 限制以及应注意的安全问题。

> **提示**：了解 VS Code 中使用 AI 的控制机制和安全注意事项，请参阅 [AI 安全](../../work-with-ai/permissions-and-security/2.2.12.3-AISecurity/)。

## 保持控制 {#stay-in-control}

　　智能体可以读取文件、编辑代码、运行终端命令和调用外部服务。VS Code 的信任模型分层设置多种控制机制，让你始终掌控进入代码库的内容：

* **整合前审查。** 智能体可以直接将会话文件夹或工作树中的编辑保存。提交、合并或创建拉取请求之前，请在差异中检查更改。对于受支持会话，[检查点](../../work-with-ai/2.2.8-ReviewAndRevertChanges/#restore-a-checkpoint)会将受影响工作区文件和聊天恢复到较早时间点。
* **批准敏感操作。** 在 Copilot 运行框架会话中使用[手动审批](../../work-with-ai/permissions-and-security/2.2.12.1-ApprovalsAndPermissions/#permission-levels)时，审批设置未覆盖的操作需要确认。文件编辑可能自动批准。当编辑必须在应用前确认时，请配置[敏感文件审批](../../work-with-ai/2.2.8-ReviewAndRevertChanges/#require-approval-before-sensitive-edits)。
* **限制自主性。**[权限级别](../../work-with-ai/permissions-and-security/2.2.12.1-ApprovalsAndPermissions/#permission-levels)决定智能体的自主程度，从每次调用审批到广泛自动批准，直到 Autopilot 的完全自主运行。
* **在操作系统级强制执行边界。**[智能体沙盒](#agent-sandboxing)限制终端命令的文件系统和网络访问，使自动批准的操作不能越过定义范围。
* **信任边界。** VS Code 对工作区、扩展、MCP 服务器和网络域使用信任决定。工作区 MCP 服务器继承工作区信任。

　　这些控制的分步配置（审批规则、敏感文件保护、沙盒设置、组织策略）请参阅 [VS Code 中的 AI 安全](../../work-with-ai/permissions-and-security/2.2.12.3-AISecurity/)。

　　提交之前始终审查 AI 生成的代码。验证它处理边界情况、遵循项目约定且不引入安全问题。停止请求或恢复工作区文件不会撤销已完成的终端命令、网络请求、部署或对外部服务的更改。

## 信任边界 {#trust-boundaries}

　　VS Code 安全模型使用信任边界限制不受信任代码的潜在影响。边界被视为受信任之前必须授予信任。单个信任决定可以覆盖相关边界，例如工作区及其 MCP 服务器配置。

* **工作区**：控制 VS Code 是否启用任务、调试和工作区设置等可能执行项目代码的功能。不受信任的工作区在[受限模式](../../../editor/3.2-WriteCode/3.2.8-Workspaces/3.2.8.3-WorkspaceTrust/)中运行，这也会禁用智能体。
* **扩展发布者**：控制是否可以安装和运行来自特定发布者的扩展。VS Code 会提示你[信任发布者](../../../editor/3.3-ConfigureTheEditor/3.3.6-Extensions/3.3.6.3-ExtensionRuntimeSecurity/)，然后激活其扩展。
* **MCP 服务器**：控制 MCP 服务器是否可以启动并提供工具。在 `.vscode/mcp.json` 或工作区根 `.mcp.json` 中配置的服务器继承工作区信任。其他来源的服务器可能需要[单独的 MCP 服务器信任决定](../../customize-and-extend/2.4.8-ManageMCPServers/#mcp-server-trust)，并在配置更改后再次提示。
* **网络域**：控制智能体是否可以从 URL 获取内容。VS Code 在请求域之前提示信任，并与[受信任域](https://code.visualstudio.com/docs/editing/editingevolved#_outgoing-link-protection)列表集成。也可以启用 `chat.agent.networkFilter` 限制 fetch 工具和集成浏览器的域。[沙盒网络控制](../../work-with-ai/permissions-and-security/2.2.12.2-AgentSandboxing/)单独适用于终端命令。

　　可以随时通过命令面板中的专用命令撤销信任。更改工作区信任会控制工作区 MCP 服务器能否运行。对于有单独信任决定的服务器，请运行 **MCP: Reset Trust**。配置这些控制的步骤请参阅 [VS Code 中的 AI 安全](../../work-with-ai/permissions-and-security/2.2.12.3-AISecurity/)。

　　授权 [Copilot 连接器](../../customize-and-extend/2.4.6-CopilotConnectors/)会授予对连接服务的访问。这与单个工具调用审批分开。会话的权限和审批设置仍决定工具操作是否需要确认。

## 智能体沙盒 {#agent-sandboxing}

　　智能体沙盒使用操作系统级隔离，限制终端命令在运行机器上可以访问的内容。沙盒不单纯依赖每次操作前的审批提示，而是强制执行配置的文件系统和网络边界。

　　在使用默认工具的 Copilot 会话中，沙盒限制 shell 执行和子进程。当相应设置激活时，它还可以沙盒为会话启动或管理的 MCP 服务器和语言服务器。两个设置默认激活。内置和其他非进程工具不在沙盒内，使用单独权限检查。开启沙盒默认不会阻止出站网络访问。了解如何[配置智能体沙盒](../../work-with-ai/permissions-and-security/2.2.12.2-AgentSandboxing/)。

　　沙盒和审批是独立控制。沙盒限制进程可以访问的资源，会话权限设置决定操作是否需要确认。

> **注意**：**对于 Local 运行框架会话：** 沙盒适用于终端命令及其子进程。其审批行为和配置与 Copilot 运行框架的默认工具不同。请参阅 [Local 运行框架沙盒兼容性](../../work-with-ai/permissions-and-security/2.2.12.2-AgentSandboxing/)。

### 沙盒为什么重要 {#why-sandboxing-matters}

　　基于审批的安全要求你在每个终端命令或工具调用运行前确认。这提供控制，但有实际限制：

* **审批疲劳。** 反复批准命令可能导致你不太注意批准内容，尤其是在长智能体会话中。
* **解析限制。** 自动批准规则使用尽力而为的命令解析，存在已知限制。shell 别名、引号拼接和复杂 shell 语法可能绕过规则而不被发现。
* **提示词注入。** 文件、工具输出或网页中的恶意内容可能试图诱骗智能体运行有害命令。如果不仔细审查就批准，可能导致意外操作和安全风险。
* **对外部服务的意外操作。** 即使没有恶意意图，有网络访问权限的智能体也可能代表你执行难以撤销的操作。例如，智能体可能配置云资源、修改基础设施设置、将代码推送到远程仓库或调用触发部署或金融交易的 API。阻止出站连接，或在支持域筛选时将其限制到所需域，可以降低沙盒命令的风险。

　　沙盒通过在操作系统级强制执行边界解决这些挑战。沙盒阻止自动批准的命令访问允许范围之外的文件或网络资源。如果需要额外权限，VS Code 会提示你在沙盒外运行命令。可以配置 VS Code 在显示提升提示前尝试在沙盒内运行命令。

### 沙盒如何工作 {#how-sandboxing-works}

沙盒强制执行两类隔离：

* **文件系统隔离** 限制对配置路径的读写访问，保护 SSH 密钥和 shell 配置等敏感位置，并适用于包管理器和构建脚本等子进程。
* **网络隔离** 阻止出站连接，或在支持时将其限制到配置域。域筛选能力因终端实现和平台而异。

　　终端和子进程边界使用操作系统保护。其他支持的操作可以使用运行智能体的进程内检查。可以分别配置文件系统和网络访问。默认行为和配置步骤请参阅[沙盒智能体终端命令](../../work-with-ai/permissions-and-security/2.2.12.2-AgentSandboxing/)。

### 操作系统级强制执行 {#os-level-enforcement}

　　智能体沙盒依赖操作系统安全原语强制执行文件系统和网络限制。由于强制执行发生在内核级，沙盒进程及其所有子进程无法绕过这些边界，即使命令被精心构造。

| 平台 | 技术 | 前提条件 |
|----------|-----------|---------------|
| macOS | Apple 沙盒框架（“Seatbelt”），内置于操作系统。在内核级强制执行细粒度文件系统和网络限制。 | 无，开箱即用。 |
| Linux 和 WSL2 | 文件系统隔离使用 [bubblewrap](https://github.com/containers/bubblewrap)，网络代理使用 `socat`。 | 安装所需包：`sudo apt-get install bubblewrap socat`（Debian/Ubuntu）或 `sudo dnf install bubblewrap socat`（Fedora）。 |
| Windows | Microsoft MXC 进程容器对命令进程应用文件系统和网络策略。 | 安装适用的 Windows 安全更新。 |

　　不支持 WSL 版本 1，因为 bubblewrap 需要仅 WSL2 提供的 Linux 内核功能（用户命名空间）。

### 沙盒不覆盖的内容 {#what-sandboxing-does-not-cover}

　　智能体沙盒是为其覆盖的进程增加的层。它不是虚拟机或用户账户边界、独立安全边界，也不能替代终端安全。沙盒不保护你显式注入的凭据。开发工具配置和缓存、允许路径、不受限或本地网络访问、非沙盒回退和绕过也会削弱隔离。

　　内置和其他非进程工具不受进程沙盒覆盖。智能体的读取、编辑和写入工具直接使用 VS Code 权限系统。

> **提示**：`chat.agent.networkFilter` 为 fetch 工具和集成浏览器提供网络域筛选，独立于终端沙盒。它不会为 Copilot 内置 shell 或 Windows 终端沙盒添加域筛选。请参阅[沙盒网络能力](../../work-with-ai/permissions-and-security/2.2.12.2-AgentSandboxing/)。

　　使用[审查流程](../../work-with-ai/2.2.8-ReviewAndRevertChanges/)和[敏感文件保护](../../work-with-ai/2.2.8-ReviewAndRevertChanges/#require-approval-before-sensitive-edits)控制这些操作。

　　[Dev Container 会话](../../work-with-ai/2.2.3-AgentsWindow/#run-a-session-in-a-dev-container)在项目容器内运行智能体及其工作区工具，容器位于你的计算机或受支持的连接主机。这不同于隔离代码更改的 Git 工作树和限制命令访问的终端沙盒。

　　Dev Container 不会自动阻止对主机或网络的所有访问。其边界取决于容器配置，包括挂载的主机文件夹、权限和网络。请审查该配置并继续使用适用的审批和安全控制。

　　智能体沙盒仍在发展，以覆盖更多工具和场景。

## 应注意的 AI 限制 {#ai-limitations-to-watch-for}

**错误输出。** 模型可能生成看起来正确但包含错误、使用已弃用 API 或未处理边界情况的代码。始终测试 AI 生成的代码，尤其是影响安全、数据完整性或关键流程的逻辑。

**提示词注入。** 文件、工具输出或网页中的恶意内容可能试图重定向智能体行为。这就是 VS Code 包含工具审批门和信任边界的原因。详细了解 [AI 安全](../../work-with-ai/permissions-and-security/2.2.12.3-AISecurity/)。

　　将 AI 生成输出视为初稿：作为起点有用，但始终需要你的审查和判断。关于模型如何工作（包括非确定性、知识边界和上下文限制），请参阅[语言模型](../2.7.2-HowModelsWork/)。
