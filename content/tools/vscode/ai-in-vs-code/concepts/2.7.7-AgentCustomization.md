# 2.7.7 智能体自定义

　　AI 模型拥有广泛知识，但这些知识不能替代项目当前需求或组织内部实践。智能体自定义通过添加持久上下文、可重复工作流、专门角色、外部工具和确定性控制，使智能体适应你的环境。

　　本文解释不同自定义类型的区别、适用时机以及它们能控制什么、不能控制什么。使用它为你工作流选择合适构建块。要安装、创建和验证自定义项，请参阅[为工作流自定义智能体](../../customize-and-extend/2.4.1-Overview/)。

> **提示**：按照动手教程了解自定义选项并为项目配置，请参阅[为项目自定义 AI](../../tutorials-and-guides/2.6.10-AdaptAgentsToYourProject/)。

## 自定义如何改变智能体 {#how-customization-changes-an-agent}

　　模型带来训练期间学习的一般知识。智能体将这些知识与提示词、当前对话和可用上下文（例如工作区文件）结合。组织内部实践和其他项目中的信息不会自动可用。自定义项提供可复用指导和额外能力访问，因此无需在每个提示词中提供相同上下文。

　　不同机制改变智能体工作的不同部分。指令和工作流引导模型决策。工具扩展可执行操作。钩子在智能体工作流特定位置运行命令（例如工具运行前后），而不依赖模型请求。插件打包相关自定义项以便安装和共享。

　　向指令文件添加规则不等同于执行验证脚本。两种机制本身都不建立安全边界。

　　相关自定义项通过从一开始为智能体提供项目上下文，减少往返和返工。避免纠正轮次和丢弃实现有助于减少 [AI 点数使用量](../../tutorials-and-guides/2.6.14-ReduceCreditUsage/)。保持自定义项聚焦，因为其内容也会占用模型上下文窗口空间。

## 自定义选项概览 {#customization-options-at-a-glance}

　　自定义类型在用途和激活方式上都不同。激活决定指导何时进入请求或操作何时运行。支持取决于[智能体运行框架](../2.7.6-AgentHarnesses/)——协调模型和工具的运行时，而不是所选语言模型。

| 需求 | 使用 | 示例 | 激活 |
|------|-----|---------|------------|
| 在项目中应用标准 | [始终启用的指令](../../customize-and-extend/2.4.4-Instructions/) | 要求特定日志库和错误处理模式 | 自动包含在每个请求中 |
| 将指导应用于特定代码或任务 | [基于文件的指令](../../customize-and-extend/2.4.4-Instructions/) | 智能体处理 `.tsx` 文件时应用 React 约定 | 文件模式匹配时包含。在 Local 会话中，智能体还可以按任务相关性加载指令。 |
| 教授带支持资源的 workflow | [智能体技能](../../customize-and-extend/2.4.3-AgentSkills/) | 通过指令、模板文件和设置脚本创建服务 | 智能体可以加载相关技能，或你直接调用 |
| 按需运行保存的任务 | [提示词文件](../../customize-and-extend/2.4.10-PromptFiles/) | 搭建 React 组件 | 将提示词作为斜杠命令调用（仅 Local 运行框架会话） |
| 使用专门角色和工具配置 | [自定义智能体](../../customize-and-extend/2.4.5-CustomAgents/) | 使用只读工具审查代码 | 选择智能体、将其用作子智能体或由另一个智能体委派 |
| 连接外部系统 | 手动配置的 [MCP 服务器](../../customize-and-extend/2.4.7-AddMCPServers/)或托管的 [Copilot 连接器](../../customize-and-extend/2.4.6-CopilotConnectors/) | 查询数据库或更新议题 | 任务需要时智能体调用 MCP 工具 |
| 在智能体工作流特定点运行代码 | [钩子](../../customize-and-extend/2.4.9-Hooks/) | 文件编辑后运行格式化程序或阻止危险命令 | 配置事件发生且执行条件满足时，运行框架运行钩子 |
| 安装打包自定义设置 | [智能体插件](../../customize-and-extend/2.4.2-Plugins/) | 添加包含技能、智能体、钩子和 MCP 服务器的测试工作流 | 每个捆绑自定义项遵循自己的激活规则 |

最接近的替代方案区别如下：

* **指令或技能**：指令提供常设指导，例如项目约定。技能描述如何执行特定任务，可以包含脚本、模板和其他资源。
* **技能或提示词文件**：技能可以为相关任务被发现或直接调用。提示词文件是保存的提示词，在 Local 运行框架会话中显式调用。
* **技能或自定义智能体**：技能提供工作流。自定义智能体定义执行工作的角色和工具配置，并可以将技能作为工作的一部分。
* **指令或自定义智能体**：`AGENTS.md` 文件为现有智能体提供指导。尽管名称如此，它不定义自定义智能体。

　　对于受支持服务，Copilot 连接器提供托管 MCP 连接，无需本地服务器设置或配置文件。需要其他集成或其配置选项时，请使用手动配置的 MCP 服务器。

　　一次性需求不需要自定义项，请将其添加到当前请求。问题反复出现时，[选择最小的有用自定义项](../../customize-and-extend/2.4.1-Overview/#choose-how-to-customize)。

## Marketplace 和可复用自定义项 {#marketplaces-and-reusable-customizations}

　　不必自己编写每个自定义项。Marketplace 帮助你发现社区发布者或组织的现有工作流和集成。

* **自定义项** 是智能体使用的指令、工作流、工具和其他构建块。
* **插件** 打包相关自定义项以便一起安装。插件可以包含技能、自定义智能体、钩子和 MCP 服务器。
* **插件 Marketplace** 是插件目录。添加 Marketplace 使其插件可浏览。安装插件使其支持的组件对运行框架可用。

　　**自定义 Marketplace** 是智能体自定义编辑器中统一的 **浏览** 体验（预览）。它汇集受支持来源，包括插件 Marketplace、GitHub 源和 Copilot 连接器。某些来源提供单个技能或 MCP 服务器，其他来源提供捆绑自定义项的插件。可用来源取决于运行框架和组织策略。

　　Marketplace 是发现和分发机制，不是另一种自定义类型。已安装组件保留自己的激活规则。安装前审查发布者、包含文件和设置要求，然后在工作流中测试结果。请参阅[发现和安装现有自定义项](../../customize-and-extend/2.4.1-Overview/#discover-and-install-existing-customizations-preview)。

## 模型驱动与确定性行为 {#model-driven-vs-deterministic-behavior}

　　大多数自定义项引导模型或为其提供更多选项。模型解释指令、判断技能是否相关并选择何时调用可用工具。结果取决于请求、可用上下文和模型推理。

　　运行时在配置事件发生时触发钩子，例如工具调用开始或结束。使用钩子执行验证工具调用或在编辑后启动格式化程序等操作。发现、信任、筛选、超时和错误处理仍会影响执行。当希望引导智能体如何推理或编写代码时，请使用指令。

　　例如，“编辑文件后运行格式化程序”的指令要求模型记住并执行该操作。配置为在编辑工具完成后运行的钩子会执行该操作，无论模型是否记住指令。

## 自定义项如何组合 {#how-customizations-combine}

　　自定义类型是构建块，不是互斥替代方案。以下拉取请求工作流展示它们如何协同，不是必须创建的最小设置。只添加工作流需要的部分：

1. **指令** 提供仓库编码标准和拉取请求约定。
2. **自定义智能体** 为智能体提供聚焦角色，并将其限制为任务所需工具。
3. **智能体技能** 提供准备拉取请求的步骤、脚本和模板。
4. **MCP 服务器** 提供从外部议题跟踪器检索相关议题的工具。
5. **钩子** 在智能体编辑文件后运行配置验证，或在运行前拒绝不允许的工具调用。

　　每一层有单独职责。可以在不更改工作流的情况下更新编码标准，或在不重写智能体角色的情况下替换外部系统。

　　插件可以分发完整配置（例如在组织内），使其他开发者可以安装相同技能和 MCP 服务器。

## 自定义作用域 {#customization-scope}

　　作用域决定自定义项在哪里可用以及谁可以共享。它独立于激活：工作区自定义项不一定包含在每个请求中。根据自定义类型，可以在一个或多个级别定义：

* **用户**：跨工作区对你可用。
* **工作区或仓库**：与项目一起存储，并通过源代码管理与贡献者共享。
* **组织**：集中管理并跨仓库共享（如果支持）。

　　选择与信息匹配的最窄作用域。个人偏好属于用户级别。项目架构和仓库特定工作流属于仓库。组织范围要求在该自定义类型支持时属于组织级别。

　　智能体[记忆](../../work-with-ai/sessions/2.2.11.1-ManageSessions/)独立于项目自定义。个人偏好或尚不适合共享的新观察使用本地记忆。将贡献者依赖的已审查项目规则和工作流放入仓库文档或自定义项，以便团队审查和维护。

　　并非每种自定义类型都支持每个作用域或智能体运行框架。创建文件之前，请[检查兼容性并选择作用域](../../customize-and-extend/2.4.1-Overview/#check-harness-compatibility)。企业策略可能进一步限制可用自定义项。
