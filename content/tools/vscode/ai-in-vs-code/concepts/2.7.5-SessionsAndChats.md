# 2.7.5 会话和聊天

　　会话是 VS Code 中与智能体一起工作的单位。它汇集任务的工作区和代码更改。聊天是会话中的对话，当运行框架支持时，一个会话可以包含多个聊天。

　　本文帮助你在开始新聊天、分叉对话和创建新会话之间选择。它解释聊天共享什么、如何完成单个对话以及如何跨界面继续工作或交接给另一个智能体。

　　要创建和组织会话，请参阅[管理智能体会话](../../work-with-ai/sessions/2.2.11.1-ManageSessions/)。

## 什么是会话 {#what-is-a-session}

　　会话包含一个或多个聊天。每个聊天记录提示词、智能体响应、工具调用以及沿途累积的[上下文](../2.7.3-Context/)。其对话历史会计入语言模型[上下文窗口](../2.7.2-HowModelsWork/#context-window)，不会自动与其他聊天或会话共享。

　　使用会话组织相关对话、跟踪进度并审查组合结果。

　　会话的[执行环境](../2.7.6-AgentHarnesses/#relate-execution-environments-and-code-isolation)决定它在何处处理代码。根据运行框架，会话可以在你的计算机或连接的主机上的工作区中工作，也可以在任一位置的 Dev Container 中工作。容器更改开发环境，不改变会话组织对话和任务的方式。

## 会话中的聊天 {#chats-within-a-session}

　　会话有一个主聊天。**嵌套会话**是分组在现有会话下的单独对话。可以独立提示每个嵌套会话。这不同于[子智能体](../../work-with-ai/plan-and-run-tasks/2.2.10.4-Subagents/)，后者由智能体启动以执行委派工作。

　　每个对话有自己的历史、标题、状态以及智能体或模型选择。嵌套会话默认使用父会话的文件夹或工作树。在智能体窗口中，受支持的运行框架允许嵌套会话使用其他文件夹、自己的工作树或无工作区。新嵌套会话从空白开始，不继承父会话中其他聊天的历史。

　　使用[混合运行框架聊天](../../work-with-ai/sessions/2.2.11.1-ManageSessions/#use-different-harnesses-in-a-session)时，每个聊天可以使用自己的运行框架、模型和权限设置，即使分组在使用其他运行框架的会话下。

　　在一个会话中运行多个聊天，可以同时针对同一代码库处理相关任务，而无需切换会话。了解如何[在一个会话中运行多个聊天](../../work-with-ai/sessions/2.2.11.1-ManageSessions/#run-multiple-chats-in-a-session)。

例如，你正在添加登录表单。使用一个聊天构建表单，同一会话中的另一个聊天编写测试。编写测试的聊天可以在实现文件保存后读取它们，但不会继承第一个聊天的对话。请在第二个聊天的提示词中包含“拒绝空电子邮件地址”等需求，而不是依赖之前讨论。

　　如果两个聊天使用相同文件夹或工作树，它们可以编辑相同文件。当需要单独工作目录时，请为嵌套会话选择 **新工作树**（如果支持），或使用带[工作树隔离](../../work-with-ai/2.2.3-AgentsWindow/#choose-where-an-agent-makes-changes)的单独顶级会话。

　　也可以[移动嵌套会话](../../work-with-ai/sessions/2.2.11.1-ManageSessions/)组织相关工作。移动更改会话分组，不更改其运行的文件夹或工作树。

## 选择新聊天、分叉或新会话 {#choose-a-new-chat-a-fork-or-a-new-session}

　　当仍在处理同一任务且对话历史相关时，继续使用同一聊天。需要单独对话时，根据是否保留该历史以及共享同一工作区来选择。

　　如果任务需要另一个文件夹或新 Git 工作树，不必开始新对话。在智能体窗口支持的单一聊天会话中，可以[移动现有聊天](../../work-with-ai/sessions/2.2.11.1-ManageSessions/)并在对话历史完整的情况下继续。

| 选择 | 使用时机 | 对话历史 | 工作区和代码更改 |
|--------|----------------|----------------------|----------------------------|
| [嵌套会话](../../work-with-ai/sessions/2.2.11.1-ManageSessions/#run-multiple-chats-in-a-session) | 处理相关任务但使用全新对话，例如为另一个聊天正在实现的功能编写测试。 | 不包含其他聊天历史。 | 默认使用父会话文件夹或工作树。受支持的嵌套会话可以使用其他文件夹或单独工作树。 |
| [分叉对话](../../work-with-ai/sessions/2.2.11.1-ManageSessions/#fork-a-chat-session) | 探索替代方法，同时保留目前需求和讨论。 | 继承源对话到分叉点。原始对话仍可用。 | 可以共享原始会话和工作树。分叉不保证代码更改独立。 |
| [新会话](../../work-with-ai/sessions/2.2.11.1-ManageSessions/) | 开始无关任务、在另一个项目中工作，或选择单独执行环境或工作树。 | 不包含先前聊天历史。 | 使用为新会话选择的文件夹或工作树。 |

　　分叉可以作为同一会话中的另一个聊天或新会话打开，取决于运行框架。分叉对话不同于创建 Git branch 或单独工作树。例如，Copilot 工作树会话的分叉会继续使用原始工作树。

> **重要**：单独对话不保证单独文件。如果两个聊天或会话使用相同文件夹或工作树，其编辑会影响相同文件。当更改必须隔离时，请为嵌套或顶级会话选择单独工作树（如果支持）。了解如何[选择智能体更改位置](../../work-with-ai/2.2.3-AgentsWindow/#choose-where-an-agent-makes-changes)。

　　会话可以并行运行，并在切换时继续运行。要将现有对话和受影响工作区文件返回到较早时间点而不是分叉对话，请参阅[恢复检查点](../../work-with-ai/2.2.8-ReviewAndRevertChanges/#restore-a-checkpoint)。

## 跨界面的会话 {#sessions-across-surfaces}

> **注意**：当 [GitHub Copilot 企业托管设置生效](../../../enterprise/7.2-ManageAISettings/#claude-and-codex-availability)时，Claude 和 Codex 运行框架会被禁用。此限制不会删除现有会话。请联系部署设置的 IT 团队讨论访问权限。

　　可以在聊天视图和智能体窗口中访问并继续同一活动 **Copilot** 或 **Claude** 会话。要在两个界面中使用 **Codex**，请配置[实验性 Codex 集成](../../choose-models-and-agents/2.3.2-ChooseAnAgentHarness/#codex)。在这些界面之间切换不会创建会话、分叉对话或更改其运行框架、工作区或工作树。

　　两个界面都提供会话主聊天，并在运行框架支持时提供嵌套会话。它们的导航和管理控件不同。每个界面的步骤请参阅[在一个会话中运行多个聊天](../../work-with-ai/sessions/2.2.11.1-ManageSessions/#run-multiple-chats-in-a-session)。

> **注意**：**对于 Local 运行框架会话：** 请在编辑器窗口中使用聊天视图。这些会话在智能体窗口中不可用。OpenAI Codex 扩展的会话也仅在编辑器中可用。

　　VS Code 还可以发现 GitHub Copilot CLI、GitHub Copilot 应用、Claude Code 和 Codex 中创建的受支持本地会话。在你从 VS Code 发送消息之前，发现的会话是外部会话。发送消息后，**外部** 筛选器不再控制其是否显示。了解如何[查看其他应用程序的会话](../../work-with-ai/sessions/2.2.11.1-ManageSessions/#view-sessions-from-other-applications)。

　　使用 Copilot 或 Claude，或通过[实验性集成](../../choose-models-and-agents/2.3.2-ChooseAnAgentHarness/#codex)使用 Codex 时，智能体还可以跨会话协调工作：列出会话、创建新会话或聊天、读取其他会话的最近上下文并在会话之间发送后续消息。

## 交接会话 {#hand-off-a-session}

　　交接使用不同的智能体配置继续正在进行的工作，并携带完整对话历史和上下文。交接可以更改[运行框架](../2.7.6-AgentHarnesses/)、执行环境或智能体角色。当另一个配置更适合任务下一部分时，请使用交接。

　　例如，使用 [Plan 智能体](../../work-with-ai/plan-and-run-tasks/2.2.10.1-PlanWork/)生成已审查计划，然后交接给实现智能体。要在[云会话](../../work-across-apps-and-machines/2.5.3-CloudSessions/)中工作，请启动单独会话。云会话不会接收本地会话交接。

> **注意**：**对于 Local 运行框架会话：** 也可以使用 **会话目标** 下拉列表将进行中的任务交接给 Copilot、Claude 或 Codex。该下拉列表仅在从 Local 运行框架会话开始交接时可用。目标会话使用所选运行框架的工具、权限和模型。

　　了解如何[交接进行中的会话](../../choose-models-and-agents/2.3.2-ChooseAnAgentHarness/#continue-with-a-different-harness)。

## 远程和同步会话 {#remote-and-synced-sessions}

　　会话不必在本地计算机上运行，也不必只留在一台设备上：

* **远程会话** 在你工作计算机之外的机器上运行。[GitHub Environments（预览）](../../work-across-apps-and-machines/2.5.2-RemoteAgentSessions/)注册该机器，以便跨受支持的 Copilot 客户端访问。对于 VS Code 专用访问，请通过 [SSH 或开发隧道](../../work-across-apps-and-machines/2.5.2-RemoteAgentSessions/)连接。主机、工作区和运行中的会话保留在远程机器上。
* **云会话** 在受管理的云环境中运行，而不是在你注册的机器上。请[重新打开现有云会话](../../work-across-apps-and-machines/2.5.3-CloudSessions/)重新连接并继续工作。这不会迁移现有本地对话，环境生命周期由服务管理。
* **同步会话** 备份到 GitHub 账户，以便跨设备访问。详细了解[同步会话](../../work-across-apps-and-machines/2.5.4-SessionHistory/)。
* **会话见解** 让你查询会话历史，以审查做过的工作。详细了解[会话见解](../../work-across-apps-and-machines/2.5.4-SessionHistory/)。

## 关闭聊天或完成工作 {#close-a-chat-or-finish-work}

　　关闭、标记完成和删除用途不同：

* **关闭聊天选项卡**：从聊天区域隐藏聊天，但不删除对话。之后可以重新打开。
* **将聊天标记为完成**：从活动会话列表移除已完成对话，同时保留标题和历史。想继续时可以恢复。
* **删除聊天**：永久移除对话。与关闭或标记完成不同，删除无法撤销。

　　在智能体窗口中，受支持的额外交聊可以独立标记为完成。这不会将主聊天、其他聊天或所属会话标记为完成。主聊天、侧边聊天和子智能体聊天不支持独立标记完成。

　　步骤和可用操作请参阅[管理会话中的聊天](../../work-with-ai/sessions/2.2.11.1-ManageSessions/#run-multiple-chats-in-a-session)和[将单个聊天标记为完成](../../work-with-ai/sessions/2.2.11.1-ManageSessions/#mark-an-individual-chat-as-done)。
