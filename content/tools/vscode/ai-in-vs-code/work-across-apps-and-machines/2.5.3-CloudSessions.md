# 2.5.3 云会话

　　云会话在受管理执行环境中运行智能体，因此无需保持开发机器在线即可工作。可以启动任务、发送后续指令，并从 VS Code 重新连接现有会话。代码和工具在云环境中运行，而不是在显示对话的设备上。

　　云会话通过将会话执行与当前客户端分离来支持连续性。

> **提示**：探索自己的私有仓库云会话，然后从普通终端继续同一对话，请遵循[云连续性教程](../../getting-started/2.1.5-CloudContinuityTutorial/)。

## 选择云端还是自己的机器 {#choose-cloud-or-your-own-machine}

| 选项 | 选择时机 |
|--------|----------------|
| **云会话** | 希望将智能体工具和更改移出本地机器，或在受管理云计算上工作，而无需维护主机或保持自己的机器在线。重新连接现有会话继续任务。 |
| **[GitHub Environments（预览）](../2.5.2-RemoteAgentSessions/)** | 希望跨受支持 Copilot 客户端访问现有开发机器上的会话。该机器及其 Agent Host 必须保持运行。 |
| **[SSH 或开发隧道](../2.5.2-RemoteAgentSessions/)** | 希望从 VS Code 特定访问另一台机器上的 agent host。 |

　　云执行将智能体活动与本地机器分离，但智能体仍可能影响云工作区及其有权访问的服务。请参阅[云会话安全注意事项](../../work-with-ai/permissions-and-security/2.2.12.3-AISecurity/)。

　　云会话目前仅支持 Copilot 运行框架。可以选择可用模型，但不能在云会话中切换到 Claude 或 Codex 运行框架。

## 前提条件 {#prerequisites}

* 使用有权访问云服务和目标仓库的 GitHub 账户登录。可用性取决于账户和组织。
* 开启 `chat.agentHost.cloudSandbox.enabled` 设置以创建和发现云会话。在智能体窗口中，这会为新的 **Cloud** 会话取代 GitHub Actions 上的 Copilot 云智能体工作流。
* 对于下面的仓库工作流，请选择账户可访问的 GitHub.com 托管仓库。

　　要阻止此客户端连接远程 agent host（包括云会话主机），请关闭 `chat.remoteAgentHostsEnabled`。

## 启动云会话 {#start-a-cloud-session}

　　可以在智能体窗口或聊天视图中启动云会话，前提是启用了云会话支持。

**智能体窗口**

1. 选择 **新建** 启动会话。
2. 选择 **云端** 环境，然后使用 **选择仓库...** 选择任务仓库。
3. 选择可用模型，审查会话可用模式和权限控制。
4. 输入任务及验证标准，然后发送提示词。
5. 等待云环境连接并准备仓库。智能体开始响应后，在会话中继续。

**聊天视图**

1. 创建新聊天。
2. 打开 **会话目标** 控件，选择 **云端** 选项。
3. 审查任务仓库。当前工作区中的单个 GitHub 仓库会自动选择。如果工作区有多个 GitHub 仓库，请在 **仓库** 选择器中选择一个。没有可用工作区仓库时，使用 **选择仓库...** 搜索 GitHub，或保持不变以启动无仓库云会话。
4. 选择可用模型，审查会话可用模式和权限控制。
5. 输入任务及验证标准，然后发送提示词。
6. 等待云环境和所选仓库准备就绪。智能体开始响应后，在会话中继续。

### 云工作区 {#cloud-workspace}

　　所选仓库会在云环境中准备。本地机器上的文件、依赖项、终端状态和未提交更改不会自动复制。请在提示词中提供智能体所需上下文，并使用云会话可用能力，不要假设本地扩展工具存在。

> **注意**：`chat.agentHost.cloudSandbox.earlyPreparation` 设置可以在编写提示词时、发送前准备云计算。默认关闭。

## 继续现有云会话 {#continue-an-existing-cloud-session}

要接续同一任务，请打开其现有会话，而不是创建另一个 **Cloud** 会话：

1. 使用拥有云会话的账户登录 VS Code。
2. 在[会话列表](../../work-with-ai/sessions/2.2.11.1-ManageSessions/)中找到会话。如果不可见，请检查仓库和列表筛选器。
3. 发送后续消息前打开会话并检查连接状态。
4. 连接后，在同一对话中发送下一条指令。

　　在智能体窗口中，打开或恢复云聊天会连接或唤醒其环境。要等到开始编写提示词或显式连接，请关闭 `chat.agentHost.cloudSandbox.autoConnectOnOpen`。

　　在聊天视图中，打开现有云会话会在环境已在线时连接，但不会自动唤醒离线环境。

　　记录在环境未连接时也可能可用。阅读历史不同于恢复实时工作。如果会话只读，请检查环境是否仍可用，并在尝试发送消息前连接。

　　云执行不依赖本地应用保持打开，但服务控制环境可用性和生命周期。不要将云环境视为永久存储，也不要假设记录保证环境正在运行。

## 审查工作并完成会话 {#review-work-and-finish-a-session}

　　整合前，在连接的会话中审查智能体更改和验证结果。要求运行相关测试并检查云环境中实际执行了什么。希望分享结果供审查时，请使用仓库 branch 和拉取请求工作流。

这些操作效果不同：

| 操作 | 效果 |
|--------|--------|
| 停止活动请求 | 请求取消当前智能体工作。不会撤销已完成编辑或外部操作。 |
| 关闭聊天或断开连接 | 结束交互或连接，不结束云环境生命周期。 |
| 将会话标记为完成 | 组织已记录任务。不是计算关闭控件。 |
| 删除会话 | 删除云任务。不确认底层计算环境是否已删除。 |

　　服务独立于会话列表管理云资源。删除任务或依赖之后的环境访问前，请将所需工作保存在仓库中。

## 排查云会话 {#troubleshoot-cloud-sessions}

| 症状 | 检查内容 |
|---------|---------------|
| 云会话创建不可用 | 检查功能可用性、账户访问、组织限制和 `chat.remoteAgentHostsEnabled`。 |
| 仓库无法选择或克隆 | 使用 GitHub.com 仓库和有权访问它的账户。重试前检查报告的仓库或身份验证错误。 |
| 现有会话缺失 | 使用拥有账户，检查仓库分组和会话筛选器。已删除任务不是可恢复的现有会话。 |
| 记录打开但无法接受消息 | 检查环境可用性和连接状态。仅历史不提供活动主机。 |
| 本地工具或文件缺失 | 云执行使用自己的工作区和工具。本地编辑器状态和已安装扩展不会自动可用。 |
