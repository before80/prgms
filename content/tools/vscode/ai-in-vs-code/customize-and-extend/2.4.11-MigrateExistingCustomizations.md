# 2.4.11 迁移现有自定义项

　　将现有 Local 自定义项迁移到 Copilot 运行框架，同时保留依赖的工作流。使用迁移列表执行支持的文件移动和转换，然后用代表性任务验证结果，再停用原始设置。

　　从下面适合你的自定义项路径开始。不需要完成本文中的每个迁移。关于保留 Local、MCP 机密、自定义发现路径和智能体工具名称的答案，请参阅[迁移常见问题](#frequently-asked-questions)。

　　更广泛的工作流过渡（包括会话连续性、组织推广和策略验证）请遵循[从 Local 迁移到 Copilot 运行框架](../../choose-models-and-agents/2.3.3-MoveFromLocalToCopilot/)。

> **注意**：本文介绍迁移到 Copilot 运行框架。Claude 或 Codex 运行框架请使用提供商文档中的位置和格式。
>
> 当 [GitHub Copilot 企业托管设置生效](../../../enterprise/7.2-ManageAISettings/)时，Claude 和 Codex 运行框架会被禁用。请联系部署设置的 IT 团队讨论访问权限。

## 选择迁移路径 {#choose-a-migration-path}

| 现有自定义项 | 目标或替代 | 迁移方式 | 重新检查 |
|------------------------|----------------------------|----------------|-----------------|
| 工作区或配置文件 MCP 服务器 | 可移植 Copilot MCP 配置 | [迁移兼容服务器条目](#migrate-mcp-servers)。手动审查不支持的属性。 | 身份验证、可用工具、启用状态和沙盒设置 |
| 工作区或用户提示词文件 | 项目或用户技能 | [转换提示词文件](#convert-prompt-files-to-skills)。工作流还需要智能体或工具配置时使用 **使用智能体迁移**。 | 显式调用以及省略的 `agent`、`model` 或 `tools` 属性 |
| 配置文件用户数据中的智能体和指令 | Copilot 用户文件夹 | [移动用户自定义项](#move-user-agents-and-instructions)。 | 新 Copilot 会话中的发现和行为 |
| 已配置搜索位置中的文件 | 原生工作区或用户文件夹 | [从配置位置移动文件](#move-customizations-from-configured-locations)。 | 目标作用域和重复活动副本 |
| 文件、设置、智能体或插件中的钩子 | 受支持 Copilot 钩子源和脚本 | [手动迁移钩子](#migrate-hooks)。没有自动钩子转换。 | 事件时机、脚本输入输出、审批和失败路径 |
| 用户定义工具集 | 工作流特定工具配置 | [替换工具集引用](#replace-tool-sets)。 | 所需能力和工具限制 |
| 聊天参与者 | 发布者提供的替代品或直接智能体请求 | [替换参与者工作流](#replace-chat-participants)。 | 服务访问、附加上下文和预期结果 |
| 插件或扩展提供的自定义项 | 兼容安装 | [单独管理](#customizations-without-automatic-migration)。 | 发布者设置、运行框架兼容性和所需扩展 |

　　只有维护参与者实现时才使用[发布者指南](#if-you-maintain-a-participant)。安装替代品不需要构建插件。

## 打开迁移列表 {#open-the-migration-list}

更改自定义项之前：

* 提交或备份可能更改的工作区文件、脚本和用户设置。
* 选择在原始自定义项下可工作的小任务。记录预期结果、所需工具和审批，以便迁移后比较。
* 审查每个项的源和目标。原始副本和迁移副本不会同步。
* 如果不维护仓库，请使用 **使用智能体迁移** 准备拉取请求，或请仓库维护者进行更改。

　　工作区需要自定义迁移时，聊天中会出现通知。选择 **审查迁移** 打开列表。要直接打开：

1. 在聊天视图或智能体窗口中，选择 **Copilot** 作为 **会话目标**。
2. 从命令面板（`Ctrl + Shift + P`，macOS：`Cmd + Shift + P`）运行 **Chat: Open Customizations**。
3. 选择 **迁移**。

　　迁移树按工作区和用户作用域分组检测到的工作。

选择迁移处理方式：

* **迁移**：选择组中的项，可用时审查或更改目标，然后选择 **迁移**。VS Code 执行支持的文件移动或转换。
* **使用智能体迁移**：在聊天中为需要语义更改或仓库工作的自定义项启动引导式迁移。此操作使用 Copilot 点数。智能体创建恢复包，默认保留源文件，并在清理源之前单独询问。工作区迁移可以准备拉取请求。
* **审查**：打开 **需要手动审查** 下的项，了解无法自动迁移的原因并编辑其源配置。

　　不想现在处理某组时，使用迁移组操作中的 **忽略**。选择 **显示已忽略的迁移** 恢复已忽略组。

　　保留备份，直到[验证迁移](#verify-the-migration)。自动 MCP 迁移会移除成功迁移的源条目，而 **使用智能体迁移** 默认保留源文件。原始文件仍存在时，仅在验证后停用，避免两个副本都处于活动状态。

## 为什么需要迁移 {#why-migration-is-needed}

　　Copilot 运行框架从 Copilot 文件夹和可移植格式读取自定义项。将自定义智能体、指令和技能从编辑器特定存储和配置的自定义位置移到原生运行框架文件夹，以便跨 Copilot 客户端发现。VS Code 可以[转发配置位置中的文件](#move-customizations-from-configured-locations)以兼容现有编辑器工作流，但其他客户端不会继承这些设置。

> **注意**：**对于 Local 运行框架会话**：智能体读取 VS Code 配置文件自定义项以及通过这些设置配置的额外位置。为 Copilot 运行框架移动自定义项不会改变 Local 运行框架读取的源。

将自定义项移到这些位置有以下好处：

* Copilot 运行框架可以直接加载它们，无需依赖编辑器提供。
* 工作区自定义项保留在仓库中，可以通过源代码管理共享。
* VS Code 和 Copilot CLI 读取相同的 Copilot 自定义文件。GitHub Copilot 应用也使用仓库和 Copilot CLI 技能及 MCP 服务器配置。
* 可以移除旧位置设置，避免维护重复副本。

　　目标取决于迁移类型和作用域。用户数据迁移保留用户作用域。工作区迁移保留在工作区。迁移树显示每组选择的目标。

　　自定义类型和受支持位置的完整列表请参阅 [Copilot 自定义速查表](https://docs.github.com/en/copilot/reference/customization-cheat-sheet)。这些自定义项在 [GitHub Copilot 应用](https://docs.github.com/en/copilot/how-tos/github-copilot-app/customize-github-copilot-app)中的显示方式请参阅相关文档。

## 迁移 MCP 服务器 {#migrate-mcp-servers}

　　MCP 服务器迁移将兼容配置移到 Copilot 运行框架直接读取的文件：

| 现有配置 | 目标 |
|------------------------|-------------|
| 工作区 `.vscode/mcp.json` | 对应工作区根目录的 `.mcp.json` |
| VS Code 配置文件 `mcp.json` | `$COPILOT_HOME/mcp-config.json`，未设置 `COPILOT_HOME` 时为 `~/.copilot/mcp-config.json` |

　　自动迁移将工作区服务器写入工作区根目录 `.mcp.json`。团队应共享配置时，请将文件提交到源代码管理。远程或 Dev Container 会话中，路径和用户配置属于智能体运行的机器或容器。

迁移 MCP 服务器：

1. 展开工作区或配置文件的 **MCP 服务器** 组。
2. 选择要迁移的服务器。
3. 审查源、目标以及目标格式无法保留的属性。
4. 为组选择 **迁移**。也可以打开单个服务器并从详情页选择 **迁移**。
5. 打开目标文件，用 Copilot 运行框架测试服务器。

　　VS Code 在从源文件移除迁移条目之前，会写入并验证每个目标条目。未选择的服务器和无法迁移的服务器保留在当前文件中。

　　带更改的迁移可能移除 VS Code 特定元数据，包括注册表更新信息、版本元数据、开发模式行为或每服务器沙盒设置。迁移页面列出每个服务器的更改。

> **重要**：禁用状态不存储在 `.mcp.json` 或 `mcp-config.json` 中。VS Code 尽可能在当前配置文件中保留工作区禁用状态，但用户级禁用状态可能丢失。其他 Copilot 客户端和其他机器可能将迁移服务器视为已启用。使用前请在每个客户端中审查服务器的启用状态。

　　无法自动迁移的服务器出现在 **需要手动审查** 下。选择 **审查** 打开服务器详情和源配置。解决配置错误、缺失值或重复服务器名称，然后重试。也可以使用 **使用智能体迁移** 获得引导帮助。MCP 格式和受支持位置请参阅 [MCP 配置参考](../../reference-and-help/reference/2.8.1.8-MCPConfiguration/)。

### 迁移前检查 MCP 值 {#check-mcp-values-before-migration}

使用下表判断服务器能否自动迁移以及需要审查什么。

| 源配置 | 迁移结果 | 操作 |
|----------------------|------------------|------------|
| 标准 `command`、`args`、`env`、`url` 和 `headers` 值 | 自动迁移并添加 `tools: ["*"]` | 检查服务器工具。不希望所有服务器工具可用时，将 `*` 替换为 Copilot 应调用的特定工具。 |
| `${workspaceFolder}`、`${workspaceRoot}`、`${workspaceFolderBasename}`、`${workspaceRootFolderName}`、`${cwd}` 或 `${pathSeparator}` | VS Code 解析变量并写入当前值后迁移 | 共享目标文件或在其他机器使用前审查结果值。 |
| `gallery`、`version`、`dev` 或 `sandboxEnabled` | 带更改迁移并移除这些属性 | 审查迁移警告。决定迁移后如何处理更新、开发行为或沙盒。 |
| 同一源文件中声明的合格非密码 `promptString` 或 `pickString` 输入 | 迁移为环境变量引用 | 审查生成的变量名和默认值。Stdio 条目可以在 `env` 中包含默认或空值。HTTP 条目在 URL 或标头中使用引用。 |
| 密码输入、命令输入、`${command:...}` 或其他不支持变量 | 不会自动迁移 | 如果环境变量满足要求，[将输入替换为环境变量引用](#replace-input-prompts-with-environment-variables)。不要将已解析机密复制到 MCP 文件。 |
| `${config:...}` | 合格设置引用根据有效设置值迁移为环境变量条目 | 共享文件前审查生成值。与环境变量引用不同，此转换可能将设置值写入目标配置。 |
| `${env:NAME}` | 合格引用自动迁移为 `${NAME}` | 保留引用，不写入解析后的环境值。在运行或连接服务器的宿主环境中定义变量。 |
| `cwd` | 不会自动迁移 | 仅在服务器需要时手动添加 `cwd`，并在智能体运行的机器上验证路径。 |
| `envFile` | 不会自动迁移 | 在启动智能体的环境中导出所需变量，并从 `env` 引用。不要将机密值复制到 MCP 文件。 |
| SSE 传输 | 不会自动迁移 | 仅在服务器不支持 Streamable HTTP 时使用 `type: "sse"`。SSE 已弃用。 |
| VS Code `oauth` 对象 | 不会自动迁移 | 移除嵌套对象以使用 OAuth 发现，或将支持的客户端设置转换为扁平 Copilot OAuth 字段。Copilot 提示时进行身份验证。 |
| 值为 `null` 的环境变量 | 不会自动迁移 | 移除条目或提供支持的值。 |
| 额外 VS Code 特定属性 | 不会自动迁移 | 重试前移除或替换不支持的属性。 |
| 目标或另一工作区根目录中同名但不同的服务器 | 迁移停止，不更改源 | 重命名或移除冲突服务器，然后重试。 |

　　输入变量需要特别注意。VS Code MCP 格式可以通过 `${input:api-key}` 提示输入 API 密钥等值。Copilot MCP 格式不使用此输入流程。迁移会将合格非机密输入转换为环境变量，但密码和命令输入需要手动更改。

> **重要**：VS Code 每服务器沙盒设置和顶级 `sandbox` 规则不会转移到 Copilot 运行框架配置。Copilot 运行框架使用会话级沙盒设置。仅当启用本地沙盒和 MCP 服务器沙盒时，本地 stdio MCP 服务器才会在 Copilot 运行框架沙盒中运行。远程 HTTP 和 SSE 服务器不会在本地沙盒中运行。启用迁移服务器前请审查这些设置。

服务器需要手动处理时：

1. 保留原始配置，直到 Copilot 服务器启动并提供预期工具。
2. 打开源配置，识别每个不支持的字段或变量。
3. 目标配置请遵循 [Copilot CLI MCP 服务器指南](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-mcp-servers)。
4. 决定如何提供机密、身份验证或环境特定路径。不要将敏感值复制到已提交文件。
5. 从 Copilot 运行框架测试服务器后，再移除原始条目。

### 将输入提示替换为环境变量 {#replace-input-prompts-with-environment-variables}

　　可移植 `.mcp.json` 和 Copilot 用户 `mcp-config.json` 支持环境变量引用。如果安全要求允许环境变量，请使用它们替代输入提示。这使凭据值不进入配置文件，但不提供提示或机密存储。

例如，`.vscode/mcp.json` 中的 HTTP 服务器可能使用 `"Authorization": "Bearer ${input:api-key}"`。创建使用 `${SERVICE_API_KEY}` 的对应可移植条目：

```json
{
    "mcpServers": {
        "service": {
            "type": "http",
            "url": "https://api.example.com/mcp",
            "headers": {
                "Authorization": "Bearer ${SERVICE_API_KEY}"
            },
            "tools": ["*"]
        }
    }
}
```

　　将示例 URL 替换为服务器终结点。对于 stdio 服务器，在 `env` 值中引用变量：

```json
{
    "env": {
        "API_KEY": "${SERVICE_API_KEY}"
    }
}
```

　　将此 `env` 对象添加到服务器现有命令和参数。要更新可移植条目，请使用 **Chat: Open Customizations** > **MCP 服务器**，选择服务器，在[配置表单](../../work-with-ai/plan-and-run-tasks/2.2.10.2-UseTools/)中编辑标头或环境变量。输入引用而不是凭据值，然后选择 **保存**。

测试前：

1. 通过组织批准的环境或凭据注入机制提供 `SERVICE_API_KEY`。它必须对运行 stdio 服务器或连接 HTTP 服务器的宿主可用。
2. 远程或 Dev Container 会话中，在该宿主或容器中配置变量。在无关终端设置不会更新已运行的 Agent Host。如果更改启动环境，请重启受影响客户端或 Agent Host 以继承更改。
3. 验证服务器连接且工具在 Copilot 会话中可用。仅在不再有服务器使用旧输入声明后移除它，并在验证后停用原始服务器条目。

　　在可移植文件中使用 `${NAME}`，而不是 VS Code 特定的 `${env:NAME}`。非机密默认值也支持 `${NAME:-default}`。不要在默认值中放置机密，也不要在表单或 JSON 中用字面凭据替换引用。

　　环境变量不是机密存储。此迁移不满足同时避免环境变量和文件凭据的要求。请参阅[提示式机密限制](#can-copilot-pass-a-prompted-secret-to-an-http-mcp-server-without-an-environment-variable-or-a-file)。

## 将提示词文件转换为技能 {#convert-prompt-files-to-skills}

　　Copilot 运行框架会话使用[智能体技能](../2.4.3-AgentSkills/)处理可复用工作流，不加载 `*.prompt.md` 文件。将工作区和用户提示词文件转换为技能，以便在 Copilot 运行框架中使用。Local 运行框架会话仍支持提示词文件。

> **重要**：转换通过向生成的技能添加 `disable-model-invocation: true` 保留显式调用。如果以后移除该限制，智能体可以在相关任务中自动选择技能。为共享技能启用自动调用前，请与仓库维护者一起审查描述和指令。个人工作流请转换为用户技能。

转换提示词文件：

1. 展开工作区或个人配置文件的 **将提示词转换为技能**。
2. 选择要转换的提示词文件。
3. 审查源和目标。需要检查时打开提示词。
4. 选择 **迁移**。

　　转换将提示词文件的 `name`、`description` 和参数指导映射到技能。它不保留提示词特定的 `agent`、`model` 或 `tools` 选择。VS Code 会在迁移后列出省略的属性。如果提示词依赖特定智能体、模型或工具集，请使用 **使用智能体迁移** 创建对应自定义智能体或适配工作流。

　　在新的 Copilot 会话中显式调用转换后的技能，并将其输出和工具活动与原始提示词结果比较。单独检查任何替代智能体或工具限制。仅在工作流满足要求后移除旧提示词文件。

## 移动用户智能体和指令 {#move-user-agents-and-instructions}

　　Copilot 运行框架不读取存储在 VS Code 配置文件用户数据中的自定义智能体和指令。用户自定义迁移将智能体复制到 `~/.copilot/agents`，将指令复制到 `~/.copilot/instructions`，不更改名称、类型或内容。

移动用户自定义项：

1. 在 **你的配置文件** 下展开 **用户数据**。
2. 选择要移动的自定义智能体和指令。
3. 审查组显示的用户目标。
4. 选择 **迁移**。

　　迁移文件不包含在[设置同步](../../../editor/3.3-ConfigureTheEditor/3.3.5-SettingsSync/)中。

　　迁移后，启动 Copilot 运行框架会话并验证智能体和指令可用。受支持目标请参阅[自定义智能体位置](../../reference-and-help/reference/2.8.1.5-CustomAgentFileReference/)和[指令文件位置](../../reference-and-help/reference/2.8.1.6-CustomInstructionsReference/)。

## 从配置位置移动自定义项 {#move-customizations-from-configured-locations}

　　使用原生 Copilot 文件夹，而不是添加自定义搜索位置。原生位置让运行框架无需依赖编辑器即可发现自定义项。Copilot CLI 和 GitHub Copilot 应用不会继承 VS Code 位置设置。

　　以下设置仍受支持以兼容现有编辑器工作流，且未弃用：

* `chat.agentFilesLocations`
* `chat.instructionsFilesLocations`

　　`chat.agentSkillsLocations` 设置已弃用。请将技能移到原生运行框架文件夹，而不是添加新技能搜索位置。旧的 `chat.modeFilesLocations` 设置也已弃用。

　　VS Code 将其他配置位置发现的文件转发到 Agent Host 运行框架（包括 Copilot）。运行框架本身不读取这些设置。额外位置补充运行框架的内置位置，不会移除它们。

　　尽管这些设置仍受支持，但不建议在 Copilot 工作流中使用自定义位置，因为它们是编辑器特定的。如果 MCP 工具下载专业智能体，请更新它写入原生工作区或用户智能体文件夹，而不是添加另一个搜索位置。

将现有文件移到其作用域的原生 Copilot 文件夹：

| 自定义项 | 工作区目标 | 用户目标 |
|---------------|-----------------------|------------------|
| 自定义智能体 | `.github/agents` | `~/.copilot/agents` |
| 指令 | `.github/instructions` | `~/.copilot/instructions` |
| 技能 | `.github/skills` 或 `.agents/skills` | `~/.copilot/skills` 或 `~/.agents/skills` |

迁移自定义位置：

1. 展开工作区或个人配置文件的 **自定义位置设置**。
2. 选择要移动的智能体、指令和技能。
3. 审查或更改组的目标。
4. 选择 **迁移**。

　　`chat.promptFilesLocations` 中的提示词文件由[提示词文件迁移](#convert-prompt-files-to-skills)处理，而不是位置迁移。

　　独立 Copilot CLI 不会继承这些编辑器设置。它通过 `COPILOT_CUSTOM_INSTRUCTIONS_DIRS` 单独支持额外指令目录。VS Code 不会迁移或清除该环境变量。

> **注意**：即使文件通过编辑器转发工作，迁移列表也可能建议移动配置位置中的文件。请审查目标，并在迁移后避免留下重复活动副本。迁移建议行为记录在 [microsoft/vscode#342185](https://github.com/microsoft/vscode/issues/342185)。
## 验证迁移 {#verify-the-migration}

完成自定义项的迁移路径后：

1. 在打算使用的仓库和环境中启动新的 Copilot 运行框架会话。
2. 确认迁移的智能体、指令、技能、MCP 服务器或插件出现在智能体自定义编辑器中。这检查发现，不检查是否工作。
3. 重复迁移前选择的代表性任务，不要重述自定义项指导。
4. 通过引用、工具活动或钩子执行日志检查实际包含或调用情况。将输出、工具和审批与预期结果比较。
5. 对于替换的工具集，检查缺失能力和保留的工具限制。对于替换的参与者，测试其工作流、服务不可用错误、审批和任何 MCP 应用交互。
6. 检查旧副本和迁移副本没有同时活动。
7. 团队应共享工作区迁移时，审查并提交。仅在迁移后的自定义项工作后移除剩余旧文件和设置。

　　远程或 Dev Container 会话中，请在目标环境执行这些检查。用户自定义文件夹属于智能体运行的机器或容器。钩子迁移还需要下面的[脚本和实时会话检查](#verify-before-retiring-the-original)。

## 无法自动迁移的自定义项 {#customizations-without-automatic-migration}

迁移列表不会自动转换每种自定义类型：

* **具有 Local 运行框架特定行为的自定义智能体**：智能体依赖 Local 工具名称、工具集、钩子或其他需要语义更改的行为时，使用 **使用智能体迁移**。
* **工具集**：已弃用，Copilot 运行框架不支持。[替换工具集引用](#replace-tool-sets)为工作流配置的工具。
* **聊天参与者**：已弃用，Copilot 运行框架不支持。[替换参与者能力](#replace-chat-participants)为结合技能、MCP 工具以及需要时 MCP 应用的插件。
* **钩子**：没有自动钩子迁移。请遵循[迁移钩子](#migrate-hooks)审查发现、命令配置、脚本输入和输出决定。
* **插件和 Marketplace**：与迁移列表分开管理。请参阅[发现和安装插件](../2.4.2-Plugins/)。
* **扩展提供的自定义项**：扩展可以提供工具、MCP 服务器、自定义智能体、技能和指令。保持贡献扩展安装。扩展工具仅在扩展运行时在编辑器聊天中可用。了解如何[为 Copilot 运行框架管理扩展工具](../../work-with-ai/plan-and-run-tasks/2.2.10.2-UseTools/)。

## 迁移钩子 {#migrate-hooks}

迁移钩子的配置**和**脚本。文件可以在 Copilot 运行框架中加载，但其脚本不再匹配工具、读取错误参数或返回目标不使用的输出。仅复制文件或更改事件名称不能验证迁移。

　　此过程适用于个人钩子和共享钩子。VS Code、GitHub Copilot 应用和 Copilot CLI 使用相同 Copilot 运行框架和钩子格式。迁移是从旧 Local 钩子契约到该共享契约，而不是迁移到命令行工具。

　　[Copilot 钩子参考](https://docs.github.com/en/copilot/reference/hooks-reference)记录共享配置和命令钩子负载。[Local 钩子参考](../../reference-and-help/reference/2.8.1.9-HooksReference/)描述现有 Local 钩子的源格式。

### 准备迁移钩子 {#prepare-hooks-for-migration}

编辑配置或启动 Copilot 会话前：

1. 备份原始配置**及其**脚本，包括不在源代码管理中的用户设置。
2. 记录哪些钩子被 Local 发现设置启用、禁用或排除。`chat.useHooks`、`chat.useClaudeHooks` 和 `chat.hookFilesLocations` 不会在 Copilot 运行框架中保留这些选择。以前忽略的文件可能未经移动就变为活动。
3. 将未验证配置放在发现源之外。例如，用 `.json.disabled` 后缀暂存独立文件，并使用新脚本文件名而不是覆盖原始文件。内联设置请在合并前单独准备新的 `hooks` 条目。
4. 使用目标控件保留有意禁用的钩子。不要同时激活原始配置和转换后的配置。

　　独立 Copilot 钩子文件中，顶级 `disableAllHooks: true` 仅跳过该文件中的钩子。仓库 Copilot 设置中，同一属性跳过该仓库所有非策略源的钩子。策略钩子不会被此控件禁用。请参阅[禁用钩子](https://docs.github.com/en/copilot/reference/hooks-reference#disable-all-hooks)，并与管理员协调托管钩子更改。

### 查找每个钩子源 {#find-every-hook-source}

更改前清点每个配置及其调用的脚本。个人钩子保留在用户作用域，共享钩子保留在其仓库或插件中。

| 源 | Copilot 运行框架需审查的内容 |
|--------|---------------------------------------|
| 仓库钩子文件 | 使用仓库根目录 `.github/hooks/*.json`。审查脚本路径以及 JSON。 |
| 用户钩子文件 | 使用 `~/.copilot/hooks/` 下的 `*.json`，Windows 上为 `%USERPROFILE%\.copilot\hooks\`。设置 `COPILOT_HOME` 时 Copilot 使用 `$COPILOT_HOME/hooks/`。检查目标进程的主目录。 |
| 额外 Local 位置 | `chat.hookFilesLocations` 不配置 Copilot 发现。将配置及其依赖项移到受支持源，或将共享钩子打包到插件中。 |
| 仓库设置 | Copilot 运行框架读取 `.github/copilot/settings.json` 和 `.github/copilot/settings.local.json` 中的内联 `hooks` 映射。它也读取仓库 `.claude/settings.json` 和 `.claude/settings.local.json`。保留其他设置；不要用独立钩子文件信封替换设置文件。 |
| 用户设置 | Copilot 从 `~/.copilot/settings.json` 读取内联钩子，而不是 `~/.copilot/config.json`。不要假设 `~/.claude/settings.json` 中的 Local 钩子会被 Copilot 发现。请将其移到文档化的 Copilot 用户源。 |
| 自定义智能体 frontmatter | 保留智能体的 `hooks` 映射并审查[智能体作用域钩子契约](https://docs.github.com/en/copilot/reference/hooks-reference#agent-scoped-hooks)。VS Code 会转发转换后智能体（包括插件提供的智能体）的作用域钩子。完成迁移前验证执行和预期决定。Copilot 从远程或组织托管智能体定义中排除作用域钩子。 |
| 已安装插件 | 更新插件源包或从发布者获取更新版本。不要修补安装缓存。将脚本与插件一起保留，并审查其路径变量、事件和负载。请参阅[插件中的钩子](../../reference-and-help/reference/2.8.1.7-AgentPluginAuthoringReference/)。 |
| 管理员托管钩子 | 与管理员协调更改。策略钩子和托管插件钩子与个人文件有不同发现和信任规则。请参阅[企业钩子控制](../../../enterprise/7.2-ManageAISettings/)。 |

　　Copilot 运行框架组合来自多个源的适用钩子；添加仓库副本不会替换用户或插件副本。避免同时运行原始钩子和迁移钩子。跨仓库使用的共享设置，请考虑将转换后的钩子和脚本分发到插件中，而不是复制到每个仓库。

　　插件级钩子和插件提供智能体 frontmatter 中的钩子是独立配置。打包智能体时，将其作用域钩子保留在 frontmatter 中。将它们移到插件级或仓库级执行会扩大触发它们的智能体范围，不是等价迁移。

### 比较配置和脚本契约 {#compare-configuration-and-script-contracts}

下表比较 [Local 实现](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/workbench/contrib/chat/common/promptSyntax/hookSchema.ts)与文档化的 [Copilot 命令钩子契约](https://docs.github.com/en/copilot/reference/hooks-reference#command-hooks)。兼容性别名不会使两个执行环境完全相同。

| 领域 | 现有 Local 钩子 | Copilot 迁移操作 |
|------|---------------------|--------------------------|
| 文件格式 | `hooks` 事件映射，通常使用 PascalCase 名称。Local 也接受 Copilot 事件和命令别名。 | 使用带 `version: 1` 的文档化独立 JSON 格式，或在受支持设置文件中使用内联 `hooks` 映射。 |
| 命令选择 | `command`，带 `windows`、`linux` 和 `osx` 覆盖。Local 也接受 `bash` 和 `powershell`。 | 独立命令钩子将 `command` 记录为后备，将 `bash` 或 `powershell` 记录为平台命令。需要时在脚本中保留单独的 Linux 和 macOS 行为。智能体作用域钩子也记录 `windows`、`linux` 和 `osx`；不要假设每个源支持相同字段。 |
| 参数 | 事件数据通过 stdin 到达，不是位置命令参数。 | 继续从 stdin 读取 JSON。带 `args` 的 `exec` 是单独的无 shell 调用选项，不是事件负载映射。不要与 shell 命令字段组合。 |
| 工作目录 | 相对 `cwd` 从工作区根解析；Local 也解析绝对路径和 `~`。 | Copilot 支持仓库相对或绝对 `cwd`。将用户钩子、插件或工作区移到远程主机或工作树时重新检查路径。 |
| 环境 | `env` 向扩展宿主继承环境添加值。 | 审查目标的继承变量和文档化展开规则。`env` 和 `cwd` 都不会授予额外沙盒访问。 |
| 超时 | 默认 30 秒。两者都存在时 Local 优先 `timeout`。 | 默认 30 秒。Copilot 优先 `timeoutSec` 而不是其 `timeout` 别名。只指定一个字段。 |
| 通用输入 | ISO 时间戳、`session_id`、`hook_event_name` 和可选记录信息。 | camelCase 事件使用 `sessionId` 和数字 epoch 毫秒 `timestamp`。PascalCase 别名选择兼容的 snake_case 字段和 ISO 时间戳。 |
| 工具输入 | `tool_name`、`tool_input` 和 `tool_use_id`。 | camelCase 事件使用 `toolName` 和 `toolArgs`。PascalCase `PreToolUse` 可能报告 `Read`、`Write` 或 `Edit` 等名称，而不是运行时名称。检查实际工具参数；名称和 schema 不是 Local 的一对一映射。 |
| 工具结果 | `PostToolUse` 接收 `tool_response`。 | `postToolUse` 接收 `toolResult`；兼容格式使用 `tool_result`。重写结果读取器，而不仅是输入读取器。 |
| 工具决定 | 嵌套 `hookSpecificOutput.permissionDecision` 和可选 `updatedInput`。 | 使用文档化顶级 `permissionDecision`、`permissionDecisionReason` 和 `modifiedArgs`。没有钩子决定时返回 `{}`，不要用 `allow` 授予批准。 |
| 工具后上下文 | `hookSpecificOutput.additionalContext`。 | 返回顶级 `additionalContext`。工具后钩子在操作完成后运行，不能撤销已完成操作。 |
| 退出代码 | 退出 `2` 表示阻止。其他非零退出产生非阻塞警告。 | GitHub 将命令 `preToolUse` 错误和非零退出记录为拒绝工具，但超时记录为继续正常权限。其他事件有不同失败行为。测试每个事件的错误路径。 |

　　完整输出和失败规则请参阅 [Copilot 决定控制](https://docs.github.com/en/copilot/reference/hooks-reference#pretooluse-decision-control)和[命令钩子退出代码](https://docs.github.com/en/copilot/reference/hooks-reference#exit-codes-for-command-hooks)。

### 审查事件时机 {#review-event-timing}

使用下表找到智能体工作流中相同位置对应的事件，不要将其视为机械重命名列表。将配置事件从 PascalCase 改为 camelCase 也会改变其 stdin 负载。

| Local 事件 | Copilot 事件 | 需验证行为 |
|-------------|---------------|--------------------|
| `SessionStart` | `sessionStart` | Copilot 包括新会话和恢复会话。不要假设 `source` 始终为 `new`。 |
| `UserPromptSubmit` | `userPromptSubmitted` | 在提交提示词时运行。此事件的命令钩子输出被忽略；程序化 SDK 提示词重写不是 shell 钩子功能。 |
| `PreToolUse` | `preToolUse` | 在工具执行前运行。验证工具名称、参数 schema 和权限结果。 |
| `PostToolUse` | `postToolUse` | 在工具成功后运行。Copilot 有单独的 `postToolUseFailure` 事件。 |
| `PreCompact` | `preCompact` | Copilot 记录手动和自动触发。它是通知，不是阻止压缩的方式。 |
| `SubagentStart` | `subagentStart` | 审查智能体身份字段以及哪些子智能体类型发出事件。钩子参考排除内置 `general-purpose` 智能体。 |
| `SubagentStop` | `subagentStop` | 审查响应和身份字段、阻止决定和继续限制。 |
| `Stop` | `agentStop` | 智能体正在结束一轮。这**不是** `sessionEnd`，后者表示会话终止。 |

### 处理没有文档化等价项的字段 {#handle-fields-without-a-documented-equivalent}

不要将这些假设带入迁移后的脚本：

* **通用 Local 输出**：`continue`、`stopReason` 和 `systemMessage` 不是文档化的跨事件 Copilot 命令钩子契约。请选择目标的事件特定输出。不要将拒绝一个工具视为停止整个会话。
* **嵌套输出信封**：接受 PascalCase 输入别名并不意味着支持每个 Local `hookSpecificOutput` 字段。请发出文档化的 Copilot 输出。
* **记录和工具 ID**：不要要求每个事件都有 `transcript_path` 或 `tool_use_id`。Copilot 为智能体工作流中的特定事件记录记录路径，而不是所有工具事件。记录文件名或子字符串不能证明智能体读取或遵循了指令。
* **匹配器行为**：Local 忽略匹配器值。Copilot 应用文档化匹配器规则，包括兼容 `PreToolUse` 名称的不同语义。重新检查每个筛选器，包括无效模式及其不应匹配的工具。
* **SDK 回调类型**：程序化回调不是 JSON 文件命令钩子。SDK 源中的字段（例如仅回调的提示词覆盖）不能证明 shell 钩子可以使用它。
* **强制执行**：`ask` 依赖交互式审批流；不要假设它会暂停无人值守会话。GitHub 还记录失败开放超时，包括策略钩子。指令或迁移钩子本身都不能建立安全边界。

### 示例转换 {#example-conversion}

　　此示例请求对一个工具进行手动审查。它不运行工具，也不将其参数插值到 shell 命令。验证时使用一次性会话和无害工具。

　　保留原始 `review-tool.cjs`。将转换后的脚本保存为 `review-tool-copilot.cjs`，并将其配置暂存为 `.github/hooks/review-copilot.json.disabled`，直到直接检查通过。该后缀使新文件不进入钩子发现。

**之前，Local 配置：**

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "type": "command",
        "command": "node .github/hooks/review-tool.cjs",
        "env": { "REVIEW_TOOL_NAME": "<local-tool-name>" },
        "timeout": 10
      }
    ]
  }
}
```

**之前，Local 脚本：**

```javascript
const fs = require('node:fs');
const event = JSON.parse(fs.readFileSync(0, 'utf8'));
const toolName = process.env.REVIEW_TOOL_NAME;
if (!toolName || typeof event.tool_name !== 'string') {
  throw new Error('Configure REVIEW_TOOL_NAME and provide a Local tool event.');
}
process.stdout.write(JSON.stringify(event.tool_name === toolName ? {
  hookSpecificOutput: {
    hookEventName: 'PreToolUse',
    permissionDecision: 'ask',
    permissionDecisionReason: 'Review this tool call before it runs.'
  }
} : {}));
```

**之后，Copilot 配置：**

```json
{
  "version": 1,
  "hooks": {
    "preToolUse": [
      {
        "type": "command",
        "command": "node .github/hooks/review-tool-copilot.cjs",
        "env": { "REVIEW_TOOL_NAME": "<copilot-tool-name>" },
        "timeoutSec": 10
      }
    ]
  }
}
```

**之后，Copilot 脚本：**

```javascript
const fs = require('node:fs');
const event = JSON.parse(fs.readFileSync(0, 'utf8'));
const toolName = process.env.REVIEW_TOOL_NAME;
if (!toolName || typeof event.toolName !== 'string') {
  throw new Error('Configure REVIEW_TOOL_NAME and provide a Copilot tool event.');
}
process.stdout.write(JSON.stringify(event.toolName === toolName ? {
  permissionDecision: 'ask',
  permissionDecisionReason: 'Review this tool call before it runs.'
} : {}));
```

　　用每个会话中观察到的名称替换占位符，不要猜测重命名。使用[工具名称诊断](../../customize-and-extend/2.4.9-Hooks/)识别 Copilot 会话中的无害工具。验证参数的钩子还必须在使用 `toolArgs` 前验证其结构。此示例要求执行宿主安装 Node.js，而不是 CLI。

工具后提醒也需要输出转换：

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PostToolUse",
    "additionalContext": "Review the edited documentation against the writing guidelines."
  }
}
```

Copilot 命令钩子输出为：

```json
{
  "additionalContext": "Review the edited documentation against the writing guidelines."
}
```

### 个人钩子和内联设置 {#personal-hooks-and-inline-settings}

　　个人钩子使用相同的转换脚本。将 `review-tool-copilot.cjs` 存储在用户钩子目录，而不是仓库中。将此配置暂存为 `~/.copilot/hooks/review-copilot.json.disabled`：

```json
{
  "version": 1,
  "hooks": {
    "preToolUse": [
      {
        "type": "command",
        "command": "node \"<absolute-user-hooks-path>/review-tool-copilot.cjs\"",
        "env": { "REVIEW_TOOL_NAME": "<copilot-tool-name>" },
        "timeoutSec": 10
      }
    ]
  }
}
```

　　将 `<absolute-user-hooks-path>` 替换为执行宿主上的用户钩子目录。保留脚本路径引号，包括路径包含空格时：

| 平台 | JSON `command` 值示例 |
|----------|------------------------------|
| macOS | `"node \"/Users/<user>/.copilot/hooks/review-tool-copilot.cjs\""` |
| Linux | `"node \"/home/<user>/.copilot/hooks/review-tool-copilot.cjs\""` |
| Windows | `"node \"C:\\Users\\<user>\\.copilot\\hooks\\review-tool-copilot.cjs\""` |

　　设置了 `COPILOT_HOME` 时，使用其 `hooks` 目录。审查脚本不创建日志。使用[诊断脚本](../../customize-and-extend/2.4.9-Hooks/)时，其日志写入用户目录中脚本旁边。

　　也可以将配置内联保留在 `~/.copilot/settings.json`，同时将脚本保留在用户钩子目录。**验证脚本后**，将以下 `hooks` 成员合并到现有设置对象：

```json
{
  "hooks": {
    "preToolUse": [
      {
        "type": "command",
        "command": "node \"<absolute-user-hooks-path>/review-tool-copilot.cjs\"",
        "env": { "REVIEW_TOOL_NAME": "<copilot-tool-name>" },
        "timeoutSec": 10
      }
    ]
  }
}
```

　　保留无关设置和现有钩子条目。如果 `hooks` 或 `preToolUse` 已存在，请合并到其中，不要添加重复 JSON 属性。此内联映射不需要独立钩子文件的 `version` 属性。此钩子请选择独立文件或内联设置之一，不要同时使用。

　　共享插件请使用[捆绑脚本配置](../../reference-and-help/reference/2.8.1.7-AgentPluginAuthoringReference/)，而不是个人绝对路径。

### 直接检查转换后的脚本 {#check-the-converted-script-directly}

　　这些检查仅调用转换后的脚本，不调用智能体或指定工具。运行期间保持钩子配置非活动。在仓库根目录终端中通过 stdin 传入匹配事件：

**macOS 或 Linux：**

```bash
printf '%s\n' '{"toolName":"view","toolArgs":{"path":"README.md"}}' |
  REVIEW_TOOL_NAME=view node .github/hooks/review-tool-copilot.cjs
printf '\nExit code: %s\n' "$?"
```

**Windows PowerShell：**

```powershell
$env:REVIEW_TOOL_NAME = 'view'
'{"toolName":"view","toolArgs":{"path":"README.md"}}' |
  node .github/hooks/review-tool-copilot.cjs
Write-Host "`nExit code: $LASTEXITCODE"
```

　　个人钩子请将脚本参数替换为带引号的绝对路径。匹配夹具必须返回以下 JSON 并以代码 `0` 退出：

```json
{
  "permissionDecision": "ask",
  "permissionDecisionReason": "Review this tool call before it runs."
}
```

　　保持 `REVIEW_TOOL_NAME=view`，使用以下 stdin 重复：

| 输入 | 预期 stdout | 预期退出代码 |
|-------|-----------------|--------------------|
| `{"toolName":"grep","toolArgs":{}}` | `{}` | `0` |
| `{}` | 无决定 JSON；stderr 错误 | 非零 |
| `not-json` | 无决定 JSON；解析错误到 stderr | 非零 |

　　这些夹具检查脚本输入输出处理，不建立实时工具覆盖或审批行为。会话检查时，将 `REVIEW_TOOL_NAME` 设置为[工具名称诊断](../../customize-and-extend/2.4.9-Hooks/)找到的实际名称，然后在交互式 Copilot 会话中验证钩子。

### 停用原始钩子前验证 {#verify-before-retiring-the-original}

1. 目标配置非活动时运行[直接脚本检查](#check-the-converted-script-directly)。自己的脚本还要测试参数验证和格式错误输入。
2. 禁用原始钩子但不删除备份。仅激活打算使用的转换配置。独立示例请将 `review-copilot.json.disabled` 重命名为 `review-copilot.json`；设置请将验证后的钩子条目合并到现有 `hooks` 映射。
3. 选择 **Copilot** 作为 **会话目标** 并启动新的一次性会话。确认发现预期源且钩子实际触发。仅文件可见不能证明执行。
4. 适用时测试允许、拒绝和审批路径。单独测试命令错误和超时；它们不一定有相同结果。
5. 测试智能体工作流中的相关事件，包括恢复会话或完成子智能体。检查每个钩子只运行一次，而不是每个重复源运行一次。
6. 在目标操作系统、远程主机、容器或工作树中重复。验证 `cwd`、脚本依赖项、用户文件夹和沙盒访问，不要记录凭据或完整提示词。
7. 然后才停用旧配置。通过仓库或插件的正常审查流程发布共享更改。

## 替换工具集 {#replace-tool-sets}

　　用户定义工具集已弃用，Copilot 运行框架不支持。工具集文件将现有工具分组到可复用名称下，不实现工具。请移动工具选择，而不是文件。

> **注意**：工具集文件仍是 Local 运行框架兼容功能。Copilot **工具** 选项卡显示的工具组和受支持内置工具别名与用户定义工具集文件不同。

根据使用工具集的原因选择替代方案：

| 以前用途 | 替代 |
|--------------|-------------|
| 为重复角色选择相同能力 | 在[自定义智能体的 `tools` 属性](../../reference-and-help/reference/2.8.1.5-CustomAgentFileReference/)中直接指定受支持工具。 |
| 控制编辑器提供的工具 | 在[智能体自定义编辑器的 **工具** 选项卡](../../work-with-ai/plan-and-run-tasks/2.2.10.2-UseTools/)管理工具可用性。选择保存在配置文件中，不是每请求工具集别名。 |
| 将命名组附加到提示词，例如 `#reader` | 描述任务并选择相关自定义智能体。用户定义 `#reader` 别名没有直接替代。 |
| 共享工作流及其外部集成 | 将工作流打包为技能，将工具打包为 [智能体插件](../2.4.2-Plugins/)中的 MCP 服务器。插件打包能力，不重建工具集别名或强制工具允许列表。 |

替换现有工具集：

1. 打开其 `.toolsets.jsonc` 文件并列出包含的工具。展开对其他工具集的引用。
2. 在自定义智能体 `tools` 列表、提示词文件和提示词文本中查找该集合的使用。遵循[提示词文件迁移](#convert-prompt-files-to-skills)将提示词文件转换为技能。
3. 在 Copilot 运行框架会话中审查 **工具** 选项卡中的可用工具。将每个旧工具匹配到所需能力。不要假设 Local 工具 ID 有相同 Copilot 等价项。
4. 用受支持工具名称配置替代自定义智能体。将工作流指令保留在智能体或技能中，不要将工具集 JSON 复制进去。
5. 移除原始集合前测试工作流并检查实际使用的工具。

例如，`reader` 集合可能组合代码搜索、符号用法、诊断和源代码管理更改。创建一个具有相应可用工具的审查智能体，不要将 `reader` 复制到其 `tools` 列表。能力依赖扩展时，保持扩展安装且编辑器连接。没有等价工具时，请适配工作流以使用显式附加上下文、添加适当集成或记录缺失能力。

> **重要**：技能指令不能替代工具允许列表。将提示词转换为技能不会保留其 `tools` 选择。工具可用性也独立于[权限和审批](../../work-with-ai/permissions-and-security/2.2.12.1-ApprovalsAndPermissions/)。

## 替换聊天参与者 {#replace-chat-participants}

　　聊天参与者（包括扩展提供的 `@participant` 集成）已弃用，Copilot 运行框架不支持。聊天参与者 API 仍可用于 Local 运行框架兼容，但新集成不应依赖它。

### 如果使用参与者 {#if-you-use-a-participant}

　　内置参与者工作流请直接询问 Copilot 智能体。例如，将 `@vscode how do I enable word wrapping` 替换为 `How do I turn on word wrapping in the editor?`。代码库或终端问题请附加相关文件、终端输出或其他[上下文](../../work-with-ai/2.2.7-AddPromptContext/)。

　　扩展提供的参与者请检查发布者是否提供[智能体插件](../2.4.2-Plugins/)、MCP 服务器或扩展工具。安装替代品并遵循其设置说明。移除 `@name` 前缀不会让 Copilot 访问参与者的私有数据、服务或实现。

　　已安装参与者没有自动转换。发布者未提供替代品时，请请求一个。仅在仍需要原始集成时保留 Local 兼容性。

　　如果维护参与者实现，请在常见问题后遵循单独的[发布者指南](#if-you-maintain-a-participant)。

## 常见问题 {#frequently-asked-questions}

### 适配自定义项时可以继续使用 Local 运行框架吗？ {#can-i-keep-using-the-local-harness-while-adapting-my-customizations}

　　可以，前提是组织控制允许。在编辑器聊天视图中启动新会话，选择 **Local** 作为 **会话目标**。Local 运行框架可用性和自动 Copilot 选择取决于设置和组织策略。请参阅[迁移期间保持 Local 可用](../../choose-models-and-agents/2.3.3-MoveFromLocalToCopilot/)。

　　管理员可以使用从 1.142 版开始提供的临时 `vscode.temporaryDefaultToLocalHarness` 企业托管设置。它保持 Local 运行框架可用并抑制自动 Copilot 路由，但 Local 不执行 Copilot 运行时独有的沙盒和权限规则。它不会覆盖从 1.143 版开始提供的 `vscode.temporaryAllowLocalHarness: false`。请审查[管理员指导和安全注意事项](../../../enterprise/7.2-ManageAISettings/)。

### 为什么带输入提示的 MCP 服务器缺失？ {#why-are-mcp-servers-with-input-prompts-missing}

　　需要 `${input:...}` 或 `${command:...}` 变量的服务器不会从 `.vscode/mcp.json` 或配置文件 `mcp.json` 转发到 Copilot 运行框架。因此服务器工具在会话中不可用。先在 Local 会话解决提示没有帮助：Copilot 转发在解析值（包括缓存值）之前拒绝这些变量。

　　将相同配置移到 `.mcp.json` 不会添加输入提示支持。迁移会将合格非机密输入转换为环境变量。密码输入或其他手动更改请参阅[将输入提示替换为环境变量](#replace-input-prompts-with-environment-variables)。保留原始配置，直到有受支持身份验证方法并在 Copilot 会话中验证工具。请参阅 [MCP 输入变量](../../reference-and-help/reference/2.8.1.8-MCPConfiguration/)以及未解决报告 [microsoft/vscode#334271](https://github.com/microsoft/vscode/issues/334271) 和 [microsoft/vscode#337311](https://github.com/microsoft/vscode/issues/337311)。

### Copilot 可以在没有环境变量或文件的情况下将提示式机密传递给 HTTP MCP 服务器吗？ {#can-copilot-pass-a-prompted-secret-to-an-http-mcp-server-without-an-environment-variable-or-a-file}

　　没有内置 MCP 配置选项可以将 VS Code `${input:...}` 值或现有 `SecretStorage` 值读入 Copilot 运行框架 HTTP 服务器的身份验证标头。在输入上设置 `password: true` 不会改变此限制。

　　服务器支持 OAuth 时，请使用其支持的授权流程，而不是配置静态 bearer token。OAuth 是单独身份验证机制，不是转发提示式 API 密钥的方式。身份验证 UI 差距记录在 [microsoft/vscode#339960](https://github.com/microsoft/vscode/issues/339960)。

　　服务器需要固定 bearer token 且要求同时排除环境变量和文件凭据时，Copilot 运行框架没有等价的內置输入提示工作流。评估受支持身份验证选项期间，请继续对该集成使用 Local。不要在共享或个人 MCP 文件中用字面机密替换占位符：个人文件也可能被工具读取并包含在日志或其他工件中。请参阅[身份验证和机密](../../reference-and-help/reference/2.8.1.8-MCPConfiguration/)。

### 需要将每个自定义智能体移到仓库 agents 文件夹吗？ {#do-i-need-to-move-every-custom-agent-into-the-repository-agents-folder}

　　使用原生 Copilot 位置，但不一定是仓库文件夹。共享智能体放在 `.github/agents`，个人智能体放在 `~/.copilot/agents`。这些是跨 Copilot 客户端使用智能体的推荐位置。

　　`chat.agentFilesLocations` 设置未弃用，编辑器会从其他配置位置向 Copilot 运行框架转发智能体。这是兼容性支持，不是推荐设置：Copilot CLI 和 GitHub Copilot 应用不读取此编辑器设置。请参阅[配置位置迁移](#move-customizations-from-configured-locations)。

　　动态下载的智能体，请配置生成它们的工具使用原生工作区或用户智能体文件夹。验证生成文件是有效智能体文件，并在所选运行框架的 **Chat: Open Customizations** 中出现。如果仍然缺失，请在缺陷报告中包含产品版本、本地或远程环境、路径和最小智能体定义。从报告中移除机密。

### 为什么协调者的子智能体调用停止工作？ {#why-does-my-coordinators-subagent-invocation-stop-working}

　　Local 使用 `runSubagent` 调用子智能体。Copilot 运行框架使用原生 `task` 工具。要求特定 Local 工具名称的指令不会自动切换到 Copilot 工具。

　　请审查协调者的 Markdown 指令和 `tools` 列表。工作流应跨运行框架工作时，优先使用“将此审查委派给 reviewer 智能体”等指令。如果工作流要求显式工具调用，请适配其名称和参数到所选运行框架，而不只是重命名工具。验证每个专业智能体被发现并可用于子智能体调用。请参阅[按运行框架划分的子智能体](../../work-with-ai/plan-and-run-tasks/2.2.10.4-Subagents/)。

### 为什么智能体因工具发现能力错误而失败？ {#why-does-an-agent-fail-with-a-tool-discovery-capability-error}

　　找到智能体文件并不意味着其工具列表与所选运行框架兼容。`agent/runSubagent` 和用户定义工具集等 Local 委派引用不是可移植 Copilot 工具配置。限定客户端工具引用（包括 `vscode/<tool>`）在这些工具提供给 Copilot 会话时可以有效。

　　根据 Copilot 会话中的可用能力审查 `tools` 中的每个条目。在[编辑智能体文件](../../reference-and-help/reference/2.8.1.5-CustomAgentFileReference/)前选择 Copilot，并使用其补全保留规范工具引用。检查[工具选项卡](../../work-with-ai/plan-and-run-tasks/2.2.10.2-UseTools/)、[自定义智能体工具参考](../../reference-and-help/reference/2.8.1.5-CustomAgentFileReference/)和[工具集迁移指导](#replace-tool-sets)。保持所需能力显式配置。移除整个工具限制不是等价迁移。

　　不要假设移除前缀或替换工具名称能修复所有发现错误。这些编辑器提示不能证明运行时工具发现失败。

　　另一个报告 [microsoft/vscode#342961](https://github.com/microsoft/vscode/issues/342961) 描述即使 MCP 工具可调用，工具搜索也返回空结果。兼容工具仍无法发现时，请报告确切错误、所选模型、智能体工具列表和环境，不要将所有发现失败视为身份验证问题。

## 如果维护参与者 {#if-you-maintain-a-participant}

　　本节面向替换参与者实现的扩展发布者。仅使用已安装参与者时，请遵循[替换聊天参与者](#replace-chat-participants)。

以**包含技能和 MCP 服务器的智能体插件**开始。技能描述领域工作流，MCP 工具提供完成工作所需的数据和操作。用户需要持续专家角色时添加自定义智能体。这将可复用专业知识与访问服务的代码分离，使集成可在一个编辑器之外使用。

　　交互式控件请使用 [MCP 应用](https://code.visualstudio.com/api/extension-guides/ai/mcp#mcp-apps)。它们可以在聊天中提供按钮、表单、可视化和多步交互。集成需要编辑器 API 或独立 MCP 服务器无法访问的实时编辑器上下文时，请优先使用[扩展工具](https://code.visualstudio.com/api/extension-guides/ai/tools)。

选择组件前清点参与者的职责：

| 参与者职责 | 迁移方式 | 审查内容 |
|----------------------------|--------------------|----------------|
| 领域指令和示例 | 将任务特定知识放入技能。持续角色使用自定义智能体，常驻项目指导使用指令文件。 | 移动有用指令，而不是整个请求处理程序实现。 |
| `@tutor /exercise` 等斜杠命令 | 为工作流创建显式调用技能。只应在请求时运行时设置 `disable-model-invocation: true`。 | 选择技能名称和参数指导。插件技能使用插件命令前缀，而不是旧 `@participant` 语法。 |
| 服务访问、检索或操作 | 将有界操作公开为 MCP 工具，并在插件中包含服务器配置。 | 保留身份验证、输入验证、取消、错误报告和审批要求。不要将机密放入插件。 |
| 工作流中的按钮、表单或确认步骤 | 从工具返回 MCP 应用并在其 UI 中实现交互。 | 这需要新的 UI 实现，而不是转换 `ChatResponseStream` 调用。应用的确认步骤不能替代宿主工具审批或服务授权。 |
| 选择、诊断或其他编辑器状态 | 让用户附加上下文，或通过扩展工具公开编辑器特定操作。 | MCP 服务器不会自动访问 VS Code API。扩展工具需要贡献扩展和连接的编辑器。 |
| 必须按固定顺序运行的过程 | 将过程保留在脚本或工具实现中，并使用技能描述何时调用。 | 模型指令不能替代确定性执行或验证。 |
| 自定义模型调用、对话历史或响应呈现 | 将有界操作重构为工具，或在扩展命令和视图中保留定制体验。 | 自定义智能体或技能不会接管运行框架对话循环。参与者历史、反馈事件、路由规则和任意响应部分没有自动映射。 |

　　MCP 应用需要支持其 UI 的客户端。为不支持客户端提供有用的文本或结构化工具结果。在每个目标客户端测试应用行为，不要假设每个 Copilot 界面都呈现相同控件。在 VS Code 中，请审查 [MCP 应用行为和限制](https://code.visualstudio.com/api/extension-guides/ai/mcp#vs-code-behavior-and-limitations)，包括应用如何添加消息和上下文。

### 示例：将代码导师迁移到插件 {#example-migrate-a-code-tutor-to-a-plugin}

不要用一个大型自定义智能体提示词替换代码导师参与者，而是分离其能力：

* **教学流程**：`teach-concept` 技能询问学习者经验、解释概念并提出练习。
* **练习操作**：MCP 工具检索练习并检查答案。
* **交互式练习**：MCP 应用显示问题、接受答案并显示反馈。为不支持应用的客户端保留基于文本的练习路径。
* **可选 Tutor 智能体**：自定义智能体保存较长对话的教学风格。
* **可选编辑器集成**：工作流需要实时编辑器 API 时，扩展工具提供诊断或所选代码。否则请让学习者附加代码。

插件可以打包可移植部分：

```text
code-tutor/
  plugin.json
  skills/
    teach-concept/
      SKILL.md
  mcp.json
  com.github.copilot/
    agents/
      tutor.agent.md
```

　　使用[插件清单和格式指导](../../reference-and-help/reference/2.8.1.7-AgentPluginAuthoringReference/)配置包。MCP 服务器提供练习工具和应用资源；插件不会自动转换或嵌入旧参与者扩展。

教学技能请保留显式调用：

```markdown
---
name: teach-concept
description: Explain a programming concept and guide the learner through an exercise.
argument-hint: "[concept or code to explain]"
disable-model-invocation: true
---

Ask about the learner's experience and the concept or code they want to understand.
Explain the concept with a short example before offering an exercise.
Use the exercise server's tools when available. If they are unavailable, explain
that limitation and offer a text-only exercise instead.
```

　　插件名为 `code-tutor` 时，用户以 `/code-tutor:teach-concept` 调用此技能，而不是 `@tutor /teach`。停用参与者前，测试已安装插件、身份验证、应用交互和纯文本路径。
