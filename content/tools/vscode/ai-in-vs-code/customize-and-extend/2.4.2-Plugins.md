# 2.4.2 智能体插件

　　智能体插件将相关自定义项（例如技能、智能体和工具集成）打包在一起，以便一起安装。例如，测试插件可以包含测试运行技能、审查智能体和报告集成，它们设计为协同工作。

　　本文介绍如何发现和安装插件、使用文档审查工作流验证它并管理安装。要创建或打包插件，请参阅[智能体插件编写参考](../../reference-and-help/reference/2.8.1.7-AgentPluginAuthoringReference/)。

　　如果只需要项目规则或单个技能，请从[单独自定义项](../../concepts/2.7.7-AgentCustomization/#customization-options-at-a-glance)开始。当捆绑包的组件支持你想一起采用的工作流时，再选择捆绑包。

> **注意**：使用 `chat.plugins.enabled` 设置启用或禁用智能体插件支持。

## 插件提供的内容 {#what-plugins-provide}

　　插件可以提供以下自定义项。所选运行框架和插件格式决定可用组件。

| 能力 | 用途 |
|------------|---------|
| [技能](../2.4.3-AgentSkills/) | 专门工作流的指令、脚本和资源 |
| [MCP 服务器](../2.4.7-AddMCPServers/) | 与外部系统交互的工具 |
| [画布](../../work-with-ai/2.2.6-Canvases/) | 受支持 Copilot 会话中由你和智能体共享的交互式视觉表面 |
| [自定义智能体](../2.4.5-CustomAgents/) | 专门角色和工具配置 |
| [自定义指令](../2.4.4-Instructions/) | 作为插件规则提供的可复用指导 |
| [钩子](../2.4.9-Hooks/) | 在智能体工作流特定位置运行的命令 |
| [自动化模板](../../work-with-ai/plan-and-run-tasks/2.2.10.5-Automations/#start-from-a-template) | 创建自动化前审阅的起始提示词和计划 |
| 斜杠命令 | 在聊天中使用 `/` 调用的命令 |

　　已安装插件的自定义项会与你本地定义的自定义项一起显示。例如，插件中的技能会显示在 **配置技能** 中，MCP 服务器会出现在 MCP 服务器列表中。安装自动化模板不会启动自动化；请在开启前审查和配置。

　　安装之前，请检查插件支持的客户端和组件。关于可移植组件与客户端特定组件的差异，请参阅[跨工具兼容性](#cross-tool-compatibility)。

> **警告**：插件可能包含会在你的计算机上运行代码的钩子和 MCP 服务器。安装之前，请审查插件内容和发布者，尤其是来自社区 Marketplace 的插件。

## 发现和安装插件 {#discover-and-install-plugins}

　　使用智能体自定义编辑器浏览 Marketplace 并安装插件。也可以直接从 Git 仓库或本地文件夹安装插件。可用插件和操作取决于所选[智能体运行框架](../../concepts/2.7.6-AgentHarnesses/)和组织策略。

　　安装前选择运行框架，并使用同一运行框架验证结果。以下演练使用 **Copilot**。

　　插件 Marketplace 让你复用社区或组织发布的工作流。如果不需要捆绑包，[自定义 Marketplace](../2.4.1-Overview/#discover-and-install-existing-customizations-preview)还支持从受支持来源发现单个技能和 MCP 服务器。

### 从 Marketplace 安装插件 {#install-a-plugin-from-a-marketplace}

1. 从命令面板运行 **Chat: Open Customizations**，选择聊天视图标题栏中的 **打开自定义项**，或选择智能体窗口侧边栏中的 **自定义项**，打开智能体自定义编辑器。
2. 从[已配置的 Marketplace](#configure-plugin-marketplaces) 浏览可用插件。可用来源取决于所选运行框架和组织策略。

    * 在统一自定义 Marketplace（预览）中，选择 **浏览**，使用来源菜单选择插件 Marketplace，或跨可用来源搜索。
    * 如果统一 **浏览** 页面不可用，请选择 **插件**，然后选择 **浏览 Marketplace** 查找可用插件。

3. 选择插件，审查其发布者、包含的自定义项以及 **插件 README**（如果提供）。
4. 选择 **安装** 安装插件。

　　首次从新 Marketplace 安装插件时，VS Code 会显示信任提示。确认前请审查 Marketplace 来源。信任 Marketplace 不能替代审查每个插件的内容、设置要求或未来更新。

### 从源安装插件 {#install-a-plugin-from-source}

　　可以直接从 Git 仓库或本地文件夹安装插件，而无需先添加完整 Marketplace。对于仓库 URL，VS Code 会克隆并安装插件。

1. 在智能体自定义编辑器中选择 **插件**，然后根据安装位置选择 **用户** 或 **工作区** 旁的添加（`+`）按钮。
2. 输入 Git 仓库 URL（例如 `https://github.com/rwoll/markdown-review`）或本地文件夹路径。

　　也可以从命令面板运行 **Chat: Install Plugin from Source**。

### 试用文档审查工作流 {#try-a-document-review-workflow}

　　社区 [Markdown Review 插件](https://github.com/rwoll/markdown-review)提供一个技能，可在浏览器中打开 Markdown 文件以收集评论，并将反馈返回给智能体。用它检查完整工作流，而不仅是插件是否出现在编辑器中。

　　对于此示例，请使用 **Copilot** 运行框架打开本地项目。安装带可用 `npx` 的 Node.js，并使用可以打开本地浏览器的计算机。安装前审查插件的 README 和捆绑的 `markdown-plan-review-feedback` 技能。

1. 使用 `https://github.com/rwoll/markdown-review` [从源安装插件](#install-a-plugin-from-source)。选择 **用户** 进行个人试用。
2. 在项目中启动新的 Copilot 会话并输入：

    ```text
    Create plugin-review.md with a short documentation plan for this repository.
    Use the Markdown Review plugin to open it for my review, then summarize
    the feedback I submit. Do not change application code.
    ```

3. 检查技能和工具活动。在发布者的 CLI 运行之前审查任何审批请求。该工作流会启动临时本地 Web 服务器，并在浏览器中打开审查 UI。
4. 在浏览器中为文档添加评论，然后提交反馈。
5. 检查智能体是否收到评论并准确总结。确认 Markdown 文件存在，且没有更改应用代码。

　　当你能将浏览器评论追溯到智能体响应时，工作流成功。如果浏览器未打开或反馈未返回，请检查插件的运行时要求和命令输出，然后重复请求。

　　试用后，关闭审查选项卡，如果不需要 `plugin-review.md` 请删除。如果不想保留工作流，可以[卸载插件](#uninstall-plugins)。

### 使用深层链接共享和安装插件 {#share-and-install-plugins-with-deep-links}

　　插件提供商可以创建可共享的深层链接，帮助用户在 VS Code 中注册 Marketplace 或直接安装特定命名插件。

> **重要**：智能体插件不同于 VS Code 扩展。要从 Visual Studio Marketplace 安装扩展，请使用 `vscode:extension/<publisher>.<extensionName>`，如 [URL 处理](../../../editor/3.3-ConfigureTheEditor/3.3.10-CommandLineInterface/#url-handling)所述。

#### 安装特定插件 {#install-a-specific-plugin}

　　使用 `chat-plugin/install` 路由添加 Marketplace（如果尚未注册）并安装特定命名插件：

```text
vscode://chat-plugin/install?source=<url-encoded-source>&plugin=<url-encoded-plugin-name>
```

参数：

* **`source`**（必需）：远程 Marketplace 来源（例如 `owner/repo` 或 Git 仓库 URL）。
* **`plugin`**（必需）：插件清单（`plugin.json`）中声明的确切插件名。不要包含 CLI 使用的 `@marketplace` 限定符。

　　对参数值进行 URL 编码（例如将 `/` 编码为 `%2F`）。

**示例：**

```text
vscode://chat-plugin/install?source=owner%2Frepo&plugin=plugin-name
```

　　打开后，VS Code 会要求用户确认添加 Marketplace 并安装插件。确认后，VS Code 注册 Marketplace、按名称定位插件、将其安装到 Copilot Agent Host 会话，并打开筛选到该插件的智能体自定义编辑器。

#### 添加插件 Marketplace {#add-a-plugin-marketplace}

　　要注册 Marketplace 而不安装任何插件，请使用 `chat-plugin/add-marketplace` 路由：

```text
vscode://chat-plugin/add-marketplace?ref=<url-encoded-source>
```

**示例：**

```text
vscode://chat-plugin/add-marketplace?ref=owner%2Frepo
```

　　打开后，VS Code 会提示用户确认添加 Marketplace。仅添加 Marketplace 只会使其插件可发现，不会自动安装任何插件。

#### 深层链接要求和安全性 {#deep-link-requirements-and-security}

* **同意和安全性**：插件可以通过钩子或 MCP 服务器执行代码。深层链接始终会在注册 Marketplace 或安装插件前请求用户明确确认，不能绕过信任对话框、工作区信任或企业策略。
* **前提条件**：插件深层链接要求启用 `chat.plugins.enabled`，并可使用 Copilot Agent Host 支持。如果没有合适的会话，VS Code 会提示用户创建。
* **Insiders 和 Web 重定向**：对于 VS Code Insiders，请使用 `vscode-insiders://` 方案。要在网页或 Markdown 徽章上发布链接，请使用 HTTPS 重定向包装：

  ```text
  https://vscode.dev/redirect?url=vscode%3A%2F%2Fchat-plugin%2Finstall%3Fsource%3Downer%252Frepo%26plugin%3Dplugin-name
  ```

### 由 Copilot CLI 安装的插件 {#plugins-installed-by-copilot-cli}

　　VS Code 会自动发现你使用 [GitHub Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/plugins-finding-installing)安装的插件，以便你也能在 VS Code 中使用它们。来自 `~/.copilot/installed-plugins/` 的已发现插件会显示在智能体自定义编辑器的 **插件** 页面。

　　CLI 将插件存储在 `~/.copilot/installed-plugins/<marketplace>/<plugin>/` 下。直接从 Git URL（而不是 Marketplace）安装的插件位于 `_direct` 桶中，例如 `~/.copilot/installed-plugins/_direct/github--moda-linter--copilot-plugin/`。

### 查看已安装插件 {#view-installed-plugins}

　　在智能体自定义编辑器中，选择 **插件** 查看所选运行框架可用的插件。在此页面可以检查、启用、禁用或卸载插件。

　　选择已安装插件打开其详情。审查其 **插件 README** 和包含的自定义项。在 **技能** 下选择技能可打开其指令。

### 安装后验证插件 {#verify-a-plugin-after-installation}

　　安装插件会使支持的组件可用，但不能保证智能体在每个任务中都使用它们。

1. 在智能体自定义编辑器中选择 **插件**，确认插件已列出，并为目标运行框架和工作区启用。
2. 审查发布者的设置说明，完成所需配置。对于捆绑的 MCP 服务器，请检查[服务器控件和连接要求](../2.4.8-ManageMCPServers/#open-the-server-controls)。
3. 使用目标运行框架和工作区启动新会话。确认所需组件可用。例如，如果插件的技能出现在 `/` 菜单中，请[运行其中一个技能](../2.4.3-AgentSkills/#use-skills-as-slash-commands)。
4. 尝试一个预期插件能帮助的小任务，然后对照具体结果审查智能体操作和结果。例如，[文档审查演练](#try-a-document-review-workflow)检查提交的评论是否到达智能体，而不仅是技能运行。

　　如果只需要技能，请考虑[使用或调整现有技能](../2.4.3-AgentSkills/#use-an-existing-skill)，而不是安装插件。要更改和维护插件，请遵循[插件编写参考](../../reference-and-help/reference/2.8.1.7-AgentPluginAuthoringReference/)。

### 启用或禁用插件 {#enable-or-disable-plugins}

可以为当前配置文件或特定工作区启用或禁用插件：

1. 在智能体自定义编辑器中选择 **插件**，打开插件详情。
2. 使用 **启用** 或 **禁用** 更改当前配置文件的状态，或使用 **启用（工作区）** 或 **禁用（工作区）** 更改当前工作区。使用按钮的下拉菜单选择作用域。

　　启用/禁用状态与插件配置分开存储，因此不会影响共享工作区设置。

　　策略管理的插件会标识为受策略管理，其切换控件被锁定。

　　插件禁用后，其技能、智能体、钩子、MCP 服务器、斜杠命令和自动化模板不再可用。例如，禁用插件的技能不会出现在 **Chat: Configure Skills** 中，自动化模板不会出现在 **来自插件的模板** 中。禁用的插件在智能体自定义编辑器中以淡化样式显示。

### 卸载插件 {#uninstall-plugins}

　　在智能体自定义编辑器中，选择 **插件**，打开插件详情，选择 **卸载**。

　　不能卸载组织要求的插件，包括通过其捆绑技能、提示词或其他自定义项提供的插件。

　　从外部来源（例如 npm、PyPI 或外部 Git 仓库）安装的插件会从磁盘移除。内联在 Marketplace 仓库中的插件会保留在磁盘上，但不再活动。

## 配置插件 Marketplace {#configure-plugin-marketplaces}

　　插件 Marketplace 是包含插件定义目录的 Git 仓库。在智能体自定义编辑器中添加社区或组织 Marketplace，或在设置中配置其来源。

　　添加 Marketplace 只会使其插件可浏览，不会安装或启用它们。

### 在自定义编辑器中管理 Marketplace（预览） {#manage-marketplaces-in-the-customizations-editor-preview}

1. 打开智能体自定义编辑器，选择 **浏览**。
2. 打开来源菜单，选择 **配置 Marketplace**。
3. 选择 **添加 Marketplace**，输入 GitHub 仓库、Git 仓库 URL 或本地仓库 URI。只添加你信任的 Marketplace。
4. 返回 **浏览**，从来源菜单选择已添加的 Marketplace 浏览其插件。

　　要管理现有 Marketplace，请在 **配置 Marketplace** 中选择它。可用操作取决于所选运行框架，包括 **浏览**、**刷新 Marketplace**、**打开文件夹** 和 **移除 Marketplace**。使用 **返回** 回到 Marketplace 列表。

　　组织管理的 Marketplace 不能被移除，某些运行框架还会保护内置 Marketplace。如果提示 **移除 Marketplace 和插件**，请先审查将卸载哪些插件。

### 在设置中配置 Marketplace {#configure-marketplaces-in-settings}

　　可以从 [copilot-plugins](https://github.com/github/copilot-plugins) 和 [awesome-copilot](https://github.com/github/awesome-copilot/) 等 Marketplace 发现插件。要在设置中配置其他 Marketplace，请使用 `chat.plugins.marketplaces`（实验性）。语法和示例请参阅 [Marketplace 来源格式和修订选择](../../reference-and-help/reference/2.8.1.7-AgentPluginAuthoringReference/#marketplace-source-formats)。

> **注意**：企业管理员可以集中控制开发者可用的插件和 Marketplace。更多信息请参阅[管理智能体插件和 Marketplace](../../../enterprise/7.2-ManageAISettings/#manage-agent-plugins-and-marketplaces)。

## 使用本地插件 {#use-local-plugins}

　　要从本地文件夹安装插件，请使用智能体自定义编辑器中的[从源安装插件](#install-a-plugin-from-source)。

　　如果正在开发插件，或需要注册现有目录而不安装它，请使用实验性 `chat.pluginLocations` 设置，遵循[本地插件注册](../../reference-and-help/reference/2.8.1.7-AgentPluginAuthoringReference/#local-plugin-registration)。

## 在远程窗口中使用插件 {#use-plugins-in-remote-windows}

　　使用 Remote - SSH、WSL、Dev Containers 或 Remote - Tunnels 时，可以使用存储在远程计算机上的插件。**Copilot** 运行框架在远程环境中运行，并加载插件的自定义智能体、技能和钩子。

　　在连接的窗口中使用智能体自定义编辑器的 **插件** 页面[查看和管理已安装插件](#view-installed-plugins)。

要注册远程计算机上的现有插件目录而不安装副本：

1. 在远程窗口中从命令面板运行 **Preferences: Open Remote Settings (JSON)**。
2. 添加 `chat.pluginLocations`（实验性）并指向远程文件系统上的插件路径。配置语法请参阅[本地插件注册](../../reference-and-help/reference/2.8.1.7-AgentPluginAuthoringReference/#local-plugin-registration)。
3. 使用 **Copilot** 运行框架启动新聊天，并[验证插件的组件](#verify-a-plugin-after-installation)。

　　钩子在远程计算机或容器内运行。请在相应位置安装其所需运行时和工具，例如 Node.js，而不是只安装在本地计算机上。

## 更新插件 {#update-plugins}

　　在智能体自定义编辑器中选择 **插件**，然后在已安装插件组旁选择 **检查并应用更新**（刷新图标）。也可以从命令面板运行 **Chat: Update Plugins**。

　　更新会从克隆的 Marketplace 仓库拉取更改，并检查外部来源插件的新版本。

　　启用 `extensions.autoUpdate` 时，插件也可以自动更新。来自 npm 或 PyPI 的插件从不自动更新。请使用智能体自定义编辑器中的更新操作，并在安装命令运行前审查确认提示。

　　决定是否信任插件时，请考虑此更新行为。采用更新时，请审查其捆绑工具、钩子和设置要求的变化。不再信任某个插件时，请禁用该插件，而不是让其组件继续可用。

## 工作区插件推荐 {#workspace-plugin-recommendations}

　　项目可以在工作区设置（`.claude/settings.json` 或 `.github/copilot/settings.json`）中配置插件设置，为团队成员推荐插件。

　　在 Local 运行框架中，VS Code 会在首次发送聊天消息时显示通知。要从项目 Marketplace 浏览和安装插件，请打开智能体自定义编辑器并选择 **浏览**；如果统一浏览体验不可用，请选择 **插件** > **浏览 Marketplace**。

　　在 Copilot 运行框架中，`.github/copilot/settings.json` 提供仓库插件和 Marketplace 默认值。可以在智能体自定义编辑器的 **插件** 中关闭可选插件，而不更改共享默认值。企业托管设置优先于仓库默认值和你的选择。

　　配置字段、命名规则和完整示例请参阅[工作区插件设置](../../reference-and-help/reference/2.8.1.7-AgentPluginAuthoringReference/#workspace-plugin-settings)。启用推荐插件之前请先审查，就像审查自己发现的插件一样。

## 使用斜杠命令管理插件 {#manage-plugins-with-slash-commands}

　　除了智能体自定义编辑器，可以在 Copilot 运行框架会话中输入 `/plugin ` 查看插件和 Marketplace 操作的补全。请使用安装插件时所用的界面，因为其清单与编辑器的清单分开。命令目录和限制请参阅[插件管理命令](../../reference-and-help/reference/2.8.1.7-AgentPluginAuthoringReference/#plugin-management-commands)。

## 跨工具兼容性 {#cross-tool-compatibility}

　　[智能体插件](https://agent-plugins.org/)是跨兼容客户端打包技能和 MCP 服务器的开放标准，包括 VS Code 中的 GitHub Copilot、GitHub Copilot CLI 和 GitHub Copilot 应用。其他组件（例如自定义智能体、斜杠命令、规则、钩子和自动化模板）可能是客户端特定的。

　　VS Code 还支持现有 Copilot、Claude 和旧版 OpenPlugin 格式。支持某种包格式并不保证每个组件都能在每个运行框架或客户端中工作。请检查插件要求。文件布局和客户端特定命名空间请参阅[插件编写兼容性参考](../../reference-and-help/reference/2.8.1.7-AgentPluginAuthoringReference/#cross-tool-compatibility)。

## 故障排除 {#troubleshooting}

### 安装后插件不出现 {#plugin-does-not-appear-after-installation}

* 确认智能体插件已启用：检查 `chat.plugins.enabled` 是否设置为 `true`。
* 验证插件的 `name` 字段遵循其格式的命名规则。Agent Plugins 1.0 名称使用小写字母、数字、连字符和句点。旧版 Copilot 插件名称使用小写字母、数字和连字符。不支持斜杠和冒号。
* 检查 `plugin.json` 是否位于[可识别位置](../../reference-and-help/reference/2.8.1.7-AgentPluginAuthoringReference/#plugin-formats)。

### 插件中的技能不加载 {#skills-from-a-plugin-do-not-load}

* 打开 `SKILL.md` 文件，检查 YAML frontmatter 中的 `name` 字段。名称必须是纯 kebab-case，不带命名空间前缀（例如 `test-runner`，不是 `myorg/test-runner`）。无效名称会导致技能被静默跳过。
* 确保技能目录名与 `SKILL.md` frontmatter 中的 `name` 字段一致。

### 插件版本不更新 {#plugin-version-does-not-update}

* 在智能体自定义编辑器中选择 **插件**，然后选择 **检查并应用更新**（刷新图标）。
* 如果维护该插件，请审查其[版本和更新要求](../../reference-and-help/reference/2.8.1.7-AgentPluginAuthoringReference/#test-and-distribute-a-plugin)。

### 重试后插件安装失败 {#plugin-installation-fails-after-retry}

　　重试安装。VS Code 会验证 Marketplace 仓库缓存，并自动替换不完整或无效的缓存。

　　如果仍然失败，请检查错误中是否有无效仓库、修订或插件路径。如果来源有效且重试仍失败，请运行 **Help: Report Issue**。不要手动删除或修改内部插件缓存。
