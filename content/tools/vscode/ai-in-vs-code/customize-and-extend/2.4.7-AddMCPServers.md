# 2.4.7 添加 MCP 服务器

　　当智能体需要现有工具无法提供的能力时（例如查询数据库或从外部服务检索信息），请添加 MCP 服务器。[模型上下文协议（MCP）](https://modelcontextprotocol.io/)将智能体连接到这些工具和数据源。如果现有工具已满足需求，就不需要再添加服务器。

　　对于受支持的服务，[Copilot 连接器](../2.4.6-CopilotConnectors/)为 Copilot 运行框架会话提供 GitHub 托管的 MCP 连接，无需本地服务器设置或手动 MCP 配置。

　　本文从添加服务器讲到验证第一次工具调用。请选择起点：

* **无需服务器设置即可连接受支持的服务**：[使用 Copilot 连接器](../2.4.6-CopilotConnectors/)。
* **使用打包工作流中的工具**：[安装捆绑 MCP 服务器的智能体插件](../2.4.2-Plugins/#discover-and-install-plugins)。
* **已有服务器 URL 或命令**：[连接服务器](#connect-a-server)。
* **需要帮助找到服务器**：[选择要尝试的服务器](#choose-a-server-to-try)或[浏览自定义 Marketplace](#discover-servers-in-the-customization-marketplace-preview)。
* **服务器已配置但无法工作**：[检查连接](#if-the-server-does-not-work)。

## 开始之前 {#before-you-start}

* [启用 AI 功能](../../../get-started/#enable-ai-features)，并在 VS Code 中打开本地项目文件夹。
* 在 **会话目标** 下拉列表中选择目标运行框架。下面的演练使用 **Copilot** 和个人配置。如需共享服务器或使用 Local 运行框架配置，请选择其他目标。
* 对于手动配置的服务器，请检查发布者的前提条件。远程 HTTP 服务器可能需要账户或登录。通过命令启动的服务器需要在运行它的计算机上安装相应运行时。

> **警告**：本地 MCP 服务器可以在你的计算机上运行代码，工具可以使用你的权限访问外部服务。安装或启动服务器之前，请审查发布者、命令或终结点以及请求的访问权限。只信任你审查过的配置。了解 [MCP 服务器信任](../2.4.8-ManageMCPServers/#mcp-server-trust)。

## 选择配置目标 {#choose-a-configuration-destination}

　　在添加服务器之前选择目标，使其工具对预期的运行框架和用户可用：

| 目标 | 配置 |
|-----------|---------------|
| 跨工作区使用服务器 | **全局** > **Copilot 全局** 写入 `$COPILOT_HOME/mcp-config.json`；未设置 `COPILOT_HOME` 时写入 `~/.copilot/mcp-config.json`。 |
| 与使用兼容 Copilot 工具的团队共享服务器 | 工作区根目录 `.mcp.json`。启用实验性 `chat.mcp.workspaceRootConfig.enabled` 时，引导流程会提供此目标。 |
| 使用带输入变量或每服务器沙盒的 Local 运行框架配置 | 工作区 `.vscode/mcp.json` 或用户配置文件 `mcp.json`。这些目标保留用于兼容性，在引导流程中标记为已弃用。 |

　　可移植文件使用顶级 `mcpServers` 对象。VS Code 格式使用 `servers`。在两者之间复制配置之前，请检查[格式和能力参考](../../reference-and-help/reference/2.8.1.8-MCPConfiguration/#configuration-file)。

> **重要**：可移植配置不支持 VS Code 输入变量或环境文件。需要交互输入的服务器不会转发到 Copilot 运行框架会话。请使用[配置的身份验证指南](../../reference-and-help/reference/2.8.1.8-MCPConfiguration/#authentication-and-secrets)，不要添加不受支持的凭据占位符。

　　关于 [Dev Container](../2.4.8-ManageMCPServers/#remote-workspaces-and-dev-containers)或[命令行安装](../../reference-and-help/reference/2.8.1.8-MCPConfiguration/#command-line-installation)，请遵循特定环境的说明。

## 选择要尝试的服务器 {#choose-a-server-to-try}

　　如需具体的本地示例，请使用 [Playwright MCP 服务器](https://github.com/microsoft/playwright-mcp)。它需要 **Node.js 18 或更高版本**，并可使用 `npx`。在终端中检查安装：

```bash
node --version
npx --version
```

　　本演练使用 Playwright 演示连接外部工具提供商。对于日常浏览器交互，请先尝试[内置浏览器工具](../../work-with-ai/plan-and-run-tasks/2.2.10.3-BrowserTools/)，它们不需要 MCP 服务器。

　　如果要改为尝试远程文档服务器，请遵循 [Context7 设置要求](https://context7.com/docs/resources/all-clients)了解其当前身份验证要求和服务限制。在下面的连接步骤中使用 HTTP 终结点 `https://mcp.context7.com/mcp`。远程服务器不需要本地 Node.js。

## 连接服务器 {#connect-a-server}

　　使用发布者的 URL 或启动命令。对于 Playwright 示例，请使用第二步中的命令。

1. 在选中目标运行框架的情况下，从命令面板（`Ctrl + Shift + P`）运行 **Chat: Open Customizations**，选择 **MCP 服务器**。在所选作用域的 **用户** 或 **工作区** 组中选择 **添加服务器**（**+**）。

2. 选择与发布者提供内容匹配的选项：

    | 已有内容 | 选择 | 输入 |
    |---------------|--------|-------|
    | 服务器 URL | **HTTP（HTTP 或 Server-Sent Events）** | 发布者的 MCP 终结点。 |
    | 启动命令 | **命令（stdio）** | 命令及其参数。服务器通过标准输入输出通信。 |

    对于 Playwright，选择 **命令（stdio）** 并输入：

    ```bash
    npx -y @playwright/mcp@latest
    ```

3. 输入未在目标配置中使用的服务器 ID，例如 `playwright` 或 `context7`。计划一起使用的不同服务器应使用不同 ID。

4. 对于个人配置，选择 **全局**，然后在提示时选择 **Copilot 全局**。这会将服务器存储在项目之外。对于团队配置或其他运行框架，请[选择配置目标](#choose-a-configuration-destination)。

    如果 **Copilot 全局** 不可用，请检查 [Copilot 运行框架要求](../../choose-models-and-agents/2.3.2-ChooseAnAgentHarness/#copilot)后再继续。

5. 接受任何服务器信任或身份验证提示之前先审查。如果服务需要身份验证，请遵循发布者的登录说明。不要将凭据粘贴到聊天中或提交到项目。

　　除了智能体自定义编辑器，也可以从命令面板运行 **MCP: Add Server** 启动引导流程。按照提示为运行框架选择目标。

　　其他添加服务器的方法请参阅[查找其他服务器](#find-another-server)。

## 验证第一次工具调用 {#verify-the-first-tool-call}

　　添加配置并不能证明智能体可以使用该服务器。完成一个请求并检查工具调用：

1. 在智能体会话中，输入明确指定服务器和低影响操作的提示词。对于 Playwright：

    ```text
    使用 Playwright MCP 服务器打开 <你的 URL> 并报告页面标题。使用它的工具，
    不要使用内置浏览器工具。不要更改文件。
    ```

    对于 Context7：

    ```text
    使用 Context7 MCP 工具查找 React 的 useState 文档。总结基本用法，
    并引用工具返回的文档。不要更改文件。
    ```

2. 在启动、登录和工具审批请求出现时进行审查。只批准你理解的操作。

3. 展开对话中的工具调用。检查它属于你添加的服务器，并查看返回的输出。

**当以下三项检查都通过时，连接正常工作：**

* 会话中调用了目标 MCP 服务器的工具。
* 工具返回请求的页面或文档，没有连接错误。
* 智能体的回答反映了该工具输出。仅凭看似合理的回答不够。

　　如果只是想试用服务器，请打开 **Chat: Open Customizations** > **MCP 服务器**，使用其省略号（**...**）菜单选择 **禁用** 或 **卸载**。停止服务器只会结束当前运行；后续请求可以再次启动它。如果 **卸载** 不可用，请按照[其配置来源的移除说明](../2.4.8-ManageMCPServers/#control-or-remove-a-server)。

　　要控制 Copilot 会话中可用的工具，请打开 **Chat: Open Customizations** > **工具**。对于 Local 运行框架会话，请使用聊天输入框中的 **配置工具**。差异请参阅[管理可用工具](../../work-with-ai/plan-and-run-tasks/2.2.10.2-UseTools/#manage-available-tools)。

## 查找其他服务器 {#find-another-server}

### 在自定义 Marketplace 中发现服务器（预览） {#discover-servers-in-the-customization-marketplace-preview}

　　使用[自定义 Marketplace](../2.4.1-Overview/#discover-and-install-existing-customizations-preview)查找技能和插件旁边的现有服务器集成。

1. 对于 Copilot 会话，运行 **Chat: Open Customizations**，选择 **浏览**。
2. 从来源菜单选择 **GitHub 源**，按名称或 `@type:mcp` 搜索。
3. 审查发布者、服务器能力和设置要求，可用时选择 **安装**。
4. 完成发布者设置并[验证工具调用](#verify-the-first-tool-call)。

　　实验性 GitHub 源需要提供 Marketplace 搜索的运行框架。Local 会话不提供此来源。可用性还取决于组织策略。如果不支持自动安装，请遵循发布者说明或[添加其 URL 或命令](#connect-a-server)。

　　也可以选择插件 Marketplace，并[安装捆绑 MCP 服务器的插件](../2.4.2-Plugins/#install-a-plugin-from-a-marketplace)。仅添加 Marketplace 不会安装其服务器。

<details>
<summary>从扩展视图或命令面板打开发现</summary>

　　当 `chat.customizations.marketplace.enabled` 开启（默认）时，在扩展视图中搜索 `@mcp` 或运行 **MCP: Browse MCP Servers** 会打开 **在自定义项中查找 MCP 服务器**，而不是画廊结果列表。选择 **浏览 MCP 服务器** 在智能体自定义编辑器中继续。该设置关闭时，仍可能显示旧版扩展画廊。

</details>

### 从其他来源添加服务器 {#add-a-server-from-another-source}

　　如果运行框架或组织无法使用 Marketplace 发现，请使用发布者提供的 URL 或命令，通过 [MCP: Add Server](#connect-a-server) 添加。

　　要复用其他应用程序的配置，请运行 **MCP: Add Server**，选择 **从其他应用程序添加...**。支持的来源请参阅[自动发现 MCP 服务器](../../reference-and-help/reference/2.8.1.8-MCPConfiguration/#automatic-mcp-server-discovery)。

<details>
<summary>从包或 Docker 镜像添加（模型辅助）</summary>

　　如果只有包或镜像名称而没有启动命令，可以使用模型辅助生成服务器配置：

1. 运行 **MCP: Add Server**，选择 **NPM 包**、**Pip 包** 或 **Docker 镜像**。
2. [选择配置目标](#choose-a-configuration-destination)，然后在提示时输入包或镜像名称。例如，为 **NPM 包** 输入 `@playwright/mcp`。
3. 审查确认中显示的包名称、版本和发布者。只有在信任来源时才选择 **允许**，然后遵循模型辅助设置提示。
4. 确认目标配置中未使用的服务器 ID。接受任何服务器信任或工具审批提示之前，请审查生成的命令、参数和凭据要求。
5. 从添加的服务器[验证工具调用](#verify-the-first-tool-call)。

　　这些选项仅在当前配置支持模型辅助设置时出现。如果不可用，请使用发布者的启动命令和 **命令（stdio）**。运行时前提条件仍然适用：生成配置不能替代安装所需运行时。

</details>

## 使用服务器提供的上下文和提示词 {#use-context-and-prompts-from-your-server}

　　服务器可以提供的不只是工具。可用能力取决于服务器和会话：

* **资源**：从 **添加上下文** > **MCP 资源** 将服务器提供的数据附加到请求，或运行 **MCP: Browse Resources**。
* **提示词**：在聊天中输入 `/<服务器>.<提示词>`，使用服务器的提示词模板。
* **MCP 应用（实验性）**：受支持的服务器可以在聊天中显示交互式表单或可视化。请参阅 [MCP 应用支持](https://code.visualstudio.com/blogs/2026/01/26/mcp-apps-support)。

## 如果服务器无法工作 {#if-the-server-does-not-work}

| 观察到的现象 | 下一步 |
|------------------|--------|
| 服务器不出现或无法启动 | 检查其配置作用域、运行时要求和[服务器输出](../2.4.8-ManageMCPServers/#view-server-output)。 |
| 登录或连接失败 | 检查发布者的身份验证说明和组织的访问限制。请参阅 [MCP 故障排除](../2.4.8-ManageMCPServers/#troubleshoot-mcp-servers)。 |
| 服务器运行，但没有调用其工具 | 检查[工具可用性和调用](../../reference-and-help/troubleshooting/2.8.2.2-DebugChatInteractions/#an-mcp-tool-is-not-being-invoked)。 |

　　解决问题后，请重复请求并再次检查工具输出。

　　特定任务请参阅 [MCP 沙盒](../2.4.8-ManageMCPServers/#sandbox-mcp-servers)、[跨设备同步配置](../2.4.8-ManageMCPServers/#synchronize-mcp-configuration-across-devices)或[企业访问管理](https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-mcp-usage/configure-enterprise-allowlist)。
