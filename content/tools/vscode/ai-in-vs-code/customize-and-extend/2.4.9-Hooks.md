# 2.4.9 钩子

　　钩子会在智能体工作流的特定位置运行自定义操作，例如工具运行之前或之后。它们可用于添加上下文、验证工具调用、运行格式化程序或记录事件，而无需依赖模型请求该操作。

　　使用[智能体自定义编辑器](#find-and-manage-hooks)为共享 Copilot 运行时创建和管理钩子。本文介绍创建钩子、添加支持脚本并验证结果。如果已有其他运行框架的钩子，请从[迁移钩子](../2.4.11-MigrateExistingCustomizations/#migrate-hooks)开始。迁移包括用户文件夹、设置、自定义智能体和插件，而不仅是仓库文件。

> **注意**：VS Code 的钩子体验处于预览阶段。各个提供商实现的生命周期状态和发布时间可能不同。

> **重要**：组织可能限制可运行的钩子。当 [GitHub Copilot 企业托管设置生效](../../../enterprise/7.2-ManageAISettings/#claude-and-codex-availability)时，Claude 和 Codex 运行框架会被禁用。请联系部署设置的 IT 团队讨论访问权限。管理员可以了解如何[在企业环境中管理钩子](../../../enterprise/7.2-ManageAISettings/#enable-or-disable-hooks)。

## 为会话选择钩子实现 {#choose-the-hook-implementation-for-your-session}

　　从 **会话目标** 控件选择 **Copilot** 以使用 Copilot 运行框架。VS Code、GitHub Copilot 应用和 GitHub Copilot CLI 共享此运行框架及其钩子格式。在编辑器中配置钩子不需要安装或使用 CLI。

　　命令配置、事件输入和输出请使用 [Copilot 钩子参考](https://docs.github.com/en/copilot/reference/hooks-reference)。

其他会话目标使用各自的钩子实现：

| **会话目标** 选项 | 配置和事件参考 |
|--------------------------|-----------------------------------|
| **Claude** | [Claude 钩子参考](https://code.claude.com/docs/en/hooks) |
| **Codex** | [Codex 钩子文档](https://developers.openai.com/codex/hooks/) |

　　[云会话](../../work-across-apps-and-machines/2.5.3-CloudSessions/)在受管理环境中使用 Copilot 运行框架。本地钩子文件不会自动复制到该环境。请检查云工作区中可用的配置，不要假设你计算机上的钩子在那里适用。

　　较旧的 Local 运行框架有单独的 [Local 钩子参考](../../reference-and-help/reference/2.8.1.9-HooksReference/)。请用它解释迁移期间的现有钩子，不要将其作为新 Copilot 钩子的 schema。

### 在运行框架之间迁移钩子 {#migrate-hooks-between-harnesses}

　　共享钩子文件位置并不建立运行时兼容性。事件命名可能选择不同的负载，工具名称和参数可能变化，输出或错误行为也可能不同。

　　复用钩子之前，请遵循[钩子迁移过程和兼容性矩阵](../2.4.11-MigrateExistingCustomizations/#migrate-hooks)。选择目标运行框架并启动测试会话；仅更改语言模型不能测试迁移。

## 复用插件中的钩子 {#reuse-hooks-from-a-plugin}

　　对于现有自动化工作流，请[浏览自定义 Marketplace](../2.4.1-Overview/#discover-and-install-existing-customizations-preview)，查找包含钩子及其支持脚本的插件。

　　安装之前，请审查脚本、所需可执行文件和受支持的运行框架。钩子可以在配置的事件发生时运行，而无需模型请求。Marketplace 列表不能证明钩子的事件格式或命令与会话兼容。

　　遵循[插件安装步骤](../2.4.2-Plugins/#install-a-plugin-from-a-marketplace)，完成发布者设置，并在目标环境中验证钩子执行。在另外添加独立副本之前，请检查[重复钩子来源](#choose-a-hook-source)。如果执行与预期不同，请遵循[钩子故障排除](#troubleshoot-hooks)。

## 查找和管理钩子 {#find-and-manage-hooks}

　　打开钩子界面之前请选择运行框架，以便编辑器显示相关的自定义来源。

1. 打开聊天视图或智能体窗口。
2. 从 **会话目标** 控件选择 **Copilot**。
3. 打开智能体自定义编辑器：
    * 在聊天视图中选择标题栏的 **打开自定义项**，然后选择 **钩子**。
    * 在智能体窗口中选择侧边栏的 **自定义项**，然后在编辑器中选择 **钩子**。
    * 在聊天视图中输入 `/hooks`。
4. 在 **工作区** 或 **用户** 旁选择 **新建钩子**（加号图标）创建钩子，或选择现有钩子打开其配置。

　　要使用 AI 生成钩子，请在聊天中描述所需钩子。`/create-hook <描述>` 和 **Chat: Generate Hook** 快捷方式仅适用于 Local 会话。运行生成的配置和脚本之前，请对照目标参考审查它们。生成不是自动迁移或验证。

## 创建第一个 Copilot 钩子 {#create-your-first-copilot-hook}

　　从一个只记录工具名称、不记录参数或结果的诊断钩子开始。此示例创建工作区钩子，并要求执行主机安装 Node.js。要创建可跨仓库使用的钩子，请遵循[设置个人钩子](#set-up-a-personal-hook)。

1. 打开项目文件夹，从 **会话目标** 控件选择 **Copilot**。
2. 打开智能体自定义编辑器，选择 **钩子** 选项卡。
3. 在 **工作区** 旁选择 **新建钩子**（加号图标）。
4. 选择 **工具使用前**。如果列出了现有钩子，请选择 **添加新钩子...**。
5. 选择 **创建新钩子配置文件...**，在提示时选择仓库的 `.github/hooks` 文件夹，并输入 `audit` 作为文件名。
6. 在生成的配置中使用以下 JSON。测试钩子之前，请完成支持脚本。

编辑器会创建并打开配置文件。此示例使用 `preToolUse` 事件名，因为脚本需要对应的 camelCase 负载：

```json
{
  "version": 1,
  "hooks": {
    "preToolUse": [
      {
        "type": "command",
        "command": "node .github/hooks/log-tool-use.cjs",
        "timeoutSec": 10
      }
    ]
  }
}
```

接下来，在 `.github/hooks/log-tool-use.cjs` 添加支持脚本。钩子创建流程只创建配置，不创建此脚本：

```javascript
const fs = require('node:fs');
const path = require('node:path');
const event = JSON.parse(fs.readFileSync(0, 'utf8'));
if (typeof event.toolName !== 'string') {
  throw new Error('Expected a Copilot preToolUse event with toolName.');
}
fs.appendFileSync(
  path.join(__dirname, 'tool-use.log'),
  `${JSON.stringify(event.toolName)}\n`
);
process.stdout.write('{}');
```

将 `.github/hooks/tool-use.log` 添加到 `.gitignore`。启动新的 **Copilot** 会话，请求一个使用工具的无害任务，例如读取项目文件。确认日志包含工具名称，并且任务继续经过正常权限检查。返回 `{}` 表示不做权限决定，不是自动批准工具。

　　日志写在脚本旁边，因此将脚本移动到用户钩子目录时，日志也会留在那里。对于共享插件钩子，请使用[捆绑脚本示例](https://docs.github.com/en/copilot/reference/hooks-reference)，不要将日志写入已安装插件的代码目录。

　　验证后删除 `tool-use.log`。如果继续使用诊断，请保留其 `.gitignore` 条目；如果不再需要，请删除诊断配置和脚本。共享钩子之前，请审查脚本、记录其 Node.js 依赖，并在每个目标环境（例如容器或远程工作区）中重复检查。本地检查成功不能确认执行主机具有相同路径、依赖或权限。

　　如果希望直接创建配置，请将 JSON 保存为 `.github/hooks/audit.json`，必要时创建文件夹，添加相同的支持脚本并执行上述验证。

## 选择钩子来源 {#choose-a-hook-source}

　　在智能体自定义编辑器中，选择 **工作区** 使用共享仓库钩子，或选择 **用户** 使用个人钩子。下表列出底层来源和其他分发钩子的方式：

| 需求 | 来源 |
|------|--------|
| 跨仓库的个人自动化 | `~/.copilot/hooks/` 中的用户钩子文件；设置 `COPILOT_HOME` 时为 `$COPILOT_HOME/hooks/`。 |
| 与仓库共享自动化 | 仓库根目录的 `.github/hooks/*.json` |
| 与其他个人或仓库设置放在一起 | 受支持 Copilot 设置文件中的内联 `hooks` 映射 |
| 带脚本和其他自定义项的可复用设置 | [智能体插件](../2.4.2-Plugins/) |
| 仅对一个自定义智能体生效的自动化 | [智能体作用域钩子](#agent-scoped-hooks) |
| 组织管理的验证 | [企业钩子控制](../../../enterprise/7.2-ManageAISettings/#enable-or-disable-hooks) |

　　Copilot 运行框架读取 `.github/copilot/settings.json`、`.github/copilot/settings.local.json` 和 `~/.copilot/settings.json` 中的内联钩子设置。它还读取仓库的 `.claude/settings.json` 和 `.claude/settings.local.json`。用户 `config.json` 不是钩子设置文件。所有受支持来源、优先级和策略目录请参阅 [Copilot 钩子位置](https://docs.github.com/en/copilot/reference/hooks-reference#hooks-locations)。

　　来自多个来源的适用钩子会一起运行。新的仓库钩子不会替换同一事件的用户或插件钩子。启用迁移副本之前请检查重复项。

　　还要保留禁用状态。`chat.useHooks` 等本地设置不会阻止 Copilot 运行框架加载配置。切换之前请遵循[准备步骤](../2.4.11-MigrateExistingCustomizations/#prepare-hooks-for-migration)。

　　在远程会话和容器中，用户文件夹和可执行依赖项属于运行时运行的环境。`chat.hookFilesLocations` 等本地编辑器设置不会配置 Copilot 发现。

### 设置个人钩子 {#set-up-a-personal-hook}

要跨仓库使用新钩子：

1. 在选中 **Copilot** 运行框架的情况下，打开智能体自定义编辑器中的 **钩子**。
2. 在 **用户** 旁选择 **新建钩子**（加号图标）。
3. 选择事件，添加新钩子，并按照提示在受支持的用户钩子文件夹中创建配置。
4. 将支持脚本添加到该文件夹，并在钩子的 `command` 中使用其带引号的绝对路径。路径和可执行文件必须存在于智能体运行时运行的环境中。

　　例如，将 `log-tool-use.cjs` 放入用户钩子文件夹并更新命令路径，以调整[诊断钩子](#create-your-first-copilot-hook)。启动新会话并按上述方式验证日志。测试之前，请在 **钩子** 页面检查重复命令。

　　如果希望直接创建文件，请使用 `~/.copilot/hooks/`；设置 `COPILOT_HOME` 时使用 `$COPILOT_HOME/hooks/` 存放配置和脚本。

## 配置命令和事件数据 {#configure-commands-and-event-data}

　　命令钩子通过标准输入（stdin）接收 JSON 事件数据，并可以在标准输出（stdout）返回一个 JSON 输出对象。请将诊断文本与该输出分开。

　　Copilot 运行框架支持跨平台 `command` 回退以及平台特定的 `bash` 或 `powershell` 命令。命令参数应放在命令字符串中。还提供无 shell 的 `exec` 和 `args` 形式；这些参数不能替代 stdin 上的事件 JSON。

　　仅在[命令钩子参考](https://docs.github.com/en/copilot/reference/hooks-reference#command-hooks)允许的情况下使用 `cwd`、`env` 和 `timeoutSec`。将命令移动到用户文件夹、插件、远程主机或容器时，请审查其依赖项和工作目录。

### 事件和负载 {#events-and-payloads}

根据需要执行的操作选择事件：

| 目标 | Copilot 事件 |
|------|---------------|
| 会话开始或恢复时添加上下文 | `sessionStart` |
| 观察提交的提示词 | `userPromptSubmitted` |
| 检查工具调用或做出决定 | `preToolUse` |
| 验证成功结果或添加上下文 | `postToolUse` |
| 压缩前保存信息 | `preCompact` |
| 观察子智能体开始或结束 | `subagentStart`、`subagentStop` |
| 检查智能体是否应结束回合 | `agentStop` |
| 会话终止时清理 | `sessionEnd` |

　　完整事件列表、时机、字段和子智能体覆盖范围请参阅[事件参考](https://docs.github.com/en/copilot/reference/hooks-reference#hook-event-input-payloads)。并非每个事件都会消费所有输出。例如，`userPromptSubmitted` 会忽略命令钩子输出；通过 SDK 以编程方式重写提示词是另一个 API。

　　事件名称还决定输入格式。`preToolUse` 接收 `toolName` 和 `toolArgs`。兼容别名 `PreToolUse` 接收 snake_case 字段，但可能报告 Claude 风格的工具名称，例如 `Read`、`Write` 和 `Edit`。两种格式都不能保证与旧 Local 钩子具有相同工具参数。

### 决定和失败 {#decisions-and-failures}

　　对于 `preToolUse`，返回文档化的顶级决定：

```json
{
  "permissionDecision": "deny",
  "permissionDecisionReason": "This operation requires manual review."
}
```

　　返回 `{}` 表示不做决定。`ask` 需要交互式审批流程；不要假设它会为无人值守会话暂停等待批准。`postToolUse` 钩子可以添加顶级 `additionalContext`，但不能撤销已经完成的动作。

　　将错误处理视为钩子约定的一部分。GitHub 文档指出，命令 `preToolUse` 错误会拒绝工具调用，但超时会落入正常权限流程，包括策略钩子。其他事件和 HTTP 钩子的失败行为不同。请测试[退出代码和超时规则](https://docs.github.com/en/copilot/reference/hooks-reference#exit-codes-for-command-hooks)，不要假设每次失败都会阻止工作。

## 智能体作用域钩子 {#agent-scoped-hooks}

　　智能体作用域钩子在自定义智能体的 `hooks` frontmatter 中声明，并在该智能体活动期间适用。它会在其他来源的适用钩子之外运行。

　　[Copilot 智能体作用域钩子参考](https://docs.github.com/en/copilot/reference/hooks-reference#agent-scoped-hooks)说明了支持的命令字段、信任要求、子智能体行为以及远程或组织托管定义的排除项。

　　VS Code 在为 Copilot 转换自定义智能体（包括插件提供的智能体）时会保留 `hooks` 字段。钩子映射仍限定于各自智能体。

　　[自定义智能体](../2.4.5-CustomAgents/)会验证钩子结构，但选择智能体或没有看到验证提示并不能证明其钩子会执行。依赖钩子之前，请在受信任会话中验证预期事件和任何工具拒绝行为。

　　将智能体特定的自动化保留在智能体 frontmatter 中。将命令移动到仓库级或插件级事件会改变哪些智能体触发它，并非等价配置。

## 现有 Local 钩子 {#existing-local-hooks}

　　本节仅用于在[迁移](../2.4.11-MigrateExistingCustomizations/#migrate-hooks)之前识别现有 Local 设置。

* Local 会发现仓库和用户钩子文件、配置的 `chat.hookFilesLocations` 以及智能体或插件钩子。Claude 设置文件需要 `chat.useClaudeHooks`。
* `chat.useHooks` 控制 Local 执行。这些设置不会配置共享 Copilot 运行时。
* Local 解析器接受 PascalCase 和 Copilot 事件别名、命令别名以及嵌套 Claude 命令组。它忽略匹配器值，并仍发送 Local 负载。
* Local 智能体作用域钩子需要受信任工作区和 `chat.useHooks`。当智能体作为子智能体运行时，作用域 `Stop` 钩子会被视为 `SubagentStop`。

　　[Local 参考](../../reference-and-help/reference/2.8.1.9-HooksReference/)保留了转换这些脚本所需的配置、输入和输出细节。对于新钩子，请使用上面的 Copilot 示例。

## 排查钩子问题 {#troubleshoot-hooks}

1. 确认 **会话目标**、安装的运行时版本和钩子来源。
2. 检查其他用户、仓库、设置、智能体或插件来源是否贡献了相同命令。
3. 使用非敏感事件夹具直接运行脚本。检查其退出状态和精确 JSON 输出，包括格式错误输入的行为。
4. 启动一次性会话，确认钩子在预期事件和工具上触发。编辑器中显示文件并不能证明其脚本已执行。
5. 检查执行环境中的依赖项、路径引号、`cwd` 和权限。将超时与命令错误分开测试。

　　使用[智能体调试日志](../../reference-and-help/troubleshooting/2.8.2.2-DebugChatInteractions/)和提供商诊断进行调查。避免记录可能包含敏感数据的完整提示词、参数、结果或环境变量。

　　对于旧 Local 设置，**Chat: Configure Hooks** 会列出其文件，**GitHub Copilot Chat Hooks** 输出通道会显示其命令错误。

## 安全注意事项 {#security-considerations}

> **警告**：钩子配置和脚本是可执行代码。使用之前请审查它们，包括插件中捆绑或共享仓库中存储的钩子。

* 使用事件输入之前先验证。不要将不受信任的工具参数插入 shell 命令。
* 只授予脚本所需的文件系统和网络访问权限。钩子的 `cwd` 或 `env` 不会扩大沙盒访问权限。
* 不要让凭据进入配置、脚本、输出、日志或智能体上下文。
* 保护配置和脚本，防止意外更改。
* 在每个目标中验证来源限制、失败行为和事件覆盖范围。钩子和指令不能替代强制权限、沙盒或企业控制。
