这一节是**按场景编排的美式英语口语对话**，共 7 章 122 个场景文件、607 段细化对话。目的很直接：让你在真正遇到那个场合之前，就已经把该说的话练过一遍。

## 怎么用这一节

**不要只读。** 对话是用来"演"的：

1. **先听自己的声音**——挑一个角色，出声读完一遍，别在心里默读。口语的肌肉记忆只能靠嘴练出来。
2. **换角色再来一遍**——第二遍读另一个人的台词，你会发现有些句子站在对面说会很别扭，那就是你要重点练的地方。
3. **遮住中文**——把中文翻译盖住，看自己能不能把英文说出来；反过来，看着中文说英文更难，也更有用。
4. **替换词槽**——每个场景末尾的"可替换句型"是把它变成你自己的句子的工具。把里面的词换成你真实生活里的信息，再说一遍。

## 对话为什么长这样

这些对话刻意保留了真实口语的样子，而不是教科书英语：

- **缩略形式**：gonna、wanna、kinda、gotta、ain't、'em。这些在美剧字幕语料里是百万级高频词，真人日常就是这么说的。每个缩略形式在文末都给出完整写法。
- **没有完整句子**：真人对话大量使用省略——"You okay?"、"This one."、"Same here."、"No way."。这不是语法错误，是口语常态。
- **填充词和语气词**：well、so、like、you know、I mean、uh-huh、hmm。它们不承载信息，但决定你说的话听起来自不自然。
- **真实的停顿和修正**：说话人会说到一半改口、会被打断、会重复对方的话确认。这是母语者的真实节奏。
- **接话而不是答题**：对方说一句，你要能顺着接下去（backchannel），而不是等着轮到自己念台词。

## 对话怎么读

每一段对话都是**英文一句、中文一句**的对照格式：**英文整句加粗（人名也在加粗里），中文整行不加粗、前面有 💬 标记，并标注中文说话人**。

```
**Kayla: Hi folks, I'm Kayla. Can I start you off with something to drink?**

💬 凯拉： 大家好，我是凯拉。要先来点喝的吗？
```

**为什么中文行也标说话人**：英文名（Kayla、Marcus、Priya）对初学者不一定是即时可读的信息，中文名一出来，谁在说话一眼就清楚，方便你按角色演。

**怎么练**：

1. **先遮住中文**，出声把英文读一遍——不要默读，口语的肌肉记忆只能靠嘴练。
2. **再遮住英文**，看着中文把英文说出来。这一步比上一步难得多，也更有用。
3. **换角色再演一遍**，你会发现站在对面说某些句子会很别扭，那就是要重点练的地方。
4. **替换词槽**——每段末尾的「这一幕的核心句型」是模板，把里面的信息换成你真实生活里的，再说一遍。

## 给中文母语者的三个提醒

**一、先解决"听不懂"，再解决"说不出"。**
绝大多数人卡住不是因为不会说，而是对方语速一快、一整段没跟上，然后就再也接不回去了。所以第二章之前，请先把 [听不懂时怎么救场](../life/clarification/) 练熟——它是所有场景的公共底座。

**二、客气程度要用对档位。**
中文里"请、麻烦你"很通用，英文里客气分好几个档，用错了会显得生硬或者没礼貌：

| 档位 | 说法 | 什么时候用 |
| --- | --- | --- |
| 直接 | Give me the check. | 很熟的人、或者赶时间 |
| 中性 | Can I get the check? | 日常最常用，安全 |
| 客气 | Could I get the check, please? | 正式餐厅、对长辈或陌生人 |
| 很客气 | Would you mind bringing the check? | 想特别有礼貌、或者对方在忙 |

**三、闲聊不是废话。**
在美国，跟陌生人搭话是日常礼貌，不是套近乎。电梯里、排队时、结账时，冷场反而尴尬。第一章的寒暄和第五章的办公室闲聊专门练这个——它们看着"没内容"，其实是最实用的一类口语。

> [!TIP] 遇到不确定的表达怎么办
>
> 这一节的对话用词参照影视字幕口语语料（每百万词出现次数）挑选，避开了只在书本里出现的过时说法。但语言会变，如果你在美剧或播客里听到不一样的说法，**以你听到的为准**——真实语料永远比教材新。

## 写作规范

这一节是**维护和续写时必须遵守的规范**。新增场景、修改既有文件，都照这一份来。

### 一、文件与目录

- 七个章节各一个子目录：`life/` `social/` `sports/` `study/` `work/` `health/` `occasions/`
- 一个场景一篇 markdown 文件，放在所属章节目录下，文件名用**小写英文短横线**形式（`playing-basketball.md`、`asking-colleagues.md`）
- 每章一个 `_index.md` 列出本章全部场景；章节的顺序用 `weight` 控制，场景在章内的顺序用 `_index.md` 表格里的序号控制
- 新增文件后必须同时更新本章 `_index.md`，否则页面上点不进去

### 二、Front matter

**每篇必须有**，字段照下面的来：

```toml
+++
title = "中文标题"
linkTitle = "中文短标题"
date = 2026-09-22T10:00:00+08:00
weight = 场景在本章内的序号
type = "docs"
description = "一句话中文描述，含场景关键词"
isCJKLanguage = true
categories = ["English", "口语"]
tags = ["英语口语", "场景对话", "本章标签", "场景关键词", "美式英语"]
draft = false
+++
```

**注意**：`description` 里**不要写会过期的数字**（比如"五段共 120 回合"）。内容一改数字就错，这类描述要写成不含数字的场景概括。

### 三、标题层级

| 层级 | 用途 | 约束 |
| --- | --- | --- |
| `#` 一级标题 | **不写** | 本站 Hugo 主题会从 front matter 的 `title` 自动生成页面标题，正文再写会出现两个 H1 |
| `##` 二级标题 | **只用于细化场景**（末尾可有一节 `## 通用句型与说明`） | 总览、"核心句型""关联词汇"等**都不许**占用二级标题 |
| `###` 三级标题 | 每幕的附属内容 | `### 这一幕的核心句型`、`### 口语小注`、`### 中式英语纠正`、`### 关联词汇`、`### 语调和发音提示` |
| `####` 及更深 | 一般不用 | 需要时用加粗小标题代替 |

**总览内容直接写在 front matter 之后，不加任何标题**：这个场景什么时候用、中美习惯差异、注意事项、文化背景。段落之间留空行，可以放表格。

### 四、每个文件的对话结构

四层：

1. **总览**（无标题）：2–4 段中文说明，讲清什么时候用、跟中国有什么不同
2. **3–6 段细化场景**，每段一个 `##` 小标题 + 完整对话
3. **每幕的句型与提示**，挂在各自场景下面，用 `###`
4. **末尾可选** `## 通用句型与说明`，放全篇速查表、全篇词汇表、语调提示

**细化场景**是这一节的核心设计：

- 可以**同一批人在不同时间**（一次看诊的五个阶段），也可以**不同人物、不同场合**（同样点餐，一次快餐店、一次正式餐厅）
- 小标题要**具体、有画面感**：「临出门前对方临时取消」，不要写「场景三」「对话二」
- 每幕开头先列**角色表**，每个角色写成 `**英文名**（中文身份或性格说明）`
- 每幕 **15–30 个回合**（双方发言合计），低于 15 显得单薄，超过 30 读起来累

### 五、对话的书写格式

**英文整句加粗，且说话人姓名在加粗范围内；中文整行不加粗，行首放 💬，并标注中文说话人。**

```
**Kayla: Hi folks, I'm Kayla. Can I start you off with something to drink?**

💬 凯拉： 大家好，我是凯拉。要先来点喝的吗？
```

要点：

- 中文说话人用**中文名或中文职能**：Marcus→马库斯、Referee→裁判、Professor Ellis→Ellis 教授、Tutor→家教、You→你
- 同一个说话人在同一文件内的中文名必须**前后一致**，跨文件也尽量统一
- **英文一句，中文紧跟一句**，中间空一行；不许出现只有英文没有译文的行
- **舞台提示**用斜体、放在说话人之前：`*（周六早上十点，公园球场）* **Dave: Alright, let's run it back.**`
- 动作类提示若无台词，写成独立的斜体行：`*（往频道里贴了三十行日志）*`
- 同一个中文说法要在英文侧固定一个说话人标签：民宿房东写 `Landlord`（中文"房东"），餐厅带位写 `Host`（中文"带位员"），不要混用

### 六、内容要求

**必须真实**：

- 对话是**欧美人在该场合真实会说的话**，不是教科书英语。写之前先想"这个场景里美国人第一句会说什么"
- 真实口语特征要写进去：缩略（gonna / wanna / gotta / kinda / 'em / ain't）、省略句（`Got it.` `My way.` `Fair enough.` `Same here.`）、填充词（well / so / like / you know / I mean / honestly）、话语标记（`Anyway,` `Oh hey,` `By the way,`）
- 要有**真实的来回**：接话、追问、打断、改口、妥协，不能一句问一句答像问卷
- **文化和流程细节必须准确**：小费比例、保险术语、DMV 流程、离营时间、学校截止日、职场表达的客气档位等，写错比不写更糟
- 拿不准的说法，宁可换一个确定的，也不要编

**禁止**：

- 教科书腔（`How do you do?`、`It is very nice to meet you.`）
- 完美完整句堆砌，真人说话不是那样
- 英语里不存在的表达（例如把"加油"翻成 `Add oil`）
- 把人物写得没有情绪：真实对话里有惊讶、犹豫、玩笑、敷衍、认错

**翻译要求**：

- 中文要**自然**，宁可意译，不要逐字硬译
- 英文里的语气词、缩略形式在中文里要找到对应的口语感（`I mean…` → "我是说……"）
- 专有名词、地名、品牌保留原文；金额、单位照美国习惯写（华氏度、英寸、美元）

### 七、每幕的附属内容

- **`### 这一幕的核心句型`**：表格，三列 `| 英文 | 中文 | 备注 |`，备注里写什么时候用、是不是只对熟人用
- **`### 中式英语纠正`**：表格 `| 常见错法 | 问题 | 改成 |`，问题一栏要写清"为什么错"
- **`### 口语小注`**：3–5 条，讲真实用法、文化提醒、易混点
- **`### 关联词汇`**：表格 `| 单词 | 英 /…/ | 美 /…/ | 意思 |`，**音标必须来自校对过的 5000 词表**，不在表里的词宁可不列，也不要自己编

### 八、音标与用词核验

音标以 `words/` 目录里那 5000 个词的音标为准（已经过维基词典与 CMU 发音词典校对）。用词是否真在日常口语里，参照影视字幕语料词频（每百万词出现次数），出现次数极低的词说明不常用，应换掉。

| 检查项 | 要求 |
| --- | --- |
| 场景数 | 每文件 3–6 个细化场景 |

| 标题层级 | 正文无 H1；`##` 只用于细化场景；附属内容全是 `###` |
| 中英对照 | 每个英文句后面紧跟配对的中文译文，说话人一致 |

### 十、省 token 的执行规则（硬性）

这一节的要求**跟内容质量同等重要**。对话写作是长文本生成，铺开写会迅速烧钱，必须按下面的规矩执行。

#### 十条禁令

| # | 禁止 | 必须 |
| --- | --- | --- |
| 1 | 一次铺开多个并行子代理（曾一次起 16 个写 60 篇，费用失控） | **一次最多 2 个子代理**，且必须先说明预计花费 |
| 2 | 让子代理在提示里重抄一遍完整规范（每个代理重读一遍就等于同一份钱付多次） | 子代理提示里**只写本次任务 + 指向规范文件路径**，让它自己读一次 |
| 3 | 用子代理做机械活儿（替换、统计、重命名、格式校验） | 这类活儿**一律用脚本**，脚本本身几乎不花钱 |
| 4 | 一次生成大量文件后再统一返修 | **先写 1 篇样稿确认格式**，确认后按同一模板批量推进 |
| 5 | 反复通读大文件做校验（读一次 5000 词表约 6 万 token） | 校验**只跑脚本看结论**，不要读全文 |
| 6 | 读完整个文件只为改其中几行 | 先 `grep -n` 定位行号，再按 `offset/limit` 读片段 |
| 7 | 让主代理和子代理做重复的复核 | 复核**只做一遍**，用脚本 + 抽查，不搞多轮交叉验证 |
| 8 | 每轮回复都做大段总结 | 输出**按需给结论**，过程细节不必复述 |
| 9 | 用户没要求就扩范围（顺手重构、顺手补别的章） | **严格按要求的范围做**，不加戏 |
| 10 | 把一个任务拆成多轮追加需求（每追加一次，前面的内容都要重发计费） | **一次把范围、格式、篇数说清** |

#### 最省的执行顺序

1. **先出 1 篇样稿**（主代理自己写，不派代理），给用户确认格式与风格
2. **批量时用脚本 + 少量代理**：能用脚本做的（生成骨架、替换格式、统计、校验）绝不交给代理
3. **单批控制在 10–15 篇以内**，写完立即校验、立即收尾
4. **需要 20 篇以上时**，先跟用户对齐"分几批、大概花多少"，不要默认全铺开
5. 长文档任务**不要放在一个超长会话里反复追加**——会话历史每轮都会重发，越到后面每一问越贵。跨天或跨任务时**开新会话**

#### 成本量级参考

| 做法 | 相对成本 |
| --- | --- |
| 主代理自己串行写一篇对话 | 1× |
| 一个子代理写一篇（要重读规范、重发上下文） | 约 3–5× |
| 十几个子代理并行写几十篇 | 几十倍，且大部分花在重复读同一份规范上 |
| 跑本地脚本做替换／统计／校验 | 近乎为零（只有输出计费） |

**结论很简单：批量写作的省钱关键不是"写得快"，而是"少重复读、少重复写、多用脚本"。**
