一对一（写作 one-on-one，办公室里一般直接说 1:1，读作 "one on one"）是你和直属上司每隔一到两周单独聊三十分钟的那个会。它跟中国职场里"领导找你去办公室谈一下"最大的区别是：**这个会是你的会，议程由你来定**。美国经理默认你会带着想聊的事情坐下，空着手等领导开口，在他眼里就是"这次没什么可聊的"，连着几次，他会觉得你对这份工作不上心。

所以一对一不是汇报会。如果你说的只有"我这周做了什么、下周做什么"，三十分钟就白费了。真正该放进这个会的，是那些平时没地方说的事：卡住你的依赖、你对自己优先级的疑问、你想听到的反馈、你想去的方向。这些在群里说太重，在项目会上没机会，一对一就是给它们留的位置。

| 中国人习惯的做法 | 美国职场期待的做法 |
| --- | --- |
| 等领导问"你最近怎么样" | 自己开口：`I had a couple things I wanted to cover.` |
| 只汇报进度，不提出问题 | 带一个需要上司拍板的阻塞点来 |
| 有困难自己扛，怕显得能力不行 | 早说 + 给方案：`I'm blocked on X. I need it by Friday.` |
| 等领导主动给反馈 | 直接问：`Do you have any feedback for me?` |
| 发展的事等公司安排 | 自己讲清楚想要什么：`What would it take to get to the next level?` |
| 活太多就熬夜硬扛 | 摆出取舍：`Something has to give.` |
| 有机会等着被点名 | 主动举手：`I'd like to be on it. Here's why I'd be a good fit.` |

还有两点要提前有心理准备。第一，美国上司**很少主动批评你**。不是因为你没问题，而是他们的默认设置是"你没问，那就是没事"。所以问反馈不是示弱，而是这段工作关系里的常规动作。第二，开头那两三句 `How's it going?` 是真实的问候，不是纯过场，但忙起来的上司会很快切到正事，被"打断"不代表他不耐烦。

**反馈这件事，关键在"追问一层"。** 你问 `Do you have any feedback for me?`，八成会得到 `No, you're doing great.`——这不是敷衍，而是美式职场默认"没提就是没问题"，批评要你自己去要。把问题问具体，真话才会出来：`Is there anything you'd want me to do differently?`、`What's one thing I could do better?`，或者干脆指着某一件具体的事问 `How did that presentation land?`。拿到真话以后的标准动作是三段：`That's fair.` → `I appreciate you saying it straight.` → `Can you give me an example so I can work on it?`。**千万不要现场辩解**，辩解一次，他下次就不说了。

**要资源不等于抱怨，这条线要划清楚。** 抱怨是"我活太多了"，谈优先级是"三件事我都想做，但时间只够两件，你想让我先做哪件"。前者把问题推给上司的情绪，后者把选择权交回上司手里，还顺手给了他一个可以做的决定。同理，说 `Something has to give.` 不是讨价还价，而是把一个不现实的计划摆到台面上——美国经理宁可现在听你说这句话，也不愿意两周后听到"来不及了"。

## 季度中期一对一：议程自己定，先报进度再报卡点
**Engineering Manager**（你的直属上司）
**Senior Software Engineer**（就是你）

*（周三上午，一间小会议室，30 分钟的 1:1）*

---

**Engineering Manager: Hey, come on in. How's it going?**

💬 工程经理： 嘿，进来坐。最近怎么样？

**Senior Software Engineer: Good. Busy week. How about you?**

💬 高级软件工程师： 挺好的。这周挺忙。你呢？

**Engineering Manager: Can't complain. How's the week treating you? I know the migration's been a lot.**

💬 工程经理： 没什么可抱怨的。这周过得怎么样？我知道迁移那摊事挺重的。

**Senior Software Engineer: Yeah, heads down. But I had a couple things I wanted to cover today, if that works.**

💬 高级软件工程师： 是啊，一直埋头干。不过我今天有几件事想聊，方便的话。

**Engineering Manager: Yeah, absolutely. What do you want to start with?**

💬 工程经理： 当然，说吧。你想从哪儿开始？

**Senior Software Engineer: I put a little agenda together. Nothing formal. Quick status first, then a blocker I want a decision on, and then I wanted to ask you for some feedback.**

💬 高级软件工程师： 我列了个小议程，不正式。先快速过一下进度，然后有个卡点想请你拍板，最后想让你给我点反馈。

**Engineering Manager: Perfect. Let's do it.**

💬 工程经理： 好，那就这么来。

**Senior Software Engineer: So, short version: the migration's on track for the 15th. Two of the four services are done, the third one's in review.**

💬 高级软件工程师： 简单说：迁移 15 号能按时交。四个服务做完两个，第三个在评审。

**Engineering Manager: Nice. Any surprises?**

💬 工程经理： 不错。有什么意外吗？

**Senior Software Engineer: One thing. The search service is taking longer than I estimated. Nothing's on fire, but I want to flag it early.**

💬 高级软件工程师： 有一件。搜索服务比我估的费时间。没到着火的程度，但我想早点说。

**Engineering Manager: Appreciate that. How big is the gap?**

💬 工程经理： 谢谢你说出来。差多少？

**Senior Software Engineer: About three days. I can absorb it if I drop the cleanup work, the dead code and the old config. That's kind of the decision I wanted from you.**

💬 高级软件工程师： 大概三天。如果把清理那部分放掉（废弃代码和旧配置），我能把这三天吃掉。这就是我想让你定的那件事。

**Engineering Manager: Let's do this. Push the cleanup to next sprint, keep the 15th. Does that work for you?**

💬 工程经理： 这样吧：清理推到下个迭代，15 号不动。你看行吗？

**Senior Software Engineer: That works. I'll write it down as a known gap so it doesn't get lost.**

💬 高级软件工程师： 行。我把它记成已知缺口，免得以后丢掉。

**Engineering Manager: Good. What else?**

💬 工程经理： 好。还有呢？

**Senior Software Engineer: Second thing. I'm blocked on the API access for the payments team. I can keep going on the UI, but I need it by Friday or the timeline moves.**

💬 高级软件工程师： 第二件。我卡在支付团队的 API 权限上。界面我可以继续做，但周三前得拿到，不然排期就得动。

**Engineering Manager: Who do you need it from?**

💬 工程经理： 需要谁给你开？

**Senior Software Engineer: Their platform lead. I've pinged him twice. I think it needs a nudge from you.**

💬 高级软件工程师： 他们的平台负责人。我催过两次了。我觉得得你去推一下。

**Engineering Manager: Send me the ticket. I'll ping him today.**

💬 工程经理： 把工单发我，我今天去找他。

**Senior Software Engineer: Will do. Thanks.**

💬 高级软件工程师： 好，谢谢。

**Engineering Manager: And the last one. You said feedback.**

💬 工程经理： 还有最后一件。你说要反馈。

**Senior Software Engineer: Yeah. Do you have any feedback for me? Anything you'd want me to do differently?**

💬 高级软件工程师： 对。你有什么反馈给我吗？有没有哪里你希望我换个做法？

**Engineering Manager: Honestly, you're doing well. One thing. You go quiet when you're heads down. I don't hear from you for four days and I start wondering.**

💬 工程经理： 说实话你做得不错。有一点：你一埋头就不出声了。四天没你的消息，我就开始瞎猜。

**Senior Software Engineer: That's fair. I appreciate you saying it straight.**

💬 高级软件工程师： 有道理。谢谢你直说。

**Engineering Manager: It's not a big thing. A two-line update Tuesday and Thursday would be plenty.**

💬 工程经理： 不是什么大事。周二和周四各来两行更新就够了。

**Senior Software Engineer: Okay, I can do that. I'll post a short update in the channel twice a week.**

💬 高级软件工程师： 好，我可以。我一周在频道里发两次简报。

**Engineering Manager: That's perfect. Anything you need from me?**

💬 工程经理： 那太好了。你需要我做什么吗？

**Senior Software Engineer: No, I'm good. Nothing's blocking me. I just wanted to keep you in the loop on the rest.**

💬 高级软件工程师： 不用，我没事。没有卡点。剩下的就是跟你同步一下。

### 口语小注

**1. 头两分钟是关系，不是过场。**

`How's it going?` 这类问候在上司那边是真话，不是客套，你答一句 `Good, busy week. How about you?` 就够了。但别把它拖成十分钟的闲聊：忙的时候上司会主动切到正事，那不是在打断你，是在给你省时间。

**2. 议程是你的责任，这一点美国人非常当真。**

`I had a couple things I wanted to cover.` 这一句就完成了"我主导这次会"的动作。偶尔一次空手来没关系，连续几次没有议题，上司会默认你没有想法。会前把议题发在日历邀请里，是加分动作。

**3. `Nothing's on fire` 是美国人报坏消息的常用开场。**

它的意思是"这事不紧急，但我还是要让你知道"。先说"不严重"，再说具体数字（`about three days`），上司就不会进入救火模式，也不会怀疑你在隐瞒。

**4. `I don't need anything from you, just wanted to keep you in the loop.` 是美国人最常用的一句"没事"。**

它的作用是把"同步"和"求助"分开，让上司知道这条信息不需要他动手。学会说这句，你就不会每次开口都像在要资源。

## 主动要反馈：把「你做得不错」追问成一句真话
**Engineering Manager**（Dave）
**Senior Software Engineer**（就是你）

*（两周后的 1:1，你特意在议程最后留了十分钟谈反馈）*

---

**Engineering Manager: Hey. Before we start — how'd the migration demo go?**

💬 工程经理： 嘿。开始之前问一句——迁移的演示怎么样？

**Senior Software Engineer: Pretty well, I think. Which is kind of what I wanted to talk about today, actually.**

💬 高级软件工程师： 我觉得挺好的。其实这正是我今天想聊的事。

**Engineering Manager: Oh yeah? Go ahead.**

💬 工程经理： 哦？你说。

**Senior Software Engineer: I blocked out the last ten minutes for feedback. Do you have any feedback for me?**

💬 高级软件工程师： 我把最后十分钟留给了反馈。你有什么反馈给我吗？

**Engineering Manager: Honestly? No, you're doing great. The migration's in good shape.**

💬 工程经理： 说实话？没有，你做得挺好。迁移状态很好。

**Senior Software Engineer: I appreciate that. But I want to make sure I'm not just collecting compliments here.**

💬 高级软件工程师： 谢谢。但我想确认一下，我不是只在这儿收表扬。

**Engineering Manager: (laughs) Okay. Fair.**

💬 工程经理： *（笑）* 好吧。有道理。

**Senior Software Engineer: So let me ask it differently. Is there anything you'd want me to do differently?**

💬 高级软件工程师： 那我换个问法。有没有哪里你希望我换个做法？

**Engineering Manager: Hmm. Let me think for a second.**

💬 工程经理： 嗯，我想一下。

**Senior Software Engineer: Take your time. That's why I asked for ten minutes.**

💬 高级软件工程师： 你慢慢想。我特意要了十分钟就是这个原因。

**Engineering Manager: Okay. Here's one. When you present, you spend most of the time on what you built. You don't spend much time on why it matters.**

💬 工程经理： 好，有一条。你做汇报的时候，大部分时间在讲你做了什么，很少讲它为什么重要。

**Senior Software Engineer: That's fair. Can you give me an example so I can work on it?**

💬 高级软件工程师： 有道理。能举个例子吗，我好改。

**Engineering Manager: The demo on Tuesday. You showed the architecture for twenty minutes. You didn't say what it unblocks for the business.**

💬 工程经理： 周二那次演示。你讲了二十分钟架构，没说它给业务解开了什么。

**Senior Software Engineer: Yeah. I had the numbers ready, I just didn't think that was my part.**

💬 高级软件工程师： 是啊。数据我都准备了，我只是觉得那不是该我讲的部分。

**Engineering Manager: It is your part. If you want the next level, that's exactly the gap.**

💬 工程经理： 那就是该你讲的部分。如果你想上下一级，这正是差距所在。

**Senior Software Engineer: Okay. That's fair, and I appreciate you saying it straight.**

💬 高级软件工程师： 好。有道理，谢谢你直说。

**Engineering Manager: I'd rather you hear it from me now than in a review six months from now.**

💬 工程经理： 我宁可你现在从我这儿听到，而不是半年后从评审里听到。

**Senior Software Engineer: Agreed. And how am I doing, honestly, against what you'd expect at my level?**

💬 高级软件工程师： 同意。那说真的，按我这个级别的要求，我做得怎么样？

**Engineering Manager: Solid on delivery. The gap is the explaining. People outside the team judge you on the story, not the code.**

💬 工程经理： 交付很稳。差距在"讲清楚"这件事上。团队之外的人靠你的说法评判你，不靠代码。

**Senior Software Engineer: So more "why" and less "how."**

💬 高级软件工程师： 那就是少讲"怎么做"，多讲"为什么"。

**Engineering Manager: Yeah. Start with the why, then one slide of how. That's it.**

💬 工程经理： 对。先讲为什么，然后一页纸讲怎么做，就这样。

**Senior Software Engineer: Okay. I'm gonna try that on the next one, and I'll ask you how it landed. Can I come back to this in two weeks?**

💬 高级软件工程师： 好。下次我按这个来，然后问你觉得效果怎么样。两周后能再聊这个吗？

**Engineering Manager: Yeah, put it on the agenda. If I don't see a change, I'll say so.**

💬 工程经理： 可以，放进议程。要是我没看到变化，我会直说。

**Senior Software Engineer: Deal. Thanks, Dave. That was worth the ten minutes.**

💬 高级软件工程师： 一言为定。谢谢，Dave。这十分钟值了。

**Engineering Manager: Anytime. Anything else you need from me?**

💬 工程经理： 随时。还有别的需要我做的吗？

**Senior Software Engineer: Not right now. Maybe a chance to walk the search team through the same story, for practice.**

💬 高级软件工程师： 现在没有。也许给我个机会，让我跟搜索团队讲一遍同样的东西，练一下。

**Engineering Manager: Good idea. I'll set up a weekly sync and you can take the first ten minutes.**

💬 工程经理： 好主意。我搞个每周同步会，前十分钟你来。

**Senior Software Engineer: That'd help. Thanks.**

💬 高级软件工程师： 那会有帮助。谢谢。

**Engineering Manager: Thanks for pushing on the feedback thing. Most people don't.**

💬 工程经理： 谢谢你追着要反馈。大部分人不会。

**Senior Software Engineer: (laughs) It's uncomfortable. But I'd rather know.**

💬 高级软件工程师： *（笑）* 挺不舒服的。但我宁愿知道。

### 口语小注

**1. 第一问基本拿不到真话，这不代表对方在敷衍。**

`Do you have any feedback for me?` 得到的固定答案就是 `No, you're doing great.`。美式职场的默认设置是"没提就是没问题"，批评要你自己去要。**所以问一次不够，要换个问法再问一次**，`Is there anything you'd want me to do differently?` 就是那个更好用的第二问。

**2. `How did that presentation land?` 是最容易问出真话的一句。**

问"我整体怎么样"太大，上司只能给个笼统的评价；指着某一件具体的事问，他脑子里有画面，回答自然具体。**汇报完的当天或第二天问，效果最好**——隔两周他就忘了。

**3. 听到批评的三段动作：接住、道谢、要例子。**

`That's fair.` → `I appreciate you saying it straight.` → `Can you give me an example so I can work on it?` 顺序别乱。第一句让对方知道你听进去了，第二句让他觉得值得说，第三句把批评落到能改的事情上。

**4. 千万不要现场辩解。**

`No, that's not true` 或者 `But I did say that` 说一次，对方下次就不说了，而你还在以为"我们关系挺好"。有不同看法可以问 `Can I give you some context on that?`——先接受，再补充，顺序反过来效果完全不同。

**5. 反馈要有闭环。**

拿到反馈以后自己约下一次：`I'm gonna try that on the next one, and I'll ask you how it landed.` 这句话会让上司记住你，因为**大多数人不做这件事**。

## 谈发展路径：晋升差在哪，怎么落到日期
**Engineering Manager**（Dave）
**Senior Software Engineer**（就是你）

*（月初的 1:1，你提前在议程里写了 "career path"）*

---

**Engineering Manager: Hey. How are you holding up? Busy month, huh?**

💬 工程经理： 嘿。你还扛得住吗？这个月挺忙的吧。

**Senior Software Engineer: Yeah, it's been a lot. But good. I actually wanted to talk about where I'm headed, if we have time.**

💬 高级软件工程师： 是啊，事很多。不过都还行。其实我想聊聊我后面的方向，有时间的话。

**Engineering Manager: We've got the whole half hour. Go ahead.**

### 口语小注

**1. 谈晋升要问"标准"，不要问"时间"。**

`What would it take to get to the next level?` 和 `When will I get promoted?` 是两回事。前者上司愿意答，因为那是个业务问题；后者让他必须做出他做不了的承诺，只能给你空话。

**2. `Visibility and scope` 是美国晋升评审的两个高频词。**

美国公司评晋升，看的不只是"活干得好不好"，还有"团队之外有没有人知道你做的事""你负责的范围有多大"。所以"多带一个人""去全员会上讲一次"这类要求，都是在补这两块，不是虚的。

**3. 听到"继续保持"一定要当场追。**

`just keep doing what you're doing` 是美式职场最敷衍的一句安慰。**当场追一句 `How do we make that concrete?`**，把它换成时间 + 动作 + 见证人。追不出来的话，这次谈发展就等于没谈。

**4. 上司说 `I'll confirm by Friday`，你要记下来。**

这是承诺，不是客套。周五没消息，就礼貌地 ping 一下：`Hey, any word on the all-hands date?` 美国职场里 follow up 是专业表现，不是催命。

**5. 别把"我不想一个人扛"说成"我太累了"。**

`I'd rather not be the only one on the migration. Is there room to bring someone else in?` 的重点是**怎么把事做成**，上司的回答空间很大；`I'm exhausted` 的重点是你的感受，上司只能安慰你两句。

### 口语小注

**1. 说"我忙"没有用，说"总得放掉一样"才有用。**

`I'm very busy` 在上司耳朵里是情绪，没有信息量。`Something has to give.` 是一句判断：三件事同时做，质量一定垮。**美国经理对第二句的反应速度比第一句快十倍**，因为他可以处理它——他只需要决定放掉哪个。

**2. 给数字，不给形容词。**

`I'm spending about a day a week on interviews` 这句话比 `interviews take a lot of time` 有用得多。有了"每周一天"，上司立刻能心算：三件事就是三天的缺口。**谈工作量的时候，数据是最强的礼貌**。

**3. 主动把"抱怨"的标签撕掉。**

`This isn't me saying I can't do it. It's me saying I can't do all three well.` 这一组句子专门用来防误解。说完成量问题以后，很多人会被听成"他在推活"，加这一句就变成"他在保质量"。

**4. `That's on me` 是好事，不是坏事。**

美国上司说 `That's on me. I kept adding things.` 是在认账，不是在自责，更不需要你去安慰他。**标准回应是接住并往前推**：`I could have said something sooner. What do we drop?` 气氛就顺了。

**5. 上司的反向承诺要接住。**

`Tell me when it's two things, not three.` 这句话给了你一个许可。**下次真的在两件事的时候就开口**，两次以后，你们的沟通节奏就稳了；要是还憋着不说，他下次就不会再给了。

💬 高级软件工程师： 太好了。谢谢，Dave。迁移的交接方案我照样写出来——不管结果如何都有用。

### 口语小注

**1. 先用"听说"开场，别一上来就递申请。**

`I heard the recommendations project is kicking off. I'd like to be on it.` 两句就够了：第一句给对方留了余地（万一消息不准，大家都不尴尬），第二句把意图说清楚。**美国人很吃这种直球**，绕圈子反而显得你没底气。

**2. 说服力来自"同一类问题"，不是"我很努力"。**

`I've done the event pipeline work, and this is the same shape of problem.` 是这一场里最有用的一句。它把你的过去和新项目连成一条线，上司不需要想象你的潜力，他已经看过你的成品。

**3. 主动提风险，会加分而不是减分。**

`I know it might leave a gap on the migration. Here's how I'd hand it off.` **先说风险，再说方案，中间不能停。** 上司最怕的是你拍胸脯说没问题，然后两个项目一起塌。你把交接写出来，他就少了一个拒绝你的理由。

**4. `Let me see how the staffing shakes out` 可能是软拒绝。**

这句话的真实含义有三种：真的还没定、需要时间去推、或者他不想直接说不。**分辨方法是要一个日期**：`Can I check back with you next week?` 真在推进的上司会立刻给你时间；给不出任何时间点的，多半是第三种，你就该准备第二个方案了。

**5. 收尾的姿态很重要：不卑不亢。**

`If it doesn't work out, I'd rather hear it from you than find out from the org chart.` 加 `I'll write up the handoff plan anyway — it's useful either way.` 这两句让你即使没拿到项目，也留下一个"这人成熟、想的是事"的印象。**这是一种投资，不是嘴硬。**

### 中式英语纠正

| 常见错法 | 问题 | 改成 |
| --- | --- | --- |
| `I have nothing to report.` | 一对一不是等领导来问；说"没什么可汇报"等于把这次机会作废，上司会认为你没准备 | `Nothing's blocking me. Two things I wanted to cover, though.` |
| `Please give me your feedback.` | 语法没错但像在索要评价，很生硬；美式习惯是问"有没有" | `Do you have any feedback for me?` |
| `My work is very hard.` | 直译是"我的工作很难"，听起来像在说自己能力不够，而不是在说活多 | `I've got a lot on my plate right now.` |
| `I want to improve myself.` | 太抽象，上司没法接话，也落不到任何具体行为上 | `I'd like to work on my presentation skills.` |
| `I will try my best.` | 在美国职场等于没有承诺，上司听到的是"可能会砸" | `I'll have it to you by Thursday.` |
| `Leader, I have a problem.` | 美国人不叫 leader，也没有这种称呼；先叫人名，再直接说事 | `Hey Dave, I'm blocked on the API access.` |
| `I have no problem.` | 答非所问，"没问题"不是"我没有困难" | `I'm good. Nothing's blocking me.` |
| `Please give me more work.` | 听起来很奇怪，美国人不这样要活；要说想接触什么方向、想上哪个项目 | `I'd like to be on the recommendations project.` |
| `You didn't tell me clearly.` | 把责任推给上级，即使事实如此也会破坏信任 | `I think I missed something. Can we go over the priorities again?` |
| `I am very busy, I cannot do it.` | 拒绝得太硬，也没给上司留选择空间 | `Something has to give. Where would you like me to prioritize?` |
| `No, that's not true.` | 当场辩解，上司下次就不给你反馈了 | `That's fair. Can I give you some context on that?` |
| `I want to join this project.` | 意思对但少了"为什么是你"，听起来像在挑活 | `I'd like to be on it. Here's why I think I'd be a good fit.` |

### 语调与发音提示

**1. 问反馈的句子，尾音要降下来。**

`Do you have any feedback for me?` 如果尾音上扬，听起来像在确认"你是不是有意见"；轻轻降下来，才是在认真要一个答案。同一个句子，语调不同，对方给的东西完全不一样。

**2. `I appreciate you saying it straight.` 里 straight 要重读。**

整句节奏是：快 → 慢 → 重。`I appreciate you saying it STRAIGHT.` 重音落在最后一个词上，感谢才显得真诚；平着念完，听上去像在背台词。

**3. `Something has to give.` 要说得平，不要说得重。**

这句最容易出事的地方是语气。说重了像在下最后通牒，说平了才是"我在陈述一个客观情况"。**降调、语速放慢、不要加重 has**，效果最好。

**4. 举手要机会时，`I'd like to be on it` 的 to 要弱读。**

读成 /aɪd laɪk tə bi ˈɑn ɪt/，`to` 几乎吞掉。这样听起来是自然的口语；一字一顿念成 /tuː/ 会显得很郑重，反而像在宣读申请。

**5. `That's fair.` 说得短、说得快。**

两个词，一口气说完，语调平。**拖长或者加重会变成"好吧，随你"**，完全变了意思。这是接收反馈时最常用的一句，值得单独练十遍。
