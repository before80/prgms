# 14.1 参与 Kotlin 早期访问预览

> 目前没有可用的预览版本。

你可以参与 Kotlin 早期访问预览（EAP），在正式发布之前试用最新的 Kotlin 特性。

在每次语言版本（_2.x.0_）和工具版本（_2.x.20_）发布之前，我们都会提供早期访问预览（EAP）构建，供你在真实项目中测试并尽早反馈。Kotlin EAP 构建通常包含以下阶段：

| EAP 构建 | 说明                                                                                                                                                                                              |

| **Beta1** | 引入第一批即将推出的特性、改进和其他重要变更。让你有机会尽早评估新功能并提供反馈。                             |
| **Beta2** | 通常会根据我们收到的反馈增加更多特性并加以完善。此阶段功能已完整，继续预览即将发布的版本，并让此前引入的特性更加成熟。 |
| **RC**    | 第一个发布候选版本。重点是稳定 Beta1 和 Beta2 中交付的变更，并修复测试期间发现的回归问题。                                                        |
| **RC2**   | 包含用于最终确定版本并确认就绪状态的重要修复。                                                                                                                                  |

如果你把发现的任何缺陷报告到我们的问题跟踪器 [YouTrack](https://kotl.in/issue)，我们将非常感激。大多数情况下，我们可以在最终发布前修复它们，因此你不必等到下一个 Kotlin 版本才能看到问题被解决。

通过参与早期访问预览并报告缺陷，你就在为 Kotlin 做贡献，帮助我们为[不断壮大的 Kotlin 社区](https://kotlinlang.org/community/)中的每个人把它变得更好。

如果你有任何疑问或想参与讨论，欢迎加入 [Kotlin Slack 中的 #eap 频道](https://app.slack.com/client/T09229ZC6/C0KLZSCHF)。在这个频道中，你还可以收到关于新的 EAP 构建的通知。

**[为 Kotlin EAP 版本配置你的项目](../14.2-ConfigureBuildForEap/)**

> **注意：** 参与 EAP 即表示你明确知悉 EAP 版本可能不可靠、可能无法按预期工作，并且可能包含错误。我们不保证同一版本线的 EAP 版本与最终版本之间的兼容性。

## EAP 如何帮助你更高效地使用 Kotlin {#how-the-eap-can-help-you-be-more-productive-with-kotlin}

* **为稳定版发布做好准备**。如果你在做复杂的多模块项目，参与 EAP 可以让你在采用稳定版时更加顺畅。越早升级到稳定版，就能越早享受它的性能改进和新语言特性。

庞大而复杂的项目迁移可能需要一段时间，这不仅是因为它们的规模，也因为某些特定用例可能还没有被 Kotlin 团队覆盖。通过参与 EAP 并持续测试新的 Kotlin 版本，你可以就自己的特定用例向我们提供早期反馈。这将帮助我们解决尽可能多的问题，并确保你在稳定版发布时能够安全升级。[看看 Slack 如何从测试 Android、Kotlin 和 Gradle 的预发布版本中受益](https://slack.engineering/shadow-jobs/)。
* **让你的库保持最新**。如果你是库作者，升级到新的 Kotlin 版本极其重要。使用较旧的版本可能会阻碍你的用户在他们的项目中升级 Kotlin。使用 EAP 版本可以让你在稳定版发布时几乎立刻支持最新的 Kotlin 版本，这会让你的用户更满意，也会让你的库更受欢迎。
* **分享体验**。如果你是 Kotlin 爱好者，并且喜欢通过创作教学内容为 Kotlin 生态做贡献，那么在 Kotlin EAP 中试用新特性可以让你成为最早与社区分享这些酷炫新特性使用体验的人之一。
