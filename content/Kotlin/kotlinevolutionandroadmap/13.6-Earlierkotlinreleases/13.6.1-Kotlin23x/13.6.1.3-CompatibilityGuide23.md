# 13.6.1.3 Kotlin 2.3.x 兼容性指南

_[保持语言的现代性](../../../13.3-KotlinEvolutionPrinciples/)_ 和 _[舒适的更新](../../../13.3-KotlinEvolutionPrinciples/)_ 是 Kotlin 语言设计中的基本原则。前者指出，阻碍语言演进的构造应该被移除；后者指出，这种移除应事先充分沟通，以便代码迁移尽可能顺畅。

虽然大多数语言变更已经通过其他渠道公布过（例如更新日志或编译器警告），但本文汇总了所有这些变更，为从 Kotlin 2.2 迁移到 Kotlin 2.3 提供完整参考。本文还包含与工具相关的变更信息。

## 基本术语 {#basic-terms}

本文介绍了以下几种兼容性：

- _源码级_：源码不兼容的变更会让原本能正常编译（无错误或警告）的代码不再能编译
- _二进制级_：如果互换两个二进制产物不会导致加载或链接错误，则称它们是二进制兼容的
- _行为级_：如果同一个程序在应用变更前后的行为不同，则该变更属于行为不兼容

请记住，这些定义仅针对纯 Kotlin。从其他语言（例如 Java）的视角来看 Kotlin 代码的兼容性不在本文讨论范围内。

## 语言 {#language}

### 放弃对 1.8 和 1.9 的 `-language-version` 支持 {#drop-support-in-language-version-for-1-8-and-1-9}

> **Issue**：[KT-76343](https://youtrack.jetbrains.com/issue/KT-76343)、[KT-76344](https://youtrack.jetbrains.com/issue/KT-76344)。**组件**：编译器 **不兼容变更类型**：源码级 **简要说明**：从 Kotlin 2.3 开始，编译器不再支持 [`-language-version=1.8`](../../../../compilerandplugins/12.1-Kotlincompiler/12.1.4-CompilerReference/#language-version-version)。对于非 JVM 平台，对 `-language-version=1.9` 的支持也已被移除。**弃用周期**：- 2.2.0：使用 `-language-version` 指定 1.8 和 1.9 版本时报告警告 - 2.3.0：在所有平台上把 1.8 版本、在非 JVM 平台上把 1.9 版本的 `-language-version` 警告提升为错误

### 对带类型别名的推断类型报告上界约束违规错误 {#report-upper-bound-constraint-violation-errors-for-inferred-types-with-typealiases}

> **Issue**：[KTLC-287](https://youtrack.jetbrains.com/issue/KTLC-287) **组件**：核心语言 **不兼容变更类型**：源码级 **简要说明**：此前编译器从不对推断类型的上界约束违规报错。Kotlin 2.3.0 修复了这一点，使该错误在所有类型参数上一致地报告。**弃用周期**：- 2.2.20：对隐式类型实参造成的边界违例报告弃用警告 - 2.3.0：把隐式类型实参上 `UPPER_BOUND_VIOLATED` 的警告提升为错误

### 禁止在 `inline` 和 `crossinline` lambda 上使用 `@JvmSerializableLambda` 注解 {#prohibit-jvmserializablelambda-annotation-on-inline-and-crossinline-lambdas}

> **Issue**：[KTLC-9](https://youtrack.jetbrains.com/issue/KTLC-9) **组件**：核心语言 **不兼容变更类型**：源码级 **简要说明**：你不能再把 `@JvmSerializableLambda` 注解应用于 `inline` 或 `crossinline` lambda。这些 lambda 不可序列化，因此应用 `@JvmSerializableLambda` 没有效果。**弃用周期**：- 2.1.20：把 `@JvmSerializableLambda` 应用于 `inline` 和 `crossinline` lambda 时报告警告 - 2.3.0：把该警告提升为错误；该变更可以在渐进模式下启用

### 当泛型签名不匹配时禁止把 Kotlin 接口委托给 Java 类 {#prohibit-delegating-a-kotlin-interface-to-a-java-class-when-the-generic-signatures-don-t-match}

> **Issue**：[KTLC-267](https://youtrack.jetbrains.com/issue/KTLC-267) **组件**：核心语言 **不兼容变更类型**：源码级 **简要说明**：Kotlin 2.3.0 禁止委托给那些以非泛型覆盖实现泛型接口方法的 Java 类。此前允许这种做法会在运行时导致类型不匹配和 `ClassCastException`。这一变更把错误从运行时提前到编译期。**弃用周期**：- 2.1.20：报告警告 - 2.3.0：把该警告提升为错误

### 弃用在表达式体函数中使用 `return`（未显式指定返回类型时） {#deprecate-use-of-return-in-expression-bodied-functions-without-explicit-return-type}

> **Issue**：[KTLC-288](https://youtrack.jetbrains.com/issue/KTLC-288) **组件**：核心语言 **不兼容变更类型**：源码级 **简要说明**：Kotlin 现在弃用在未显式声明函数返回类型时在表达式体中使用 `return`。**弃用周期**：- 2.3.0：报告警告 - 2.4.0：把该警告提升为错误

### 禁止继承通过类型别名引入的可为空父类型 {#prohibit-inheritance-from-nullable-supertypes-introduced-via-typealias}

> **Issue**：[KTLC-279](https://youtrack.jetbrains.com/issue/KTLC-279) **组件**：核心语言 **不兼容变更类型**：源码级 **简要说明**：Kotlin 现在尝试继承可为空的类型别名时会报错，这与它对直接的可为空父类型既有的处理方式一致。**弃用周期**：- 2.2.0：报告警告 - 2.3.0：把该警告提升为错误

### 统一顶层 lambda 与调用实参的泛型签名生成 {#unify-generic-signature-generation-for-top-level-lambdas-and-call-arguments}

> **Issue**：[KTLC-277](https://youtrack.jetbrains.com/issue/KTLC-277) **组件**：反射 **不兼容变更类型**：行为级 **简要说明**：Kotlin 2.3.0 对顶层 lambda 使用与作为调用实参传入的 lambda 相同的类型检查逻辑，确保两种情况下生成的泛型签名一致。**弃用周期**：- 2.3.0：引入新行为；在渐进模式下不适用

### 禁止把 reified 类型参数推断为交叉类型 {#prohibit-reified-type-parameters-from-being-inferred-as-intersection-types}

> **Issue**：[KTLC-13](https://youtrack.jetbrains.com/issue/KTLC-13) **组件**：核心语言 **不兼容变更类型**：源码级 **简要说明**：Kotlin 2.3.0 禁止把 reified 类型参数推断为交叉类型的情况，因为这可能导致不正确的运行时行为。**弃用周期**：- 2.1.0：把 reified 类型参数推断为交叉类型时报告警告 - 2.3.0：把该警告提升为错误

### 禁止通过类型参数边界暴露可见性更低的类型 {#prohibit-exposing-less-visible-types-through-type-parameter-bounds}

> **Issue**：[KTLC-275](https://youtrack.jetbrains.com/issue/KTLC-275) **组件**：核心语言 **不兼容变更类型**：源码级 **简要说明**：Kotlin 2.3.0 禁止使用会暴露可见性比函数或声明本身更严格的类型的类型参数边界，使函数的规则与已应用于类的规则保持一致。**弃用周期**：- 2.1.0：对有问题的类型参数边界报告警告 - 2.3.0：把该警告提升为错误

## 标准库 {#standard-library}

### 弃用 Char 与数值之间的转换，并引入显式的 digit 和 code API {#deprecate-char-to-number-conversions-and-introduce-explicit-digit-and-code-apis}

> **Issue**：[KTLC-321](https://youtrack.jetbrains.com/issue/KTLC-321) **组件**：kotlin-stdlib **不兼容变更类型**：源码级 **简要说明**：Kotlin 2.3.0 弃用了数值类型的 `Char.toX()` 和 `X.toChar()` 转换，并引入了用于访问字符编码值和数字值的新显式 API。**弃用周期**：- 1.4.30：以实验性形式引入新函数 - 1.5.0：把新函数提升为稳定；对旧函数报告警告并给出替代建议 - 2.3.0：把这些警告提升为错误

### 弃用 `Number.toChar()` 函数 {#deprecate-number-tochar-function}

> **Issue**：[KT-56822](https://youtrack.jetbrains.com/issue/KT-56822) **组件**：kotlin-stdlib **不兼容变更类型**：源码级 **简要说明**：`Number.toChar()` 函数已被弃用。请改用 `toInt().toChar()` 或 `Char` 构造器。**弃用周期**：- 1.9.0：使用 `Number.toChar()` 函数时报告警告 - 2.3.0：把该警告提升为错误

### 弃用 `String.subSequence(start, end)` 函数 {#deprecate-string-subsequence-start-end-function}

> **Issue**：[KTLC-282](https://youtrack.jetbrains.com/issue/KTLC-282) **组件**：kotlin-stdlib **不兼容变更类型**：源码级 **简要说明**：`String.subSequence(start, end)` 函数已被弃用。请改用 [`String.subSequence(startIndex, endIndex)`](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin/-string/sub-sequence.html) 函数。**弃用周期**：- 1.0：使用 `String.subSequence(start, end)` 时报告警告 - 2.3.0：把该警告提升为错误

### 弃用 `kotlin.io.createTempDirectory()` 和 `kotlin.io.createTempFile()` 函数 {#deprecate-kotlin-io-createtempdirectory-and-kotlin-io-createtempfile-functions}

> **Issue**：[KTLC-281](https://youtrack.jetbrains.com/issue/KTLC-281) **组件**：kotlin-stdlib **不兼容变更类型**：源码级 **简要说明**：`kotlin.io.createTempDirectory()` 和 `kotlin.io.createTempFile()` 函数已被弃用。请改用 [`kotlin.io.path.createTempDirectory()`](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin.io.path/create-temp-directory.html) 和 [`kotlin.io.path.createTempFile()`](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin.io.path/create-temp-file.html) 函数。**弃用周期**：- 1.4.20：使用 `kotlin.io.createTempDirectory()` 和 `kotlin.io.createTempFile()` 函数时报告警告 - 2.3.0：把该警告提升为错误

### 隐藏 `InputStream.readBytes(Int)` 函数 {#hide-inputstream-readbytes-int-function}

> **Issue**：[KTLC-280](https://youtrack.jetbrains.com/issue/KTLC-280) **组件**：kotlin-stdlib **不兼容变更类型**：源码级 **简要说明**：在长期弃用之后，`InputStream.readBytes(estimatedSize: Int = DEFAULT_BUFFER_SIZE): ByteArray` 函数现在已被隐藏。**弃用周期**：- 1.3.0：报告警告 - 1.5.0：把该警告提升为错误 - 2.3.0：隐藏该函数

### 统一 Kotlin/Native 与其他平台的堆栈跟踪打印 {#unify-kotlin-native-stack-trace-printing-with-other-platforms}

> **Issue**：[KT-81431](https://youtrack.jetbrains.com/issue/KT-81431) **组件**：Kotlin/Native **不兼容变更类型**：行为级 **简要说明**：在格式化异常堆栈跟踪时，如果同一个异常原因已经被打印过，就不会再打印额外的原因。**弃用周期**：- 2.3.20：把 Kotlin/Native 的异常堆栈跟踪格式与其他 Kotlin 平台统一

### 修正 `Iterable<T>.intersect()` 和 `Iterable<T>.subtract()` 的行为 {#correct-iterable-t-intersect-and-iterable-t-subtract-behavior}

> **Issue**：[KTLC-268](https://youtrack.jetbrains.com/issue/KTLC-268) **组件**：kotlin-stdlib **不兼容变更类型**：行为级 **简要说明**：[`Iterable<T>.intersect()`](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin.collections/intersect.html) 和 [`Iterable<T>.subtract()`](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin.collections/subtract.html) 函数现在会在把每个接收者元素加入结果集之前先测试其隶属关系。结果集使用 `Any::equals` 比较元素，因此即使参数集合使用引用相等（例如 `IdentityHashMap.keys`）也能得到正确结果。**弃用周期**：- 2.3.0：启用新行为

## 工具 {#tools}

### 同时使用 `kotlin-dsl` 和 `kotlin("jvm")` 插件时收到不受支持的 KGP 版本警告 {#unsupported-kgp-version-warning-when-using-kotlin-dsl-and-kotlin-jvm-plugins}

> **Issue**：[KT-79851](https://youtrack.jetbrains.com/issue/KT-79851) **组件**：Gradle **不兼容变更类型**：行为级 **简要说明**：在 Kotlin 2.3 中，如果你的 Gradle 项目同时使用 `kotlin-dsl` **和** `kotlin("jvm")` 插件，可能会看到关于不受支持的 Kotlin Gradle 插件（KGP）版本的 Gradle 警告。**迁移步骤**：一般来说，我们不建议在同一个 Gradle 项目中同时使用 `kotlin-dsl` 和 `kotlin("jvm")` 插件。这种组合不受支持。对于约定插件、预编译脚本插件或任何其他未发布的构建逻辑，你有三种选择：1. 不要显式应用 `kotlin("jvm")` 插件，而是让 `kotlin-dsl` 插件自动提供兼容的 KGP 版本。2. 如果你想显式应用 `kotlin("jvm")` 插件，请使用 [`embeddedKotlinVersion`](https://docs.gradle.org/current/kotlin-dsl/gradle/org.gradle.kotlin.dsl/embedded-kotlin-version.html) 常量指定内嵌的 Kotlin 版本。要升级内嵌的 Kotlin 和语言版本，请更新 Gradle 版本。你可以在 Gradle 的 [Kotlin 兼容性说明](https://docs.gradle.org/current/userguide/compatibility.html#kotlin)中找到兼容的 Gradle 版本。3. 不要使用 `kotlin-dsl` 插件。对于不与特定 Gradle 版本绑定的二进制插件，这可能更合适。作为最后的手段，你可以把项目配置为使用语言版本 2.1 或更高版本，这会覆盖 `kotlin-dsl` 插件的冲突行为。不过，我们强烈建议不要这样做。如果你在迁移过程中遇到困难，请在我们的 [Slack](https://surveys.jetbrains.com/s3/kotlin-slack-sign-up) 的 #gradle 频道寻求支持。**弃用周期**：- 2.3.0：引入一项诊断，用于检测 `kotlin-dsl` 插件与不兼容的编译器语言或 API 版本一起使用的情况

### 弃用 AGP 9.0.0 及更高版本下的 `kotlin-android` 插件 {#deprecate-kotlin-android-plugin-for-agp-versions-9-0-0-and-later}

> **Issue**：[KT-81199](https://youtrack.jetbrains.com/issue/KT-81199) **组件**：Gradle **不兼容变更类型**：源码级 **简要说明**：在 Kotlin 2.3.0 中，当使用 Android Gradle 插件（AGP）9.0.0 或更高版本时，`org.jetbrains.kotlin.android` 插件已被弃用。从 AGP 9.0.0 开始，[AGP 内置了对 Kotlin 的支持](https://kotl.in/gradle/agp-built-in-kotlin)，因此不再需要 `kotlin-android` 插件。**弃用周期**：- 2.3.0：当 `kotlin-android` 插件与 AGP 9.0.0 或更高版本一起使用，并且 `android.builtInKotlin` 和 `android.newDsl=false` 两个 Gradle 属性都设置为 `false` 时报告警告

### 弃用 `testApi` 配置 {#deprecate-testapi-configuration}

> **Issue**：[KT-63285](https://youtrack.jetbrains.com/issue/KT-63285) **组件**：Gradle **不兼容变更类型**：源码级 **简要说明**：Kotlin 2.3.0 弃用了 `testApi` 配置。该配置会把测试依赖和源码暴露给其他模块，而 Gradle 不支持这种行为。**迁移选项**：把任何 `testApi()` 用法替换为 `testImplementation()`，其他变体同理。例如，把 `kotlin.sourceSets.commonTest.dependencies.api()` 替换为 `kotlin.sourceSets.commonTest.dependencies.implementation()`。对于 Kotlin/JVM 项目，请考虑改用 Gradle 的 [test fixtures](https://docs.gradle.org/current/userguide/java_testing.html#sec:java_test_fixtures)。如果你希望在多平台项目中支持 test fixtures，请在 [YouTrack](https://youtrack.jetbrains.com/issue/KT-63142) 中分享你的用例。**弃用周期**：- 2.3.0：报告警告

### 弃用 `createTestExecutionSpec()` 函数 {#deprecate-createtestexecutionspec-function}

> **Issue**：[KT-75449](https://youtrack.jetbrains.com/issue/KT-75449) **组件**：Gradle **不兼容变更类型**：源码级 **简要说明**：Kotlin 2.3.0 弃用了 `KotlinJsTestFramework` 接口中的 `createTestExecutionSpec()` 函数，因为它已不再使用。**弃用周期**：- 2.2.20：报告警告 - 2.3.0：把该警告提升为错误 - 2.4.0：移除该函数

### 移除 `closureTo()`、`createResultSet()` 和 `KotlinToolingVersionOrNull()` 函数 {#remove-closureto-createresultset-and-kotlintoolingversionornull-functions}

> **Issue**：[KT-64273](https://youtrack.jetbrains.com/issue/KT-64273) **组件**：Gradle **不兼容变更类型**：源码级 **简要说明**：Kotlin 2.3.0 从 `closure` DSL 中移除了 `closureTo()`、`createResultSet()` 函数，因为它们已不再使用。此外，`KotlinToolingVersionOrNull()` 函数也被移除。请改用 `KotlinToolingVersion()` 函数。**弃用周期**：- 1.7.20：报告错误 - 2.3.0：移除这些函数

### 弃用 `ExtrasProperty` API {#deprecate-the-extrasproperty-api}

> **Issue**：[KT-74915](https://youtrack.jetbrains.com/issue/KT-74915) **组件**：Gradle **不兼容变更类型**：源码级 **简要说明**：自 Kotlin 2.0.0 起已被弃用的 `ExtrasProperty` API 在 Kotlin 2.3.0 中变为 internal。请改用 Gradle 的 [`ExtraPropertiesExtension`](https://docs.gradle.org/current/dsl/org.gradle.api.plugins.ExtraPropertiesExtension.html) API。**弃用周期**：- 2.0.0：报告警告 - 2.1.0：把该警告提升为错误 - 2.3.0：把该 API 改为 internal

### 弃用 `KotlinCompilation` 中的 `HasKotlinDependencies` {#deprecate-haskotlindependencies-in-kotlincompilation}

> **Issue**：[KT-67290](https://youtrack.jetbrains.com/issue/KT-67290) **组件**：Gradle **不兼容变更类型**：源码级 **简要说明**：Kotlin 2.3.0 弃用了 [`KotlinCompilation`](https://kotlinlang.org/api/kotlin-gradle-plugin/kotlin-gradle-plugin-api/org.jetbrains.kotlin.gradle.plugin/-kotlin-compilation/) 中的 `HasKotlinDependencies` 接口。与依赖相关的 API 现在通过 [`KotlinSourceSet`](https://kotlinlang.org/api/kotlin-gradle-plugin/kotlin-gradle-plugin-api/org.jetbrains.kotlin.gradle.plugin/-kotlin-source-set/) 接口暴露。**弃用周期**：- 2.3.0：报告警告

### 弃用 npm 和 Yarn 包管理器的内部函数与属性 {#deprecate-npm-and-yarn-package-manager-internal-functions-and-properties}

> **Issue**：[KT-81009](https://youtrack.jetbrains.com/issue/KT-81009) **组件**：Gradle **不兼容变更类型**：源码级 **简要说明**：以下与 npm 和 Yarn 包管理器相关的函数和属性已被弃用：* `CompositeDependency.dependencyName`、`CompositeDependency.dependencyVersion`、`CompositeDependency.includedBuildDir`。* `KotlinNpmInstallTask.Companion.NAME`。* `LockCopyTask.Companion.STORE_PACKAGE_LOCK_NAME`、`LockCopyTask.Companion.RESTORE_PACKAGE_LOCK_NAME`、`LockCopyTask.Companion.UPGRADE_PACKAGE_LOCK`。* `Npm.npmExec()`。* `NpmProject.require()`、`NpmProject.useTool()`。* `PublicPackageJsonTask.jsIrCompilation`。* `YarnBasics.yarnExec()`。* `YarnPlugin.Companion.STORE_YARN_LOCK_NAME`、`YarnPlugin.Companion.RESTORE_YARN_LOCK_NAME`、`YarnPlugin.Companion.UPGRADE_YARN_LOCK`。* `YarnSetupTask.Companion.NAME`。**弃用周期**：- 2.2.0 和 2.2.20：使用这些函数或属性时报告警告 - 2.3.0：把这些警告提升为错误 - 2.4.0：移除这些函数和属性
