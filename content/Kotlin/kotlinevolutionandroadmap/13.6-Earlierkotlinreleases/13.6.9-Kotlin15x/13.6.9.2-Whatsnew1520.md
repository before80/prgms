# 13.6.9.2 Kotlin 1.5.20 的新变化

阅读 Kotlin 1.5.20 的发行说明，涵盖新的语言特性、Kotlin Multiplatform、JVM、Native、JS 的更新，以及对 Gradle 和 Maven 构建工具的支持。

## Kotlin/JVM {#kotlin-jvm}

Kotlin 1.5.20 在 JVM 平台上带来了以下更新：
* [通过 invokedynamic 进行字符串拼接](#string-concatenation-via-invokedynamic)
* [支持 JSpecify 可空性注解](#support-for-jspecify-nullness-annotations)
* [支持在同时包含 Kotlin 和 Java 代码的模块中调用 Java 的 Lombok 生成方法](#support-for-calling-java-s-lombok-generated-methods-within-modules-that-have-kotlin-and-java-code)

### 通过 invokedynamic 进行字符串拼接 {#string-concatenation-via-invokedynamic}

Kotlin 1.5.20 在面向 JVM 9+ 的目标时会把字符串拼接编译为[动态调用](https://docs.oracle.com/javase/7/docs/technotes/guides/vm/multiple-language-support.html#invokedynamic)（`invokedynamic`），从而与现代化 Java 版本保持一致。更准确地说，它使用 [`StringConcatFactory.makeConcatWithConstants()`](https://docs.oracle.com/javase/9/docs/api/java/lang/invoke/StringConcatFactory.html#makeConcatWithConstants-java.lang.invoke.MethodHandles.Lookup-java.lang.String-java.lang.invoke.MethodType-java.lang.String-java.lang.Object...-) 进行字符串拼接。

要切换回以前版本使用的、通过 [`StringBuilder.append()`](https://docs.oracle.com/javase/9/docs/api/java/lang/StringBuilder.html#append-java.lang.String-) 进行拼接的方式，请添加编译器选项 `-Xstring-concat=inline`。

在 [Gradle](../../../../buildtools/11.1-Gradle/11.1.5-GradleCompilerOptions/)、[Maven](../../../../buildtools/11.2-Maven/11.2.4-MavenKotlinCompiler/#specify-compiler-options) 和[命令行编译器](../../../../compilerandplugins/12.1-Kotlincompiler/12.1.4-CompilerReference/#compiler-options)中了解如何添加编译器选项。

### 支持 JSpecify 可空性注解 {#support-for-jspecify-nullness-annotations}

Kotlin 编译器可以读取各种[可空性注解](../../../../interoperability/7.1-Javainterop/7.1.2-JavaInterop/#nullability-annotations)，以便把可空性信息从 Java 传递到 Kotlin。1.5.20 版本引入了对 [JSpecify 项目](https://jspecify.dev/)的支持，其中包含一套标准统一的 Java 可空性注解。

借助 JSpecify，你可以提供更详细的可空性信息，帮助 Kotlin 在与 Java 互操作时保持空安全。你可以为声明、包或模块作用域设置默认可空性，指定参数化可空性等等。[JSpecify 用户指南](https://jspecify.dev/docs/user-guide)中有更多细节。

下面是一个示例，展示 Kotlin 如何处理 JSpecify 注解：

```java
// JavaClass.java
import org.jspecify.nullness.*;

@NullMarked
public class JavaClass {
  public String notNullableString() { return ""; }
  public @Nullable String nullableString() { return ""; }
}
```

```kotlin
// Test.kt
fun kotlinFun() = with(JavaClass()) {
  notNullableString().length // 可以
  nullableString().length // 警告：接收者可空性不匹配
}
```

在 1.5.20 中，根据 JSpecify 提供的可空性信息检测到的所有可空性不匹配都会以警告形式报告。在使用 JSpecify 时，请使用 `-Xjspecify-annotations=strict` 和 `-Xtype-enhancement-improvements-strict-mode` 编译器选项启用严格模式（以错误形式报告）。请注意，JSpecify 项目正在积极开发中，其 API 和实现可能随时发生重大变化。

[进一步了解空安全和平台类型](../../../../interoperability/7.1-Javainterop/7.1.2-JavaInterop/#null-safety-and-platform-types)。

### 支持在同时包含 Kotlin 和 Java 代码的模块中调用 Java 的 Lombok 生成方法 {#support-for-calling-java-s-lombok-generated-methods-within-modules-that-have-kotlin-and-java-code}

> **警告：** Lombok 编译器插件是[实验性](../../../13.4-ComponentsStability/)的。它可能随时被移除或更改。请仅将其用于评估目的。我们非常欢迎你在 [YouTrack](https://youtrack.jetbrains.com/issue/KT-7112) 上提供反馈。

Kotlin 1.5.20 引入了实验性的 [Lombok 编译器插件](../../../../compilerandplugins/12.2-Kotlincompilerplugins/12.2.4-Lombok/)。该插件让你可以在同时包含 Kotlin 和 Java 代码的模块中生成并使用 Java 的 [Lombok](https://projectlombok.org/) 声明。Lombok 注解只在 Java 源码中生效，如果你在 Kotlin 代码中使用它们，会被忽略。

该插件支持以下注解：
* `@Getter`、`@Setter`
* `@NoArgsConstructor`、`@RequiredArgsConstructor` 和 `@AllArgsConstructor`
* `@Data`
* `@With`
* `@Value`

我们仍在继续开发该插件。要了解当前的详细状态，请访问 [Lombok 编译器插件的 README](https://github.com/JetBrains/kotlin/tree/master/plugins/lombok)。

目前我们没有支持 `@Builder` 注解的计划。不过，如果你在 YouTrack 上为 [`@Builder`](https://youtrack.jetbrains.com/issue/KT-46959) 投票，我们会考虑它。

[了解如何配置 Lombok 编译器插件](../../../../compilerandplugins/12.2-Kotlincompilerplugins/12.2.4-Lombok/#gradle)。

### 选择启用把 KDoc 注释导出到生成的 Objective-C 头文件 {#opt-in-export-of-kdoc-comments-to-generated-objective-c-headers}

> **警告：** 把 KDoc 注释导出到生成的 Objective-C 头文件的能力是[实验性](../../../13.4-ComponentsStability/)的。它可能随时被移除或更改。需要选择启用（详见下文），并且你应仅将其用于评估目的。我们非常欢迎你在 [YouTrack](https://youtrack.jetbrains.com/issue/KT-38600) 上提供反馈。

现在你可以让 Kotlin/Native 编译器把 Kotlin 代码中的[文档注释（KDoc）](../../../../development/6.7-Developmenttooling/6.7.5-KotlinDoc/)导出到由它生成的 Objective-C framework 中，使 framework 的使用者可以看到它们。

例如，以下带 KDoc 的 Kotlin 代码：

```kotlin
/**
 * 打印各参数之和。
 * 正确处理了和不适合 32 位整数的情况。
 */
fun printSum(a: Int, b: Int) = println(a.toLong() + b)
```

会生成以下 Objective-C 头文件：

```objc
/**
 * 打印各参数之和。
 * 正确处理了和不适合 32 位整数的情况。
 */
+ (void)printSumA:(int32_t)a b:(int32_t)b __attribute__((swift_name("printSum(a:b:)")));
```

这在 Swift 中同样可以很好地工作。

要试用把 KDoc 注释导出到 Objective-C 头文件的能力，请使用 `-Xexport-kdoc` 编译器选项。在你希望导出注释的 Gradle 项目的 `build.gradle(.kts)` 中添加以下几行：

**Kotlin**

```kotlin
kotlin {
    targets.withType<org.jetbrains.kotlin.gradle.plugin.mpp.KotlinNativeTarget> {
        compilations.get("main").kotlinOptions.freeCompilerArgs += "-Xexport-kdoc"
    }
}
```

**Groovy**

```groovy
kotlin {
    targets.withType(org.jetbrains.kotlin.gradle.plugin.mpp.KotlinNativeTarget) {
        compilations.get("main").kotlinOptions.freeCompilerArgs += "-Xexport-kdoc"
    }
}
```

如果你能通过这个 [YouTrack 议题](https://youtrack.jetbrains.com/issue/KT-38600)与我们分享反馈，我们将非常感激。

### 编译器缺陷修复 {#compiler-bug-fixes}

Kotlin/Native 编译器在 1.5.20 中获得了多项缺陷修复。你可以在[更新日志](https://github.com/JetBrains/kotlin/releases/tag/v1.5.20)中找到完整列表。

其中有一项影响兼容性的重要缺陷修复：在此前版本中，包含不正确 UTF [代理对](https://en.wikipedia.org/wiki/Universal_Character_Set_characters#Surrogates)的字符串常量会在编译期间丢失其值。现在这类值会被保留。应用开发者可以放心更新到 1.5.20 —— 不会有任何东西被破坏。不过，用 1.5.20 编译的库与更早的编译器版本不兼容。细节请参阅[这个 YouTrack 议题](https://youtrack.jetbrains.com/issue/KT-33175)。

### 改进同一数组内 Array.copyInto() 的性能 {#improved-performance-of-array-copyinto-inside-one-array}

我们改进了 `Array.copyInto()` 在源和目标为同一个数组时的行为。由于针对这一用例的内存管理优化，这类操作现在快最多 20 倍（取决于所复制的对象数量）。

## Gradle {#gradle}

Kotlin 1.5.20 引入了以下可以改善 Gradle 使用体验的特性：

* [kapt 中注解处理器类加载器的缓存](#caching-for-annotation-processors-classloaders-in-kapt)
* [弃用 `kotlin.parallel.tasks.in.project` 构建属性](#deprecation-of-the-kotlin-parallel-tasks-in-project-build-property)

### 在 kapt 中缓存注解处理器的类加载器 {#caching-for-annotation-processors-classloaders-in-kapt}

> **警告：** kapt 中注解处理器类加载器的缓存是[实验性](../../../13.4-ComponentsStability/)的。它可能随时被移除或更改。请仅将其用于评估目的。我们非常欢迎你在 [YouTrack](https://youtrack.jetbrains.com/issue/KT-28901) 上提供反馈。

现在有一个新的实验性特性，可以在 [kapt](../../../../compilerandplugins/12.2-Kotlincompilerplugins/12.2.3-Kapt/) 中缓存注解处理器的类加载器。该特性可以提升连续多次 Gradle 运行时 kapt 的速度。

要启用该特性，请在 `gradle.properties` 文件中使用以下属性：

```none
# positive value will enable caching
# use the same value as the number of modules that use kapt
kapt.classloaders.cache.size=5

# disable for caching to work
kapt.include.compile.classpath=false
```

进一步了解 [kapt](../../../../compilerandplugins/12.2-Kotlincompilerplugins/12.2.3-Kapt/)。

### 弃用 kotlin.parallel.tasks.in.project 构建属性 {#deprecation-of-the-kotlin-parallel-tasks-in-project-build-property}

从本次发布开始，Kotlin 的并行编译由 [Gradle 并行执行标志 `--parallel`](https://docs.gradle.org/current/userguide/performance.html#parallel_execution)控制。使用该标志，Gradle 会并发执行任务，从而提升编译任务的速度并更高效地利用资源。

你不再需要使用 `kotlin.parallel.tasks.in.project` 属性。该属性已被弃用，并将在下一个大版本中移除。

## 标准库 {#standard-library}

Kotlin 1.5.20 修改了若干处理字符的函数的平台特有实现，从而实现了跨平台的统一：
* [在 Kotlin/Native 和 Kotlin/JS 中支持 Char.digitToInt() 的所有 Unicode 数字](#support-for-all-unicode-digits-in-char-digittoint-in-kotlin-native-and-kotlin-js)。
* [统一各平台上 Char.isLowerCase()/isUpperCase() 的实现](#unification-of-char-islowercase-isuppercase-implementations-across-platforms)。

### 在 Kotlin/Native 和 Kotlin/JS 中支持 Char.digitToInt() 的所有 Unicode 数字 {#support-for-all-unicode-digits-in-char-digittoint-in-kotlin-native-and-kotlin-js}

[`Char.digitToInt()`](https://kotlinlang.org/api/latest/jvm/stdlib/kotlin.text/digit-to-int.html) 返回该字符所表示的十进制数字的数值。在 1.5.20 之前，该函数只在 Kotlin/JVM 上支持所有 Unicode 数字字符：Native 和 JS 平台上的实现只支持 ASCII 数字。

从现在开始，无论是 Kotlin/Native 还是 Kotlin/JS，你都可以对任何 Unicode 数字字符调用 `Char.digitToInt()` 并得到它的数值表示。

```kotlin
fun main() {
    val ten = '\u0661'.digitToInt() + '\u0039'.digitToInt() // 阿拉伯-印度数字一 + 数字九
    println(ten)
}
```

### 统一各平台上 Char.isLowerCase()/isUpperCase() 的实现 {#unification-of-char-islowercase-isuppercase-implementations-across-platforms}

函数 [`Char.isUpperCase()`](https://kotlinlang.org/api/latest/jvm/stdlib/kotlin.text/is-upper-case.html) 和 [`Char.isLowerCase()`](https://kotlinlang.org/api/latest/jvm/stdlib/kotlin.text/is-lower-case.html) 根据字符的大小写返回布尔值。对于 Kotlin/JVM，其实现会同时检查 `General_Category` 和 `Other_Uppercase`/`Other_Lowercase` 这两个 [Unicode 属性](https://en.wikipedia.org/wiki/Unicode_character_property)。

在 1.5.20 之前，其他平台的实现行为不同，只考虑通用类别。在 1.5.20 中，各平台的实现得到统一，会使用这两个属性来判断字符大小写：

```kotlin
fun main() {
    val latinCapitalA = 'A' // 具有 "Lu" 通用类别
    val circledLatinCapitalA = 'Ⓐ' // 具有 "Other_Uppercase" 属性
    println(latinCapitalA.isUpperCase() && circledLatinCapitalA.isUpperCase())
}
```
