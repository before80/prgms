# 6.3.12 Kotlin/Native 常见问题

## 如何运行我的程序？ {#how-do-i-run-my-program}

定义一个顶层函数 `fun main(args: Array<String>)`；如果你不关心传入的实参，也可以只写 `fun main()`，请确保它不在任何包中。此外，还可以使用编译器开关 `-entry`，把任何接收 `Array<String>` 或不接收参数、返回 `Unit` 的函数设为入口点。

## Kotlin/Native 的内存管理模型是什么？ {#what-is-kotlin-native-memory-management-model}

Kotlin/Native 使用与 Java 或 Swift 类似的自动内存管理方案。

[了解 Kotlin/Native 内存管理器](../6.3.5-Memorymanager/6.3.5.1-NativeMemoryManager/)

## 如何创建共享库？ {#how-do-i-create-a-shared-library}

使用 `-produce dynamic` 编译器选项，或在 Gradle 构建文件中使用 `binaries.sharedLib()`：

```kotlin
kotlin {
    iosArm64("mylib") {
        binaries.sharedLib()
    }
}
```

它会生成平台特定的共享对象（Linux 上为 `.so`，macOS 上为 `.dylib`，Windows 目标上为 `.dll`）以及一个 C 语言头文件，让你可以从 C/C++ 代码中使用 Kotlin/Native 程序中所有公开 API。

[完成「Kotlin/Native 作为动态库」教程](../../../interoperability/7.3-Swiftobjectivecandcinterop/7.3.3-Cinterop/7.3.3.3-NativeDynamicLibraries/)

## 如何创建静态库或目标文件？ {#how-do-i-create-a-static-library-or-an-object-file}

使用 `-produce static` 编译器选项，或在 Gradle 构建文件中使用 `binaries.staticLib()`：

```kotlin
kotlin {
    iosArm64("mylib") {
        binaries.staticLib()
    }
}
```

它会生成平台特定的静态对象（`.a` 库格式）以及一个 C 语言头文件，让你可以从 C/C++ 代码中使用 Kotlin/Native 程序中所有公开 API。

## 如何在企业代理后面运行 Kotlin/Native？ {#how-do-i-run-kotlin-native-behind-a-corporate-proxy}

由于 Kotlin/Native 需要下载平台特定的工具链，你需要把 `-Dhttp.proxyHost=xxx -Dhttp.proxyPort=xxx` 指定为编译器或 `gradlew` 的参数，或者通过 `JAVA_OPTS` 环境变量来设置。

## 如何为我的 Kotlin 框架指定自定义 Objective-C 前缀/名称？ {#how-do-i-specify-a-custom-objective-c-prefix-name-for-my-kotlin-framework}

使用 `-module-name` 编译器选项或对应的 Gradle DSL 语句。

**Kotlin**

```kotlin
kotlin {
    iosArm64("myapp") {
        binaries.framework {
            freeCompilerArgs += listOf("-module-name", "TheName")
        }
    }
}
```

**Groovy**

```groovy
kotlin {
    iosArm64("myapp") {
        binaries.framework {
            freeCompilerArgs += ["-module-name", "TheName"]
        }
    }
}
```

## 如何重命名 iOS 框架？ {#how-do-i-rename-the-ios-framework}

iOS 框架的默认名称是 `<project name>.framework`。要设置自定义名称，请使用 `baseName` 选项。这同时也会设置模块名。

```kotlin
kotlin {
    iosArm64("myapp") {
       binaries {
          framework {
              baseName = "TheName"
          }
       }
    }
}
```

## 如何为我的 Kotlin 框架启用 bitcode？ {#how-do-i-enable-bitcode-for-my-kotlin-framework}

Bitcode 嵌入在 Xcode 14 中已被弃用，并在 Xcode 15 中针对所有 Apple 目标被移除。从 Kotlin 2.0.20 起，Kotlin/Native 编译器不再支持 bitcode 嵌入。

如果你使用的是较早版本的 Xcode，但想升级到 Kotlin 2.0.20 或更高版本，请在你的 Xcode 项目中禁用 bitcode 嵌入。

## 如何为 iOS 获得更好的崩溃报告？ {#how-do-i-get-better-crash-reports-for-ios}

当未被处理的 Kotlin 异常传播到 iOS 代码时，崩溃报告工具可能显示一条含糊的报告，指出这是 Kotlin/Native 的内部问题，而不是异常实际抛出的代码行。这是因为在记录崩溃时，原始的 Kotlin 堆栈轨迹已经丢失了。

你可以用第三方方案绕过这个问题，例如 [NSExceptionKt](https://github.com/rickclephas/NSExceptionKt)，它会把未捕获的 Kotlin 异常转换为 `NSException` 实例，从而使你的崩溃报告工具捕获到正确的堆栈轨迹。它为流行的崩溃报告工具提供了专门的集成：

* [Bugsnag](https://kotlinlang.org/docs/https://github.com/rickclephas/NSExceptionKt/blob/master/NSExceptionKtBugsnag/README.html)
* [Firebase Crashlytics](https://kotlinlang.org/docs/https://github.com/rickclephas/NSExceptionKt/blob/master/NSExceptionKtCrashlytics/README.html)

## 如何在不同协程之间安全地引用对象？ {#how-do-i-reference-objects-safely-from-different-coroutines}

要在 Kotlin/Native 中跨多个协程安全地访问或更新对象，请考虑使用并发安全的构造，例如 `@Volatile` 和 `AtomicReference`。

使用 [`@Volatile`](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin.concurrent/-volatile/) 标注 `var` 属性。这样可以让对该属性幕后字段的所有读写都成为原子操作。此外，写入会立即对其他线程可见。当另一个线程访问该属性时，它不仅能观察到更新后的值，还能观察到更新之前发生的所有改动。

或者使用 [AtomicReference](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin.concurrent.atomics/-atomic-reference/)，它支持原子读取和更新。在 Kotlin/Native 上，它包装了一个 volatile 变量并执行原子操作。Kotlin 还针对特定数据类型提供了一组原子操作类型。你可以使用 `AtomicInt`、`AtomicLong`、`AtomicBoolean`、`AtomicArray`，以及 `AtomicIntArray` 和 `AtomicLongArray`。

关于访问共享可变状态的更多信息，请参阅[协程文档](../../../libraryguides/9.2-Coroutineskotlinxcoroutines/9.2.10-SharedMutableStateAndConcurrency/)。
