`async-std` 遵循 https://semver.org/。

简而言之：我们以 `MAJOR.MINOR.PATCH` 格式为软件版本编号。我们在以下情况下递增版本号：

* MAJOR（主版本）：存在不兼容的 API 变更时
* MINOR（次版本）：以向后兼容的方式引入新功能时
* PATCH（补丁版本）：进行向后兼容的 bug 修复时

我们会在主版本之间提供迁移文档。

## 未来预期

`async-std` 对以下概念使用自己的实现：

* `Read`
* `Write`
* `Seek`
* `BufRead`
* `Stream`

为与生态系统集成，所有实现这些 trait 的类型也同时实现了 `futures-rs` 库中对应接口的实现。
请注意，我们的语义化版本保证不延伸至对这些接口的使用。我们预期这些接口会保守地更新，并保持同步。

## 最低版本策略

当前暂定策略是：使用本 crate 所需的最低 Rust 版本可以在次版本更新中提高。例如，如果 `async-std` 1.0 需要 Rust 1.37.0，那么所有 z 值的 `async-std` 1.0.z 也将需要 Rust 1.37.0 或更新版本。但是，对于 y > 0 的 `async-std` 1.y 可能需要更新的最低 Rust 版本。

一般而言，本 crate 对最低支持的 Rust 版本会持保守态度。不过，由于 `async/await` 是新特性，我们最初会以适度的节奏跟踪相关变更。

## 安全修复

安全修复将应用于本库所有_受支持_主版本修订中的_所有_次版本分支。此策略未来可能变更，届时我们将至少提前 _3 个月_ 通知。
