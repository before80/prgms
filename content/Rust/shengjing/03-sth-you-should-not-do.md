# 避免从入门到放弃

Rust 会带来前所未有的编程体验，但入门阶段比 Go/Python 更难：接触所有权、借用、生命周期、智能指针后，难度会陡升。不认真应对，往往只剩「重学」或「放弃」。

## 避免「试一试」心态

三点建议：

1. **做好遇阻准备** — 学 Rust 不只是学语法，还在学一套内存与并发思维
2. **不要浅尝辄止** — 连续七年「最受喜爱」的语言，值得系统投入
3. **跟一本好书走完全程** — 看一遍语法无法上手写项目（对比 Go 尤甚）

## 深入学习一本好书

勿指望「菜鸟教程 + demo」即可开工；踩坑后回炉的时间成本更高。应沉下心读**系统、成体系**的教程，提前趟过需大量实践才能悟到的坑。

## 千万别从链表或图开始练手

CS 课常教「新语言先写链表」，在 Rust 中**极不推荐**：

- 自引用结构（链表、图）是 Rust 难点，源于无 GC 又要内存安全
- 不会手写链表**不影响**日常开发与学习进度
- 练手首选：书中入门/进阶实战项目；若执意挑战，可跟本书链表专题

## 仔细阅读编译错误

Rust 编译器是「严师」：错误信息往往直接指出修改方向。读不懂时，**完整阅读** error 与 warning（含 Clippy lint），多数问题可据此解决。

## 勿生搬其他语言范式

Rust 非纯 OOP 也非纯 FP。可保留习惯，但需遵循 Rust 惯用法（见 [Rust 最佳实践](https://beatai.org/rust-course/practice/intro) 专题）。

## 总结

| 应避免 | 应坚持 |
|--------|--------|
| 从链表/图练手 | 系统读一本好书 |
| 只看错误前几行 | 完整读编译器提示 |
| 试一试就放弃 | 相信前方是星辰大海 |
