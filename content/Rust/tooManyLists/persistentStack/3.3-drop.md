> 原文链接: [https://rust-unofficial.github.io/too-many-lists/third-drop.html](https://rust-unofficial.github.io/too-many-lists/third-drop.html)

和可变链表一样，我们有递归析构问题。对不可变链表来说这没那么糟：若遇到某处另一链表的头节点，我们不会递归 drop 它。但仍值得关注，而且怎么处理不那么明显。之前是这样解决的：

```rust
impl<T> Drop for List<T> {
    fn drop(&mut self) {
        let mut cur_link = self.head.take();
        while let Some(mut boxed_node) = cur_link {
            cur_link = boxed_node.next.take();
        }
    }
}
```

问题在循环体：

```rust
cur_link = boxed_node.next.take();
```

这是在变异 Box 里的 Node，但 Rc 不行；它只给共享访问，因为可能有很多其他 Rc 指向它。

但若我们知道自己是最后一个还知道这个节点的链表，从 Rc 里移出 Node 其实没问题。也能知道何时停止：每当*无法*把 Node 取出来时。

看，Rc 有正好做这事的方法：`try_unwrap`：

```rust
impl<T> Drop for List<T> {
    fn drop(&mut self) {
        let mut head = self.head.take();
        while let Some(node) = head {
            if let Ok(mut node) = Rc::try_unwrap(node) {
                head = node.next.take();
            } else {
                break;
            }
        }
    }
}
```
