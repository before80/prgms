好了，`push` 和 `pop` 都写好了，现在可以真正测试我们的栈了！Rust 和 cargo 把测试当作一等公民，所以这会超级简单。我们只需写一个函数，并用 `#[test]` 标注。

在 Rust 社区里，我们通常把测试放在被测代码旁边。不过一般会为测试新建一个命名空间，避免与「真实」代码冲突。就像我们用 `mod` 指定 `first.rs` 应包含在 `lib.rs` 里一样，也可以用 `mod` 基本上*内联*创建一个全新文件：


```rust
// 在 first.rs 中

mod test {
    #[test]
    fn basics() {
        // TODO
    }
}
```

用 `cargo test` 运行。

耶，啥也不干的测试通过了！让它干点事。用 `assert_eq!` 宏。这不是什么特殊的测试魔法。它只是比较你给它的两个东西，不匹配就让程序 panic。没错，向测试框架表示失败的方式就是抓狂！

```rust
mod test {
    #[test]
    fn basics() {
        let mut list = List::new();

        // 检查空链表行为正确
        assert_eq!(list.pop(), None);

        // 填充链表
        list.push(1);
        list.push(2);
        list.push(3);

        // 检查正常弹出
        assert_eq!(list.pop(), Some(3));
        assert_eq!(list.pop(), Some(2));

        // 再推入一些，确保没有损坏
        list.push(4);
        list.push(5);

        // 检查正常弹出
        assert_eq!(list.pop(), Some(5));
        assert_eq!(list.pop(), Some(4));

        // 检查耗尽
        assert_eq!(list.pop(), Some(1));
        assert_eq!(list.pop(), None);
    }
}
```

哎呀！因为我们新建了模块，需要显式引入 `List` 才能用。

```rust
mod test {
    use super::List;
    // 其余相同
```

那个警告怎么回事……？我们明明在测试里用了 `List`！

……但只在测试时！为了安抚编译器（也对使用者友好），应标明整个 `test` 模块只在运行测试时编译。


```rust
#[cfg(test)]
mod test {
    use super::List;
    // 其余相同
}
```
