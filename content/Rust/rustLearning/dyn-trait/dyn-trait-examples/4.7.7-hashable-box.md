# 可哈希的 Box {#hashable-box}


> 原文链接: [https://quinedot.github.io/rust-learning/dyn-trait-hash.html](https://quinedot.github.io/rust-learning/dyn-trait-hash.html)


假设我们有一个[实现了 `Eq` 的 `dyn Trait`](../4.7.4-dyn-partial-eq/)，但我们还希望它实现 `Hash`，以便能在 `HashSet` 中使用 `Box<dyn Trait>`，或作为 `HashMap` 的键等。

<details>
<summary>这是我们的起点</summary>

与[之前](../4.7.4-dyn-partial-eq/)相比，唯一更新是要求 `Eq`：
```diff
-impl<T: Any + PartialOrd> DynCompare for T {
+impl<T: Any + PartialOrd + Eq> DynCompare for T {

+impl Eq for dyn DynCompare {}
+impl Eq for dyn Trait {}
```

完整代码：
```rust
use core::cmp::Ordering;
use std::any::Any;

trait DynCompare: Any {
    fn dyn_eq(&self, other: &dyn DynCompare) -> bool;
    fn dyn_partial_cmp(&self, other: &dyn DynCompare) -> Option<Ordering>;
}

impl<T: Any + PartialOrd + Eq> DynCompare for T {
    fn dyn_eq(&self, other: &dyn DynCompare) -> bool {
        if let Some(other) = (other as &dyn Any).downcast_ref::<Self>() {
            self == other
        } else {
            false
        }
    }

    fn dyn_partial_cmp(&self, other: &dyn DynCompare) -> Option<Ordering> {
        (other as &dyn Any)
            .downcast_ref::<Self>()
            .and_then(|other| self.partial_cmp(other))
    }
}

impl Eq for dyn DynCompare {}
impl PartialEq<dyn DynCompare> for dyn DynCompare {
    fn eq(&self, other: &dyn DynCompare) -> bool {
        self.dyn_eq(other)
    }
}

impl PartialOrd<dyn DynCompare> for dyn DynCompare {
    fn partial_cmp(&self, other: &dyn DynCompare) -> Option<Ordering> {
        self.dyn_partial_cmp(other)
    }
}

trait Trait: DynCompare {}
impl Trait for i32 {}
impl Trait for bool {}


impl Eq for dyn Trait {}
impl PartialEq<dyn Trait> for dyn Trait {
    fn eq(&self, other: &dyn Trait) -> bool {
        (self as &dyn DynCompare) == (other as &dyn DynCompare)
    }
}

impl PartialOrd<dyn Trait> for dyn Trait {
    fn partial_cmp(&self, other: &dyn Trait) -> Option<Ordering> {
        (self as &dyn DynCompare).partial_cmp(other as &dyn DynCompare)
    }
}

impl PartialEq<&Self> for Box<dyn Trait> {
    fn eq(&self, other: &&Self) -> bool {
        <Self as PartialEq>::eq(self, *other)
    }
}

impl PartialOrd<&Self> for Box<dyn Trait> {
    fn partial_cmp(&self, other: &&Self) -> Option<Ordering> {
        <Self as PartialOrd>::partial_cmp(self, *other)
    }
}
```

与[我们讨论 `Clone` 时](../4.7.3-cloneable-box/)类似，`Hash` 不是对象安全的 trait。因此我们不能简单地将 `Hash` 作为超 trait 约束添加。这次不是因为需要 `Sized`，而是因为[它有泛型方法：](https://doc.rust-lang.org/std/hash/trait.Hash.html#tymethod.hash)
```rust
# use core::hash::Hasher;
pub trait Hash {
    fn hash<H>(&self, state: &mut H)
       where H: Hasher;
}
```

幸运的是，我们可以使用[擦除 trait](../4.7.6-erased-traits/) 方法：

```rust
use std::collections::HashSet;
use core::hash::{Hash, Hasher};

trait DynHash {
    fn dyn_hash(&self, state: &mut dyn Hasher);
}

// impl<T: ?Sized + Hash> DynHash for T {
impl<T: Hash> DynHash for T {
    fn dyn_hash(&self, mut state: &mut dyn Hasher) {
        self.hash(&mut state)
    }
}

impl Hash for dyn DynHash + '_ {
    fn hash<H: Hasher>(&self, state: &mut H) {
        self.dyn_hash(state)
    }
}
```
此时值得指出我们依赖的几点：
- [`Hasher`](https://doc.rust-lang.org/std/hash/trait.Hasher.html) *是*对象安全的。

    若不是这样，我们就无法在 `dyn_hash` 方法中接受 `&mut dyn Hasher`。

- `Hash::hash<H: Hasher>` 中的泛型 `H` 有隐式 `Sized` 约束
    <br>若不是这样，我们就无法在 `dyn DynHash` 的实现中将 `&mut H` 强制转换为 `&mut dyn Hasher`。我们也不会完全无路可走——[此递归定义](https://doc.rust-lang.org/std/hash/trait.Hasher.html#impl-Hasher-for-%26mut+H)意味着我们可以将 `&mut &mut H` 强制转换为 `&mut dyn Hasher`，代价是一些间接层。

    然而，这确实表明*放宽* `Sized` 约束可能是破坏性变更！


继续，我们仍需将此新功能接入我们自己的 trait。
```diff
-trait Trait: DynCompare;
+trait Trait: DynCompare + DynHash {}
```
```rust
# use core::hash::{Hash, Hasher};
# trait DynHash { fn dyn_hash(&self, _: &mut dyn Hasher); }
# trait Trait: DynHash {}
// 与我们对 `dyn DynHash` 所做的一样
impl Hash for dyn Trait {
    fn hash<H: Hasher>(&self, state: &mut H) {
        self.dyn_hash(state)
    }
}
```
[就是这样！](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&gist=8c9bcb89f72f7267bc2babda8e1efe8a)
```rust
    let bx1a: Box<dyn Trait> = Box::new(1);
    let bx1b: Box<dyn Trait> = Box::new(1);
    let bx2: Box<dyn Trait> = Box::new(2);
    let bx3: Box<dyn Trait> = Box::new(true);

    let hm: HashSet<_> = HashSet::from_iter([bx1a, bx1b, bx2, bx3].into_iter());
    assert_eq!(hm.len(), 3);

```

## 结语 {#closing-remarks}

若适用，[借用具体类型](../4.7.5-generalizing-borrows/) 可能是更好的方法，因为它不需要 `Any + 'static`。

尽管效率极低，对所有内容返回相同哈希值的 `Hash` 实现也是正确实现。其他「粗略近似」亦然，例如只哈希 `TypeId`。逻辑行为所要求的只是两个相等的值必须有相等的哈希。因此可以说，我们不必费尽周折去得到值的精确哈希。

你可能注意到这行被注释掉了：
```rust
// impl<T: ?Sized + Hash> DynHash for T {
impl<T: Hash> DynHash for T {
```

我选择较不通用实现的原因有二：
- 示例不需要更通用版本
- 审慎：因为我们 `impl Hash for dyn DynHash`，技术上与编译器对 `DynHash for dyn DynHash` 的实现重叠。
[见该小节最后一段。](../../4.2-implementations/#the-implementation-cannot-be-directly-overrode)
