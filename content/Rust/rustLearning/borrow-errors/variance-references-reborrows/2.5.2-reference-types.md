# 引用类型 {#reference-types}


> 原文链接: [https://quinedot.github.io/rust-learning/st-types.html](https://quinedot.github.io/rust-learning/st-types.html)


先从一个问题开始：`&str` 是一种类型吗？

在不咬文嚼字、不追求形式严谨时，几乎所有人都会说是，`&str` 是一种类型。然而从技术上讲，它是一个由泛型生命周期参数参数化的*类型构造器*。因此严格来说 `&str` 不是类型，某个具体生命周期的 `&'a str` 才是类型。`&'a str` 与 `&'b str` 不是同一类型，除非 `'a == 'b`。

类似地，对泛型 `T` 而言 `Vec<T>` 是类型构造器，而 `Vec<i32>` 是类型。`Vec<T>` 与 `Vec<U>` 不是同一类型，除非 `T == U`。

不存在适用于所有可能内容的单一 `Vec` 类型，也不存在适用于所有可能生命周期的单一 `&str` 类型。

所谓「具体生命周期」，我指的是在编译期确定的生命周期。Rust 中「生命周期」的精确定义出人意料地复杂，超出本指南范围，但下面是一些 `&str` 及其具体类型的例子。

```rust
// 具体的生命周期 `'a` 在每个调用点确定。我们稍后会更深入探讨这意味着什么。
//
// `b` 的类型中的生命周期同理，只是我们没给它起名。
fn example<'a>(a: &'a str, b: &str) {
    // 字面量字符串是 `&'static str`。
    let s = "literal";

    // 局部借用的生命周期由编译器分析确定，
    // 没有名字（但仍是一个单一生命周期）。
    let local = String::new();
    let borrow = local.as_str();

    // 下面两者相同，只是告诉编译器推断生命周期。
    // 在这个小例子里，与不写类型标注效果相同。
    let borrow: &str = local.as_str();
    let borrow: &'_ str = local.as_str();
}
```
